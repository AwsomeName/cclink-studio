# 最近会话统一切换器

> 状态：RS-1 已实现并通过完整工程门禁；真实在线远程 Agent 验收待执行。最后更新：2026-08-17。

## 用户验收目标

1. 打开本地工作空间，顶部直接显示当前工作空间的 2–5 个最近会话；点击即可切换，更多会话进入“···”。
2. 打开已配对的远程工作空间，同一位置改为显示远程会话，不再在 Agent 工具栏出现第二个下拉框和第二个“＋”。
3. 点击顶部唯一“＋”：本地工作空间新建本地会话，远程工作空间新建远程会话。
4. 远程会话发送第一条用户消息后，自动用消息内容生成可识别标题；已有随机尾号标题在本地历史可安全补齐。
5. 远程离线时仍可查看已有会话；新建入口不可用。本地工作空间及本地 Agent 不受影响。
6. 完整会话搜索、归档和恢复继续在左侧“会话”列表完成。

## RS-1 问题记录

本地工作空间顶部使用横向最近会话标签，远程 Agent 工具栏使用原生下拉框。远程侧栏已经拥有完整会话列表，因此工具栏下拉与侧栏重复；顶部本地“＋”和远程工具栏“＋”同时出现，也无法清楚表达新建作用域。随机尾号远程标题进一步增加了识别成本。

## 当前决策

- `ConversationQuickSwitcher` 是统一的顶部最近会话投影；根据当前 `WorkspaceRef.kind` 读取本地 Agent 或 CCLink 远程会话 owner。
- 最近会话最多保留 5 个，并按面板宽度展示 2–5 个；当前会话必须可见，其余进入“···”。
- `agent.newConversation` 是唯一新建命令，执行时按当前工作空间类型路由；不创建远程工作空间下的伪本地会话。
- 本地 `agent-store` 与远程 `cclink-store` 继续分别拥有各自状态。统一组件不持久化第二份会话数据，也不改变 `RemoteWorkspaceRef` 边界。
- 远程 Agent 工具栏只保留 Agent 状态、设备信息和诊断；完整列表仍由 `RemoteSessionsSidebar` 管理。
- CCLink 远程服务在首条用户消息时生成最多 30 个字符的标题；同步只返回占位标题时保留本机已有的明确标题，远端返回明确标题时仍采用远端事实。

## 失败降级与边界

- 未登录、远程离线、协议不兼容或缺少远程会话能力时，不清除已持久化的远程会话历史；新建和发送按现有 CCLink 能力门禁失败或禁用。
- 切换工作空间后只展示严格匹配 endpoint、workspace ID 的远程会话，异步加载继续使用现有 generation 丢弃过期结果。
- 远程会话使用独立 `remote-thread` 上下文目标，不伪装为本地 Thread；右键可打开、拖入中间 Tab 或关闭（归档）空闲会话。运行中会话因当前协议不支持可靠停止，关闭动作保持禁用。
- 自动标题只使用已持久化的首条用户消息，不调用模型、不访问网络，也不把消息内容写入新的状态文件。

## 验证

- 组件与视图模型测试覆盖本地/远程顶部投影、远程工作空间过滤、当前会话保留和响应状态。
- 命令测试覆盖同一个新建命令分别路由本地与远程 owner。
- CCLink 服务测试覆盖历史占位标题补齐和标题工具函数边界。
- `pnpm verify` 已通过：270 个测试文件、1578 项测试通过、2 项跳过；格式、lint、类型检查、架构边界和生产构建均通过。
- 真实在线 Agent 仍需按“用户验收目标”完成一次人工回归；自动化通过不能替代该结果。

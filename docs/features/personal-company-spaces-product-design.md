# “我的空间 / 我的公司”固定入口产品设计

> 日期：2026-11-12，Asia/Shanghai。
> 状态：用户已确认采用两个固定入口，本轮交付产品设计、效果图与实施计划；应用功能尚未实现，未授权本轮编码或发布。
> 效果图：[交互预览](../design/personal-company-spaces/preview.html)、[图片与场景说明](../design/personal-company-spaces/README.md)。
> 实施：[实施计划](personal-company-spaces-development-plan.md)。长期边界：[ADR 0024](../decisions/0024-personal-company-space-bindings.md)。
> 本文定义下一版目标：实施后取代单一默认入口和“公司经营跟随当前空间”的入口规则。旧文档中的已实现行为仍是当前运行事实；账目、发布及公司 AI 工作的独立验收不受影响。

## 产品结论

顶栏左侧常驻“我的空间”和“我的公司”，右侧继续打开普通本地或远程工作空间。两个固定入口对应不同的本地资料归属：个人工作有默认落点，公司经营有稳定入口。打开研发目录不会改变“我的公司”的指向。

“我的空间”首次启动即可使用；“我的公司”入口始终存在，首次使用时连接已有公司或启用新公司。公司未启用、公司资料不可用或远程服务离线，不阻挡个人笔记、对话、浏览器、终端等本地能力。

固定入口是现有普通本地工作空间的用途与导航关联，不新增公司账号、团队权限、Workspace 类型或运行系统。“个人 / 公司”区分资料组织，不构成多人安全隔离。

## 顶栏与命名

顺序固定：`我的空间 | 我的公司 | 分隔 | 普通工作空间… | 打开其他空间 | 历史空间`。

- 两个固定入口常驻左侧，不参与普通空间拖拽排序，不提供关闭按钮。它们只固定导航位置，不强制后台加载公司数据或启动 Agent。
- 主标签固定为“我的空间”“我的公司”。实际公司名称在公司页、归属提示及入口说明中展示；修改公司显示名称不改目录名、不换工作空间身份。
- 普通空间保留原标签、关闭、排序及远程标识；已经绑定固定入口的同一稳定空间在顶栏不重复生成普通标签。
- 同一时刻只高亮实际激活的空间。打开首次启用、旧公司选择或目录恢复面板时，尚未成功切换前保留原选中状态。
- 900px 以上优先完整保留两个固定标签；普通空间先进入溢出区。保持当前选择可达，不靠截断“我的空间 / 我的公司”区分。
- 历史入口使用“历史空间”名称，并保留“未归档”历史入口；不把未归档草稿悄悄转存个人空间。

## 两个空间的页面

### 我的空间

默认进入个人工作台：新建笔记、新建会话、打开网页，以及当前个人空间最近使用的真实文档与会话。没有资料时展示空态，不补演示内容，不做跨空间聚合。

它是具有本地资料归属的 Workbench 页面；原全局 Home、未归档草稿和系统 Tab 的语义不改变。普通文件、会话、浏览器、终端和流程继续作用于当前空间。

### 我的公司

默认进入已绑定公司的公司总览，展示已有业务、财务入口、运营资料和原记录下钻。首次启用仍沿用现有“名称 → 启用 → 创建业务”的能力边界，不借此增加 AI 员工、经营评分或自动执行。

公司内部使用“公司总览 / 业务项目 / 财务 / 运营 / 资料与会话”页内导航。建议放在主区标题下，减少与顶栏固定入口、左侧能力栏重复的纵向公司导航。文件树等真正需要的 Sidebar 继续按原能力显示；右侧仍复用原 Agent Panel。

公司已停用时保留入口与关联，显示“重新启用原公司”；停用不删除资料，也不等于解绑后创建另一家公司。

## 侧边激活栏调整

推荐使用稳定的跨空间能力栏：展开态保留现有约 140px 的图标＋文字，收起态沿用现有 48px 图标栏及统一收放规则。公司页通过页内导航释放原公司 Sidebar 的占用；不新增独立导航状态所有者。

| 分组     | 入口                             | 行为                                                                                       |
| -------- | -------------------------------- | ------------------------------------------------------------------------------------------ |
| 工作     | 工作台、文件、会话、浏览器、终端 | 作用于当前空间；工作台回该空间的落地页                                                     |
| 经营     | 公司经营、公司账目               | 全局快捷入口：先切到绑定的“我的公司”，再打开总览或原账目；非公司空间显示跳转标识与目标说明 |
| 流程     | 文章发布、事务、定时任务         | 保持当前空间归属；不因为它们也能用于经营而暗中切换公司                                     |
| 资源     | 网站与账号、角色、数据源         | 保持各领域现有资源及授权范围；网站账号仍本机全局复用                                       |
| 更多工具 | 视频创作、硬件生产、CCLink 远程  | 收纳低频入口，仍可通过一个显式入口、键盘和原命令到达，不删除原功能                         |
| 底部     | 设置、统一收放                   | 保留原设置与收放生命周期                                                                   |

“公司账目”快捷入口与旧账目深链接必须区分：前者进入固定公司，后者使用记录本身的原工作空间。不能统一重定向导致旧账目打不开。

侧栏只有当前能力项的实际选中状态；顶栏表达空间归属，页面内导航表达公司业务位置。会话列表和 Agent 面板仍遵守既有会话导航规则，不用一套新增侧栏状态替代它们。

## 现有公司资料兼容

### 原则：关联入口，保留原资料

“我的公司”保存对已有普通本地工作空间的引用。公司库、账目库、文件、会话、发布事务和任务仍由原领域服务拥有，不复制到新建的“公司总库”。原稳定 workspace ID 与所有业务 ID 保持不变。

只检查 Studio 已登记、用户已授权的本地空间；不扫描整块磁盘，不遍历云盘，不读取历史系统钥匙串。目录名、最近打开时间、有一份账单或运营稿，都不足以证明它就是主公司。

只有公司元数据与基础层稳定身份匹配、读取有效，才列为“已发现公司”。停用但有保留资料的公司也要展示为“已停用”；损坏、无权限、失效路径单独展示，不能当成“没有公司”。识别过程必须只读，不能通过调用会建库或迁移的普通打开方法探测。

| 两入口指向同一目录或同一稳定身份         | 拒绝完成重复关联                       | 保留已有有效归属                         | 必须为另一用途选独立空间；同目录别名／符号链接不算独立 |

新建两个默认目录为同级目录。若用户选择的个人和公司根目录相互包含，首版不完成该关联，说明资料范围重叠并让用户选择独立目录。原混合目录仍可访问，不以“整改”为由移动原件。

### 第一次接回已有公司

1. 用户点击“我的公司”，仍保持原空间激活；显示候选公司及其原路径。
2. 单候选预选；多候选由用户选择。明确显示“只关联入口，原目录、原账目、原会话保持原位”。
3. 如旧默认目录已用于公司，说明“我的空间使用独立目录；原目录中的个人内容仍在原处”。
4. 用户选择“使用这份公司资料”，基础层验证身份及可访问性后保存入口关联，并完成原工作空间切换。
5. 成功才选中顶栏“我的公司”，打开原公司总览。失败保留原界面与已完成的可恢复初始化；重试不会创建第二份公司。

对旧安装，个人目录的自动归属必须先完成只读兼容检查。旧默认目录疑似已有公司但无法核验时，不把它先认领为个人空间。可继续恢复原工作空间；点击“我的空间”时创建独立个人目录。

如果用户后来选择的原公司目录已被绑定为个人空间，不直接报错后卡住。提供一次明确的“整目录用途调整”：说明原目录全部内容留在原处并作为公司资料，新建独立个人空间；用户确认后，先验证新个人空间可用，再一次提交两个互不重叠的关联。任何一步失败保留原绑定。这里不分类移动文件，用户不接受则取消或另选公司目录。

### 原记录、后台运行与回退

- 账目流水、原件、业务关联、稿件和会话沿用原 owner；在 userData 中保存的事务继续按原 workspace ID 读取，本轮不做事务目录化。
- 发布步骤、平台结果、等待与未知状态不随入口绑定改变；绑定不触发发布或重发。
- 定时任务、正在运行的 Agent、Terminal 和 Browser 仍按原归属继续；改变入口绑定不继承或撤销执行授权，不启动旧任务。
- 历史 Tab 与深链接携带原空间。其他公司仍能作为普通空间打开，不迁移到被选为主公司的空间。
- 用户以后在空间设置中更换主公司，只更换入口关联；旧公司保留在历史空间。新公司校验失败不覆盖原关联。
- 兼容升级保存旧入口设置快照及一次版本化完成标记；中断可重试。回退旧版本时原业务目录未改写，新增个人目录仍是可手动打开的普通空间；不承诺旧版本认识两个固定入口。

## 首次启用与故障文案

- 无公司：`启用我的公司`；同时提供`选择已有公司资料`，避免用户误建空公司。
- 有旧公司：`继续使用已有公司资料`；主按钮为`使用这份公司资料`。
- 多公司：`选择从“我的公司”进入的资料`；明确其余公司仍保留。
- 路径丢失：`原公司资料暂时无法打开`；提供`定位原目录`、`选择其他已有公司`、`留在我的空间`。
- 不同身份：`所选目录不是原公司资料`；不能只凭同名目录覆盖原入口。
- 只读：明确标记只读；允许原服务支持的查看，写操作按真实能力禁用。不得为继续使用而降低路径或身份校验。

## 范围与验收边界

本轮不实现公司数据拆分／合并、跨设备同步、多人协作、公司级权限、完整备份恢复、自动经营、公开发布或新远程能力。既有默认空间、工作空间切换、公司与账目服务作为基础，不以创建新系统替代复用。

效果图中的公司、业务、文件均为示意。侧栏重排是推荐设计，实施需要保留原能力可达性并完成真实 Browser 遮挡及缩放验收。文档与图片交付不能写成用户功能已经上线。

## 拷问结论

方向成立，但最容易失败的不是两个按钮，而是旧资料归属：同一旧默认目录不能同时被标成个人和公司；混合资料不能自动分拣；多个公司不能靠猜测选择；跳转前不能让顶栏假装已切换。

下一步应先验收“新用户个人记录 + 老用户原公司接回 + 重启原记录可打开”这一条纵向闭环，再调整侧栏。没有这条闭环，不能把效果图完成或入口常驻算作功能交付。

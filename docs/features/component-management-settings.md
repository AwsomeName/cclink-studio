# 组件管理配置页

> 状态：页面、Claude 和首批 Runtime 资源的安装、检查、修复、卸载闭环已实现；真实双版本更新和通用插件仍未实现。
> 最后更新：2026-08-13。

## 用户现在能做什么

- 打开“设置 > 组件管理”，在一张清单中查看 Runtime、能力插件和内容包。
- 查看每项能力的类型、安装状态与当前版本、限定版本、可用版本和独立“安装”按钮。
- 在全新安装第一次进入工作台时自动看到该页面。
- 在 macOS arm64 上从固定 npm 包安装 Claude Runtime `2.1.211`，查看进度和失败原因。
- 安装包不携带 Claude 可执行文件；未安装且本机没有 Claude 时仅 Agent 不可用，工作台仍能启动。
- 从固定可信来源安装 OCCT `0.0.23`、scrcpy server `2.3.1` 和 agent-device Android
  Helper `0.17.2`；每行独立显示进度、结果与版本。
- 安装 OCCT 后，新 CAD 转换真实使用 `userData` 中的 WASM；文件损坏时退回随 App WASM。
- 安装 scrcpy server 后，下一次 Android 投屏连接使用 `userData` 中的 JAR；文件损坏时
  退回随 App JAR。
- Android Helper 明确显示“已下载 · 待宿主支持”，不会把仅完成下载伪装成业务已激活。
- App 替换并重启后继续使用 `userData` 中已安装的 Runtime，无需重装。
- 对四个受管 Runtime 逐行检查完整性；文件损坏时明确显示“可修复”。
- 强制重新下载并修复受管 Runtime；新文件校验失败时继续保留原有健康版本。
- 经二次确认卸载受管 Runtime；Claude 配置和 API Key 保留，OCCT/scrcpy 的随 App 回退资源不删除。
- 在 Agent 设置选择已安装的 managed Runtime 后，沿用现有 Provider、国内服务地址、
  API Key 和模型配置执行任务；组件安装不会改写这些配置。

## 用户现在还不能做什么

- 在两个真实 Claude 版本之间更新/回滚。
- 使用远程签名目录检查新版本，或查看权限差异。
- 让下载的 agent-device Helper APK 替换随 App 资源；当前上游 host 没有稳定注入接口。

因此当前页面已完成四类固定版本的独立安装、完整性检查、修复和卸载通道，但当前“检查”只对照
Studio 内置的可信固定目录，不访问尚未建立的远程签名目录，不能宣称真实版本更新或通用插件闭环完成。

## 页面位置

```text

└─ 组件管理
   └─ 清单
      ├─ 能力
```

## 清单范围

页面固定覆盖 `npm-updatable-capability-inventory.md` 中允许独立分发的能力：

- Runtime：Claude Code、CAD / OCCT / FreeCAD、`scrcpy-server.jar`、受控 WASM / 辅助程序；
- 能力插件：MCP 工具、模型或图片 Provider、数据源 Adapter、平台 Adapter、声明式命令；
- 内容包：模板、提示词、帮助文案、模型目录、兼容规则和静态资产。

完整 App 核心不混入这张清单。Electron、main、preload、IPC、主 React UI、权限系统和更新器
仍在“更新”页走完整应用 Release。

## 每行字段

| 字段     | 含义                                                 | 缺省显示                         |
| -------- | ---------------------------------------------------- | -------------------------------- |
| 能力     | 用户能理解的名称和用途                               | 必须有值                         |
| 类型     | Runtime、能力插件或内容包                            | 必须有值                         |
| 安装状态 | 已安装、未安装、检测中或不可用，并显示来源和当前版本 | 无法确认版本时不显示虚假版本     |
| 限定版本 | Studio 已验证并允许安装的精确版本或跟随策略          | 尚未完成兼容性定义时显示“待定义” |
| 可用版本 | 经过兼容性和信任校验、可以安装的远程版本             | 更新源未接入时显示“未接入更新源” |
| 操作     | 检查、安装/更新、修复和卸载受管版本                  | App 核心行显示“随 App 更新”      |

“已安装”和“已启用”是两件事。组件页显示安装来源和版本；Agent 设置拥有当前启用来源。
已下载但完整性校验或 probe 失败的版本不能显示成可用。

## 首次安装行为

1. 主进程以 `componentSetupPageSeenVersion` 作为全局唯一事实源。
2. 真正没有 `settings.json` 的新安装默认值为 `0`。
3. 工作台完成基础启动后，自动打开“组件管理”Tab，并记录当前页面版本 `2`。
4. 从携带 bundled Runtime 的旧版升级时再次打开一次；历史 bundled 选择迁移为 managed `2.1.211`。
5. 恢复默认设置不重置该标记，避免每次重置配置都重新弹出。
6. 页面可以关闭；首次进入不阻断用户使用工作台，也不强迫联网或下载。

未来若首次配置流程发生必须重新确认的重大变化，可以提升页面版本；普通文案和布局变化不能
借此反复打扰用户。

## 更新选择规则

- 没有可信的 `availableVersion` 时，该行“安装”按钮必须禁用。
- 只有远程目录、包哈希、维护者签名、平台、架构和 Host 兼容范围校验通过后，才能显示可更新。
- 扩大权限的版本不能自动安装。
- 当前固定 Claude 包点击“安装”后直接显示下载进度；未来远程目录若引入权限变化，必须在下载前确认。
- 当前“检查”重新验证本机文件并与内置可信固定目录比较；没有远程目录时明确报告“当前可信目录没有更新”。
- 有运行中任务的 Runtime 显示“任务结束后生效”，不得中途偷换。
- 部分更新失败时逐项显示结果，成功项不回滚，失败项回到其上一已知可用版本。

## 状态所有权

| 状态                          | 唯一所有者                              |
| ----------------------------- | --------------------------------------- |
| 首次配置页是否展示过          | `SettingsService`                       |
| 页面筛选和本次勾选            | renderer 临时状态                       |
| Runtime 安装版本与验证记录    | `RuntimeComponentManager`               |
| Claude 当前运行版本和活动任务 | `ClaudeRuntimeManager`                  |
| 插件安装、启用、健康和回滚    | 计划中的 `PluginManager`                |
| 内容包安装版本                | 计划中的内容包管理器，实施前由 ADR 定名 |
| 完整 App 更新                 | `UpdateService`                         |

## 端到端验收

页面和 Claude 安装验收：

1. 使用空白 `userData` 启动应用。
2. 用户进入工作台后，当前 Tab 自动打开“设置 > 组件管理”。
3. 表格包含上述全部能力，每行都有六个固定字段和独立“安装”按钮。Claude Runtime 明确限定为 `2.1.211`。
4. 本机 Claude 和 CAD 检测失败不影响其他行和工作台。
5. Claude、OCCT、scrcpy 和 Android Helper 显示各自固定可用版本且按钮可用；其他更新源未接入的行按钮不可用。
6. 关闭并重启应用，不会再次自动打开该页面。
7. 普通升级不反复弹出；从引导版本 1 升到瘦安装包的版本 2 时只再打开一次。恢复默认设置后也不重新弹出。

8. 点击 Claude“安装”后，真实下载并校验 npm 包，成功状态和版本立即更新。
9. 退出并替换整个 packaged `.app` 后安装状态、设置和凭证保留，且不重新下载。
10. 下载瞬断自动有限重试；最终校验失败或替换中途退出时，旧安装可恢复。
11. 启用 managed Runtime 后，在当前工作空间由 Agent 写入并读回文件，且两步都经过
    Studio MCP：2026-08-12 已用 `glm-5.2` 真实通过。
12. OCCT、scrcpy 和 Helper 三行通过真实来源下载与校验；完整替换 packaged `.app` 后复用且
    不重新下载、安装记录逐字节不变：2026-08-12 已通过真实 Electron UI smoke。
13. OCCT 安装后通过主进程 IPC 报告 `managed` 来源并完成真实 STEP 转换；scrcpy 无连接真机
    的验收环境，本批只完成 JAR 路径解析和完整性门禁，真机投屏仍是发布前人工验收项。
14. 打包后的 `.app` 不包含 `Contents/Resources/agent-runtime`，压缩包体积不再包含 Claude 二进制。
15. 已安装的四个 Runtime 每行显示“检查、修复、卸载”；检查能发现文件损坏，修复后恢复健康。
16. 修复候选最终校验失败时原健康版本仍可解析；卸载后受管文件消失，但 Claude 配置/API Key
    和随 App 的 OCCT、scrcpy 回退资源保留。
17. Agent 正在响应时 Claude 修复被拒绝；当前启用 managed Claude 时卸载被拒绝，并提示先切换来源。

双版本更新闭环仍必须另行验收远程目录签名、离线、错架构、安全点切换和回滚，不能用固定版本
安装或页面渲染通过代替。

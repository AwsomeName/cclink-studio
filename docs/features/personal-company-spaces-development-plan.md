## 本轮交付与下一轮目标

本轮用户可以查看六种界面状态、切换效果图中的固定入口、预览旧公司接回流程，审阅兼容矩阵。真实应用尚不能使用两个固定入口。

下一轮最小可验收能力：新用户不选目录即可记录个人资料；已有公司用户从固定入口打开原公司并下钻原账目与会话；打开专项目录、切回与重启后归属保持一致。先定义这条真实动作链，再分工程工作。

| `workspace-open-controller` / 原 transition          | 授权目录激活、代次取消、现场恢复                                 | 从固定用途解析普通本地 ref 后接入同一切换事务              |

## 实现前必须固定的约束

| 方面       | 约束                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 能力边界   | 固定入口与资料归属；已有公司业务范围保持原样                                                                                              |
| 状态所有者 | 固定用途关联进入现有 WorkspaceStateService 管理的本机状态；引用基础层稳定 ID 和登记路径。设置只保留启动偏好，不成为第二份可独立编辑的绑定 |
| 身份       | 两入口都是普通 local WorkspaceRef；相同 ID、相同规范路径或相互包含的根目录不能绑定为两份独立空间                                          |
| 生命周期   | 继续使用原 runtime 注册／停止、原 transition 与退出 flush；无需常驻的新公司 runtime                                                       |
| 权限面     | 可信 renderer、有界参数、已登记／显式授权目录、基础层 realpath 与身份核验；探测只读、无整盘扫描                                           |
| 人工确认点 | 旧公司候选选择、新公司启用、主公司更换、失效目录定位；不把识别结果当作移动或执行授权                                                      |
| 降级       | 公司失败保留个人和普通空间，个人失败保留公司和普通空间；失败不清空有效绑定，不冒充初始化完成                                              |
| 诊断       | 脱敏源／目标 ID、来源为固定入口或原记录、切换代次、失败分类、兼容完成版本；无账目金额、原文、凭证                                         |
| 验证       | 定向 contract／迁移故障测试、真实 Electron 目录与数据库验收、用户手动步骤、Browser 专项；分开报告                                         |

## 拟定绑定与兼容提交

命名为设计候选，实施时通过现有 shared contract/schema 定义，不在本文粘贴伪实现。

- 本机状态增加一个版本化固定用途关联对象，记录 personal 与可为空的 company 引用，以及兼容完成版本。引用使用现有稳定工作空间 ID 和登记路径，不复制公司业务。
- personal 与 company 不得指向同一身份，真实目录也不得相同或相互包含。公司显示名称仍由公司服务拥有，入口只读投影。
- 兼容完成前读取旧 `defaultWorkspacePath` 作为候选；完成后固定用途关联为入口事实源，旧字段只为回退保留，不双向同步两套绑定。
- 上次激活空间与固定用途是不同事实。`lastWorkspacePath`／启动偏好继续由原激活流程维护；临时恢复失败不能改写成用户主动选择个人空间。
- 多个窗口、双击与并发点击通过原主进程写队列、同一兼容版本和原切换代次收敛。创建目录、绑定与激活有不同提交点，不能以 UI 已显示来证明磁盘完成。

提交顺序：读取并保存旧设置快照 → 只读核验已登记候选 → 创建或复用个人目标（如有必要）→ 用户确认公司候选／新公司 → 校验引用与领域身份 → 原子保存固定用途关联及兼容版本 → 原 transition 激活 → 显示成功。

如果个人空间已可用、公司尚待选择，可提交 personal 与空 company，不标公司已启用；保留公司候选判断与旧默认来源，后续不重复创建个人空间。如果目录已初始化但入口提交失败，保留登记以供重试复用，不能删除用户可能已写入的资料。

公司业务库不因兼容探测而写入。现有 `getSnapshot`／普通打开路径是否会自动迁移或创建数据库必须先核查；若会，则在现有公司服务内增加窄只读描述能力，不另造 CompanyRegistry。坏库与读取失败显式记录，不返回“无公司”。

当用户要把当前已绑定个人空间的旧目录整体用于公司时，单独展示用途调整确认。先创建并验证新的个人空间，再原子替换 personal 与 company 两个引用；不允许中间状态两个入口指向同一目录，也不自动移动其中的个人内容。取消或提交失败保留原绑定；已初始化的新目录保留登记供重试。

## 分批交付

### P1：两个入口与原公司资料的最小闭环

用户验收：U1、U2、U3、U5、U6、U7 的基本路径。先保留现有侧栏外观，完成可实际进入的空间与公司。

1. 补齐基础层固定用途的有界 contract、身份校验和兼容原子提交；只为上述动作提供初始化、候选描述、绑定与读取。
2. 顶栏呈现两个固定入口，解析到普通 local ref 后走原切换事务；首次设置面板保持原选中，成功后才提交 UI。
3. 个人空间提供最小落地页，引用现有文档和会话创建能力；不把已有 global Home 改成本地空间。
4. 公司快捷命令解析固定公司；旧公司、账目、事务深链接保留原空间 scope。没有绑定时显示候选／启用面板。
5. 对新安装、旧单默认含公司、独立公司、混合目录及多候选执行真实目录和数据库检查；保留公司、业务及记录 ID 的前后证据。
6. 实际写个人笔记、进入原公司打开一笔原流水及一个原会话，再完整重启验证。此条通过才声明首批用户能力增量。

止损：单项前置超过 60 分钟，或同一阻塞连续失败两次，说明阻塞与替代路径；优先保留简单侧栏完成资料接回，不扩张为目录迁移、业务合并或新工作空间框架。

### P2：导航与切换体验

用户验收：U3、U4、U8、U9。基于 P1 已可用的真实数据，再调整界面。

1. 两固定入口与普通空间去重，普通空间关闭／排序不影响固定引用；显式未归档入口保留。
2. 侧栏按产品表重排，复用原 command 和 context-action；“更多工具”保持所有原入口、键盘和快捷键可达。
3. 公司导航放入主工作区，旧 CompanySidebar 入口与已保存 panel/tab 做兼容，不同时保留两套可独立切换的公司导航状态。
4. 处理“公司经营／公司账目”跳到公司与“文章发布／事务／任务”留在当前空间的差别；提示目标，顶栏和右侧 Agent scope 同步。
5. 1200/1440/900px 宽度、短窗口、深浅主题、收放与重启恢复下做真实应用几何检查；设计预览的窄屏适配不能代替桌面尺寸验收。
6. 重跑真实 Browser WebContentsView 的新 Tab、页内导航、pane 变宽、手动 30% 恢复和重启；保留 page zoom 与 visual scale 诊断。

不把导航整洁度当作公司数据兼容已经通过，也不通过隐藏功能减少验收项。

### P3：故障、回退与交付收口

用户验收：U5–U9 的完整反例与长期往返使用。

- 覆盖兼容各提交点中断、重复启动、主公司换绑失败、默认目录丢失／只读、重复身份与数据库损坏。
- 升级前后对比原目录清单、业务 ID、公司库与账目业务行、会话 ID、事务状态与任务启用状态；允许正常应用读写的变化需解释来源。
- 老版本回退只验证原资料仍能从原路径使用；不宣称旧 UI 支持固定入口。新版再启动可识别已完成的兼容版本。
- 真人执行下方路径并分别记录个人记录恢复、公司原记录下钻、导航故障反馈；公开发布仍使用原正式流程，授权另行取得。

## 必须验证的失败矩阵

| 故障／操作                            | 预期                                                           |
| ------------------------------------- | -------------------------------------------------------------- |
| 公司候选扫描部分目录拒绝访问          | 展示未核验对象，个人工作继续；不把扫描失败判成新安装           |
| 同一旧目录含个人内容和公司库          | 原目录整体保留给公司，新个人空间独立；旧个人记录仍可打开       |
| 两个不同路径指向相同真实目录或同一 ID | 拒绝重复绑定，不修写身份文件                                   |
| 个人与公司目录相互包含                | 拒绝新绑定并提示另选独立位置；原数据保留                       |
| 绑定保存中途失败                      | 原关联保持可读；已登记初始化可重试，无半完成高亮               |
| 公司点击尚未完成时用户切换另一空间    | 旧代次取消，不在新空间补开公司 Tab                             |
| 公司设置／选择面板取消                | 保持原空间、原现场与未发送输入                                 |
| 后台任务正在原公司运行时换主入口      | 运行仍归原空间；入口只改导航，不复制或重启运行                 |
| 原事务提交结果未知，之后兼容或换绑    | 仍为未知；只允许原流程核验，不自动重发                         |
| 从另一公司历史 Tab 打开记录           | 使用原 scope；主入口不被悄悄重绑                               |
| 远程空间断线时点击个人／公司入口      | 使用原统一离开远程与激活本地流程，保留恢复语义；不扩张远程权限 |
| 关闭公司视图                          | 固定引用保留，显示重新启用原公司；不得新建公司替代             |

## 工程检查与证据

优先运行受影响的 Workspace、bootstrap、命令、Tab／导航及公司服务检查。定向 smoke 通过只说明覆盖动作通过；不写“完整公司经营已完成”。按仓库规则完成应有的 verify／受影响 smoke 后，再记录真实 App 与真人验收。设计阶段不执行应用构建、签名、发布或用户资料操作。

截图至少包含：双固定入口、个人新笔记、原公司下钻、多个候选选择、混合目录提示、丢失路径恢复、窄窗口能力可达。诊断只保留脱敏对象标识与结果，不能把用户财务明细放进报告。

## 真人验收路径

1. 升级前记下原公司的一个业务、一笔流水、一个会话和一个未提交发布事务；使用既有备份能力保存必要资料。
2. 启动修复版，从“我的空间”写一份个人笔记。
3. 点击“我的公司”，核对原公司名称与路径，选择“使用这份公司资料”。打开上述四个原记录，确认不是空公司或复制记录。
4. 打开研发目录，保留一个会话；从侧栏进入公司，再回研发目录确认现场。关闭最后一个普通目录，应回个人空间。
5. 完整退出重启；分别回个人与公司，打开原笔记和原记录。检查待执行和未知发布状态未改变。
6. 在隔离副本中测试目录失效与混合资料；不得移动生产经营目录进行破坏性验收。

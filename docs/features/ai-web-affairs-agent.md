## 结论

产品定位：**个人或公司的网页事务代理人。**

CCLink Studio 的目标不是支持若干预定义网站，也不是为备案、工商、知识产权、应用商店
分别开发互不相干的功能。

目标产品是一个可持续、可交接、可恢复的 **AI 网页事务代理人**：

> 用户把个人或公司的网页事务交给 AI；AI 负责理解目标、规划步骤、准备资料、操作网页、
> 跟踪外部进度、处理失败和恢复现场，直到取得可验证结果。流程不要求一次执行完，也不
> 要求完全无人值守；必须由本人承担责任、完成认证或作出不可逆决定时，AI 把当前步骤
> 交给用户，用户完成后可以随时交还 AI 继续。

“接管”不等于 AI 点击所有按钮。接管的完成标准是：

- AI 始终知道这件事务当前在哪里。
- AI 知道下一步应由 AI、用户还是外部机构完成。
- 任意步骤都可以实际执行、明确交接或等待外部结果，不能只是装饰性清单。
- 页面关闭、人工介入、等待数天、切换工作空间或重启应用后，事务责任不丢失。
- 没有结果证据时，不能把事务标记为完成。

当前“工作空间内运营助手”仍是轻量平台入口和操作会话，不等同于本方案；当前
`BrowserTaskRun` 只描述一次浏览器执行，也不等同于跨多次运行的网页事务。

产品入口明确拆成两个一级能力：

- **网站与账号**：由当前“运营”演进而来的全局资源库，统一管理本机 Studio 中的网站、
  业务主体、账号、登录状态和运营矩阵。账号只添加并登录一次，所有项目都能看到和手动
  打开；侧栏不再以微信公众号、知乎、V2EX 等预置平台构成支持白名单。
- **事务**：保存一件具体业务的资源引用、动态流程、节点状态、卡点、人工交接和
  结果证据。事务继续属于具体项目，可以引用全局账号或运营矩阵以及本项目本地物料，
  但不复制密码、Cookie 或登录态。账号引用是否授权 AI 调用暂不决定。

Agent、浏览器和调度器是执行能力，不是用户要管理的长期业务对象，也不能成为事务
状态所有者。

## 产品目标与真人端到端验收

第一条产品闭环必须在真实应用中完成以下操作：

1. 用户在任一项目的“网站与账号”中点击添加；Studio 立即打开使用临时隔离登录环境的
   实际 Browser Tab，不先要求用户填写网站、主体、角色或登录提示表单。
2. 用户在该 Tab 中进入目标网站并完成登录，然后只确认一个侧栏显示名称，把当前网页和
   登录环境保存为全局网站账号资源；切换项目、关闭 Tab、重启 Studio 或移动项目后，
   仍可从任何项目侧栏看到同一账号，并用同一 Profile 和 Session 重新打开。
3. 用户用自然语言交代一件未预定义的网页事务，例如“替公司完成某个平台的开发者
   认证并提交应用上架”。
4. Studio 创建一件属于当前项目的持久事务，明确当前代表的个人或公司、最终目标、
   全局账号或运营矩阵引用、本项目材料和必要边界。
5. 在 AI 账号调用方案另行确认后，AI 才能通过受约束的资源启动逻辑激活或创建正确网页
   Tab；开始操作前仍必须重新核验实际页面、账号身份和登录状态。账号全局化本身不能
   被解释为 AI 已获准调用。
6. 每个网页动作都能看到当前步骤；用户可以随时暂停、终止或接管页面。
7. 遇到扫码、人脸、短信、电子签名、法律声明、付款或最终提交时，AI 保存现场并把
   步骤转为“需要我处理”，本次 Agent 运行正常结束。
8. 用户可以在浏览器中完成一个或多个手工页面操作，然后点击“交还 AI”。
9. AI 重新观察实际页面，核对用户完成后的结果，必要时重规划，而不是从旧内存继续
   盲目执行。
10. 如果提交后需要等待外部审核，事务进入“等待外部”；浏览器和 Agent 不保持假运行。
11. 关闭并重启 Studio 后，用户仍能看到同一事务、当前步骤、使用的身份、已有材料、
    最近证据和下一步。
12. 到达检查时间或用户点击继续后，AI 创建新的关联运行，重新激活或创建正确资源 Tab，
    查询状态并继续办理。
13. 遇到驳回或补正时，AI 保存官方原始原因、准备补正方案，并再次进入 AI 或人工步骤。
14. 取得申请编号、回执、审核结果、证书、上架地址或其他明确证据后，AI 才能把相应
    步骤标记完成。
15. 所有步骤完成或由用户明确终止后，事务进入终态，并保留可审计时间线。

只有这条流程在真实未知网站或尚无专用适配器的网站上通过，才能声明“AI 网页事务
代理人”的第一条产品闭环完成。只实现事务列表、状态机、提示词、Mock 页面或单次
Browser 自动化，不能声明产品能力完成。

## 用户心智

用户只需要理解以下概念：

| 概念       | 用户含义                                         |
| ---------- | ------------------------------------------------ |
| 网站与账号 | 所有项目可见、只需配置一次的网页、账号与运营矩阵 |
| 运营矩阵   | 可跨项目复用的一组全局网站账号                   |
| 事务       | 我交给 AI 负责到底的一件事                       |
| 流程       | 这件事由哪些有依赖关系的节点组成                 |
| 当前节点   | 当前具体环节办到哪里、轮到谁处理                 |
| 证据       | 为什么可以确认节点或整件事已经完成               |

Browser Profile、Session Partition、Cookie、Agent Thread、BrowserTask、IPC、运行 ID
和调度器都是实现概念，不应要求用户理解。

## 适用范围

网页事务可以属于个人、个体工商户、公司或其他用户明确授权的主体，包括但不限于：

- 工商登记、变更、年报、公告和注销。
- 税务、社保、公积金、银行及企业服务事项。
- 知识产权账号、实名认证、申请、补正和续展。
- ICP、App、公安联网及其他备案或许可事项。
- Apple、Android 国内应用商店及其他软件分发平台账号注册、认证、提交和审核。
- 云平台、开放平台、支付平台、广告平台和电商平台入驻。
- 招聘、采购、供应商注册、投标、报销和合同流转。
- 个人证件、资格、保险、教育、出行及其他通过网页办理的事务。
- 其他由用户明确发起或通过授权事件来源进入事务收件箱的网页事务。

平台专用程序可以提高常用网站的成功率，但不得成为产品支持范围的白名单。没有专用
程序时，通用网页代理仍可观察页面、尝试执行、请求人工接管或明确失败原因。

## 非目标和不可承诺边界

第一版不承诺：

- 所有事务完全无人值守。
- 绕过验证码、短信、人脸、电子营业执照、硬件密钥、电子签名或网站风控。
- 代替用户作出法律事实判断、真实性承诺、专业法律意见或最终商业决策。
- 在页面状态无法验证时猜测成功。
- 在没有外部事件来源时自动知道个人或公司“所有应该办理的事项”。
- Studio 完全退出后仍由本地 OSS 进程准时执行或监控。
- 对所有网站提供相同成功率。
- 通过批量多账号、规避平台规则或违反网站条款的方式提高自动化覆盖。

AI 无法执行某一步时，不代表整件事务失效。它必须把该步骤转成明确、可操作的人工
任务，保留前后依赖，并在用户完成后继续负责剩余流程。

## 执行责任模型

每个步骤必须采用以下一种责任模式：

| 模式              | 当前执行者    | 典型行为                                 | 完成方式                 |
| ----------------- | ------------- | ---------------------------------------- | ------------------------ |
| AI 执行           | AI            | 查询、读取、填写、整理、下载、低风险准备 | AI 验证后记录证据        |
| AI 准备、用户确认 | AI → 用户     | 最终提交、发布、付款、法律声明           | 用户确认后继续执行或接管 |
| 用户执行、AI 接回 | 用户 → AI     | 扫码、人脸、短信、签名、主观选择         | AI 重新观察并验证        |
| 等待外部、AI 复查 | 外部机构/平台 | 审核、制证、人工处理、异步回执           | 新运行检查外部结果       |

步骤不能因为当前没有自动化工具就留成不可执行的文字。至少必须包含：

- 给用户的明确操作说明。
- 要打开的官方页面或线下入口。
- 所需材料。
- 预期完成结果。
- 用户怎样把结果交还 AI。
- AI 接回后怎样验证。

## 事务、运行和浏览器现场

三者必须严格分离：

```text
网页事务 WebAffair
├─ 持久目标、计划、当前步骤、材料、证据和责任
├─ AgentRun 1：查要求、准备资料
├─ BrowserTaskRun 1：填写第一段表单
├─ 人工步骤：扫码和签名
├─ AgentRun 2：接回页面并提交
├─ 等待外部：审核
└─ AgentRun 3：查询结果并下载回执
```

- 网页事务可以跨越多个 Agent Thread、Browser Tab、运行和日期。
- Agent 运行是有界执行；等待用户或外部时必须结束，不无限占用模型或子进程。
- Browser Tab 是当前工作空间对全局网站账号的可丢失运行投影；Tab 关闭不能删除账号、
  Session 或事务事实。
- 恢复事务时可以创建新的 Tab 和 Agent 运行，但必须通过事务保存的全局账号引用和既有
  证据重新对账，不能直接复用当前任意 Profile 或网页。AI 是否可以启动该账号仍取决于
  后续独立授权方案。
- 不能把已消失的 Agent 或 Browser 进程恢复成假运行态。

## 事务状态

事务状态描述整体责任：

```text
draft
  -> active
      -> needs-attention
      -> waiting-external
      -> paused
      -> completed
      -> failed
      -> cancelled
```

| 状态       | 用户含义                             |
| ---------- | ------------------------------------ |
| 草稿       | 目标尚未确认，AI 还没有开始负责执行  |
| 处理中     | AI 或用户正在推进当前步骤            |
| 需要我处理 | 必须由用户完成确认、认证、选择或修复 |
| 等待外部   | 已完成本方动作，等待平台或机构结果   |
| 已暂停     | 保留全部现场，但不会继续创建运行     |
| 已完成     | 最终目标已有足够证据                 |
| 已失败     | 无法继续，且有明确失败原因和替代路径 |
| 已取消     | 用户明确终止，不再继续推进           |

“需要我处理”和“等待外部”都不是运行中状态。它们必须可以持久化、关闭页面和重启
恢复。

## 流程节点状态

事务状态、节点状态和资源状态必须分开：

- 事务状态描述整件事当前由谁负责、是否等待或结束。
- 节点状态描述具体办理环节已经推进到哪个业务阶段。
- 资源状态描述材料是否有效、网站是否可访问、账号是否登录。

节点的通用执行状态描述下一次实际动作：

```text
blocked
  -> ready
      -> running
          -> waiting-human
          -> waiting-external
          -> verifying
          -> completed
          -> failed
          -> skipped
          -> cancelled
```

每个步骤至少具有：

- 目标与执行者。
- 前置条件和依赖步骤。
- 必需材料与允许使用的账号。
- 允许执行的动作和人工确认策略。
- 成功判据和需要保存的证据。
- 有界重试与失败降级。
- 人工接管说明和恢复说明。
- 所属事务、运行和项目关联。

计划允许根据页面和外部结果动态增加、删除或重排未执行步骤，但已经发生的步骤、
尝试和证据只能追加历史，不能被新计划静默覆盖。

面向用户的业务阶段可以在通用执行状态之上细分为：

```text
待准备
  -> 待提交
      -> 已提交
          -> 审核中
              -> 需要补正
              -> 已审核
                  -> 已通过
                  -> 未通过
```

不同节点可以使用不同业务阶段，但必须映射回统一执行责任、成功判据和终态；UI 不能
只凭业务文案猜测节点是否可执行。

## 动态流程与通用事务 Tab

不同事务不得各自实现一套页面。产品只维护一套通用事务 Tab，读取结构化流程模型：

```ts
interface WebAffairFlow {
  version: number
  nodes: WebAffairNode[]
  edges: WebAffairEdge[]
}

interface WebAffairNode {
  id: string
  type: string
  title: string
  status: string
  executor: 'ai' | 'user' | 'external'
  resourceRefs: string[]
  materialRefs: string[]
  evidenceRefs: string[]
  successCriteria: string[]
  blocker?: WebAffairBlocker
  availableActions: WebAffairNodeAction[]
}
```

具体流程由四层共同形成：

1. 产品提供准备材料、登录、填写、上传、确认、提交、等待、补正、查询和归档等通用
   原子节点。
2. 内置模板或插件提供 App 发布、App 备案、工商变更、知识产权认证等参考流程。
3. 平台增强程序补充已知入口、字段语义、状态识别和证据提取方式。
4. AI 根据用户目标、主体、已有资源和实际网页生成并维护当前事务实例。

模板只用于创建或提出变更，不能拥有事务状态。AI 可以自动调整尚未执行且无外部
副作用的节点；已经执行、提交或产生证据的节点不能删除或覆盖，只能追加补正、替代
节点和变更记录。重大依赖、主体、账号、最终提交或不可逆动作变化必须由用户确认。

模板升级不自动重写既有事务。既有事务固定当前流程版本，只有用户或 AI 显式提出并
通过校验的流程变更才能产生新版本。

## 人工接管与交还 AI

### 用户随时接管

用户在 AI 操作网页时必须始终能够：

- 暂停 AI。
- 接管当前页面。
- 修改 AI 已填写但尚未提交的内容。
- 完成扫码、认证、签名或选择。
- 跳过、取消或要求重规划当前步骤。
- 终止整件事务。

接管后页面进入明确的人工模式，AI 不得在后台继续点击或填写。

### AI 主动交接

出现以下情况时，AI 必须主动停止并交给用户：

- 验证码、短信、人脸、扫码、硬件密钥或电子签名。
- 需要确认法律事实、材料真实性或对外承诺。
- 付款、下单、开户、借款或费用变化。
- 发布、提交、删除、注销、撤回或其他不可逆外部动作。
- 多个合理选项需要用户作商业或主观判断。
- 页面状态不确定、账号可能错误或材料版本冲突。
- 网站风控、条款或自动化限制不允许继续。

### 用户交还 AI

用户点击“交还 AI”后：

1. AI 重新读取当前 URL、页面、事务保存的全局账号引用和可见状态。
2. 对比交接前保存的预期结果。
3. 不根据旧对话假设用户完成了哪些动作。
4. 能验证时追加人工操作结果证据。
5. 页面已经进入其他分支时更新后续计划。
6. 无法验证时询问最小必要信息，或继续保持“需要我处理”。

人工接管期间发生的具体点击不要求全部被自动记录，但交还后的外部结果必须验证并
进入事务时间线。

## 通用网页执行与平台增强

### 通用网页代理

面对未预定义网站，AI 使用当前可用能力形成观察—动作—验证循环：

```text
观察页面
  -> 判断当前阶段和可用动作
  -> 执行一个有界动作
  -> 验证页面是否达到预期
  -> 保存必要证据
  -> 继续、重试、重规划或交给用户
```

通用能力包括：

- 导航、搜索、多 Tab 和跨页面流程。
- DOM、可访问性语义和必要的视觉理解。
- 表单填写、下拉、日期、富文本、iframe 和弹窗。
- 文件上传、下载和回执保存。
- 登录态识别、全局网站账号引用和失效诊断。
- 页面错误、网络错误、风控和验证码分类。
- 页面变化后的语义重定位。

每个动作之后必须验证后置条件。不能用“工具调用成功”替代“网页业务结果成功”。

### 平台增强程序

高频平台可以通过版本化程序或连接器增强：

- 官方 API、Webhook 或 SDK。
- 站点入口和账号绑定。
- 字段语义与材料映射。
- 原始状态到用户状态的映射。
- 高风险控件和最终提交识别。
- 页面变化探测和真人验收样例。
- 失败降级和人工处理说明。

增强程序不是固定坐标宏，也不能拥有独立事务状态。程序失效时必须降级回通用网页
代理或人工步骤，不能丢失原事务。

用户完成一次真实流程后，系统未来可以基于已脱敏轨迹生成候选程序；候选程序必须
经过用户检查、版本化和真人复验后才能复用，不能让模型静默修改生产操作规则。

## 全局网站与账号、运营矩阵和工作空间 Tab

当前实现已经具备真实网页登录、独立 Profile 和项目账号资源，但 `WebAccount.projectId`
会迫使用户在多个项目重复添加、重复登录同一个真实账号。根据 ADR 0014，“网站与账号”
调整为 Studio 本机全局资源库，不再由单一项目拥有：

```text
网站与账号

＋ 添加网站与账号

Apple Developer    张三公司 · 已登录
阿里云             张三公司 · 需重新登录

运营矩阵
CCLink 国内推广     4 个账号
```

- 侧栏展示全局网站账号和运营矩阵；切换项目不切换资源集合。
- 用户可以添加任意网站；同一网站的不同账号分别拥有全局稳定 ID 和独立登录环境。
- 在任意本地项目中，点击“添加网站与账号”或手动新建默认 Browser Tab 都进入同一个浏览器
  创建入口，并自动创建尚未归属正式资源的临时隔离登录环境；默认 Tab 顶部直接显示
  “登录完成，保存账号”。侧栏不得展开创建表单，也不得提前出现未保存资源。
- 用户在 Browser Tab 中输入网址并完成真实登录；扫码、验证码、2FA 和隐私授权都在网页
  现场由用户处理。
- 登录完成后，用户点击 Browser 顶部“保存账号”。系统从当前 Tab 自动取得网站名称、
  当前 URL 和登录环境，只要求用户确认一个侧栏显示名称；能够识别账号名称时
  应自动预填。
- 保存成功后，当前 Browser Tab 原地绑定全局稳定的网站账号资源，所有项目侧栏读取同一
  资源；不得再打开账号详情页或遗留创建表单 Tab。
- 未保存前关闭 Browser Tab 等同取消新建：不创建侧栏资源，临时登录环境进入安全清理；
  未保存 Tab 不得被事务或 AI 调用。
- 全局检测到可能重复资源时，用户只能选择“打开已有账号”或“作为另一个账号保存”，
  系统不得静默覆盖或共用登录环境。
- 网站可以声明通用能力和可选平台增强能力；没有增强程序仍可被通用网页代理使用。
- 旧项目账号升级为全局账号时保留 `accountId`、Profile 和事务引用；疑似重复项不得自动
  合并，旧 `cclink-accounts.json` 和原资源文件不得被迁移过程删除。
- 用户可以把多个全局账号组成“运营矩阵”。矩阵只保存账号引用和版本，不复制账号、
  Profile 或 Session；矩阵变化不得静默扩大既有事务的账号范围。

本轮新建流程是冻结的最小产品链，不得额外设计：

- 不得增加主体、角色、登录提示、网站名称、URL、密码、Cookie 或 Profile 输入字段。
- 不得在进入实际网页前增加侧栏表单、编辑器 Tab、账号详情 Tab 或多步骤向导。
- 不得为 Apple、阿里云或其他平台增加新建分支；所有网站走同一通用流程。
- 不得把未保存 Tab 暴露给事务或 AI，也不得因为 Cookie 存在自动宣称真实账号身份。
- 不得把账号全局可见解释为 AI 默认可调用；不得借本轮实现自动登录、团队权限、云同步、
  批量发布或修改事务归属。
- 如实现必须改变以上任一约束，先修改本产品事实源并取得用户确认，不能在开发中追加。

### 侧栏资源与 Browser Tab

侧栏中的每一行都是可启动的网页资源，不是静态账号记录，也不以账号详情页作为主要
点击路径：

```text
在当前工作空间点击全局网站账号
  ├─ 当前工作空间的资源 Browser Tab 已打开 → 激活现有 Tab
  └─ 尚未打开                              → 使用全局 Profile/Session 创建当前工作空间 Tab
```

资源与 Tab 遵守以下生命周期：

- Browser Tab 保存全局稳定账号引用和当前工作空间归属；登录环境归全局账号。
- 关闭 Tab 不删除侧栏资源；再次点击侧栏时用原登录环境重新打开。
- 连续点击同一资源默认只激活当前工作空间的一个主 Tab，不重复创建；不同工作空间可以各自
  拥有 Tab 投影，但必须使用同一账号 Profile。
- 同一网站的不同账号分别拥有资源引用和隔离登录环境，不能串用。
- 页面衍生的新 Tab 可以继承同一账号环境，但必须保留来源资源关联。
- 切换项目后仍显示同一全局账号列表，但不得激活或移动其他项目的 Tab 投影。
- 行尾菜单承担编辑、重新登录、查看诊断、查看相关事务和归档等管理动作。账号被事务引用
  时不能直接物理删除。

事务资源区保存全局账号或运营矩阵的稳定引用；用户手动点击时复用侧栏的账号解析和当前
工作空间 Tab 创建语义。AI 执行节点是否可以调用账号暂未决定，不能因删除项目归属校验
而自动获得调用范围。事务、Agent 或 renderer 都不得根据当前 URL、活跃 Tab、Cookie 或
Profile 名称自行猜测账号。

### 登录状态

普通界面只显示“待登录 / 待确认 / 已登录 / 需重新登录 / 状态未知”。Browser Profile、
Session Partition 和 Cookie 名称只进入诊断详情。

- Cookie 或 Session 数据只能证明存在登录信号，不能单独证明实际账号身份。
- “已登录”至少要求用户确认过账号身份，并且当前 Session 仍有有效登录信号。
- 在未来允许 AI 执行事务节点时，必须重新观察页面身份和后置状态；侧栏“已登录”不能
  替代执行前核验。
- 无法核验身份时，节点转为明确人工步骤，不能继续猜测。
- 重新登录、退出登录或 Session 失效会影响所有引用该全局账号的项目，界面必须明确提示
  全局影响并统一刷新状态。

现有文案草稿、发布记录和 Git 备份不能继续定义“网站与账号”的产品边界，应分别回到
事务材料/证据、文档和备份能力。

AI 操作前必须知道当前代表谁：

- 个人。
- 个体工商户。
- 公司或其他组织。
- 法定代表人、经办人、管理员或被授权角色。

同一用户可以管理多个主体、多个 App 和多个平台账号。事务必须固定主体和账号绑定，
不能根据当前登录页面猜测。

敏感信息遵守以下边界：

- 密码、Token、Cookie、验证码和恢复码不得进入工作空间、普通设置、日志或完整
  renderer 状态。
- 身份证件、营业执照、银行、税务及其他敏感材料不得默认复制到 Git 可见工作空间。
- Agent 默认只获知“材料存在”和安全摘要；读取正文或上传必须有当前事务授权。
- 上传前必须展示文件、目标站点、目标主体和用途。
- Profile、凭证、敏感材料分别由自己的唯一服务拥有；网页事务只保存稳定引用。
- 诊断和证据默认脱敏，原始敏感附件只在用户明确授权时保留。

## 权限与不可逆动作

AI 可以自主完成：

- 查询公开要求和帮助文档。
- 读取当前页面和用户已授权材料。
- 整理、转换和检查资料。
- 填写尚未提交的草稿。
- 下载公开文档和当前事务回执。
- 检查已提交事项状态。

用户可以针对单个事务预授权：

- 在指定站点使用指定账号。
- 上传指定类别材料。
- 在声明范围内重复执行只读检查。
- 保存回执到指定位置。

以下动作始终需要当次人工确认：

- 对外提交、发布、发送、删除、注销或撤回。
- 接受协议、作出真实性声明或法律承诺。
- 付款、下单、开户、借款或改变费用。
- 电子签名、盖章、授权其他主体或修改账号关键资料。
- 批量影响多个对象的外部动作。

确认卡必须展示：

- 事务和当前步骤。
- 代表的主体和使用的账号。
- 目标平台、URL 和动作。
- 关键字段摘要。
- 将上传或发送的文件。
- 金额、期限和潜在影响。

全局 `auto` 权限模式不能绕过这些产品级确认。

## 证据与完成判定

AI 不能因为“页面看起来结束了”就宣称完成。证据可以是：

- 官方申请号、订单号、受理号或备案号。
- 页面明确成功状态。
- 官方 API 状态。
- 回执、通知、证书或下载文件。
- 审核邮件或用户授权接入的外部通知。
- 上架地址、公开查询结果或其他可复核输出。
- 用户完成线下步骤后，由后续官方页面验证的结果。

每条证据至少关联：

- 事务、步骤和尝试。
- 来源与观察时间。
- 原始状态安全摘要。
- 可信等级。
- 文件哈希或脱敏引用。

无法取得证据时只能标记：

- 等待验证。
- 需要人工复核。
- 外部状态未知。

不能标记完成。

## 长期等待、检查和事务收件箱

提交后需要等待时：

1. 当前运行保存结果并结束。
2. 事务进入“等待外部”。
3. 保存下次检查时间和检查方式。
4. 到期或用户点击继续时创建新的关联运行。
5. 在 AI 账号调用方案已经确认的前提下，使用事务绑定的正确全局账号重新检查。
6. 状态未变化时安排下一次检查；状态变化时推进计划或转为“需要我处理”。

第一版本地调度只在 Studio 主进程存活期间工作。Studio 退出后不伪装成仍在执行；
重新启动后必须显示错过的检查并由明确策略补查。真正全天候运行需要后续官方集成层
或用户自有常驻执行节点，不能静默扩张 OSS 默认路径。

要让 AI 发现用户没有主动说出的事务，需要后续建立统一事务收件箱。来源可以包括：

- 用户自然语言输入。
- 用户转入的文件、截图、短信或通知。
- 用户授权的邮件和日历。
- 官方 API、Webhook 和平台通知。
- App 构建、发布和其他本地事件。
- 证件、资质和合同到期日。
- 用户确认启用的周期规则。

没有事件来源和用户授权时，产品只能接管用户明确交代的事务，不能宣称掌握全部个人
或公司义务。

## 产品入口

Activity Bar 形成两个独立入口：

- 当前“运营”改名为“网站与账号”，展示全局网站、主体、账号、登录状态和运营矩阵；
  切换项目不切换账号列表。
- 新增“事务”，只展示当前项目的事务列表和事务 Tab。

“网站与账号”侧栏固定采用简洁资源列表：

```text
网站与账号

＋ 添加网站与账号

Apple Developer    张三公司 · 已登录
阿里云             张三公司 · 需重新登录

运营矩阵
CCLink 国内推广     4 个账号
```

点击“添加网站与账号”直接打开一个使用临时隔离登录环境的实际 Browser Tab，不在侧栏或
工作区先展示网站资料表单。用户完成网页登录后，从 Browser 顶部点击“保存账号”，只确认
侧栏显示名称；系统自动保存当前网站、URL 和登录环境，并把当前 Tab 绑定为全局正式账号。

点击资源直接在当前工作空间打开或激活实际网页 Browser Tab；资源编辑、重新登录、诊断和
归档放在行尾菜单，不在主要点击路径增加账号详情 Tab。

事务侧栏必须是连续事务列表，事务状态只显示在事务名称旁或辅助行中，不能按状态
建立“需要我处理 / AI 处理中 / 等待外部”等一级子目录。可以提供搜索、状态筛选和
排序，但默认仍是一个列表：

```text
事务

国内应用商店发版       AI 处理中
正在填写华为版本资料

Apple 版本审核          等待外部
明天 10:00 复查

阿里云 App 备案         需要我处理
等待负责人扫码
```

点击事务后打开或激活对应事务 Tab。不同事务共用同一套三段式页面：

点击“新建事务”时，侧栏不得展开主体、材料、模板或流程表单；工作区打开“新建事务”
草稿 Tab。用户在草稿 Tab 定义目标、绑定资源并确认初始流程，创建成功后原 Tab 转为正式
事务 Tab。重复点击“新建事务”只激活当前项目已有草稿，不能在侧栏制造第二套事务编辑器。

### 1. 相关资源

展示整件事务引用的资源全集：

- 本地物料，例如营业执照照片、身份证、软件著作权、安装包、申请表和回执。
- 目标网站、登录入口、查询入口和外部结果来源。
- 办理主体、平台账号、账号角色和登录状态。

点击本地物料打开对应预览或编辑器；点击网站、账号或运营矩阵时，使用全局稳定引用；用户
手动点击账号可以在当前工作空间打开或激活关联 Browser Tab。缺失材料、登录失效和主体
不匹配直接显示在资源上。AI 是否可以使用这些引用调用账号另行决定。

### 2. 整体流程

根据 `nodes + edges` 展示线性、分支或并行流程，显示已完成节点、当前节点、待执行
节点、执行者、依赖、卡点和整体推进情况。状态必须来自 `WebAffairService`，不能由
流程图组件自行推测。

### 3. 节点详情

点击流程节点后，在同一个事务 Tab 内展示：

- 节点名称、业务状态、当前责任人和办理情况。
- 卡点、失败原因、成功判据和最近记录。
- 本节点实际使用的网站、账号、登录状态和物料子集。
- 已提交内容、申请编号、审核回执和结果证据。
- 当前可执行的唯一主要动作，以及必要的辅助动作。

事务 Tab 顶部“继续办理”始终定位到当前卡点节点；节点详情的主要动作只作用于当前
选中节点。关闭浏览器 Tab 或 Agent 会话不能删除事务、资源引用、流程或证据。

## 产品阶段

### G1：全局网站账号与资源 Browser Tab 闭环

用户点击添加后立即进入使用临时隔离环境的实际 Browser Tab，不填写前置资料表单；完成
手动登录后只确认侧栏显示名称，即可保存一个全局网站账号。切换项目、关闭 Tab、重启
Studio 或移动项目后，所有项目仍看到同一账号并复用同一 Profile/Session；各项目 Tab
投影互不抢占，未保存的临时 Tab 不能被事务或 AI 使用。

### G2：旧项目账号迁移与运营矩阵

现有项目账号保留 ID、Profile、Session 和事务引用迁移为全局账号；疑似重复项只由用户
确认合并。用户可以创建跨项目可见的运营矩阵，矩阵只引用账号并使用版本阻止既有事务
范围被静默扩大。

### A1：持久事务和三段式事务 Tab

用户可以在当前项目创建一件事务，关联全局网站账号或运营矩阵以及本项目本地物料，看到
动态流程图，并点击节点查看办理情况和节点资源；用户手动点击网站账号时在当前工作空间
打开资源 Browser Tab。关闭 Tab 或重启应用后仍然看到同一事务、流程和选中节点对应的
主进程事实。AI 调用账号仍不是 A1 的完成条件。

### A2：人与 AI 双向交接

此阶段必须等 AI 账号调用的独立产品决策确认后才能重新进入开发。届时 AI 可以执行一个
真实网页节点；用户可以随时接管页面并交还 AI。未确认前，不得用全局账号改造顺带放开。

### A3：等待外部和恢复检查

事务可以结束当前运行并进入等待外部；到期后创建新运行检查状态，不保持假运行或
无限占用 Agent。

### A4：动态流程、主体、资料和授权

AI 可以依据实际网页提出新增、重排或补正节点，用户可以查看变更原因并确认重大
调整；多个主体、账号和敏感材料受到事务授权约束，账号和主体不能串用，已执行历史
不能被新流程覆盖。

### A5：事务收件箱与可复用程序

用户授权的事件可以生成候选事务；真人验证过的成功轨迹可以形成版本化平台增强程序，
但程序失效时仍能降级到通用网页代理或人工步骤。

每个阶段都必须以真实网站、真实人工交接、真实重启恢复和真实证据验收。Schema、
Mock、单元测试和静态流程模板只能证明工程准备度。

## 与现有能力的关系

| 现有能力          | 在本方案中的角色                 | 不能承担的职责               |
| ----------------- | -------------------------------- | ---------------------------- |
| Agent Thread      | 本次沟通和执行上下文             | 不能成为长期事务唯一事实源   |
| BrowserTaskRun    | 一次浏览器任务和动作日志         | 不能代表跨天事务             |
| Browser Profile   | 网站登录态和隔离凭证域           | 不能拥有事务状态             |
| Browser Tab       | 当前工作空间对全局账号的运行投影 | 关闭后不能删除账号或事务事实 |
| ScheduledTask     | 到期触发一次检查或运行           | 不能拥有业务步骤和结果       |
| CredentialService | 第三方秘密值唯一所有者           | 不能保存事务计划             |
| 全局网站账号      | 跨项目复用的账号与登录环境       | 不能因此默认授权 AI 调用     |
| 项目              | 事务、本地材料和工作台 Scope     | 不能拥有或复制全局账号       |
| 运营助手          | 当前轻量平台入口和兼容能力       | 不能继续扩张为第二套事务系统 |

网页事务必须由新的主进程领域服务拥有；renderer store 只保存可丢弃投影。具体服务
边界、持久化位置、敏感材料方案和与 ScheduledTask 的关系属于后续工程方案评审，
本产品文档不提前锁定未经验证的实现。

## `/grilling`

结论先说：第一版最重要的不是自动化覆盖率，而是 AI 是否始终承担事务责任。

实现和验收前必须回答：

1. 某一步无法自动化时，事务是否仍然可以通过明确人工步骤继续？答案必须是可以。
2. 用户接管后连续操作多个页面，AI 是否会依据旧对话假设结果？不能；必须重新观察。
3. 等待用户三天时，是否仍保持 Agent 进程和“运行中”状态？不能；必须进入可持久化
   的“需要我处理”。
4. 等待审核两周时，是否必须保持浏览器 Tab？不能；新检查运行应能重建现场。
5. 关闭 Tab、切换工作空间、重启 Studio 后，谁拥有当前步骤？必须是网页事务主进程
   事实源。
6. 未知网站没有适配器时，是否直接显示“不支持”？不能；应先使用通用代理，并可
   降级人工。
7. 工具调用成功但页面没有申请号，能否标记完成？不能。
8. 用户管理两个公司时，AI 是否可能因为当前 Cookie 自动选择主体？不能；事务必须
   固定主体和账号。
9. 人工确认是否只显示一个按钮？不能；必须说明主体、动作、数据、文件和影响。
10. App 退出后本地调度不运行，界面是否仍声称“AI 正在跟踪”？不能；必须明确显示
    错过和恢复状态。
11. 为了提高覆盖率，是否允许绕过验证码、风控或平台条款？不能。
12. 只做出事务列表和流程图时，能否汇报“网页事务代理人已完成”？不能；必须完成
    真实未知网站、人工交接、跨运行恢复和结果证据的纵向验收。
13. 侧栏网站账号是否只能打开静态详情页？不能；主要点击必须打开或激活实际网页
    Browser Tab。
14. 事务资源区是否另写一套网页打开逻辑？不能；用户手动打开必须复用全局账号解析和当前
    工作空间 Tab 投影。AI 调用权限另行决定，不能混入人工启动入口。
15. 项目目录移动、切换项目或关闭 Tab 后，全局账号是否会丢失、复制或被项目重新拥有？
    不能；账号事实、全局 Profile/Session 和工作空间 Tab 投影必须分离并可验证恢复。
16. 新建网站账号是否要求用户先填写网站、主体、角色和登录提示？不能；必须先进入真实
    网页现场，登录后只确认侧栏显示名称。
17. 未保存的临时 Browser Tab 是否能出现在侧栏或被事务、AI 使用？不能；只有保存成功
    并获得全局稳定账号引用后，才能进入资源选择器；AI 是否可调用仍未决定。
18. 关闭未保存 Tab 或保存失败时是否会留下孤儿 Profile 或丢失当前登录现场？不能；取消
    必须有界清理，保存失败必须保留现场并允许重试。
19. 所有项目都能看到账号，是否意味着所有 Agent 都能调用？不能；“可见、人工可打开、
    AI 可调用”是三个不同边界，本轮只确认前两个。
20. 同一真实账号在旧项目中存在多个记录，是否可以按名称或 URL 自动合并？不能；必须保留
    原 ID 和 Profile，由用户明确选择主账号。
21. 修改运营矩阵后，旧事务是否自动获得新增账号？不能；事务必须保留绑定版本或当时解析
    的账号清单。

# AI 网页事务代理人

> 状态：产品方案已确认，尚未实现；工程可行性和开发计划待评审

## 结论

CCLink Studio 的目标不是支持若干预定义网站，也不是为备案、工商、知识产权、应用商店
分别开发互不相干的功能。

目标产品是一个可持续、可交接、可恢复的 **AI 网页事务代理人**：

> 用户把个人或公司的网页事务交给 AI；AI 负责理解目标、规划步骤、准备资料、操作网页、
> 跟踪外部进度、处理失败和恢复现场，直到取得可验证结果。流程不要求一次执行完，也不
> 要求完全无人值守；必须由本人承担责任、完成认证或作出不可逆决定时，AI 把当前步骤
> 交给用户，用户完成后可以随时交还 AI 继续。

“接管”不等于 AI 点击所有按钮。接管的完成标准是：

- AI 始终知道这件事务当前在哪里。
- AI 知道下一步应由 AI、用户还是外部机构完成。
- 任意步骤都可以实际执行、明确交接或等待外部结果，不能只是装饰性清单。
- 页面关闭、人工介入、等待数天、切换工作空间或重启应用后，事务责任不丢失。
- 没有结果证据时，不能把事务标记为完成。

当前“工作空间内运营助手”仍是轻量平台入口和操作会话，不等同于本方案；当前
`BrowserTaskRun` 只描述一次浏览器执行，也不等同于跨多次运行的网页事务。

## 产品目标与真人端到端验收

第一条产品闭环必须在真实应用中完成以下操作：

1. 用户用自然语言交代一件未预定义的网页事务，例如“替公司完成某个平台的开发者
   认证并提交应用上架”。
2. Studio 创建一件持久事务，明确当前代表的个人或公司、最终目标和必要边界。
3. AI 查找或打开官方入口，形成可执行计划，并只询问当前缺少的必要信息。
4. AI 使用正确的浏览器 Profile 打开页面，读取要求、填写表单并准备材料。
5. 每个网页动作都能看到当前步骤；用户可以随时暂停、终止或接管页面。
6. 遇到扫码、人脸、短信、电子签名、法律声明、付款或最终提交时，AI 保存现场并把
   步骤转为“需要我处理”，本次 Agent 运行正常结束。
7. 用户可以在浏览器中完成一个或多个手工页面操作，然后点击“交还 AI”。
8. AI 重新观察实际页面，核对用户完成后的结果，必要时重规划，而不是从旧内存继续
   盲目执行。
9. 如果提交后需要等待外部审核，事务进入“等待外部”；浏览器和 Agent 不保持假运行。
10. 关闭并重启 Studio 后，用户仍能看到同一事务、当前步骤、使用的身份、已有材料、
    最近证据和下一步。
11. 到达检查时间或用户点击继续后，AI 创建新的关联运行，重新打开正确 Profile 和
    页面，查询状态并继续办理。
12. 遇到驳回或补正时，AI 保存官方原始原因、准备补正方案，并再次进入 AI 或人工步骤。
13. 取得申请编号、回执、审核结果、证书、上架地址或其他明确证据后，AI 才能把相应
    步骤标记完成。
14. 所有步骤完成或由用户明确终止后，事务进入终态，并保留可审计时间线。

只有这条流程在真实未知网站或尚无专用适配器的网站上通过，才能声明“AI 网页事务
代理人”的第一条产品闭环完成。只实现事务列表、状态机、提示词、Mock 页面或单次
Browser 自动化，不能声明产品能力完成。

## 用户心智

用户只需要理解三个概念：

| 概念     | 用户含义                             |
| -------- | ------------------------------------ |
| 事务     | 我交给 AI 负责到底的一件事           |
| 当前步骤 | 这件事现在正在做什么、轮到谁处理     |
| 证据     | 为什么可以确认这一步或整件事已经完成 |

网站、Tab、Agent Thread、BrowserTask、IPC、运行 ID 和调度器都是实现概念，不应要求
用户理解。

## 适用范围

网页事务可以属于个人、个体工商户、公司或其他用户明确授权的主体，包括但不限于：

- 工商登记、变更、年报、公告和注销。
- 税务、社保、公积金、银行及企业服务事项。
- 知识产权账号、实名认证、申请、补正和续展。
- ICP、App、公安联网及其他备案或许可事项。
- Apple、Android 国内应用商店及其他软件分发平台账号注册、认证、提交和审核。
- 云平台、开放平台、支付平台、广告平台和电商平台入驻。
- 招聘、采购、供应商注册、投标、报销和合同流转。
- 个人证件、资格、保险、教育、出行及其他通过网页办理的事务。
- 其他由用户明确发起或通过授权事件来源进入事务收件箱的网页事务。

平台专用程序可以提高常用网站的成功率，但不得成为产品支持范围的白名单。没有专用
程序时，通用网页代理仍可观察页面、尝试执行、请求人工接管或明确失败原因。

## 非目标和不可承诺边界

第一版不承诺：

- 所有事务完全无人值守。
- 绕过验证码、短信、人脸、电子营业执照、硬件密钥、电子签名或网站风控。
- 代替用户作出法律事实判断、真实性承诺、专业法律意见或最终商业决策。
- 在页面状态无法验证时猜测成功。
- 在没有外部事件来源时自动知道个人或公司“所有应该办理的事项”。
- Studio 完全退出后仍由本地 OSS 进程准时执行或监控。
- 对所有网站提供相同成功率。
- 通过批量多账号、规避平台规则或违反网站条款的方式提高自动化覆盖。

AI 无法执行某一步时，不代表整件事务失效。它必须把该步骤转成明确、可操作的人工
任务，保留前后依赖，并在用户完成后继续负责剩余流程。

## 执行责任模型

每个步骤必须采用以下一种责任模式：

| 模式              | 当前执行者    | 典型行为                                 | 完成方式                 |
| ----------------- | ------------- | ---------------------------------------- | ------------------------ |
| AI 执行           | AI            | 查询、读取、填写、整理、下载、低风险准备 | AI 验证后记录证据        |
| AI 准备、用户确认 | AI → 用户     | 最终提交、发布、付款、法律声明           | 用户确认后继续执行或接管 |
| 用户执行、AI 接回 | 用户 → AI     | 扫码、人脸、短信、签名、主观选择         | AI 重新观察并验证        |
| 等待外部、AI 复查 | 外部机构/平台 | 审核、制证、人工处理、异步回执           | 新运行检查外部结果       |

步骤不能因为当前没有自动化工具就留成不可执行的文字。至少必须包含：

- 给用户的明确操作说明。
- 要打开的官方页面或线下入口。
- 所需材料。
- 预期完成结果。
- 用户怎样把结果交还 AI。
- AI 接回后怎样验证。

## 事务、运行和浏览器现场

三者必须严格分离：

```text
网页事务 WebAffair
├─ 持久目标、计划、当前步骤、材料、证据和责任
├─ AgentRun 1：查要求、准备资料
├─ BrowserTaskRun 1：填写第一段表单
├─ 人工步骤：扫码和签名
├─ AgentRun 2：接回页面并提交
├─ 等待外部：审核
└─ AgentRun 3：查询结果并下载回执
```

- 网页事务可以跨越多个 Agent Thread、Browser Tab、运行和日期。
- Agent 运行是有界执行；等待用户或外部时必须结束，不无限占用模型或子进程。
- Browser Tab 是可丢失视图；Tab 关闭不能删除事务事实。
- 恢复事务时可以创建新的 Tab 和 Agent 运行，但必须使用同一事务、主体、Profile 和
  已保存证据重新对账。
- 不能把已消失的 Agent 或 Browser 进程恢复成假运行态。

## 事务状态

事务状态描述整体责任：

```text
draft
  -> active
      -> needs-attention
      -> waiting-external
      -> paused
      -> completed
      -> failed
      -> cancelled
```

| 状态       | 用户含义                             |
| ---------- | ------------------------------------ |
| 草稿       | 目标尚未确认，AI 还没有开始负责执行  |
| 处理中     | AI 或用户正在推进当前步骤            |
| 需要我处理 | 必须由用户完成确认、认证、选择或修复 |
| 等待外部   | 已完成本方动作，等待平台或机构结果   |
| 已暂停     | 保留全部现场，但不会继续创建运行     |
| 已完成     | 最终目标已有足够证据                 |
| 已失败     | 无法继续，且有明确失败原因和替代路径 |
| 已取消     | 用户明确终止，不再继续推进           |

“需要我处理”和“等待外部”都不是运行中状态。它们必须可以持久化、关闭页面和重启
恢复。

## 步骤状态

步骤状态描述下一次实际动作：

```text
blocked
  -> ready
      -> running
          -> waiting-human
          -> waiting-external
          -> verifying
          -> completed
          -> failed
          -> skipped
          -> cancelled
```

每个步骤至少具有：

- 目标与执行者。
- 前置条件和依赖步骤。
- 必需材料与允许使用的账号。
- 允许执行的动作和人工确认策略。
- 成功判据和需要保存的证据。
- 有界重试与失败降级。
- 人工接管说明和恢复说明。
- 所属事务、运行和工作空间关联。

计划允许根据页面和外部结果动态增加、删除或重排未执行步骤，但已经发生的步骤、
尝试和证据只能追加历史，不能被新计划静默覆盖。

## 人工接管与交还 AI

### 用户随时接管

用户在 AI 操作网页时必须始终能够：

- 暂停 AI。
- 接管当前页面。
- 修改 AI 已填写但尚未提交的内容。
- 完成扫码、认证、签名或选择。
- 跳过、取消或要求重规划当前步骤。
- 终止整件事务。

接管后页面进入明确的人工模式，AI 不得在后台继续点击或填写。

### AI 主动交接

出现以下情况时，AI 必须主动停止并交给用户：

- 验证码、短信、人脸、扫码、硬件密钥或电子签名。
- 需要确认法律事实、材料真实性或对外承诺。
- 付款、下单、开户、借款或费用变化。
- 发布、提交、删除、注销、撤回或其他不可逆外部动作。
- 多个合理选项需要用户作商业或主观判断。
- 页面状态不确定、账号可能错误或材料版本冲突。
- 网站风控、条款或自动化限制不允许继续。

### 用户交还 AI

用户点击“交还 AI”后：

1. AI 重新读取当前 URL、页面、Profile 和可见状态。
2. 对比交接前保存的预期结果。
3. 不根据旧对话假设用户完成了哪些动作。
4. 能验证时追加人工操作结果证据。
5. 页面已经进入其他分支时更新后续计划。
6. 无法验证时询问最小必要信息，或继续保持“需要我处理”。

人工接管期间发生的具体点击不要求全部被自动记录，但交还后的外部结果必须验证并
进入事务时间线。

## 通用网页执行与平台增强

### 通用网页代理

面对未预定义网站，AI 使用当前可用能力形成观察—动作—验证循环：

```text
观察页面
  -> 判断当前阶段和可用动作
  -> 执行一个有界动作
  -> 验证页面是否达到预期
  -> 保存必要证据
  -> 继续、重试、重规划或交给用户
```

通用能力包括：

- 导航、搜索、多 Tab 和跨页面流程。
- DOM、可访问性语义和必要的视觉理解。
- 表单填写、下拉、日期、富文本、iframe 和弹窗。
- 文件上传、下载和回执保存。
- 登录态识别、Profile 绑定和失效诊断。
- 页面错误、网络错误、风控和验证码分类。
- 页面变化后的语义重定位。

每个动作之后必须验证后置条件。不能用“工具调用成功”替代“网页业务结果成功”。

### 平台增强程序

高频平台可以通过版本化程序或连接器增强：

- 官方 API、Webhook 或 SDK。
- 站点入口和账号绑定。
- 字段语义与材料映射。
- 原始状态到用户状态的映射。
- 高风险控件和最终提交识别。
- 页面变化探测和真人验收样例。
- 失败降级和人工处理说明。

增强程序不是固定坐标宏，也不能拥有独立事务状态。程序失效时必须降级回通用网页
代理或人工步骤，不能丢失原事务。

用户完成一次真实流程后，系统未来可以基于已脱敏轨迹生成候选程序；候选程序必须
经过用户检查、版本化和真人复验后才能复用，不能让模型静默修改生产操作规则。

## 主体、账号、资料和授权

AI 操作前必须知道当前代表谁：

- 个人。
- 个体工商户。
- 公司或其他组织。
- 法定代表人、经办人、管理员或被授权角色。

同一用户可以管理多个主体、多个 App 和多个平台账号。事务必须固定主体和账号绑定，
不能根据当前登录页面猜测。

敏感信息遵守以下边界：

- 密码、Token、Cookie、验证码和恢复码不得进入工作空间、普通设置、日志或完整
  renderer 状态。
- 身份证件、营业执照、银行、税务及其他敏感材料不得默认复制到 Git 可见工作空间。
- Agent 默认只获知“材料存在”和安全摘要；读取正文或上传必须有当前事务授权。
- 上传前必须展示文件、目标站点、目标主体和用途。
- Profile、凭证、敏感材料分别由自己的唯一服务拥有；网页事务只保存稳定引用。
- 诊断和证据默认脱敏，原始敏感附件只在用户明确授权时保留。

## 权限与不可逆动作

AI 可以自主完成：

- 查询公开要求和帮助文档。
- 读取当前页面和用户已授权材料。
- 整理、转换和检查资料。
- 填写尚未提交的草稿。
- 下载公开文档和当前事务回执。
- 检查已提交事项状态。

用户可以针对单个事务预授权：

- 在指定站点使用指定账号。
- 上传指定类别材料。
- 在声明范围内重复执行只读检查。
- 保存回执到指定位置。

以下动作始终需要当次人工确认：

- 对外提交、发布、发送、删除、注销或撤回。
- 接受协议、作出真实性声明或法律承诺。
- 付款、下单、开户、借款或改变费用。
- 电子签名、盖章、授权其他主体或修改账号关键资料。
- 批量影响多个对象的外部动作。

确认卡必须展示：

- 事务和当前步骤。
- 代表的主体和使用的账号。
- 目标平台、URL 和动作。
- 关键字段摘要。
- 将上传或发送的文件。
- 金额、期限和潜在影响。

全局 `auto` 权限模式不能绕过这些产品级确认。

## 证据与完成判定

AI 不能因为“页面看起来结束了”就宣称完成。证据可以是：

- 官方申请号、订单号、受理号或备案号。
- 页面明确成功状态。
- 官方 API 状态。
- 回执、通知、证书或下载文件。
- 审核邮件或用户授权接入的外部通知。
- 上架地址、公开查询结果或其他可复核输出。
- 用户完成线下步骤后，由后续官方页面验证的结果。

每条证据至少关联：

- 事务、步骤和尝试。
- 来源与观察时间。
- 原始状态安全摘要。
- 可信等级。
- 文件哈希或脱敏引用。

无法取得证据时只能标记：

- 等待验证。
- 需要人工复核。
- 外部状态未知。

不能标记完成。

## 长期等待、检查和事务收件箱

提交后需要等待时：

1. 当前运行保存结果并结束。
2. 事务进入“等待外部”。
3. 保存下次检查时间和检查方式。
4. 到期或用户点击继续时创建新的关联运行。
5. 使用正确主体、账号和 Profile 重新检查。
6. 状态未变化时安排下一次检查；状态变化时推进计划或转为“需要我处理”。

第一版本地调度只在 Studio 主进程存活期间工作。Studio 退出后不伪装成仍在执行；
重新启动后必须显示错过的检查并由明确策略补查。真正全天候运行需要后续官方集成层
或用户自有常驻执行节点，不能静默扩张 OSS 默认路径。

要让 AI 发现用户没有主动说出的事务，需要后续建立统一事务收件箱。来源可以包括：

- 用户自然语言输入。
- 用户转入的文件、截图、短信或通知。
- 用户授权的邮件和日历。
- 官方 API、Webhook 和平台通知。
- App 构建、发布和其他本地事件。
- 证件、资质和合同到期日。
- 用户确认启用的周期规则。

没有事件来源和用户授权时，产品只能接管用户明确交代的事务，不能宣称掌握全部个人
或公司义务。

## 产品入口

Activity Bar 增加一级“事务”入口，不继续把该能力塞入现有“网站运营”分组。

建议侧栏：

```text
事务

需要我处理
  ● 法人扫码确认
  ● 核对应用商店发布内容

AI 处理中
```

事务 Tab 至少展示：

- 最终目标和当前责任状态。
- 代表的主体、账号和浏览器 Profile。
- 当前计划、步骤依赖和当前执行者。
- AI 当前动作或人工操作说明。
- 使用的材料和缺少的材料。
- 最近页面、证据、失败和外部状态。
- 下一次检查时间。
- 完整事务时间线。
- 暂停、继续、接管页面、交还 AI、终止和复制诊断入口。

Activity Bar 徽标优先显示“需要我处理”，其次是新失败和正在执行。当前工作空间可以
过滤可见事务，但事务事实不能由 renderer 当前 Tab 或侧栏状态拥有。

## 产品阶段

### A1：一件事务可以跨运行持续推进

用户可以用自然语言创建一件网页事务；AI 形成计划、执行通用网页步骤、保存证据，并
在关闭 Tab 或重启应用后继续看到同一事务。

### A2：人与 AI 双向交接

用户可以随时接管页面并交还 AI；AI 也能在认证、确认和不确定状态主动交接。交还后
AI 重新观察和重规划。

### A3：等待外部和恢复检查

事务可以结束当前运行并进入等待外部；到期后创建新运行检查状态，不保持假运行或
无限占用 Agent。

### A4：主体、资料和授权

用户可以安全管理多个个人或公司主体、账号和敏感材料；AI 只在事务授权范围内读取和
上传，账号和主体不能串用。

### A5：事务收件箱与可复用程序

用户授权的事件可以生成候选事务；真人验证过的成功轨迹可以形成版本化平台增强程序，
但程序失效时仍能降级到通用网页代理或人工步骤。

每个阶段都必须以真实网站、真实人工交接、真实重启恢复和真实证据验收。Schema、
Mock、单元测试和静态流程模板只能证明工程准备度。

## 与现有能力的关系

| 现有能力          | 在本方案中的角色             | 不能承担的职责                 |
| ----------------- | ---------------------------- | ------------------------------ |
| Agent Thread      | 本次沟通和执行上下文         | 不能成为长期事务唯一事实源     |
| BrowserTaskRun    | 一次浏览器任务和动作日志     | 不能代表跨天事务               |
| Browser Profile   | 网站登录态和隔离凭证域       | 不能拥有事务状态               |
| ScheduledTask     | 到期触发一次检查或运行       | 不能拥有业务步骤和结果         |
| CredentialService | 第三方秘密值唯一所有者       | 不能保存事务计划               |
| 工作空间          | 文件、Agent 和产物执行 Scope | 不能靠当前活跃工作空间猜测主体 |
| 运营助手          | 当前轻量平台入口和兼容能力   | 不能继续扩张为第二套事务系统   |

网页事务必须由新的主进程领域服务拥有；renderer store 只保存可丢弃投影。具体服务
边界、持久化位置、敏感材料方案和与 ScheduledTask 的关系属于后续工程方案评审，
本产品文档不提前锁定未经验证的实现。

## `/grilling`

结论先说：第一版最重要的不是自动化覆盖率，而是 AI 是否始终承担事务责任。

实现和验收前必须回答：

1. 某一步无法自动化时，事务是否仍然可以通过明确人工步骤继续？答案必须是可以。
2. 用户接管后连续操作多个页面，AI 是否会依据旧对话假设结果？不能；必须重新观察。
3. 等待用户三天时，是否仍保持 Agent 进程和“运行中”状态？不能；必须进入可持久化
   的“需要我处理”。
4. 等待审核两周时，是否必须保持浏览器 Tab？不能；新检查运行应能重建现场。
5. 关闭 Tab、切换工作空间、重启 Studio 后，谁拥有当前步骤？必须是网页事务主进程
   事实源。
6. 未知网站没有适配器时，是否直接显示“不支持”？不能；应先使用通用代理，并可
   降级人工。
7. 工具调用成功但页面没有申请号，能否标记完成？不能。
8. 用户管理两个公司时，AI 是否可能因为当前 Cookie 自动选择主体？不能；事务必须
   固定主体和账号。
9. 人工确认是否只显示一个按钮？不能；必须说明主体、动作、数据、文件和影响。
10. App 退出后本地调度不运行，界面是否仍声称“AI 正在跟踪”？不能；必须明确显示
    错过和恢复状态。
11. 为了提高覆盖率，是否允许绕过验证码、风控或平台条款？不能。
12. 只做出事务列表和流程图时，能否汇报“网页事务代理人已完成”？不能；必须完成
    真实未知网站、人工交接、跨运行恢复和结果证据的纵向验收。

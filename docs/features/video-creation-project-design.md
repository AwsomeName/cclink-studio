## 1. 用户最终验收什么

用户现在已有工程、分镜文字、素材和任务的保存基础；尚不能把四张效果图视为完整产品，
也不能保证复制一个文件夹后即可完整恢复所有内容。

本方案的最终验收动作先于工程拆分：

1. 在 Studio 选择稿件，新建一条视频，看到实际创建的工程文件夹。
2. 编辑并保存口播，关闭重开后内容、段落 ID、确认版本均保留；原稿不被改写。
3. 从已确认口播生成分镜，为不同镜头添加本地、搜索或 AI 素材；候选和选中项均可恢复。
4. 导入或生成配音，处理时长冲突，预览带字幕、旁白、音乐的整片。
5. 修改一句口播，只把有关配音、字幕和成片标为需要更新；旧文件保留，不自动收费。
6. 导出 MP4、字幕、来源清单；重启后仍能播放、查看对应版本及任务结果。
7. 关闭工程，把整个工程文件夹复制到另一个本地工作空间，断网打开：文字、已下载素材、
   配音和成片可用，不依赖原稿位置；云端查询和生成单独提示配置要求。
8. 模拟素材丢失、磁盘写入失败、云端任务状态未知，看到具体受影响项和恢复动作；
   不丢其他内容、不重复提交付费任务、不把坏文件标为成功。

所有条目当前均为验收要求，不能用本文、效果图或单元测试替代真人执行结果。

## 2. 产品对象与入口

- 一个视频工程是一条视频作品的持久容器，包含原稿、口播、分镜、素材、声音、任务和成片。
- 它是现有 Workspace 内的一类文档，不新增工作空间、项目条、Tab 或 Agent 状态所有者。
- 入口建议统一显示为“生产 → 视频创作”，列表支持新建、打开工程、查看所在文件夹。
- 新建时选择标题、工程父目录、原稿、画幅、目标时长；默认父目录为当前工作空间的 `视频/`。
- 每条视频创建独立目录，例如 `视频/丙午流光-30秒-a1b2/`；标题不是身份，稳定 ID 才是身份。
- 修改标题默认不移动目录；移动工程必须在关闭或完成本机活动写入后进行。
- 页面头部固定显示：名称、保存状态、当前版本、待处理问题数、打开工程文件夹。
- 四阶段可自由返回；“下一步”只校验实际输入，不按访问过页面认定完成。
- 首版仍是场景式剪辑，底部三条轨道是画面、旁白、音乐的受限投影，不是通用多轨编辑器。

## 3. 文件夹是作品本体

建议默认布局如下。内部文件名稳定，Studio 用中文呈现名称；用户不必手工维护 JSON。

```text
视频/丙午流光-30秒-a1b2/
├── video.json                      # 工程身份、简报、当前编辑状态和版本引用
├── source/
│   ├── original.md                 # 创建时原稿快照，不依赖源文件继续存在
│   └── attachments/                # 已导入的原稿附件
├── script/
│   └── narration.md                # 当前口播的可读副本，由结构化数据生成
├── storyboard/
│   └── storyboard.md               # 当前分镜的可读副本
├── assets/
│   ├── manifest.json               # 唯一资产元数据、哈希、探测结果、来源
│   └── files/                     # 图片、视频、配音、音乐、Logo 等实际文件
├── history/
│   └── <checkpoint-id>.json        # 确认、应用提案、开始生成/导出前的内容快照
├── proposals/
│   └── <proposal-id>.json          # AI 口播/分镜建议及其输入版本，不自动应用
├── tasks/
│   ├── video-tasks.json            # 既有视频生成服务的任务记录
│   ├── render-tasks.json           # 既有合成服务的任务记录
│   └── narration-tasks.json        # TTS 接入时才增加，由明确的音频任务 owner 管理
├── exports/
│   └── <export-id>/
│       ├── video.mp4
│       ├── subtitles.srt
│       ├── sources.md
│       └── export.json             # 输入快照、文件哈希、导出设置和核验结果
└── cache/                          # 缩略图、代理视频、波形、预览和中间片段，可重建
```

规则：

- “保存一切资源”指保存完成这条作品所需的内容和来源，不是复制全部搜索结果、所有日志和凭证。
- 默认复制导入文件，不移动原件；同工程按内容哈希去重。首版不做跨工程全局素材池或硬链接。
- 原稿本地附件只有成功复制后才标记可携带；缺失附件给出清单。远端图片不随解析静默下载。
- 工程内文件以相对路径引用；历史原始路径仅作来源提示，不是播放和恢复的必要条件。
- API Key、Cookie、签名下载 URL、机器路径绑定和全局用量账本不进入可分享工程。
  提示词、口播和生成参数作为作品数据保存在本机，分享时明确提示其中可能含隐私。
- 下载结果完成校验并原子入库后才成为可采用素材；短期 URL 不是资产。
- 字体若影响可重现输出，只能按许可复制；不可携带时明确提示替换，不承诺像素级复现。
- 缓存可以显式清理；素材、历史快照、任务证据和成片不是缓存，不随清缓存删除。
- 本轮不设计自动删除历史和未采用素材。未来清理需分析当前版本、快照、活动任务和导出的引用，
  列出影响并经用户确认；“从镜头移除”默认只解除关联，不删除文件。

## 4. 每个阶段的交互与持久对象

| 阶段       | 用户动作及进入条件                   | 必须保存                                                       | 完成证据 / 下一步                                | 失败与等待                                               |
| ---------- | ------------------------------------ | -------------------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------- |
| 新建       | 选择可写本地目录与稿件               | 工程 ID、简报、原稿内容及哈希、附件清单                        | 文件夹和工程清单实际落盘，打开口播页             | 目录不可写/空间不足：不显示创建成功                      |
| 稿件与口播 | 写口播，或让 AI 提议改写             | 独立段落、顺序、文本、版本、原稿引用；AI 候选及输入版本        | 用户确认某个口播版本，允许生成分镜               | AI 失败仍可手写；未保存不能开始依赖该内容的任务          |
| 分镜       | 从确认口播生成或手建镜头，审阅并采用 | 镜头 ID、顺序、口播段落引用、画面目标、字幕、时长、素材计划    | 当前分镜版本可保存、可逐镜编辑；缺素材不阻止保存 | 上游已改：显示差异，不覆盖新口播和已有选材               |
| 素材       | 本地导入、搜索添加、云端生成并采用   | 文件、哈希、来源、选中/备选引用、裁剪、生成请求与结果          | 选中资产可读取且满足镜头要求                     | 缺 Key/失败/过期/缺文件：仅对应项降级                    |
| 声音与节奏 | 导入配音或确认云端配音，试听和调整   | 音频资产、对应口播版本、实测时长、镜头映射、字幕时码、混音设置 | 音画冲突已处理，人工试听通过                     | 超长旁白不默认截断；缺音频可保存草稿，但不能冒充有声成片 |
| 预览       | 为固定快照生成可播放预览并检查       | 输入指纹、预览任务、可重建预览文件引用                         | 成功输出且可播放，用户知道正在看哪版             | 编辑后标记“旧版预览”；失败保留可编辑工程                 |
| 导出       | 确认本版内容和目标文件参数           | 固定输入快照、导出任务、MP4/SRT/来源、哈希、探测结果           | 文件实际存在且探测通过，用户播放验收             | 失败保留原因和中间内容；重试不覆盖已有成功成片           |

### 4.1 口播先于分镜，并且只有一份可编辑正文

- 口播是独立文档对象，不再以每个镜头的 `narration` 字段拼起来充当唯一口播。
- 每段有稳定 `segmentId`，保存顺序、正文、内容版本；段落可以还没有镜头。
- 首版默认一段对应一镜。需要跨镜头时，先显式拆段；不提前引入自由文字区间映射。
- 分镜页也可编辑口播，但编辑的是同一个段落，通过同一领域命令保存，不维护第二份文本。
- 字幕可以不同于口播：保存字幕文本及其依据的段落版本，不每次覆盖用户精简的字幕。
- `script/narration.md` 是方便阅读、复制、交给其他工具的派生文件，JSON 才是编辑事实源。
  用户外部修改 Markdown 时显示“检测到外部版本”，可预览后显式导入；不得双向静默同步。
- 原稿更新也走“载入新版原稿 → 比较 → 确认”，不会自动重写已确认口播。

### 4.2 素材的候选、下载和采用是三件事

- 搜索页记住检索词和筛选条件；只有收藏/添加的候选才持久保留来源信息。
- “搜索到”不等于“已下载”，“云端成功”不等于“本地可用”，“已下载”不等于“已采用”。
- 同一镜头可保留多个候选；选中一个才改变成片。生成返回时已改镜头，结果只进入候选区。
- 来源信息至少包含来源类型、作者/原页面、许可摘要、获取时间、内容哈希；缺项明确未知。
- 云生成确认卡展示模型、输入文本/参考素材、会上传的数据、时长、费用估算或不可估算事实。
  重新生成是新的副作用，必须再次明确确认，不因此前失败自动重复扣费。

### 4.3 音频的首版可行范围

- 先支持整条录音导入及手动镜头对齐，形成无需 TTS 的完整有声视频闭环。
- 目标增强为按口播段生成配音、单段重生成；实际 TTS Provider 尚未选定和验收。
- 整条录音修改一句文稿后，整条录音标为待核对；只有具备段落映射的配音才能精确到一段。
- 字数只给预估时长，真正对齐使用媒体探测结果。无语音对齐能力时只提供人工时码/整段字幕，
  不冒充逐字精准字幕。
- 镜头比旁白短时提供：精简旁白、延长画面、替换更长素材。延长视频必须明确选择循环、
  定格或重新生成，不能伪装成新的自然运动；图片延长也应标记为图片动效。
- 音乐音量、淡入淡出、原声开关均保存；自动压低音乐等增强只有实现并验收后才能启用。

约束：

- `videoId` 是媒体文档身份，不能成为新增 Workspace/project 身份；旧 `MediaProject` 为兼容命名。
- 当前编辑状态只在 `video.json` 中拥有；历史快照是不可变输入证据，不是第二份活动状态。
- 资产清单拥有元数据，工程只引用 ID；renderer 只有临时草稿，服务成功落盘才显示“已保存”。
- Portable 文档不固定宿主绝对 Workspace 路径。打开时由现有 Workspace 服务建立本机绑定，
  按授权根目录解析相对路径并校验 realpath、软链接逃逸与路径穿越。
- “待更新”由输入版本/哈希比较得出；人工确认记录绑定具体版本，不能靠独立布尔值永久有效。
- 任务状态沿用领域服务契约，不新增通用调度器、操作账本或另外一套工作流状态机。

## 6. 修改传播与版本规则

| 改动                 | 保留                         | 标记需要更新/确认                           | 不允许自动发生                           |
| -------------------- | ---------------------------- | ------------------------------------------- | ---------------------------------------- |
| 改一句口播           | 原稿、所有素材、旧配音和成片 | 相关字幕、配音、分镜语义核对、当前预览/导出 | 自动重新付费、重生成全部镜头、丢弃旧素材 |
| 替换一个镜头素材     | 口播、其他镜头、配音         | 本镜裁剪核对、当前预览/导出                 | 重写口播                                 |
| 调整顺序/时长        | 原始媒体、口播正文、分段音频 | 音频安排、字幕时码、整片预览/导出           | 静默截掉旁白                             |
| 改音乐/字幕样式/Logo | 分镜素材和配音文件           | 混音或合成预览/导出                         | 重新调用视频模型                         |
| 改标题/来源备注      | 有效画面与声音输出           | 只更新相关展示或来源清单                    | 把全部昂贵产物判为失效                   |

版本分两层：普通编辑递增 revision，避免覆盖新数据；确认口播、采用 AI 提案、开始生成/导出
时保存不可变 checkpoint，不把每次按键变成完整历史。AI 提案过期时要求重新比较后应用。
输出使用只包含实际输入的指纹，不能因为标题变化就误判视频内容失效。

旧成片始终可播放，显示“基于版本 X”；新编辑不会修改旧 MP4。缓存预览可重建，历史成片不覆盖。
恢复历史是把选中快照另存为新的当前版本，不倒退 revision，也不删除之后产生的资产和任务。

## 7. 保存、恢复和便携性

### 保存与跨文件一致性

- 目标为编辑自动保存 + Cmd/Ctrl+S 立即保存；显示“未保存 / 保存中 / 已保存 / 保存失败”。
- 单一主进程 owner 串行写入，expectedRevision 防冲突；快速输入只保留最新待写草稿。
- 顺序：先写资产和不可变快照并核验，再原子提交引用它们的工程清单；不声称多文件 rename
  等于整体事务。中断留下的未引用文件可对账，不能产生指向半个文件的已保存工程。
- Markdown 等派生文件带对应 revision，可在重开时重建；派生失败与主清单失败分开报告。
- 关闭 Tab 前等待保存完成；失败时允许重试或另存，丢弃需要显式选择。崩溃只承诺恢复已确认
  落盘的版本，不宣称最后一次按键一定存在。磁盘满时保留旧有效文件和可导出的当前草稿。
- 同工程多 Tab 共用现有 draft 注册机制；多进程写入需互斥或只读打开，不仅靠 renderer 状态。

### 重启与云任务

- 关闭 Tab 不拥有任务的取消权；已有领域服务继续管理。工作空间卸载须解除视图/监听，
  所有回写仍固定原工程绑定，不得写到新工作空间。
- 应用重启后，远端已有 task ID 的任务先查询；本地中断合成标记中断/失败并允许重试。
- 请求已发出但未收到 task ID 属于“状态未知”，使用 Provider 支持的幂等/查询能力对账；
  无法证明未提交时不能自动重提。付费授权和请求意图先落盘，再发请求。
- 下载失败保留远端成功事实及下载错误；重试下载不是重新生成。
- 生成/配音/渲染的成功依据真实文件及服务回执，不能依据 AI 自述或计时器。
- 服务注册、任务队列、监听和停止/flush 复用当前生命周期管理；新增 TTS 也必须对称释放。

### 搬迁和复制

- 关闭后移动：路径重绑定、完整性检查，再打开；没有活动写入才允许 Studio 内执行移动。
- 复制到新工作空间：默认作为独立副本分配新 videoId，保留 originVideoId 和内容历史；
  历史远端任务只读，不能在两份工程里自动重复轮询、采用或重试同一运行。
- 用户明确选择“迁移并恢复任务”才建立新的唯一运行绑定，并校验相应本机 Provider 配置。
- 文件夹本身不携带凭证；另一台机器可离线编辑和播放已下载文件，但云操作需重新配置。
- 原稿或原导入文件被删除不影响已有副本；工程内资产丢失时保留资产 ID，支持重新定位，
  比较哈希：相同内容修复路径，不同内容明确作为替换并更新依赖状态。
- 只读目录允许浏览与播放，编辑需另存可写副本；一个损坏工程不能阻断其他视频列表。

## 8. 当前实现差距与兼容

2026-09-29 本地代码核对：

- 当前每条视频已经存入 `.cclink-studio/media-projects/<id>/project.json`；口播位于
  `scenes[].narration`，随工程保存，不能说“当前口播完全不保存”。
- 原稿快照内嵌于工程，资产复制到 `assets/` 且已有 manifest；视频与渲染任务有独立 JSON，
  中间结果在 `renders/`，成片由用户选择输出位置。
- `workspaceRef.path`、source path、资产 path 和任务/output path 包含绝对路径；读取还校验
  原工作空间路径。因此当前目录存在，不等于已实现自包含搬迁。
- 尚无独立的前置口播对象、完整 checkpoint 依赖模型及本文的便携导入契约。
- 效果图中的 TTS、逐段对齐、素材裁剪、自动压低音乐等不能据图宣称已实现。

迁移原则：

1. 双读旧 schema 与新格式，单写新版；先备份原工程，验证转换后再切换索引，失败继续可读旧版。
2. 旧场景按稳定映射转为口播段落，保存原 sceneId、顺序和原文字，不重新让 AI 改写。
3. 实际复制并校验现有素材/成片后转换为相对引用；旧输出缺失时保留缺失记录，不能伪造成功。
4. 迁移不是普通打开时悄悄搬运大文件；用户看到目录、体积和问题清单后确认。
5. 新工程用可见子文件夹；旧工程可先原地兼容打开，再显式迁移。备份与旧目录不自动删除。

## 10. 设计拷问与还需确认的边界

- **存了一份 JSON 就等于保存作品了吗？** 不等于，必须带上可播放文件、来源、输入版本和恢复能力。
- **独立 Markdown 会不会造成两份正文？** 会，所以只允许派生展示 + 显式导入，不能双写。
- **保存全部内容会不会无限膨胀？** 会；先显示真实磁盘占用、缓存可清理，不以自动删用户资产换空间。
- **所有输出能否重新生成得一模一样？** 不能，云模型可能变化，因此保留实际产物，不能只存提示词。
- **重启是否等于继续一切？** 不等于；本地进程已中断，云任务需查询事实，未知不能伪装成失败后重试。
- **下一步最该做什么？** 确认“可见工程目录 + 自动保存 + JSON 唯一编辑源 + 复制导入素材”的产品约定，
  然后交付 P1。默认不引入外链素材模式、任意多轨或自动批量生成。

# 公司账目首版产品设计

> 状态：首版实现完成，代表性样本验收通过；真实业务验收待办
> 日期：2026-10-09
> 开发计划：[公司账目工作台最小开发计划](company-accounts-development-plan.md)

## 结论

首版只帮助用户处理完一个真实月份的账：

**导入流水和凭证 → AI 整理 → 用户查看原件并确认 → 查看用户选择月份的收支和眼镜项目支出 → 导出给现有代账 → 备份恢复。**

产品只有一个“账目”入口和一个工作台，不按报表、项目、报销、待收待付和资料归档拆成多个一级页面。

## 用户最终能完成的动作

1. 在普通本地工作空间进入账目，点击一次“开始使用”。
2. Studio 自动完成内部初始化并直接进入导入页，用户导入所选月份的银行或支付流水及对应凭证。
3. 在待核对列表查看规则与 Agent 的建议和原件。
4. 修改并人工确认记录。
5. 选择一个月份，查看该月收入、支出、净流入和各眼镜项目实际支出。
6. 回到分类核对区查看该月记录和原始凭证。
7. 导出汇总、明细和凭证索引给现有代账。
8. 创建备份并在工作空间副本中恢复。

验收只看三件事：这个月算得对、代账能使用、备份能恢复。

## 零配置启用

首次进入账目只显示两个动作：

- **开始使用**：Studio 自动创建 SQLite、必要数据表和原件目录，然后直接进入导入与核对。
- **从备份恢复**：选择已有备份，验证通过后恢复。

用户不需要预先填写公司、账户、分类、项目或会计期间：

- 币种默认人民币；
- 首版按一个默认币种汇总，不做多币种换算；
- 月份从流水中的交易日期取得；
- 账户随导入识别，需要时在核对记录中修正；
- 眼镜项目在核对记录时新建或选择；
- 公司名称只在首次导出确实需要时补充，并可保存为可选设置。

初始化失败只显示可理解的原因和“重试”，不能进入半初始化状态，也不能影响 Studio 其他功能。首版不提供公司档案、账套、会计期间、账户管理或分类配置页面。

## 一个工作台，三个任务区

### 导入与核对

- 零配置启用后直接进入此区域。
- 导入银行或支付 CSV 流水，以及 PDF 或图片格式的订单、合同和发票凭证。
- 银行和支付流水是收支统计依据；发票、订单、合同和图片只是关联凭证，不能因为导入凭证再次生成一笔收支。
- 显示导入成功、重复、失败和不支持项。
- 规则和 Agent 基于流水字段填写待核对建议；PDF 与图片首版只供人工预览和关联。
- 用户选择记录后查看原件、修改并确认。
- 未确认记录不进入汇总。

### 月度汇总

- 用户选择一个月份，显示该月收入、支出和净流入；也可以选择历史月份。
- 显示眼镜项目实际支出及采购、器件、打样和服务分类。
- 分类核对区保留该月记录与原始凭证，供用户逐笔追溯。
- 只统计已确认记录。

### 导出与备份

- 导出所选月份的汇总、确认明细和凭证索引。
- 导出说明记录本月未计入的待核对数量。
- 生成现有代账实际能使用的资料。
- 备份并恢复数据库、原件和修改历史。

## 两个状态

- **待核对**：导入、AI 整理或人工修改后尚未确认。
- **已确认**：用户确认当前版本，可以进入所选月份和项目汇总。

AI 只能创建或修改待核对记录。用户修改已确认记录的关键字段后，状态自动回到待核对。

## 项目支出的准确含义

首版展示的是某个眼镜项目已经确认的实际支出，不是完整财务成本。

它可以包含已确认的采购、器件、打样和服务支出，但不自动包含人工、折旧、税费、库存消耗、制造费用、资金成本或会计调整。界面和导出统一使用“项目支出”，不把它宣传成完整项目成本。

## 内部经营账与正式财税账

Studio 首版保存内部经营事实和用户确认记录。内部“已确认”不等于会计正式入账，也不等于完成税务申报。

现有代账继续负责正式会计核算和申报。Studio 的首版目标是减少资料整理、核对和交接工作，而不是承诺替代全部代账服务。

## 原件、确认、修改和备份

- 原始文件按内容哈希去重和校验，结构化记录始终能回到原件。
- AI 提取、人工修改和确认分别写入修改历史。
- 确认绑定记录当前版本、操作者和时间。
- 关键字段修改后必须重新确认。
- 月度汇总只读取已确认版本。
- 备份包含数据库、原件和必要校验信息；恢复验证失败不得覆盖现有数据。

## 首版删除项

以下内容不进入首版，也不预建占位页或框架：

- 报销与付款申请；
- 待收待付；
- 预算与提醒；
- 日、周、年和自定义区间报表；
- 完整项目成本；
- 器件库存；
- 多人提交与审批；
- 银行支付；
- 复式记账、法定财务报表和税务申报。

这些能力只有在真实月份闭环完成并出现明确需求证据后，才重新讨论。

## 当前最大不确定性

当前仍未拿到用户真实流水格式、凭证样本和现有代账交付清单。代表性样本已经证明产品闭环和基础 CSV 适配可用，但不能据此宣称现有代账已经接受导出资料。

下一步是用一个真实月份的脱敏样本和人工答案复验，不继续增加页面或数据模型。首版 Agent 只基于流水字段给出分类和项目建议；PDF 与图片作为原始凭证保存、预览和关联，凭证内容识别需等真实样本证明必要后再讨论。

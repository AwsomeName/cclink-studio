# 全局网站与账号开发计划

> 文档版本：1.1
> 状态：实现和自动化门禁已通过；真人登录与跨项目身份复测待完成
> 最后更新：2026-08-18
> 产品事实源：`docs/features/ai-web-affairs-agent.md`
> 架构决定：`docs/decisions/0014-global-web-account-catalog.md`；Agent 执行见
> `docs/decisions/0016-agent-web-account-execution.md`
> 本文只负责“全局网站与账号、跨项目复用、运营矩阵和事务引用兼容”的实施与验收；
> Agent 只读账号目录已纳入本文；Agent 打开和操作账号已由 ADR 0016 决定，但仍由
> `docs/features/ai-web-affairs-agent-development-plan.md` 独立施工，不并入本专项计划。

## 1. 当前结论

当前实现已移除账号的 `projectId` 所有权，网站、主体、账号、Profile 和运营矩阵由
`WebResourceService` 作为本机全局唯一事实源。事务仍按 `workspaceId` 隔离，可保存全局账号和
矩阵版本快照。代码和自动化已形成闭环，真实账号登录、重启后 Session 和人工跨项目验收
仍是完成声明前的必经步骤。

目标产品模型是：

```text
全局网站与账号 / 运营矩阵
          ↑ 稳定引用
项目 Browser Tab / 项目事务
```

- 网站、主体、账号、Profile、Session、登录状态和运营矩阵全局管理。
- Browser Tab 仍属于当前工作空间，只是引用全局账号。
- 事务仍属于项目，可以保存全局账号或矩阵引用。
- Agent 可以读取安全的账号登记元数据；Agent 执行采用 ADR 0016 的“明确任务、显式账号、
  敏感动作确认和人工接管”，但不计入全局账号资源库的完成范围。

## 2. 用户可执行的最终验收链

1. 用户在项目 A 打开“网站与账号”，点击添加并进入真实 Browser Tab。
2. 用户完成登录，只填写显示名称，保存为全局账号。
3. 用户切换到项目 B，不做导入或项目配置，就能看到同一账号和登录状态。
4. 用户从项目 B 点击账号，Studio 在项目 B 打开 Browser Tab，同时复用同一 Profile 和
   Session；项目 A 的 Tab 不被移动或夺走。
5. 用户把多个全局账号组成一个运营矩阵；切换项目后仍看到并可选择同一矩阵。
6. 用户在项目 A 创建或打开事务，关联一个全局账号或运营矩阵；切换项目 B 后，事务列表仍
   只显示项目 B 的事务。
7. 关闭 Tab、重启 Studio、移动或复制项目后，全局账号不丢失、不复制，事务归属不变化。
8. 旧项目账号升级后仍能打开原登录环境；疑似重复账号由用户决定是否合并。
9. 验收期间不要求、也不允许把“事务引用账号”解释为 AI 已获准自动操作该账号。

只有以上真实 App 链路通过，才能声明全局账号改造完成。Schema、Mock、单测或列表看起来
一致，只能证明工程准备度。

## 3. 产品 UI 与交互

### 3.1 全局“网站与账号”侧栏

```text
网站与账号

＋ 添加网站与账号

Apple Developer    张三公司 · 已登录
阿里云             张三公司 · 需重新登录
微信公众号          CCLink 品牌号 · 已登录

运营矩阵
CCLink 国内推广      4 个账号
```

- 切换项目不切换账号和运营矩阵列表。
- 列表行仍以“打开或激活实际网页”为主动作，不恢复前置资料表单或账号详情主路径。
- 手动点击账号时，在当前工作空间激活已有账号 Tab；没有时创建当前工作空间的 Browser Tab，
  但使用账号全局唯一 Profile。
- 重新登录和退出登录属于全局状态变化，界面必须提示“会影响所有项目”。
- 被事务引用的账号只允许归档，不能直接删除并留下悬空引用。

### 3.2 新建账号

```text
添加网站与账号
→ 当前工作空间打开临时 Browser Tab
→ 用户输入网址并完成登录
→ 点击“保存账号”
→ 只确认显示名称
→ 当前 Tab 原地绑定全局 accountId
```

- 不填写项目、网站名称、URL、主体角色、登录提示、密码、Cookie 或 Profile。
- 保存文案不得再写“保存到当前项目”。
- 未保存关闭仍清理临时 Profile；保存成功后 Session 归全局账号。
- 全局疑似重复时只能“打开已有账号”或“作为另一个账号保存”，不能静默覆盖。

### 3.3 运营矩阵

- 用户选择已有全局账号并命名一个运营矩阵。
- 同一账号可以属于多个矩阵；矩阵不复制账号或 Session。
- 矩阵显示成员数量和版本；成员变化需要保存确认。
- 项目或事务选择矩阵时记录矩阵 ID、版本和当时账号清单，后续成员变化不自动扩大既有事务。
- 本轮不做矩阵发布编排、内容分发、审批流、统计报表或平台适配器。

### 3.4 事务边界

- 事务列表、事务 Tab、本地物料、流程和证据继续按 `workspaceId` 隔离。
- 事务资源区可以选择并显示全局账号或运营矩阵引用。
- 用户点击事务中的账号资源，可以手动打开当前工作空间的账号 Browser Tab。
- 账号引用不复制 Profile、Session 或账号元数据。
- Agent 可以通过只读工具查看平台、账号名称、主体、角色、用户确认状态和运营矩阵；不得
  返回 Profile、登录提示、秘密值或网页内容。执行必须进入 ADR 0016 的统一启动链，不能
  根据目录中的 `accountIds` 自动使用任意账号。

## 4. 架构与状态所有权

| 状态                          | 唯一所有者                         | 作用域          | 不得发生                          |
| ----------------------------- | ---------------------------------- | --------------- | --------------------------------- |
| 网站、主体、账号、矩阵元数据  | `WebResourceService`               | Studio 本机全局 | renderer 或项目文件保存第二份账号 |
| Cookie、localStorage、Session | `BrowserManager` Profile partition | 全局账号        | WebResource 快照保存秘密值        |
| Browser Tab                   | Workspace/Tab 基础层               | 当前工作空间    | Tab 关闭删除全局账号              |
| 事务、流程、Attempt、证据     | `WebAffairService`                 | 单一工作空间    | 账号全局化带动事务全局化          |
| 本地物料                      | Workspace/File 基础层              | 单一工作空间    | 运营矩阵复制本地文件              |

调用关系：

```text
WebResourcesSidebar
  └─ resolveManualLaunch({ workspaceRef, accountId })
      ├─ WebResourceService 解析全局账号与 Profile
      └─ Workspace Tab 层在当前工作空间激活或创建投影

WebAffairTab
  └─ 保存 global accountId / matrix binding
      └─ 用户手动点击时复用 resolveManualLaunch

Agent / BrowserTask
  └─ 本计划只提供安全目录；执行路径由 ADR 0016 和主开发计划交付
```

`resolveManualLaunch` 是产品语义名称，最终 contract 命名可以沿用或调整；关键要求是人工
打开与未来 AI 授权不能通过删除 `projectId` 校验后混成一个无边界入口。

## 5. 目标数据模型与生命周期

### 5.1 WebResource v3

```ts
interface WebAccount {
  id: string
  websiteId: string
  principalId: string
  label: string
  browserProfileId: string
  loginConfirmedAt?: string
  archivedAt?: string
  createdAt: string
  updatedAt: string
}

interface WebAccountGroup {
  id: string
  name: string
  revision: number
  accountIds: string[]
  archivedAt?: string
  createdAt: string
  updatedAt: string
}

interface WebResourceRef {
  accountId: string
}

interface WebAccountGroupBinding {
  groupId: string
  groupRevision: number
  accountIds: string[]
}
```

账号不再拥有 `projectId`。工作空间只出现在 Browser Tab 投影和事务事实中，不进入账号
所有权。

### 5.2 生命周期

| 事件                 | 全局账号结果                   | 项目/事务结果                    |
| -------------------- | ------------------------------ | -------------------------------- |
| 从任一项目新建       | 创建一个全局账号和唯一 Profile | 当前项目保留一个 Tab 投影        |
| 切换项目             | 账号和状态不变化               | 侧栏仍显示全局列表               |
| 在另一项目打开       | 复用同一 Profile/Session       | 新项目创建自己的 Tab 投影        |
| 重新登录或退出       | 全局登录状态变化               | 所有项目下次刷新看到一致状态     |
| 关闭 Tab             | 账号和 Session 保留            | 只删除该工作空间 Tab 投影        |
| 移动/复制/删除项目   | 账号不复制、不删除             | 事务和 Tab 仍按工作空间规则处理  |
| 账号被事务引用后归档 | 保留 ID、Profile 和历史引用    | 旧事务仍可审计，新选择器默认隐藏 |
| 修改运营矩阵         | 新增 revision                  | 已绑定事务仍保留旧版本/解析清单  |

### 5.3 v2 → v3 迁移

1. 迁移前保留原文件和 `.bak`，迁移写入必须原子、可重试、幂等。
2. 每个 v2 账号保留 `accountId`、`browserProfileId`、网站、主体和登录确认时间，只移除单一
   `projectId` 所有权。
3. 原项目事务继续引用相同 `accountId`，事务 `workspaceId` 不变化。
4. 同 URL、同标签或相似 Cookie 只生成“疑似重复”提示，不自动合并。
5. 用户合并时明确选择保留的账号和 Profile；其他记录先归档，确认无引用后才允许清理
   Profile。
6. 迁移失败时回退 v2 读取，不写半迁移快照，不阻断普通浏览器和其他 Studio 能力。

## 6. 里程碑计划

状态只使用 `Pending / Ready / In Progress / Acceptance / Complete / Blocked`。E0 是工程
准备度，不计入用户功能进度；G1–G4、T1 和 R1 才是产品里程碑。

### E0：架构与迁移门禁

- **状态**：Complete（工程准备度）
- **目标**：让 v2 数据可以安全迁移和回滚，不新增用户能力。
- **方案**：落实 v3 schema、备份/回滚、兼容读、全局资源 contract、人工 launch 边界和
  旧项目引用盘点；为 AI 路径增加“不随账号全局化自动放开”的回归门禁。
- **验收**：v2 fixture 原子迁移、重复执行幂等、损坏回退、ID/Profile/事务引用不变；旧版
  数据备份仍可读取。
- **不得超出**：不得顺手改 UI、创建权限中心、开放 AI 调用、自动合并账号或清理 Profile。

### G1：全局账号列表与一次添加

- **状态**：Acceptance
- **目标**：用户在任一项目只添加一次账号，切换项目仍看到同一账号。
- **方案**：侧栏查询全局 Snapshot；新建草稿仍从当前工作空间打开，保存时转为全局账号；
  修改保存文案和空状态，移除项目级账号复制与认领主路径。
- **验收**：项目 A 保存账号后，项目 B 无需导入即可看到同一 `accountId`；反复切换不产生
  副本；未保存关闭不产生全局账号。
- **不得超出**：不得增加前置资料表、平台分支、密码管理、云同步、团队共享或事务改造。

### G2：跨项目 Browser Tab 与登录态复用

- **状态**：Acceptance
- **目标**：用户从任意项目打开同一账号时，复用同一登录环境，同时保持各项目 Tab 独立。
- **方案**：Tab 引用改为全局 `accountId`；主进程解析唯一 Profile；每个工作空间只复用自己
  的主 Tab，不能把另一个工作空间的 Tab 移走。
- **验收**：项目 A、B 各自打开同一账号，Profile 相同、Tab workspace 不同；关闭 A 的 Tab
  不影响 B 或账号；重启后重新打开仍使用原 Session；重新登录状态在两边一致。
- **不得超出**：不得实现账号并发调度、自动发布、AI 授权或把 Tab 变成全局工作台对象。

### G3：旧账号迁移、疑似重复与归档

- **状态**：Acceptance
- **目标**：现有用户升级后不丢账号、登录态和事务引用，并能人工处理重复记录。
- **方案**：执行 v2→v3 迁移；提供疑似重复列表、选择主账号、保留 Profile和归档其他账号
  的明确流程；引用中的账号禁止直接删除。
- **验收**：至少覆盖两个项目各有账号、同站疑似重复、既有事务引用和不同 Profile；迁移后
  全部可打开，未确认前不合并，归档不破坏历史事务。
- **不得超出**：不得根据名称、URL、Cookie 或登录提示自动判定同一真实身份；不得静默删除
  Profile、事务或历史记录。

### G4：全局运营矩阵

- **状态**：Acceptance
- **目标**：用户只配置一次账号集合，所有项目都能看到并复用。
- **方案**：新增全局 `WebAccountGroup`；支持创建、重命名、选择成员、归档和版本递增；矩阵
  只引用账号 ID。
- **验收**：项目 A 创建含多个账号的矩阵，项目 B 立即看到同一矩阵；成员变化生成新版本；
  已绑定旧版本的事务不会自动增加账号。
- **不得超出**：不得实现批量发帖、内容同步、发布队列、审批、统计、平台适配或团队权限。

### T1：项目事务引用兼容

- **状态**：Acceptance
- **目标**：事务仍属于项目，但能够保存并展示全局账号或运营矩阵引用。
- **方案**：保留事务 `workspaceId`；账号引用使用全局 `accountId`，矩阵绑定保存版本和解析
  清单；事务资源区允许用户手动打开账号 Tab。
- **验收**：项目 A、B 的事务列表继续隔离；二者可以引用同一账号；矩阵变化不静默改变旧
  事务；重启后引用和三段式事务 Tab 正常恢复。
- **不得超出**：不得把事务改成全局对象，不得因引用存在而允许 AI、MCP、BrowserTask 或
  定时任务自动调用账号。

### G5：Agent 只读账号目录

- **状态**：Acceptance
- **目标**：Agent 回答“我已经注册了哪些平台和账号”，无需用户重复描述现有资源。
- **方案**：在现有 MCP 工具宿主注册 `web-resources` 模块，只提供 `web_accounts_list`；由
  `WebResourceService` Snapshot 生成安全投影，默认隐藏归档记录；该跨域只读事实在 Agent
  的全部、浏览器、Android 和编辑器作用域均可用。
- **验收**：Agent 能返回网站名称、域名、登记账号名称、主体、角色、用户确认状态和运营矩阵；
  输出不包含 `browserProfileId`、`loginHint`、密码、Cookie、Token、深层入口或网页内容。
- **不得超出**：G5 仍不得打开 Tab、解析 Profile、检测实时登录身份、自动选号或触发网页
  动作；这些能力只能在 ADR 0016 的独立里程碑中交付。

### R1：统一真实 App 验收

- **状态**：In Progress
- **目标**：证明全局账号、跨项目登录态、迁移、矩阵和项目事务引用形成真实闭环。
- **方案**：使用至少两个本地项目、一个真实登录网站、两个测试账号、一个运营矩阵和一个
  项目事务，执行第 2 节完整链路并复核诊断。
- **验收**：G1–G4、T1 真人步骤全部通过；受影响 smoke、迁移测试和 `pnpm verify` 通过；
  记录剩余风险后才能设为 `Complete`。
- **不得超出**：不得用 Mock、单测、CI、Schema 或文档通过代替真人登录与跨项目操作；不得
  把 ADR 0016 的 Agent 执行工作混入本专项验收、自动发布或平台增强。

## 7. 实施顺序和整体链路

```text
E0 迁移门禁
  → G1 全局列表/一次添加
  → G2 跨项目 Tab/Session
  → G3 旧数据迁移/重复处理
  → G4 运营矩阵
  → T1 项目事务引用兼容
  → G5 Agent 只读账号目录
  → R1 统一真人验收
```

- G1 未形成真实列表闭环前，不开始矩阵或事务兼容。
- G2 未证明同 Profile、不同工作空间 Tab 前，不迁移正式用户数据。
- G1、G2 只允许在全新或隔离测试数据上进入 Acceptance；G3 完成旧账号迁移和回滚验收前，
  不得向现有用户发布只认识 v3 的版本。
- G3 未证明可回滚前，不删除 v2 写路径。
- G4 只交付资源集合，不提前建设运营发布系统。
- T1 只做资源引用和人工打开；Agent 调用由后续独立里程碑处理。
- G5 只提供安全元数据读取，不能被执行链路直接当作账号授权。

## 8. 验证矩阵

| 场景         | 必要结果                                                    |
| ------------ | ----------------------------------------------------------- |
| 全局可见     | A 添加后 B 立即看到同一 ID                                  |
| 登录态复用   | A/B 使用同一 Profile，登录状态一致                          |
| Tab 隔离     | A/B 各有自己的 Tab 投影，互不抢占                           |
| 关闭与重启   | 关闭 Tab、重启 App 后账号和 Session 仍在                    |
| 项目生命周期 | 移动/复制/删除项目不复制或删除账号                          |
| 迁移         | v2 ID、Profile、事务引用和备份全部保留                      |
| 重复处理     | 疑似重复只提示，合并必须由用户确认                          |
| 运营矩阵     | 跨项目可见，版本变化不静默扩张事务                          |
| 事务归属     | 事务仍按 workspace 隔离，可引用同一全局账号                 |
| AI 边界      | G5 没有新增默认授权、自动选号或自动调用路径                 |
| 降级         | WebResource 迁移失败不阻断 Browser、Agent、Editor、Terminal |

## 9. 统一禁止清单

本计划实施期间禁止：

- 重新给全局账号增加逐项目配置或复制；
- 把事务、材料、流程或证据改成全局资源；
- 在本专项里实现 ADR 0016 的 Agent 执行、自动选号、自动发布和账号并发策略；
- 增加团队、组织、云同步、远端账号中心或多用户权限；
- 增加密码管理器、Cookie 编辑器或在资源文件保存秘密值；
- 为 Apple、阿里云、微信公众号等平台增加专用新建流程；
- 自动合并疑似重复账号、静默清理 Profile 或删除被引用资源；
- 建立第二个 WebResource Store、让 renderer 拼装 Profile/URL，或绕过主进程 contract；
- 用工程门禁通过宣称产品里程碑完成。

任何一项确有必要，必须先更新产品事实源和 ADR并取得用户确认，不能在开发中追加。

## 10. 风险与失败降级

| 风险                       | 处理                                                       |
| -------------------------- | ---------------------------------------------------------- |
| 一处退出影响所有项目       | 重新登录/退出前明确提示全局影响，状态统一刷新              |
| 两项目同时手动操作同一账号 | 本轮只记录为残余风险；不擅自设计并发锁                     |
| v2 重复账号身份不明        | 保留全部记录和 Profile，人工选择，绝不自动合并             |
| 运营矩阵变更扩大范围       | 版本和解析清单固定旧事务范围                               |
| 账号归档后仍被事务引用     | 保留稳定 ID 和历史可读性，新选择器默认隐藏                 |
| 迁移文件损坏               | 保留 v2 原件和备份，WebResource 单独降级，其他能力继续可用 |
| AI 旧路径意外放宽          | ADR 0016 里程碑交付前保持 fail-closed，交付后走唯一启动链  |

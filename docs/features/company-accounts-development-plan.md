# 公司账目工作台最小开发计划

> 状态：首版实现完成，代表性样本验收通过；真实月份与代账交付验收待用户资料
> 日期：2026-10-09
> 产品方案：[公司账目首版产品设计](company-accounts-product-design.md)

## 结论

首版只完成一个真实月份的账目闭环：

**导入流水和凭证 → AI 整理为待核对记录 → 用户查看原件并确认 → 查看用户选择月份的收支和眼镜项目支出 → 导出给现有代账 → 从备份恢复。**

验收只看三件事：

1. 这个月算得对；
2. 现有代账能使用导出资料；
3. 备份能够完整恢复。

报销审批、待收待付、预算与提醒、日周年报表、库存、多人权限、银行支付、复式记账和正式财税核算全部后置。首版不为这些能力预建页面、表、状态或通用框架。

## 一、首版用户能做什么

1. 在普通本地工作空间进入账目，点击一次“开始使用”，随后立即进入导入页。
2. 导入一个月份的银行或支付 CSV 流水，以及 PDF 或图片格式的发票、订单和合同凭证。
3. 查看规则与 Agent 基于流水字段填写的待核对建议。
4. 选择记录，同屏查看原始凭证，修正金额、日期、交易对象、用途、分类或眼镜项目。
5. 将记录从“待核对”改为“已确认”；AI 不能执行确认。
6. 选择一个月份，查看该月收入、支出、净流入和各眼镜项目的实际支出。
7. 回到分类核对区查看组成记录及其关联原件。
8. 导出所选月份的汇总、确认明细和凭证索引给现有代账。
9. 备份账目数据库和原始凭证，并在工作空间副本中恢复。

## 二、首版不做什么

- 不开发报销与付款页面。
- 不开发待收待付页面。
- 不开发预算、到期提醒或主动通知。
- 不开发日、周、年和自定义区间报表。
- 不开发器件库存、领用、批次和成本结转。
- 不开发员工提交、多级审批和多人权限。
- 不开发正式会计科目、复式分录、法定报表和税务申报。
- 不开发多币种汇率换算；首版只允许已确认记录使用当前默认币种。
- 不跟踪代账交接流程状态；首版只生成可使用的导出包。
- 不支持一笔费用跨多个项目分摊；首版一笔记录只归属一个项目，确有真实样本再扩展。
- 不提供公司档案、账套、会计期间、账户管理或分类配置页面。
- 不为上述后续能力预留空表、空服务、空路由或占位页面。

## 三、产品与架构边界

### 普通工作空间中的一个账目工作台

- 公司账目是普通本地工作空间的一项能力，不新增财务工作空间或独立金融项目。
- 用户只看到一个“账目”入口和一个工作台。
- 工作台内部只有三个任务区：导入与核对、月度汇总、导出与备份。
- 研发项目只是记录上的一个归属字段和汇总筛选，不单独建立项目管理系统。
- 账目能力启动失败时，文件、Agent、浏览器、编辑器和 Terminal 继续可用。

### 零配置启用

- 首次进入账目只显示“开始使用”和“从备份恢复”。
- 点击“开始使用”后，Studio 自动创建 SQLite、七张最小表和原件目录，成功后直接进入导入页。
- 用户不填写公司、账户、分类、项目或会计期间，不出现初始化向导。
- 币种默认人民币；月份从流水日期取得并由用户选择查看；账户在导入时识别；眼镜项目在核对记录时新建或选择；公司名称到首次导出需要时再补并可保存。
- 初始化失败显示原因和重试入口；失败的临时文件必须清理或可安全重试，不能留下看似可用的半初始化账目。
- 初始化属于 CompanyAccountsService 的内部动作，不建立公司档案、账套、账户或分类管理服务。

### 唯一状态所有者

主进程 CompanyAccountsService 是账目事实的唯一写入者。Renderer 只保存筛选和选中状态；Agent、导入、确认、汇总、导出和恢复都通过该服务执行。

### 本地存储

首版保留 SQLite，因为一个月的流水、凭证关联、确认状态、修改历史和汇总查询不适合依赖多个松散 JSON 文件。用户不需要安装或配置数据库。

目标位置：

    <workspace>/.cclink-studio/company-accounts/
      accounts.sqlite
      documents/<studio-generated-name>.<ext>

- 使用 Electron 43 自带 Node 24 的 node:sqlite，不增加第三方原生依赖。
- SQLite 保存结构化记录和索引；原始文件按内容哈希去重和校验，文件名由 Studio 生成，不写入数据库 BLOB。
- 所有写入串行执行并使用事务；损坏或不支持的数据库版本进入只读故障态，不用空库覆盖。
- 首版限制单批最多 5,000 条记录、单文件 50 MiB、单批 500 MiB。
- 数据库操作保持有界；真实样本证明主进程出现明显阻塞后，才考虑 Worker，不提前搭建任务框架。

### 经营账与财税账

Studio 首版只整理内部经营事实。已确认表示用户确认了金额、日期、用途、项目和原件关系，不表示会计已经正式入账或完成申报。

“项目实际支出”只回答钱花到哪里，不能称为完整项目成本。它不包含尚未取得或无法分摊的人工、折旧、税费、库存消耗、制造费用及其他会计调整。产品文案统一使用“项目支出”，不使用“完整成本”。

### AI 边界

- AI 只读取流水字段并提出分类、记录类型和项目建议；PDF 与图片首版只供人工预览和关联，不承诺识别内容。
- AI 生成或修改的记录状态只能是“待核对”。
- 用户确认后状态才变为“已确认”。
- 修改已确认记录的关键字段时，状态自动回到“待核对”，并记录修改前后值。
- 月度汇总只统计“已确认”记录。
- Agent 不获得确认账目、清除修改历史或绕过原件检查的工具。

### 收支与凭证口径

银行和支付流水是收支统计依据；发票、订单、合同和图片只是关联凭证，不能因为导入凭证再次生成一笔收支。首版由用户把凭证关联到已有流水，Agent 只基于流水字段建议分类、记录类型和项目，不能自行新增或确认收支。

## 四、最小状态与数据

### 状态

账目记录只有两个业务状态：

- **待核对**：导入、AI 整理、人工修改但尚未确认。
- **已确认**：用户确认当前版本，可以进入月度和项目汇总。

导入任务和备份任务可以有运行状态，但不得把技术任务状态扩展成新的账目业务状态。

### 最小数据表

| 表               | 必须保存的内容                                                                   |
| ---------------- | -------------------------------------------------------------------------------- |
| settings         | 可选公司名称和默认币种；首版不保存公司档案、会计期间、账户或分类配置             |
| import_batches   | 一次导入的来源、月份、成功结果、重复明细和失败明细                               |
| documents        | 原始文件哈希、文件名、类型和存储位置                                             |
| projects         | 眼镜项目的编号和名称                                                             |
| records          | 日期、记录类型、收支方向、金额、账户、交易对象、用途、分类、项目、状态和当前版本 |
| record_documents | 记录与原始文件的关联                                                             |
| record_events    | AI 创建、人工修改、确认和重新打开的时间、操作者及前后值                          |

记录类型至少支持收入、支出、内部转账和退款；账户直接保存在记录中，不建立账户表。导入失败和重复明细保存在 import_batches 的结果中，不增加导入明细表。

不建立独立业务单、资金流水、AI 建议、确认、分摊、应收应付、交接批次或备份清单表。首版所需来源、确认和修改信息统一进入 records 与 record_events。数据库版本使用 SQLite PRAGMA user_version，不建立独立迁移表或通用迁移框架。

## 五、开发顺序

只有 M1 至 M3 三个产品里程碑。Contract、Schema、SQLite、IPC 和测试是各里程碑的必要工程工作，不单独包装成产品阶段。

### P0：真实月份样本与人工答案

- **状态**：Partial
- **用户功能进度**：已用 2026-09 代表性脱敏样本完成桌面闭环；尚未取得用户真实月份资料和现有代账交付清单。
- **准备内容**：
  - 一个真实月份的银行或支付流水；
  - 同月发票、订单、合同、PDF 和图片；
  - 现有代账要求的文件和格式；
  - 10 至 30 笔人工核对答案，包含普通收支、重复、退款、账户互转和缺凭证。
- **完成条件**：人工能够说明该月正确收入、支出、每个眼镜项目实际支出，以及哪些记录不能确认。
- **止损**：没有真实样本时，不开发通用解析器、分类框架或报表系统。

### M1：导入、原件和核对

- **状态**：Implemented；代表性桌面验收通过，真实资料验收待办
- **用户验收动作**：
  1. 在普通工作空间进入账目，只看到“开始使用”和“从备份恢复”。
  2. 点击一次“开始使用”，无需填写任何配置，立即进入导入页。
  3. 导入真实流水和凭证。
  4. 看到成功、重复、失败和待核对记录。
  5. 选择一笔记录，查看原件和 AI 填写内容。
  6. 在核对时按需新建或选择眼镜项目，修改后确认；重启 Studio 后仍能打开。
- **实施内容**：
  - 最小 shared contract、Zod schema 和错误码；
  - CompanyAccountsService、七张表、PRAGMA user_version、事务和损坏只读；
  - 一次点击的幂等初始化；自动创建数据库、表和原件目录，失败可重试；
  - trusted IPC、preload API 和工作空间范围校验；
  - 文件哈希、复制、重复检测和原件预览；
  - 只支持真实样本出现的 CSV 格式；
  - Agent 基于流水字段提供分类与项目建议，只填入待核对表单；PDF 和图片首版作为可预览、可关联的原始凭证，不承诺识别其内容；
  - 凭证优先关联已有流水，导入同一业务的流水和凭证不能形成两笔收支；
  - 两状态核对界面和 record_events 修改记录。
- **完成条件**：用户在普通工作空间点击一次启用即可立即导入；至少 10 笔真实记录完成导入、核对、确认和重启恢复。
- **降级**：AI 不可用时允许手工填写和确认；账目服务失败不阻断其他 Studio 能力。

### M2：所选月份汇总和眼镜项目支出

- **状态**：Implemented；代表性桌面验收通过，真实人工答案比对待办
- **用户验收动作**：
  1. 选择一个月份，包括历史月份，查看该月收入、支出和净流入。
  2. 查看每个眼镜项目的实际支出及分类。
  3. 回到分类核对区查看该月记录和原始凭证。
  4. 把一笔已确认记录改回待核对，汇总立即排除它。
  5. 与人工答案逐项比较。
- **实施内容**：
  - 用户选择一个月份进行查看，不做日、周、年和自定义范围模式；
  - 仅汇总已确认记录；
  - 内部账户互转不计收入或支出；
  - 退款按原支出方向冲减；
  - 项目支出按单一 project_id 汇总；
  - 分类核对区保留记录到 documents 的追溯关系。
- **完成条件**：月度总额和项目支出与 P0 人工答案完全一致，每个数字都能追溯。

### M3：导出和备份恢复

- **状态**：Implemented；本地导出、备份及自动恢复验收通过，现有代账确认待办
- **用户验收动作**：
  1. 导出用户所选月份的汇总、确认明细和凭证索引。
  2. 由现有代账打开并确认资料可使用。
  3. 创建包含 SQLite 和原始凭证的备份。
  4. 在工作空间副本中恢复。
  5. 重新核对月度总额、项目支出、原件和修改历史。
- **实施内容**：
  - CSV 明细和可阅读汇总；是否需要 PDF 以代账真实要求为准；
  - 稳定记录编号和凭证文件名；
  - 导出说明记录本月未计入的待核对数量；
  - SQLite 一致性备份、文件哈希校验和临时目录恢复；
  - 恢复验证完成前不覆盖现有账目。
- **完成条件**：代账能用，备份能恢复，恢复后汇总与原账一致。

M1、M2、M3 全部通过真人验收后，才能声明首版完成。

## 六、提交批次

建议只保留三个可回滚批次：

1. accounts-import-review：启用、存储、导入、原件、AI 草稿和人工确认。
2. accounts-month-summary：所选月份收支与项目支出。
3. accounts-export-restore：导出、代账验证、备份和恢复。

不得先提交空页面、通用财务框架、未来状态机或未被真实样本使用的数据表。

## 七、验证

### 自动门禁

- 首次进入只返回未启用状态；一次点击创建完整最小存储，重复点击幂等；
- 初始化中断或失败可安全重试，不留下被误判为可用的半初始化数据库；
- schema、PRAGMA user_version 与不支持版本保护；
- 金额精度、重复、退款和账户互转；
- 同一业务的流水与发票、订单、合同或图片只形成一笔收支；
- AI 不能写入已确认状态；
- 修改已确认记录会回到待核对；
- 汇总只统计已确认记录；
- 工作空间路径、符号链接、大小和 IPC sender 校验；
- SQLite 损坏只读、备份和恢复失败保护；
- 账目能力失败不影响其他 Studio 能力；
- 受影响 smoke 和 pnpm verify。

### 真人验收

1. **这个月算得对**：月度收支和眼镜项目支出与人工答案一致。
2. **代账能使用**：现有代账实际打开导出资料并确认可用。
3. **备份能恢复**：恢复后金额、记录、原件和历史全部一致。

工程门禁通过不能替代这三项验收。

## 八、当前实现与下一步

首版代码和代表性样本闭环已经完成，验收记录见
[公司账目首版验收](../testing/company-accounts-v1-acceptance.md)。当前实现支持中英文常见 CSV 表头、PDF 与图片凭证关联、两状态人工确认、月度与项目汇总、代账包导出以及完整备份恢复。

下一步只做真实业务验收：取得一个真实月份的脱敏流水与凭证、现有代账实际要求的交付清单和人工正确答案。若真实资料暴露格式差异，只增加有样本依据的适配，不扩展报销、应收应付、预算、库存或正式财税模块。

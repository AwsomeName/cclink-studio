# 项目同步产品设计

> 日期：2026-11-24。状态：评估与效果稿，**未实现，等待用户确认方向**。
> 效果稿：[项目同步](../design/project-sync-2026-11-24/README.md)。
> 参照：我的空间同步（[产品逻辑第 11 节](../design/personal-diary-space-2026-11-17/product-logic.md)、[GitHub 新建仓库](../design/github-new-repo-2026-11-24/mockup.html)、[验收](../testing/personal-diary.md)）。

## 结论

把“我的空间”已经验收过的自动双向同步推广到普通项目，**只对不是 Git 仓库的项目开放**（公司、文档、电子开发等）。用户在项目首页点“设置同步”，选“在 GitHub 新建私有仓库”或“使用已有仓库地址”，先看清“会上传什么 / 不会上传什么 / 只在这台电脑”，再点“保存并同步”。之后与我的空间完全相同：进入项目时、留在前台每个整点自动收发，状态栏显示“已同步 · 时间”；两边改了同一处就暂停，文字交给 AI 按用户的话合并，表格、Word、图片和 CAD 让用户选一份或两份都留。

本身已是 Git 仓库的代码项目不做自动同步，继续用左下角 Git 显式提交和推送。

**公司记录（业务、客户与售后、经营决策）和公司账目不随同步传输**，只同步项目里的文件。第二台电脑下载公司项目后，公司首页明确说明“记录在原电脑”，提供“从备份恢复”或“从空白开始”，不静默建一份空公司。是否以后同步公司记录，是本设计最需要用户决定的一件事（见“需要你决定”）。

## 现状评估

| 能力                                | 对象                  | 方式                                                                                                        | 现状                                               |
| ----------------------------------- | --------------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 我的空间同步（`diary-sync`）        | 仅我的空间            | 自动双向；只同步日记、计划目录、项目设置和共享定时任务；分叉在临时 worktree 合并，冲突交给 AI，主分支只快进 | 真实 Electron 验收通过；GitHub 新建私有仓库刚上线  |
| 手动 Git 备份（`GitBackupService`） | 任意本地项目          | 一次性：提交全部可备份变更并 Push；单向；不拉取                                                             | 已实现，真人 GitHub 验收未做；目标演进是左下角 Git |
| 左下角 Git                          | 本身是 Git 仓库的项目 | 看变更、勾选提交、显式 Push                                                                                 | G1-G3 完成，Fetch / 远程关联未完成                 |
| 公司账目备份                        | 公司账目              | 导出数据库、原件和校验到文件夹，可在另一目录恢复                                                            | 已实现并验证恢复                                   |

问题：

1. **普通项目没有双向同步**。手动备份只上传不接收，第二台电脑改的东西回不来；用户需要的是“两台电脑一致”，不是“推一份快照”。
2. **同一项目可能出现三套入口**（手动备份、左下角 Git、我的空间式同步），用户分不清该用哪个。
3. **公司数据无人负责跨设备**。`company.sqlite`、`accounts.sqlite` 与原件都在 `.cclink-studio/` 下，现有 Git 规则一律排除；第二台电脑打开同一项目会看到空公司并可能“开始使用”出第二份分叉的记录。
4. **项目比日记大得多**。整目录上传会碰到视频、STEP 等大文件（GitHub 单文件上限 100 MB）、`.env`、依赖目录。我的空间的范围天然很小，不需要上传预览；项目必须有。

推广的可行性高：`syncDiary` 的核心（初始化、范围校验、敏感文件拦截、上传历史检查、临时 worktree 合并、AI 冲突反馈、只快进、上传后核对）与“日记”无关，只有“同步哪些路径”是日记专有的。

## 用户怎么用

效果稿逐屏对应下表（`sync.html?view=…`）。

| 场景                  | 用户看到并做什么                                                                                                                                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 未设置 `home`         | 项目首页右上角“↻ 未设置同步 ›”，右栏“同步”卡片说明会同步什么、只在本机什么，按钮“设置同步”。状态栏同样显示“未设置同步”。                                                                                            |
| 设置 `setup`          | 三选一：不同步 / 在 GitHub 新建私有仓库（默认仓库名取项目目录名）/ 使用已有仓库地址。下方“第一次会上传什么”三栏：会同步（按顶层目录统计）、不会上传（大文件、疑似密钥、可再生目录）、只在这台电脑。点“保存并同步”。 |
| 首次 `running`        | 新建仓库 → 检查文件 → 上传（进度）→ 核对两端一致。可以继续工作；有未保存的编辑先保存。                                                                                                                              |
| 日常 `synced`         | 不用操作。进入项目、前台整点自动同步；首页卡片写上次收到/上传了什么、下次时间。后台项目在顶栏用小点表示“有待同步”或“暂停”。                                                                                         |
| 文字冲突 `text`       | 两份原文并排，用户写“用 659 元，保留前 100 名”，点“继续同步”；可以“稍后处理”，状态保持暂停，文件不被覆盖。                                                                                                          |
| 二进制冲突 `binary`   | 用这台的 / 用另一台的 / 两份都留（另一份加“（MacBook Air 11-24）”后缀）。没选的那份仍在同步历史里。                                                                                                                 |
| 大量删除 `deleted`    | 另一台一次删除超过 20 个文件时先暂停：“照做，删除这些文件”或“不删除，重新上传它们”。                                                                                                                                |
| 第二台电脑 `clone`    | 打开其他空间 → 从 GitHub 下载项目，列出已保存账号下的私有仓库并标出“项目同步 / 我的空间”，选保存位置，“下载并打开”。下载完自动开启同步。                                                                            |
| 下载后的公司 `cloned` | 公司首页顶部说明公司记录与账目不随同步，按钮“从备份恢复公司记录”“在这台电脑从空白开始”（后者提示两边记录各自独立）。                                                                                                |
| 代码项目 `git`        | 同步卡片写“由 Git 管理”，不提供自动同步，按钮打开左下角 Git。                                                                                                                                                       |

## 同步范围

| 类别                                                   | 处理                                                                                                      |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| 项目里的普通文件                                       | 同步                                                                                                      |
| `.cclink-studio/workspace-settings.json`、共享定时任务 | 同步（沿用现有 Schema 与密钥检查）                                                                        |
| 单个大于 50 MB 的文件                                  | 不上传，在“不会上传”和同步页列出；首版不做 Git LFS                                                        |
| `.env*`、私钥、证书、凭证文件                          | 不上传（沿用 `findSensitiveFiles`）；已被跟踪时暂停并说明                                                 |
| `node_modules/`、常见构建输出、`.DS_Store`             | 不上传                                                                                                    |
| `.cclink-studio/` 其余内容                             | 不上传：公司记录、公司账目与原件、Agent 会话与布局、媒体渲染、下载、定时任务运行结果、`project.json` 身份 |
| userData 中的内容                                      | 本来就不在项目里：网站账号登录、凭证、发布任务记录、Git 绑定                                              |

`project.json` 不同步，所以下载下来的副本获得新的稳定身份，符合“复制不继承绑定”的既有规则。

## 自动时机与状态

与我的空间第 11 节完全一致，只把“进入我的空间”换成“进入这个项目”：进入（切到项目、启动恢复到项目、窗口回到前台）立即同步一次；留在前台每个整点一次；错过的整点不补跑；手动“立即同步”随时可用；同一项目同时只跑一轮。**只同步当前激活的项目**，后台项目只在本机检测“有待同步的改动”并显示小点，不在后台联网。

状态栏、首页标签和同步页共用四种状态：同步中… / 已同步 · 时间 / 有待同步的改动 / 同步暂停 · 查看原因。暂停原因只有：冲突待决、大量删除待确认、认证失效、范围外或敏感文件、网络失败。网络失败下次触发自动重试；其余等用户处理，进入和整点不会重复弹窗。

## 架构边界（实现前须满足）

- **状态所有者不变**：同步执行仍由 `GitWorkspaceService.transfer` 拥有，新增 `action: 'project-sync'`，与 `diary-sync` 共用同一引擎；把 `syncDiary` 的“同步路径”参数化（日记目录集合 vs 整个项目减排除规则），不复制第二个同步器。绑定地址与上次结果存在 `WorkspaceStateService` 的项目段 `project-sync`，同一份事实同时供首页、状态栏和同步页读取。
- **一个项目只有一个入口**：设置了项目同步的项目，状态栏显示同步状态，不再显示手动备份；手动备份已绑定的项目提供一次“改为自动同步（沿用原仓库）”。左下角 Git 只服务原本就是 Git 仓库的项目。
- **准入**：文件夹不是 Git 仓库，或是由项目同步初始化的仓库；位于另一个仓库内、是我的空间、远程项目、只读目录时不提供。
- **权限与凭证**：沿用已保存 GitHub Token 的 `GIT_ASKPASS` 与本次 SSH 私钥路径；不读系统钥匙串；仓库只允许私有，同名公开仓库拒绝（与我的空间相同）。
- **人工确认点**：首次上传前的范围预览；冲突；大量删除；更换地址；停止同步。自动同步本身不需要确认。
- **降级**：没有 Git、没有网络、未保存 GitHub 账号、同步失败时，项目的文件、Agent、浏览器、终端、公司首页全部照常可用。
- **诊断**：同步页“最近几次”显示每轮收到/上传的文件数与失败原因；错误可复制且已脱敏。
- **ADR**：把可上传范围从“日记和共享设置”扩大到“整个项目”改变了数据外发边界，实现前提交 ADR 0026。

## 真人验收（实现后）

1. 在公司项目“蜗牛眼镜”首页点“设置同步”，选“在 GitHub 新建私有仓库”，核对三栏后“保存并同步”。预期：GitHub 出现私有仓库，里面有项目文件，没有 `.cclink-studio/company-workspace`、`company-accounts`、大文件和 `.env`。
2. 在第二台电脑（或第二个用户目录）“从 GitHub 下载项目”。预期：文件齐全，同步已开启；公司首页显示“记录在原电脑”，不出现空公司的待办。
3. 在第二台修改一篇推广稿；回到第一台切进项目。预期：不点任何按钮，文件已更新，状态栏“已同步 · 时间”。
4. 两台同时改同一段文字。预期：暂停；输入处理意见后两边一致。
5. 两台同时改同一份表格。预期：可选一份或两份都留，没选的能从历史找回。
6. 第二台删掉一个含 30 个文件的目录。预期：第一台先暂停询问。
7. 断网、清除 GitHub Token、卸载 Git 各试一次。预期：项目其余功能可用，状态如实。
8. 打开 cclink-studio 代码项目。预期：显示“由 Git 管理”，没有自动提交。

## 实现顺序（每步都有用户可验收结果）

1. **单台上传 + 双向收发**：项目首页卡片、设置页（复用 `DiarySyncChoice`）、范围预览、`project-sync` 动作、自动时机。验收 1、3、4、7、8。
2. **第二台电脑**：从 GitHub 下载项目（列出私有仓库）、公司首页“记录在原电脑”。验收 2。
3. **二进制冲突与大量删除保护**。验收 5、6。
4. **合并入口**：手动备份项目迁移为自动同步，移除重复入口。

## 需要你决定

1. **公司记录要不要跨电脑**。推荐首版不同步，理由：SQLite 是二进制，两台同时写无法合并，只能整份覆盖，会丢记录；客户资料和流水原件会离开本机到第三方平台，与此前“客户数据留在本机”的约束冲突。若需要，可在后续把记录导出为逐条文本放进仓库并加密，但这需要单独设计和你明确同意外发。
2. **单文件上限 50 MB 是否合适**。超过的视频、STEP 文件首版不同步；若这类文件必须在两台电脑间流转，要另议 Git LFS 或其他存储。
3. **代码项目是否完全不碰**。推荐是；否则自动提交会污染代码历史、绕过分支和 CI。

## /grilling

- 最危险的失败不是同步失败，而是**把不该外发的东西传上去**：整个项目范围远大于日记，首次预览、敏感文件拦截和上传历史检查是首版门槛，不是加分项。预览统计必须来自真实将要提交的文件列表，不能是前端估算。
- **删除是双向的**。用户心里的“备份”通常不包含“另一台删了我这台也删”。大量删除保护和“没选的那份可找回”必须在第一版就有，否则一次误删会传到所有电脑。
- **二进制冲突比文字冲突常见**（报价单、Word、设计稿）。AI 合并只覆盖文本；首版若只做文本冲突，就必须对二进制冲突至少做“两份都留”，不能卡死在暂停。
- **第二台电脑的公司首页**最容易出事：现有“开始使用”会在空目录建一份新公司库，之后两份记录永远分叉。必须在第 2 步之前加判断，不能等用户撞上。
- 同步依赖 GitHub 可用和 Token 有效；Token 过期时自动同步会持续暂停，状态栏必须一直可见，不能只在打开同步页时才知道。
- 这份设计只有效果稿，没有任何实现；效果稿检查（无溢出、无脚本错误、关键按钮可用）只说明页面可演示，不代表能力存在。

## 已确认的首版范围

2026-10-14 用户确认按本设计推进，并要求固定到文档。首版采用经营导航：左侧公司导航，中间业务工作台，右侧复用现有 Agent。财务、项目管理和运营同时保留，以业务项目连接工作、支出、内容和资料；先服务用户个人经营，真人共同使用后续设计。

## 产品结论

公司工作空间是普通本地工作空间可以启用的一种经营视图。用户进入后，先看到当前目标、真实卡点和需要自己处理的事项，再进入相应业务，让 AI 带着关联资料推进下一步，最终查看可验证的结果。

财务、项目管理和运营共同围绕业务项目组织。公司总览展示这些领域已有的事实与关联；各领域继续拥有自己的账目、发布、运行和确认状态。公司视图本身不成为第二套执行或财务系统。

首版服务一个人经营一家公司。AI 是现有 Agent 的协作方式，不新增持久 AI 员工、组织架构、人事系统或员工调度。这里的公司名称只是工作空间显示信息，不建立新的登录身份或法律主体认证。

## 用户端到端验收

以下是未来实现的验收动作，本轮设计与示意数据不能代替实际通过。

1. 用户打开一个本地文件夹，选择“启用公司视图”，填写可修改的显示名称，直接进入公司总览。文件、会话、Tab 和账目保留原来的工作空间归属；无须登录 CCLink。
2. 用户创建“AR 眼镜一代”业务项目，写下一句话目标和一项可判断的交付物，例如“完成首轮试戴记录及产品介绍稿”。关联选定的规格文件、已有会话和账目项目归属。
3. 用户导入一个真实月份的流水与凭证，让 AI 提出待核对建议，查看原件并人工确认。业务项目展示对应的已确认实际支出，能够下钻到原始记录；未确认金额单独显示。
4. 用户在项目内提出“根据规格和试戴记录准备一篇介绍稿”。AI 提出材料范围、输出文件和完成条件；用户接受后启动现有 Agent 执行。稿件实际保存后，任务进入“待验收”，用户可以打开文件检查并验收。
5. 用户把稿件关联到运营内容，选择一个真实支持的发布平台和显式账号，进入现有文章发布页。执行链路覆盖准备、账号与原稿核验、正文与图片、平台字段、保存、提交发布及结果核验。
6. 运营页与公司总览同步显示真实步骤、人工接管或外部等待。真实平台的公开结果核验通过时，显示公开链接及核验时间；只保存草稿、平台拒绝、结果未知均保持其实际状态。
7. 用户切换工作空间并重启 Studio。公司项目、关联资料、待处理事项和结果仍可打开；被中断的执行显示中断，由用户检查后继续。已提交但结果未知的发布只进入核验，不能自动重发。
8. 用户从选定会话确认一条经营决策，并让 AI 根据真实账目、已验收产物和平台回执准备一份经营回顾；可以逐项查看来源，AI 建议保持待决定。

成功标准是用户可以在同一业务项目内追溯“工作做了什么、实际支出了什么、对外产出了什么”，并从一件真实卡点继续到下一项可验证结果。财务、执行计划观测和公开发布分别记录验收；一项通过不代表另外两项通过。

## 用户日常路径

早上打开公司总览，先看“需要我处理”和“正在推进”。每条事项告诉用户发生了什么、影响哪件业务、事实来自哪里，以及当前允许做什么。用户可以查看凭证、打开产物、接管网页或继续 AI。

需要安排新工作时，用户在业务项目里用自然语言提出目标。AI 根据用户选定的资料提出计划；计划经接受后成为项目工作。执行中用户看得到当前动作与等待原因，完成后查看产物或外部回执。

每周回顾时，AI 基于确认过的财务记录、任务验收和平台结果准备经营回顾草稿。草稿附来源和时间；风险解释与建议标为 AI 判断，不能自动修改目标、截止日期、财务确认或发布授权。

## 公司入口与启用

“打开工作空间”提供普通文件夹和公司视图的使用路径，两者底层使用同一 Workspace 身份。已有普通工作空间也能从工作空间操作中启用公司视图，不需要复制目录或重新导入数据。

启用仅需目录和显示名称，目标、资料、账目和平台账号都在实际使用时逐步补充。首次总览展示“创建业务项目”“导入账目资料”“关联已有资料与会话”三个真实动作，不显示虚构经营数字、默认任务或假进度。

顶栏继续负责工作空间切换。新增“公司”能力入口打开公司工作台；左侧显示公司导航，中间操作当前业务，右侧复用 Agent。文件、浏览器、Terminal、账号和其他现有能力仍可正常打开。已有账目与文章发布入口继续使用相同实例、Tab 和领域服务，不能复制成另一套公司专属实现。

关闭公司视图只改变导航与默认落地页，保留业务资料及原有领域数据。归档业务项目保留关联记录和证据，不删除账目、原稿或平台文章。

| ---------- | ---------------------- | ------------------------------------------------------------ |
| 公司总览   | 现在最该处理什么       | 当前目标、需要我处理、正在推进、月度收支摘要；进入原始事项   |
| 业务项目   | 一项业务怎样推进       | 项目列表、项目目标、交付物、工作与卡点；关联支出、内容和资料 |
| 财务       | 当前月份的账是否清楚   | 复用导入与核对、月度汇总、导出与备份三个任务区               |

“需要我处理”是各领域待处理事实的聚合视图，放在总览中。其状态与动作回到原领域，不新增可独立改动的待办状态。

## 公司总览

首屏优先展示需要用户处理的事项，再展示正在推进的业务。财务摘要作为简短事实区；无真实数据时提示尚未导入，不能显示 0 元暗示公司没有收支。

事项按人工交接、执行失败、已登记的到期事项和普通进行中排序。同类事项按发生时间排序。因果影响只有存在明确项目关联和依赖时才显示；AI 推测的影响作为建议，不自动阻断执行。

每条事项包含所属业务、来源领域、当前状态、更新时间、等待或失败原因和下一步按钮。进入后直接打开该条账目、任务、发布事务或原件，而非再次让用户在聊天里解释。

总览不展示无来源的公司健康分、任意加权完成率或默认利润。项目进展优先写“3 项已验收，1 项待验收，2 项未完成”，需要时下钻看具体交付物。

## 业务项目与工作

业务项目是公司内的目标与交付容器，例如“AR 眼镜一代”“产品发布”或“本月客户调研”。它不是新的 Studio 工作空间，也不拥有独立 Browser、Agent 或 Terminal 生命周期。

最小字段为名称、目标、交付物、可选截止日期和关联资料。创建项目不强制设置预算、部门或成员。项目默认按事实展示当前工作，用户可以归档，也可以重新打开。

项目详情采用一个业务上下文与局部页签：工作、关联支出、运营内容、资料。所有数字或状态可以打开原始记录。任务列表默认优先于复杂甘特图；只有用户显式登记的依赖和日期进入时间视图。

### 工作状态与完成判断

| 状态       | 进入条件                                 | 显示内容                             | 允许下一步                   |
| ---------- | ---------------------------------------- | ------------------------------------ | ---------------------------- |
| 计划中     | 用户尚未接受 AI 建议                     | 建议动作、资料范围、产物、完成条件   | 修改或接受计划               |
| 待开始     | 用户接受工作且执行条件满足               | 执行者、完成条件、已选资料           | 开始 AI 或人工工作           |
| 执行中     | 关联真实运行已开始                       | 当前动作、开始时间、运行入口         | 查看、暂停或接管             |
| 需要我处理 | 真实运行交接、缺资料或业务选择待用户处理 | 原因、操作入口、解除条件             | 补资料、处理或交还 AI        |
| 等待外部   | 有可追溯提交回执或明确外部依赖           | 等待对象、依据、可选检查时间         | 查看证据、显式检查           |
| 待验收     | 产物真实存在，或外部结果已核验           | 产物版本、验收条件、核验依据         | 用户验收或退回               |
| 已完成     | 用户验收了当前产物版本                   | 验收结果、时间与证据                 | 查看；关键产物变化后重新验收 |
| 失败或中断 | 运行失败或恢复发现未结束运行             | 最后动作、原因、已有产物、未知副作用 | 检查结果后继续或终止         |
| 已终止     | 用户明确结束工作                         | 原因与保留证据                       | 查看或新建后续工作           |

执行任务分为两类。普通公司工作拥有目标、验收和产物引用；如果工作交给现有发布或网页事务，工作只保存委托引用，运行、步骤、等待和结果全部读取原事务。公司内的“已完成”表示该业务交付已验收，不能替代平台发布状态。

上表定义用户看到的工作视图。执行中、暂停、交接、失败和中断来自关联运行或原事务的事实投影；公司领域不另存一份可独立修改的运行状态。公司只拥有普通工作的计划接受、资料关联和业务验收决定，保留原运行引用供恢复与核对。

AI 可以准备计划、执行和提出验收材料，不能通过一句“做完了”变更完成状态。人工工作允许用户明确记录结果并验收，显示为用户提供的证据；不能伪装成平台已核验结果。

## 财务设计

复用当前 CompanyAccounts 工作台，保留零配置启用、人工确认、月度汇总、原件关联、导出和备份恢复规则。公司类型不把现有账目首版扩张为完整财税系统。

现有 Agent 建议基于流水字段，PDF 与图片作为原件预览和关联；本设计不把凭证自动识别写成已交付能力。

| 首版页面内容 | 展示口径                                                     |
| ------------ | ------------------------------------------------------------ |
| 月度摘要     | 已确认收入、支出、净流入，以及待核对数量                     |
| 项目关联支出 | 已确认实际支出；不是完整项目成本                             |
| 核对现场     | 流水字段、AI 建议、原件、确认版本与修改历史                  |
| 资料完整度   | 当前导入来源与待核对事项；无法证明完整月份时提示资料可能未齐 |
| 导出与备份   | 原有交付包、备份和恢复入口                                   |

既有账目“项目”是财务归属字段，公司业务项目是经营目标与交付容器。首版由用户显式绑定一个既有账目归属，或通过账目服务创建归属后绑定；同一归属最多关联一个公司业务项目，避免总览重复计数。不按同名自动合并，不重新录入交易，不重命名历史归属作为迁移手段。

研发采购、员工垫付、付款、库存和成本不能互相推断。首版继续采用现金收支与已确认项目支出口径。报销审批、预算、应收应付、付款、库存、正式记账和申报不在本轮实施范围；有真实业务样本后再分别定义闭环。

## 运营设计

运营以内容和当前动作组织，不按平台复制一个工作空间。首版内容从已有 Markdown 文件选择，记录主题、所属业务、原稿引用和准备任务。平台账号使用全局账号的稳定引用，不保存密码、Cookie 或独立公司登录态。

内容准备与发布是两种不同状态：稿件有产物且用户验收后显示“稿件已验收”；需要公开发布的目标仍需对应事务达到已核验的平台结果。文章保存草稿后显示“草稿已保存”，平台审核中、审核拒绝、发布结果未知分别保留。

首版一个内容目标绑定一个明确平台及账号，复用现有支持平台的实际入口。多平台扩散需要分别可审查的对象与授权，不使用一键批量发布掩盖影响范围。尚未有适配器或未通过该场景验收的平台明确显示能力边界。

执行细步骤复用 WebAffair 的准备、账号与原稿核验、正文与逐图、平台字段、保存、提交及结果核验。每一步呈现实际执行者、动作、进入条件、状态、完成证据、等待或失败原因和允许下一步；公司视图不另存步骤成功状态。

发布动作按照现有有界授权规则执行：用户看见目标平台、账号、原稿与材料快照、预期结果和范围后，点击开始构成本次一致范围的授权。验证码、扫码、法律或版权声明、付款、账号变更、破坏性或批量影响、范围变化和未知后果转人工。设计不降低现有运行时守卫；守卫尚未完成的场景如实呈现人工处理。

首版结果区只展示当前实际可验证的状态、公开链接、回执和核验时间。浏览量、转化率、广告投入与 ROI 需明确数据来源和授权后单独设计，未获取时显示“未获取”，不能展示演示数字为真实经营效果。

## 资料与会话及公司知识

用户手动选择当前工作空间内的文件或会话进行关联。会话保持原有身份、内容和恢复方式；公司只持关联引用。跨工作空间会话首版通过明确选择和已有可用导出路径把材料保存到当前目录，再关联；不默认遍历其他目录，不自动搬移或复制正在运行的会话。

AI 提取的历史决策进入候选列表，附来源会话和出处。用户接受后成为公司决策记录，记录决定、适用业务、时间与来源；AI 摘要、用户决策与原始材料明确区分。新决定改变旧决定时显示取代关系，旧记录保留。

AI 本次工作前展示可检查的上下文：当前公司、业务项目、目标、选定文件与会话、财务可读范围、目标账号以及输出位置。敏感原件默认按任务需要选择；目录或账号可见本身不扩大执行授权。

## AI 协作交互

右侧复用现有 Agent 面板，跟随用户显式选定的当前业务事项。切页面可以提出新的上下文建议，正在执行的运行继续绑定启动时的工作空间、任务和资料快照，不能随选中项漂移。

用户可以输入“本周有什么卡住了”“整理这个月的账”“准备产品介绍稿”等请求。AI 返回可执行建议：本次要做什么、使用哪些资料、产物在哪里、怎样判断完成、哪些步骤由用户处理。明确任务所授权的范围内，读取、整理与准备直接进入现有执行入口；新增目标、账号或影响范围需要重新展示范围。

首页 AI 回顾显示数据更新时间与引用来源。事实未变化时不重复制造提醒。主动定时检查通过用户显式配置的现有定时任务执行；Studio 退出或电脑睡眠时不承诺持续工作，恢复后展示错过的检查和最后观察时间。

首版按钮文案采用“让 AI 准备”“查看产物”“继续执行”“由我处理”“检查结果”和“验收完成”，避免“全自动经营”或无范围的“一键完成”。

| Agent 与 Browser 单次执行                    | 现有 Agent 与 BrowserTask owner | 关联已有运行，显示当前动作         |
| 定时触发和运行记录                           | 现有 ScheduledTask owner        | 选择是否配置检查，读取已有结果     |
| 原稿、产物、会话                             | 现有文件、编辑器与 Agent 领域   | 保存引用与版本证据                 |

公司新领域只能拥有原系统尚未定义的经营目标、业务项目、普通工作验收与关联，不建立通用 orchestrator、全步骤 operation 账本、claim/report MCP、短 Run 调度或第二个权限系统。公司领域故障只使公司视图降级。

实施前沿用共享 contract、运行时 schema、可信 sender 校验和有界资源作用域。持久化写入由主进程单一服务串行、原子地完成；Renderer 只保留筛选、选中和可重建投影。具体存储格式和 IPC 到纵向实施方案时确定，本轮不提前建立表或代码框架。

监听、执行关联与资源投影遵守现有工作空间切换和生命周期。切换后旧运行结果只能回写原归属；模块关闭释放订阅；重启恢复未完成运行时明确标为中断。公司规则文档、AI 文本或角色切换不能修改权限边界。

账户、账号、金额明细和原件正文不进入普通诊断。诊断包含脱敏工作空间标识、业务对象 ID、来源领域、关联运行、失败分类和允许恢复动作。公司视图不使用系统钥匙串，不修改云服务或独立 Agent runtime。

## 失败与降级体验

| 失败场景                 | 用户看到什么                           | 恢复动作                     |
| ------------------------ | -------------------------------------- | ---------------------------- |
| 财务未启用或缺月份资料   | 尚未导入、待补资料；不显示 0 元或利润  | 打开原财务导入入口           |
| 账目文件损坏或查询失败   | 财务不可用，保留原件，其他页面继续工作 | 查看错误；使用既有备份恢复   |
| AI Runtime 不可用        | AI 暂不可用，项目和手工核对可用        | 手工处理或进入组件诊断       |
| 文件或会话引用失效       | 材料缺失，相关工作无法开始             | 用户重新绑定或移除引用       |
| 选定资料在执行前变化     | 需要按新版本检查计划                   | 重新展示快照；保留旧产物     |
| 发布账号不明确或登录失效 | 需要我处理，显示目标账号               | 打开正确账号并人工登录       |
| 外部提交结果未知         | 结果待核验，不显示失败后直接重试       | 只读检查；无法识别时人工选择 |
| 平台拒绝或等待审核       | 原始拒绝原因或等待状态                 | 补正、继续等待或用户终止     |
| 工作空间切换、退出、重启 | 原业务记录保留，运行中断及已有证据可见 | 先核对最后结果再继续         |
| 保存失败                 | 明确未保存，禁止显示成功               | 重试或导出可恢复材料         |

## 首版范围与交付顺序

三个领域共同进入产品设计。分批实施按用户动作形成增量，不按财务、项目、运营三选一砍掉目标。

| 用户能力增量       | 本批可实际验收的动作                                               | 下一批依赖               |
| ------------------ | ------------------------------------------------------------------ | ------------------------ |
| 公司与业务关联     | 启用公司视图，创建业务项目，关联已有账目、原稿与会话；总览能下钻   | 原始领域查询可用         |
| AI 推进一件工作    | 从真实卡点启动 Agent，生成并保存产物，用户验收；重启后继续         | 同一业务目标与上下文关联 |
| 财务与运营结果联通 | 真实月份核对与导出；同一业务文章实际提交并核验结果；总览如实回流   | 真实资料和具体发布授权   |
| 经营回顾与首版验收 | 确认有来源的经营决策，生成带出处的回顾；重启后完成全部真实业务验收 | 三域结果与资料来源可核验 |

只有最后一批的三域真实验收均通过，才称为首版公司经营闭环完成。前两批只报告已验收的具体能力。构建、Schema、测试和状态映射属于工程准备度。

后续候选为真人协作、预算与报销、明确来源的运营指标和持续 AI 职责。进入这些范围前分别定义用户闭环、权限和唯一 owner。当前 AI 员工暂停决定继续有效；公司设计不自动重启员工中心或商业模板平台。

## 设计评审与当前缺口

结论：公司经营视图与单人使用范围成立；最重要的新增价值是业务关联与可恢复的工作推进。首版复用财务和发布事实，新增普通公司工作及验收，避免三套相似执行系统。

| 拷问                     | 设计回应                                                     | 仍需验证                                   |
| ------------------------ | ------------------------------------------------------------ | ------------------------------------------ |
| 只是把功能放一起吗       | 用同一业务项目把工作、支出、原稿和结果关联，并可直接继续动作 | 用户能否明显减少找资料和重新交代背景的时间 |
| 财务数字可靠吗           | 已确认口径、原件下钻、缺资料提示                             | 真实月份人工答案和代账可用性               |
| AI 说完成就算完成吗      | 产物存在进入待验收；用户验收，平台另按原始结果核验           | 真实文件变化、退回与重复执行场景           |
| 项目会复制事务状态吗     | 委托工作只引用事务；公司验收不改变事务终态                   | 切换、重启、外部等待和未知提交投影         |
| 会把公司启动做复杂吗     | 目录与显示名称即可启用，其他信息按动作补充                   | 已有工作空间启用的可理解性                 |
| 一个人用为什么要员工系统 | 首版直接用现有 Agent，真人协作与持久员工另行设计             | 本地 App 生命周期是否满足实际工作节奏      |

本轮交付是产品方案与可交互效果示意，界面内交易、任务、原稿、平台回执均为演示数据。真实 App 中的公司入口、跨域关联与普通工作验收尚未实现；原账目与发布能力的验收仍以各自当前文档为准。

实施顺序以 [公司工作空间实现方案](company-workspace-development-plan.md) 为准。首个业务样本为“AR 眼镜一代”，从公司启用、业务项目与真实资料关联开始，再接 AI 产物验收、财务与发布结果。不得以补企业档案、组织架构或通用任务平台替代该闭环。

# Markdown 文章平台发布

> 状态：首版任务框架与 CSDN 最小浏览器策略已实现；真实 CSDN 端到端发布仍待验收。
> 最后更新：2026-08-28。
> 关联事实源：`docs/architecture.md`、`docs/features/ai-web-affairs-agent.md`、
> `docs/features/browser-automation.md`、`docs/features/platform-automation.md`、
> `docs/features/markdown-wysiwyg.md`。
> 最小研发计划：`docs/features/article-platform-publishing-development-plan.md`。

## 结论

文章发布采用“一个通用发布内核 + 平台薄适配器”，不为每个平台复制完整发布系统，也不把
所有页面差异交给通用 Agent 临场猜测。

- Studio 新增独立“文章发布”Activity Bar 入口；其侧栏只展示发布历史，配置和执行统一放在
  专用文章发布 Tab。
- 每个发布 Tab 一一绑定一个持久发布事务；关闭 Tab、关闭 Agent 或重启 App 都不会把事务变成一套
  新流程，恢复时从最后一个已确认检查点继续。
- 通用发布内核负责 Markdown、图片、账号引用、任务生命周期、失败恢复、诊断、预览和结果证据。
- 平台适配器定义该网站需要填写的字段和有序发布流程，并负责识别编辑页、操作平台编辑器、上传
  图片、保存草稿和验证结果。
- 点击“开始执行”会打开绑定账号的可见 Browser Tab，同时打开绑定本任务的 Agent；Agent 只能按
  适配器生成的流程执行，包括完成已明确授权的常规发布；所有进度和卡点回写文章发布 Tab。
- 未适配网站可以继续由通用网页 Agent 尝试准备草稿或转人工，但不能宣称稳定支持。
- 第一条真实闭环只做 CSDN；成功后再根据真实需求增加知乎、掘金等薄适配器。
- 平台适配器首版随 Studio 发布，不启动通用插件平台、独立安装、远程目录或热更新系统。

本文确认产品方向和实现边界。当前代码已交付独立入口、专用 Tab、Markdown/图片解析、持久事务、
断点恢复状态和 Agent/Browser 启动骨架，但不代表真实 CSDN 发布闭环已经交付。若需要改变架构
宪法或既有暂停范围，仍需先更新事实源并按要求提交 ADR。

## 用户现在能做什么、还不能做什么

用户现在可以从独立“文章发布”入口新建专用 Tab，选择当前工作空间内的 Markdown，自动识别并
按内容哈希去重 PNG/JPEG/WebP 插图，选择已保存的 CSDN 账号，填写标题、摘要、标签、分类和封面，
保存为可从历史恢复的发布事务。点击开始后会打开绑定账号的可见 Browser Tab 和专属 Agent，并把
检查点、单图等待/核验/三次尝试上限、原 Attempt 恢复以及框架关键日志保存在事务中。

当前已实现 CSDN 受控 Origin 集合、Playwright 控件识别、三态动作分类、常规单篇发布防重放
标记，以及人工接管后恢复同一 Attempt。用户现在仍不能被承诺稳定完成真实 CSDN 的
正文填写、图片上传、草稿保存、最终发布和结果 URL 核验：尚缺一次新版本在真实 CSDN 页面上的
完整验收证据。页面不在适配器识别范围、法律/版权声明、风控或结果未知时仍必须停下转人工。

### 2026-08-28 · 账号任务限制审计与最小修复清单

连续两次真实执行暴露的不是两个独立按钮问题，而是旧“登记账号任务”守卫没有按 ADR 0016
迁移。首轮把 CSDN 图片弹窗的“确认上传”误判为最终提交；第二轮只用账号入口
`https://mp.csdn.net` 建立单 Origin 边界，而复用 Tab 位于合法的
`https://app-blog.csdn.net`，导致一次只读截图完成后仍被暂停。

本轮冻结以下问题与最小修复，不再增加按钮级特例：

| 问题              | 旧行为                                                                | 最小修复                                                                                      | 验收                                                                     |
| ----------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 单 Origin 边界    | 只允许保存账号时的入口 Origin                                         | 文章 execution ref 使用适配器声明的受控 Origin 集合；普通账号任务继续保持原安全默认           | `mp.csdn.net` 与 `app-blog.csdn.net` 间切换不暂停，非 CSDN Origin 仍暂停 |
| 关键词误判        | “确认/提交/发布”或 `type=submit` 一律暂停                             | 只对主进程核验过的文章事务调用适配器三态策略；普通中间动作允许，人工专属与未知动作暂停        | “确认上传”可执行；付款、删除、版权声明仍暂停                             |
| Selector 语义错位 | 用 DOM `querySelector` 解析 Playwright selector，解析失败即判危险     | 适配器通过 Playwright locator 读取唯一可见控件；无法唯一识别返回 unknown                      | `button:has-text(...)` 不再因语法差异误判                                |
| 只读动作后置失败  | 截图已经执行，再因 Origin 不符把结果改成失败                          | 动作前核验任务作用域；动作后只检查真实导航变化                                                | 合法页面截图直接返回；非法页面在执行写动作前暂停                         |
| CSDN 逻辑散落     | 通用 Browser 内硬编码 CSDN URL、弹窗和 intent                         | CSDN 页面、Origin 和动作分类移入版本化文章发布策略；通用 Browser 只消费 allow/handoff/unknown | 通用 Browser 不再包含 CSDN selector 和按钮特例                           |
| 人工恢复分叉      | BrowserTask 可“继续”，文章事务却停在 waiting-human；文章 Tab 不能继续 | 文章 Tab 提供“交还 Agent 并继续”，恢复同一 Attempt、创建新 Run/BrowserTask 并先重新观察       | 人工处理后不从头创建 Attempt，已核验图片不重传                           |
| 诊断不足          | 原始网络/会话能力被禁后 Agent 无法解释边界                            | Cookie、Token、原始网络拦截继续禁止；诊断补充脱敏 URL Origin、适配器判定和当前步骤            | 日志能区分 origin-mismatch、handoff 和 unknown，不暴露秘密               |

保留的硬边界：显式账号、工作空间、事务和 Attempt 绑定；Cookie/Token/密码/验证码不可见；只上传
冻结工作空间内材料；验证码、扫码、人脸、法律或版权声明、财务、账号权限、破坏性、批量、范围变化
及未知页面必须人工处理。取消这些硬边界属于新的架构变化；取消上表中的旧一刀切限制只是落实已
accepted 的 ADR 0016，不需要新增 ADR。

## Studio 产品入口与交互

### 独立入口与历史侧栏

Activity Bar 的“流程”分组新增独立图标“文章发布”，它不是 Markdown 编辑器按钮，也不借用通用
“事务”入口作为用户主界面：

```text
Activity Bar
└─ 文章发布
   └─ Sidebar
      ├─ 标题栏：文章发布                         ＋
      ├─ 状态筛选：全部 / 执行中 / 待处理 / 已完成 / 失败
      └─ 历史列表
         ├─ 文章标题 · CSDN · 账号 · 状态 · 更新时间
         └─ ...
```

- 单击“文章发布”只激活该侧栏，不隐式新建任务。
- 侧栏标题栏的 `＋` 执行唯一新建命令 `articlePublishing.create`，打开一个
  `新建文章发布` Workbench Tab。
- 侧栏正文只承担历史、状态筛选和恢复入口，不在狭窄侧栏里选择文件、填写摘要或显示执行表单。
- 单击历史记录，打开或激活对应的 `发布 · <文章标题>` Tab；同一任务只存在一个控制 Tab。
- 发布 Tab 是持久发布事务的控制面和状态投影，不是一次性上传窗口。一个 Tab 只绑定一个
  `taskId/affairId`；关闭后从历史重开仍绑定原事务，不能因为重开界面复制任务。
- 任务保存后不得隐藏配置；Tab 顶部继续展示只读配置快照，包括 Markdown 文件名和
  工作空间位置、网站、账号、标题、摘要、标签、分类和封面，供用户在开始执行前复核。
- 正文图片在新建预览和已保存任务中都要逐张展示文件名、Markdown 引用路径、
  工作空间相对位置、完整路径、类型、大小和每个正文引用位置，不能只显示去重资源数量。
- Activity 图标可以显示“执行中 + 待处理”数量徽标，但徽标不是任务状态事实源。
- 历史列表按当前工作空间隔离，因为源 Markdown、图片和执行证据属于该工作空间；网站账号仍来自
  全局账号库。没有打开受信工作空间时可以查看说明，但不能新建发布。
- 空白的“新建文章发布”Tab 不写入历史；选定 Markdown 和目标网站后才保存为“草稿”记录，避免
  每次误点 `＋` 都产生垃圾任务。
- 首版一条发布任务只绑定一个网站账号。把同一文章发到另一个网站时新建另一条任务；以后如果增加
  多平台发布，也必须拆成可独立失败和重试的目标 Attempt，不能共用一个模糊成功状态。

通用“事务”能力仍在底层保存流程、Attempt 和证据，但文章发布用户只从“文章发布”入口看到经过
筛选的文章发布任务，不需要理解 WebAffair 概念。

### 专用文章发布 Tab

新建和历史任务都使用同一种专用 Tab。新建时它是可编辑配置页；开始执行后原地变成控制台，不再
弹出另一套配置 UI：

```text
新建文章发布 / 发布 · <文章标题>
├─ 1. 文章
│  ├─ 选择 Markdown…
│  ├─ 文件名、工作空间内相对路径、内容哈希、修改时间
│  └─ 解析结果：标题、摘要候选、正文配图及每张图的插入位置
├─ 2. 发布目标
│  ├─ 网站：CSDN
│  └─ 账号：从“网站与账号”的已保存账号中选择
├─ 3. CSDN 发布设置（由 CSDN 适配器提供）
│  ├─ 标题、摘要、标签、分类
│  ├─ 封面
│  └─ 其他平台必填项与风险提示
├─ 4. 执行计划
│  └─ 打开编辑页 → 核验账号 → 上传插图 → 填写正文 → 填写平台字段
│     → 保存并复核草稿 → 动作分类 → 常规发布或人工卡点 → 验证结果
├─ 5. 运行控制与进度
│  ├─ 当前步骤、步骤状态、Agent 摘要、人工卡点、结果链接
│  └─ 开始执行 / 暂停 / 继续 / 终止 / 打开网页 / 打开 Agent / 复制完整诊断日志
└─ 底部操作：仅保存草稿 / 保存并开始执行
```

选择 Markdown 时只展示当前受信工作空间内的 `.md` 文件。选择后立即读取磁盘快照并自动解析；
未保存的编辑器内容必须先通过现有保存流程落盘，保存失败或磁盘冲突时不能开始。首版一次只选一篇，
不做目录批量发布。

### 插图位置如何识别

Studio 从 Markdown 结构中识别图片出现位置，而不是要求用户在发布时再次选择一批图片：

```md
第一段正文。

![架构图](./article.assets/architecture.png)

第二段正文。
```

解析器至少识别行内图片、引用式图片和允许的 HTML `img`，保存图片引用对应的正文节点、出现顺序、
替代文本和源路径。适配器上传成功后只替换派生正文里的图片地址，因此图片仍出现在原位置，源
Markdown 不被平台地址污染。

- 本地引用自动加入上传清单；同一文件多次出现只上传一次，但保留全部正文位置。
- HTTP(S) 图片首版保持外链并明确标记；缺失、越界、不支持格式或读取失败会阻止开始执行。
- 同目录里存在但 Markdown 没有引用的图片不自动插入。系统没有可靠证据判断它应该放在哪一段；
  这类“根据图片内容自动排版”属于以后独立的 AI 排版能力，不混入首版发布执行。
- 封面不是正文插图。它由具体网站适配器声明为独立字段，在发布 Tab 中单独选择。

### 网站、账号和平台字段

先选择网站，再选择账号。网站列表只展示 Studio 已安装且当前可用的文章发布适配器；账号列表只
展示“网站与账号”中已经保存、未归档且 origin 与该网站匹配的账号。发布页不再提供临时登录或
保存第二份账号状态；没有可用账号时引导用户到“网站与账号”添加，返回后刷新选择器。

选定网站后，发布 Tab 根据适配器提供的字段 Schema 渲染该站配置，而不是硬编码一张所有网站
共用的大表单。例如 CSDN 可以显示标题、摘要、标签、分类和封面；另一个网站可以显示专栏、话题
或可见范围。适配器还要给出字段默认值来源、必填规则、可选项读取方式和风险提示。涉及原创声明、
授权协议或其他法律承诺时不能代替用户自动选择。

### 点击“开始执行”之后

“开始执行”先冻结本次输入快照，然后建立一条有明确 `taskId`、`accountId`、适配器版本、源文件
哈希和执行计划的 Attempt，并同时完成三件事：

1. 打开或激活该已保存账号唯一的可见 Browser Tab，并固定 BrowserTask 操作此 Tab；不能跟随
   用户后来切换的活动网页。
2. 打开右侧 Agent Panel 中绑定本任务的发布 Agent 会话；会话名称为
   `发布文章 · <标题> · <网站>`，并关联同一个任务、Attempt、账号和 BrowserTask。
3. 发布 Tab 进入运行态，按适配器给出的步骤显示 `等待 / 执行中 / 已完成 / 待人工 / 失败 / 跳过`，
   Agent 每完成一步就写回结果和证据。

“开始执行”只创建一次本次发布 Attempt。后续因 App、Agent Run 或 BrowserTask 中断而点击“继续”时，
仍恢复同一个发布 Attempt；可以新建临时 Agent Run 和 BrowserTask 来接管执行，但不能新建发布 Attempt
并从第一步重跑。只有用户更换文章内容、账号、网站、平台字段或适配器版本，导致冻结输入已经变化，
才必须结束旧 Attempt 并明确开始新 Attempt。

适配器定义“做什么、按什么顺序、怎样判断完成”，Agent 负责在当前真实页面上观察和执行。通用
Agent 不能自行添加、删除或跳过平台步骤，也不能在适配器无法识别页面时继续猜测。关闭 Agent Panel
或切换 Tab 只隐藏投影，不删除任务；关闭 Browser Tab、登录失效、验证码或风控则把任务变成
“待人工处理”，处理后 Agent 必须重新观察页面才能继续。

用户已经在发布 Tab 明确选择源文章、网站和账号，并在看到平台字段与完整执行计划后点击“开始
执行”，这构成对本次单篇文章常规发布的有界授权。Agent 可以完成保存草稿、点击常规发布动作并
验证结果，不需要因为按钮名称包含“发布”就机械地再次停下。

流程只在确实需要人或风险明显升高时暂停：登录失效、验证码/扫码/人脸、平台风控、要求本人确认的
原创或法律声明、付款、账号/权限变更、批量影响、目标账号或内容与启动快照不一致、适配器无法确认
按钮后果，以及网站明确禁止自动完成的环节。用户在同一可见页面处理后选择“交还 Agent”，Agent
必须重新观察并从卡点继续。用户也可以随时主动暂停或接管，不必等系统判定。

运行中源 Markdown 发生变化时不静默换稿：当前 Attempt 继续绑定开始时的哈希，Tab 提示“源文件
已变化”；用户只能保留当前快照继续，或终止并用新版本重新开始。

### 页面、Agent 和控制 Tab 如何联动

点击“开始执行”后，发布控制 Tab 默认保持前台，让用户立即看到步骤开始推进；Studio 在工作区标签
栏创建一个正常、可随时打开的 Browser Tab，并展开右侧 Agent Panel。这个 Browser Tab 不是无头或
隐藏浏览器，只是默认不抢走控制 Tab 的焦点。

- 用户点击“打开网页”可以随时查看 Agent 正在操作的同一页面。
- 出现必须人工处理的卡点时，Studio 自动聚焦 Browser Tab，并在发布 Tab 和 Activity 徽标同时显示
  “待处理”；用户处理后从发布 Tab 或 Agent 卡片点击“交还 Agent”。
- 用户返回发布 Tab 后，右侧仍显示本次专属 Agent，主区域显示完整进度和证据。
- 关闭 Agent Panel 或发布 Tab 只隐藏 UI 投影，不取消运行；“暂停”和“终止”必须使用明确按钮。
- 用户关闭绑定的 Browser Tab 会暂停任务，不能由 Agent 悄悄创建另一个页面继续。

### 发布 Agent 的职责边界

发布 Agent 是当前发布任务的执行者和解释界面，不是第二个配置入口：

- 它只能使用任务中冻结的 Markdown 快照、网站、账号、适配器版本和平台字段。
- 用户可以在对话中询问当前进度、失败原因，或者说明已经完成人工操作。
- 用户要求换网站、换账号、换文章或改写正文时，Agent 必须引导回发布 Tab，终止当前 Attempt 或
  创建新任务；不能只改 Prompt 后继续跑。
- 发布 Tab 不提供正文编辑器。开始前要修改正文时打开源 Markdown 编辑器并重新扫描；开始后修改
  源文件不会改变当前 Attempt。
- 平台打开后如果出现配置阶段无法预知的新必填字段，适配器把它作为结构化卡点回写发布 Tab；没有
  安全默认值时 Agent 不替用户猜选项。

### 任务状态、并发和恢复

侧栏和发布 Tab 使用同一组用户状态：

| 状态     | 含义与允许操作                                                         |
| -------- | ---------------------------------------------------------------------- |
| 草稿     | 已选择文章和网站，配置仍可编辑；尚未产生网页副作用                     |
| 检查中   | 校验文件、图片、账号、适配器和平台字段；失败后返回草稿修正             |
| 执行中   | Agent 正按冻结计划执行；配置只读，可暂停或终止                         |
| 待人工   | 登录验证、风控、敏感操作或未知页面需要用户处理；处理后可交还 Agent     |
| 已中断   | App 退出、Browser/Agent 连接丢失或运行崩溃；只能重新观察后继续         |
| 核验中   | 可能已产生发布结果，正在读取 URL 和页面证据                            |
| 已发布   | 已取得文章 URL 和可复核结果证据                                        |
| 结果未知 | 可能已经发布但证据不足；只允许重新核验，禁止重放发布动作               |
| 失败     | 当前步骤已确认失败；可安全重试则留在原 Attempt，否则明确创建新 Attempt |
| 已终止   | 用户主动停止；不撤销平台已完成的上传、草稿或其他副作用                 |

首版同一 Studio 窗口同时只运行一个文章发布 Attempt，其他草稿可以编辑但不能开始；这样 Browser、Agent
和控制 Tab 始终有唯一当前执行目标。以后增加并行发布必须先证明多个可见页面、Agent Run、账号占用和
进度不会串线，不能只放宽一个并发数字。

应用退出时不在后台继续发布：未结束 Attempt 进入“已中断”。重启后用户从历史列表打开任务并点击
“继续”，系统先重新校验账号、适配器版本、源快照、页面和已有图片映射，再创建新的 Agent Run 和
BrowserTask 接管原 Attempt；不能把旧 Run 显示成仍在执行，也不能因此把发布流程从头再跑一遍。

#### Tab、Attempt 与检查点

一个发布 Tab 对应一条持久发布事务。空白“新建文章发布”Tab 尚无事务；选定 Markdown 和目标网站后
创建事务并绑定 Tab。一次点击“开始执行”创建一个发布 Attempt，Attempt 内的每个固定步骤都必须在
`WebAffairService` 持久化检查点，至少包含：稳定步骤 ID、冻结输入哈希、适配器版本、状态、执行次数、
起止时间、输出引用、核验证据、错误和恢复策略。

“保存成功”只能在主进程原子写入事务文件、renderer 重新读取当前工作空间快照并确认同一 `affairId`
存在后展示。加载、写入、备份恢复或存储失败必须进入框架关键日志，至少包含事务文件路径、revision
和事务数量，但不得记录文章正文、账号凭证或 Cookie。保存按钮返回错误时，该配置仍只是未持久化的
新建表单，不能在侧栏中伪装成可恢复任务。

每个步骤必须声明一种恢复策略：

- `skip-if-verified`：已有证据仍有效时直接跳过，例如已核验的图片映射；
- `reconcile-then-run`：先观察当前页面和平台草稿，确认未完成后才允许重做，例如填写正文或保存草稿；
- `manual-only`：无法自动证明重做安全时暂停给用户，例如结果未知的最终发布动作。

恢复时从“最早一个尚未确认完成的检查点”继续，而不是从第一步开始。处于 `执行中 / 等待平台 / 核验中`
的瞬时步骤在异常退出后先变为“待对账”；对账确认完成则补写成功证据，确认未发生才重试，无法确认则
进入待人工或结果未知。源文件、图片、账号、字段或适配器版本与冻结快照不同，不允许套用旧检查点；
用户必须明确以新输入创建新 Attempt。若平台已产生可识别草稿 URL，也要持久化它并优先从该草稿恢复。

#### 图片上传的等待、确认与重试

每张去重后的本地图片单独持久化上传状态，状态机为：

```text
pending → uploading → waiting-platform → verifying → uploaded
                         ├→ retryable-failed
                         ├→ result-unknown → reconciling ─┐
                         └→ failed                         └→ uploaded / retryable-failed / 待人工
```

- `uploading` 只表示已向可见文件控件派发上传，不算成功；派发后必须进入有上限的等待。
- `waiting-platform` 由适配器等待平台完成处理，首版默认单次最多 60 秒，并记录开始时间、轮询结果和
  页面证据；不能用固定睡眠后直接判成功。
- `verifying` 必须重新读取编辑器或平台成功提示，取得符合平台规则的远程 URL/图片节点，并证明它与
  当前素材哈希和预期插入位置对应。只有该证据成立才写入 `uploaded`。
- 明确发生在派发前、页面明确拒绝、或对账确认没有生成图片的临时故障可以自动重试；首版每张图片
  最多 3 次（首次 + 2 次重试），采用有界退避。达到上限后暂停任务，允许用户只重试失败图片。
- 派发后断线或超时且无法证明结果时进入 `result-unknown`。恢复时必须先扫描当前编辑器和已有映射：
  找到对应图片就补记成功，确认不存在才重试，仍无法判断则转人工；禁止盲目再次上传。
- 已核验成功的图片映射永久保留在本 Attempt 中；恢复或重试只处理未完成图片。同一内容哈希在正文
  出现多次只上传一次，再替换全部出现位置。
- 任一正文图片尚未 `uploaded` 时，不得进入正文最终填充、草稿核验或发布步骤。

Tab 的进度区要逐张显示“等待平台、核验中、第 N/3 次重试、失败、结果未知或已完成”，并允许打开
对应页面证据。诊断日志记录素材 ID/哈希、尝试序号、状态迁移、耗时和脱敏错误，不记录图片字节、
Cookie、Token 或带敏感查询参数的完整 URL。

重试遵循副作用优先对账：图片上传后保存内容哈希与平台 URL，草稿保存后重新读取页面。最终发布
动作一旦发起但连接中断，任务立即进入“结果未知”，后续只能观察文章列表、当前页面或用户提供的
URL；没有证明“尚未发布”之前绝不再次点击发布。

## 第一条用户端到端验收

只有用户在真实 Studio 和真实 CSDN 测试账号中完成以下动作，才可以声明第一条产品闭环完成：

1. 用户点击 Activity Bar 的“文章发布”，在只含历史记录的侧栏标题栏点击 `＋`。
2. Studio 打开“新建文章发布”Tab；用户在 Tab 内选择一篇含本地插图引用的 `.md`。
3. Tab 自动解析标题、Frontmatter、正文和图片位置，并显示缩略图、正文位置与阻断问题；用户不再
   逐张选择正文图片。
4. 用户选择 CSDN，再从已保存的 CSDN 账号中选择一个明确账号；未登记账号不能执行。
5. Tab 显示 CSDN 专属字段和执行计划；用户填写标题、摘要、标签、分类或封面。
6. 缺图、越界路径、不支持引用、未保存改动、磁盘冲突或缺少平台必填项会在打开网页前阻止继续。
7. 用户可选择“仅保存草稿”后在同一 Tab 内点击“开始执行”，或直接点击“保存并开始执行”；Studio 同时打开正确账号的可见 Browser Tab、绑定任务的 Agent 和运行态
   发布 Tab。
8. CSDN 适配器核验真实编辑页和账号，Agent 按计划上传图片、填写正文和平台字段；页面不兼容时
   停止并显示卡点，不盲目填写。
9. Agent 保存草稿并重新读取页面，发布 Tab 逐步显示图片映射、字段核对和草稿证据。
10. 没有人工卡点或特别敏感操作时，Agent 继续完成常规发布；若出现验证码、法律声明、风控或
    目标不一致，流程暂停并说明用户需要完成的操作，交还后重新观察。
11. Agent 取得文章 URL、标题和发布时间等可验证证据；无法验证时保持“结果未知”，
    不自动重放发布动作，也不标记成功。
12. 使用含两张图片的文章，在第一张已核验、第二张尚未完成时中断并重启 Studio；历史记录恢复同一
    Attempt，新 Agent 从第二张图片继续，第一张不重复上传。
13. 模拟一次可安全重试的图片上传失败，Tab 显示等待、核验和重试次数，随后只重试失败图片；模拟
    派发后结果未知时必须先对账，不能直接重复上传。
14. 用户关闭 Tab 或重启 Studio 后，仍能从“文章发布”侧栏历史记录恢复同一任务、进度、卡点、
    图片映射和结果证据。
15. 在最终发布动作后模拟连接中断，任务显示“结果未知”；点击继续只重新核验，不产生第二篇文章。

Mock、单元测试、成功调用上传控件、按钮点击返回成功或只保存本地转换稿，都不能替代上述真人
闭环。

## 产品输入与规范化

通用内核把平台差异之前的输入规范化为 `ArticlePackage`。概念字段如下：

```ts
interface ArticlePackage {
  sourceMarkdownPath: string
  sourceHash: string
  title: string
  bodyMarkdown: string
  assets: ArticleAsset[]
  metadata: {
    tags: string[]
    category?: string
    summary?: string
    coverAssetId?: string
  }
}
```

首版规则：

- 标题优先级为 Frontmatter `title`、首个一级标题、文件名；采用哪一项必须在发布前可见。
- Frontmatter 只读取已定义字段；未知字段保留在源文件中，但不猜测成平台配置。
- 相对本地图片按 Markdown 文件目录解析；只允许访问当前受信工作空间内的真实文件。
- HTTP(S) 图片保留原地址并标记为远程资源；首版不下载、转存或取得第三方站点权限。
- 缺失图片、工作区外路径和无法识别的数据 URI 默认阻止发布准备，用户明确移除或修复后再继续。
- 平台转换生成派生正文；源 Markdown 和原始图片默认只读，不因平台 URL 回写而污染。
- 平台本身支持 Markdown 导入时，适配器可以使用平台公开的可见导入入口；不支持时填写规范化正文，
  产品结果相同，不要求用户理解具体输入机制。

## 架构与状态所有权

```text
文章发布 Activity / 历史 Sidebar
  → ArticlePublishingTab（配置、控制和进度投影）
  → Markdown + 本地图片 → ArticlePackage（通用解析和校验）
  → WebAffairService（任务、Attempt、流程和证据的唯一持久 owner）
  → ArticlePublishingCoordinator（无持久状态的编排）
  → CsdnPublishingAdapter（字段 Schema、步骤和页面差异）
  → 绑定发布任务的 AgentRun
  → 固定账号的可见 Browser Tab / BrowserTask
  → Agent 完成已授权的常规发布 / 特殊卡点转人工后重新观察
  → WebAffairService 保存证据与终态
```

| 状态或资源                     | 唯一所有者                           | 本功能只做什么                       |
| ------------------------------ | ------------------------------------ | ------------------------------------ |
| Activity、Sidebar 和发布 Tab   | Workbench 现有 UI/Tab 基础层         | 投影任务，不保存第二份流程状态       |
| Markdown、图片和文档资源检查   | 文件服务与 `MarkdownDocumentService` | 读取、校验和生成不可变输入摘要       |
| 全局网站账号和 Profile 绑定    | `WebResourceService`                 | 引用明确 `accountId`                 |
| Cookie、Session、Tab 和页面    | `BrowserManager`                     | 复用可见账号 Tab，不创建隐藏浏览器   |
| 单次网页动作、暂停和结果未知   | `BrowserTaskRuntime`                 | 记录填写、上传、草稿和观察动作       |
| Agent 对话、Run 和工具调用     | 统一 Agent runtime                   | 绑定任务执行，不拥有发布终态         |
| 跨重启流程、Attempt 和结果证据 | `WebAffairService`                   | 保存发布准备进度、卡点和结果         |
| 平台页面识别和字段差异         | 版本化 `ArticlePublishingAdapter`    | 无持久 Store，不复制账号或事务状态   |
| 本次编排                       | `ArticlePublishingCoordinator`       | 调用已有 owner，不成为第二状态所有者 |

发布功能不得在 renderer 自行读取文件、拼装 Profile、保存 Cookie、维护第二个 Browser Tab Registry，
也不得把平台适配器变成文章、账号、事务或发布结果的事实源。

## 平台薄适配器契约

适配器是随 App 发布的有界内部 contribution，不是独立应用或通用插件平台。概念职责如下：

```ts
interface ArticlePublishingAdapter {
  readonly id: string
  readonly version: number
  readonly supportedOrigins: readonly string[]

  describeFields(): PlatformPublishingFieldSchema
  buildExecutionPlan(input: PreparedArticleInput): PlatformPublishingPlan
  probeEditor(): Promise<EditorProbe>
  prepareDraft(input: PreparedArticleInput): Promise<DraftPreparationResult>
  uploadAsset(input: PreparedAssetInput): Promise<PlatformAssetResult>
  readDraftSnapshot(): Promise<PlatformDraftSnapshot>
  classifyFinalAction(): Promise<FinalActionPolicy>
  performPublication(): Promise<PublicationAttemptResult>
  verifyPublished(): Promise<PublicationEvidence>
}
```

约束：

- `describeFields` 定义该站需要用户配置的字段、默认值、校验和人工声明；通用 UI 只渲染 Schema，
  不把 CSDN 字段写进公共表单。
- `buildExecutionPlan` 返回有序、可展示和可恢复的步骤；每步必须有稳定 ID、完成条件、
  `skip-if-verified / reconcile-then-run / manual-only` 恢复策略、重试策略和人工边界，Agent 不得临场
  改写流程。
- `probeEditor` 必须核验 origin、页面类型、关键控件和编辑器模式；未知版本 fail-closed。
- 适配器优先使用语义角色、稳定属性和可见页面动作；不得读取 Cookie、Token 或调用隐藏发布接口。
- 图片上传必须区分派发、等待平台和后置核验；返回平台 URL、资源哈希和页面证据后才能成功。超时或
  断线先返回 `result-unknown` 并对账，重试前核对既有映射，避免重复上传。
- `readDraftSnapshot` 必须核对标题、正文摘要、图片数量和平台字段，不能只相信写入工具返回值。
- `classifyFinalAction` 必须根据平台、当前页面、账号、任务快照和影响范围判断常规执行或人工卡点；
  不能只按按钮文本包含“发布”一刀切，也不能把未知动作默认当成安全动作。
- `performPublication` 只执行任务开始时已明确授权、适配器能够核验且未改变目标的单篇常规发布；
  人工专属或高风险状态返回卡点，不尝试绕过。
- `verifyPublished` 只根据重新观察到的页面、文章 URL 或平台回执判断结果。
- 页面结构改变、适配器版本不匹配或证据不足时降级为人工，不用任意脚本绕过可见页面。

## CSDN 第一适配器范围

`CsdnPublishingAdapter` 首版只承诺：

- 提供 CSDN 标题、摘要、标签、分类和封面的字段 Schema，以及对应的有序执行计划；
- 识别 CSDN 文章新建或编辑页面以及当前编辑器模式；
- 填写标题和 Markdown 正文；
- 上传正文引用的常见图片格式并取得平台地址；
- 用平台地址生成派生正文，保持图片顺序和替代文本；
- 填写用户明确提供且页面支持的标签、分类、摘要和封面；
- 保存草稿并重新读取核对；
- 分类并执行已授权的单篇常规发布；遇到人工专属、法律声明、风控或影响不明确时建立人工卡点；
- 发布后验证文章 URL 和可见结果。

首版不承诺批量多账号、定时无人值守发布、自动选择栏目、自动接受原创或版权声明、自动处理
验证码、规避风控、修改历史文章、跨平台同步、数据统计或发布后运营。

## 失败降级和诊断

| 失败场景                      | 必须行为                                                    |
| ----------------------------- | ----------------------------------------------------------- |
| Markdown 或图片缺失           | 打开网页前失败，列出具体引用                                |
| 工作区外图片                  | 拒绝读取；提示用户复制进工作区                              |
| 登录失效、验证码或风控        | 暂停并交给用户；处理后重新观察                              |
| 页面或编辑器版本无法识别      | 停止自动填写，保留源文件和已保存草稿                        |
| 图片等待超时或明确失败        | 记录单图 Attempt；安全故障最多尝试 3 次，只重试失败图片     |
| 图片派发后结果未知            | 先扫描编辑器和已有映射；无法证明不存在时暂停，不重复上传    |
| 图片部分上传成功              | 保存已核验的哈希到 URL 映射；恢复时跳过成功图片             |
| 草稿保存失败                  | 不进入发布确认；报告页面状态、适配器版本和失败步骤          |
| 发布动作后自动化连接中断      | 标记结果未知；只允许重新观察，不自动重放                    |
| 发布后没有文章 URL 或页面证据 | 保持待验证，用户可手动提供 URL 后由 Studio 再核验           |
| 适配器整体不可用              | 普通 Browser、Markdown 编辑器、Agent 和其他本地能力继续可用 |

发布 Tab 的“复制完整诊断日志”必须把任务时间线与统一框架诊断关联起来，至少包含任务/Attempt、
工作空间、脱敏账号 ID、适配器 ID/版本、Agent conversation/run、BrowserTask/Tab、页面 origin、
当前步骤和检查点、素材数量与哈希、单图上传尝试/等待/核验状态、动作结果，以及相关
main/renderer/Browser/Agent 关键日志。它不能只复制 Agent 对话，也不能要求用户分别去多个界面拼
日志；同时不记录正文全文、图片字节、Cookie、Token、验证码、`browserProfileId`、完整平台身份或
带敏感查询参数的完整 URL。

## 实施顺序

### P0：实施前门禁

这是工程准备度，不计用户功能进度：

- 核对 CSDN 当前公开规则、可用的官方能力和自动化边界；有覆盖目标能力的官方 API 时优先评估。
- 确认平台适配器范围与当前架构暂停项的关系；需要改变既有事实时先更新架构文档或 ADR。
- 按 ADR 0016 的 2026-08-27 修订实现“明确任务授权 + 特殊卡点人工接管”；更新现有把所有发布动作
  一刀切阻断的动作守卫，并为允许、暂停和未知三种判定补齐真实站验收。
- 冻结新的 `article-publishing` Activity/Sidebar/Tab 投影契约，并证明它只筛选和控制已有事务状态，
  不建立第二个任务 Store。
- 冻结 `ArticlePackage`、适配器 contract、状态 owner、有界授权、人工卡点和诊断脱敏边界。
- 准备一个允许测试的 CSDN 账号、一篇 Markdown 和至少一张无敏感信息的测试图片。

### P1：CSDN 最小纵向闭环

用户可见结果：用户从独立“文章发布”入口新建任务，在专用 Tab 选择一篇含一张本地图片的
Markdown、CSDN 和已保存账号；点击“开始执行”后 Studio 同时打开可见网页和发布 Agent，自动上传
图片、填入文章、保存草稿，并把逐步进度显示在原发布 Tab。

不得以只填写纯文本、只上传图片、Mock 编辑页或生成转换文件代替这一闭环。

### P2：常规发布、人工卡点和结果证据

用户可见结果：用户点击“开始执行”后，没有人工卡点时 Agent 完成常规发布并验证文章 URL；遇到
验证码、法律声明、风控或目标不一致时暂停，用户处理并交还后继续。动作后断线、重复点击和证据
不足均不能产生假成功。

### P3：恢复和适配器失效

用户可见结果：关闭 Tab、重启 Studio、登录失效或页面结构变化后，用户能恢复同一发布 Attempt，
从最后一个已确认检查点安全继续、转人工或终止；已经核验的图片不会因为盲目重试而重复上传。

P1–P3 的真实 CSDN 验收和受影响 `pnpm verify`/Electron smoke 全部通过后，才能声明 CSDN
文章发布能力完成。增加第二个平台前，必须先用 CSDN 现场证据确认通用内核与适配器边界确实成立。

## 冻结结论与剩余实施验证

以下产品选择已冻结，实施时不得重新解释：独立 Activity 入口、侧栏只做历史、专用控制 Tab、当前
工作空间内单篇 Markdown、Markdown 引用决定正文图片位置、全局已保存账号、一个任务绑定一个网站
账号、一个 Tab 绑定一个持久发布事务、原 Attempt 按检查点恢复、图片上传必须等待和后置核验、
安全失败最多尝试 3 次、结果未知先对账、首版串行运行、点击“开始执行”授权常规发布、特殊卡点
转人工、结果未知禁止重放，以及统一复制任务和框架诊断。

当前没有阻塞产品设计的问题。开始实现后仍必须用真实 CSDN 页面回答这些实施问题，但它们不能用来
改写上述产品逻辑：

- CSDN 当前编辑器模式、动态必填字段、图片上传与封面选择的真实页面结构是什么；
- 现有 Browser 动作守卫怎样从“一律阻断发布”迁移为 `允许 / 暂停人工 / 未知暂停` 三态；
- 已保存账号登录过期、验证码、风控和网页改版分别怎样稳定进入同一个人工卡点；
- 发布动作后连接中断时，怎样从文章列表、页面 URL 或平台可见结果证明“已发布”或“尚未发布”；
- 哪个允许自动化测试的 CSDN 账号、测试文章和无敏感图片用于真人端到端验收。

## 明确不做

- 不把 Markdown 编辑器工具栏按钮或通用“事务”侧栏作为文章发布的产品主入口。
- 不在文章发布侧栏塞配置表单、图片选择器或实时 Agent 对话；侧栏只做历史列表和恢复入口。
- 不为每个平台复制账号、Browser、事务、文件和重试系统。
- 不把 CSDN selector、URL 或发布判断直接散落进通用 Browser 工具和 Agent Prompt。
- 不先建设通用插件市场、远程适配器目录、热更新、脚本下载或第三方适配器执行环境。
- 不让通用 Agent 在适配器失效后继续猜测并宣称成功。
- 不自动处理验证码、2FA、版权声明、法律承诺或平台风控。
- 不做后台定时、批量多账号或脱离用户明确任务范围的无人值守发布；单次点击“开始执行”所授权的
  单篇常规发布可以由 Agent 完成。

## 拷问结论

- **为什么需要独立入口，而不是复用“事务”？** 用户目标是“发布文章”，需要稳定的文件解析、平台
  字段和进度心智；底层可以复用事务引擎，但把通用事务模型暴露给用户会让入口和操作路径再次模糊。
- **为什么侧栏只放历史？** 文件、平台字段、流程和日志需要完整工作区宽度；侧栏只负责找到、新建
  和恢复任务，避免出现一半配置在侧栏、一半执行在 Tab 的分叉。
- **为什么 Agent 不能自己规划全部步骤？** 平台字段和关键页面状态必须可测试、可恢复、可诊断；
  适配器冻结流程，Agent 只负责把流程落实到真实页面。
- **为什么恢复同一 Attempt，而不是重新执行？** 上传、草稿和发布都有外部副作用；重新创建 Attempt
  会丢掉哪些动作已经发生的事实。新 Agent Run 只是执行者更换，发布事务和核验证据不能随之重置。
- **为什么上传控件返回不算图片成功？** 控件调用只能证明动作已派发，不能证明平台处理完成或编辑器
  已引用新地址；必须等待并重新读取页面，未知结果先对账，才能避免缺图和重复图。
- **什么时候必须停下？** 不是看到“发布”两个字就停，而是需要真人身份、产生法律/财务/账号后果、
  影响范围扩大、任务目标发生变化或系统无法可靠判断动作后果时停；未知默认暂停。
- **为什么不是纯通用 Agent？** 编辑器输入、图片回调、平台字段和结果判定是稳定性最差的差异；
  临场猜测可以降级，不能成为产品承诺。
- **为什么不是每站完整实现？** 完整实现会复制状态机、账号、重试和证据逻辑，迅速形成多个 owner。
- **为什么先做 CSDN？** 它提供一条包含 Markdown、图片、登录态、草稿、常规发布和结果验证的最小
  纵向样本，足以检验通用内核是否真实可复用。
- **最大的剩余风险是什么？** 平台 DOM/编辑器变化、动作误分类和风控；版本化 probe、fail-closed、
  有界授权、人工卡点和真实站验收只能控制风险，不能消除第三方变化。

# 宣发视频工作台开发计划

> 状态：M0 已完成，M1 开发中；目标是连续完成 M0–M6 后统一执行 V0 端到端验收。
> 最后更新：2026-08-14。
> 产品事实源：[`promotional-video-workbench.md`](./promotional-video-workbench.md)。

## 1. 最终验收动作

真人必须能在真实 Studio 中完成以下完整动作，才允许声明 V0 完成：

1. 打开本地工作空间，选择真实 Markdown 稿件，创建 30～45 秒宣发视频工程；
2. 使用 Agent 生成 4～8 个结构化场景，检查并修改旁白、字幕、画面说明和提示词；
3. 为不同场景分别使用工作空间素材、本机导入、可追溯搜索素材、现有图片生成和一个真实
   国内云端视频 Provider；
4. 在任何付费视频任务提交前确认 Provider、模型、镜头、上传数据和费用事实；
5. 查看任务进度，替换或单独重试一个场景，不重做整条视频；
6. 调整场景顺序、时长、字幕、Logo、CTA、背景音乐和音量，得到可播放整片预览；
7. 导出 MP4、字幕文件和素材来源清单；
8. 关闭并重启 Studio 后重新打开工程，已保存资产、任务终态和导出结果仍可判断。

真实国内 Provider 的付费调用和用户素材上传属于最终人工确认边界。缺少账号、权限、余额或
用户拒绝付费时，可以完成所有本地能力和失败降级验收，但不能把云生成和完整 V0 标为通过。

## 3. 实施顺序

### M0：分镜工程

用户结果：从当前或选中的 Markdown 创建持久化工程，编辑标题、平台、画幅、品牌信息和场景
字段，使用统一保存命令，关闭后重新打开。

当前证据：

- `MediaProjectService`、shared contract、可信 IPC 和 preload 已接入；
- `media-production` Tab 与生产侧栏已接入；
- 定向测试、全量 `pnpm verify`、通用 UI smoke 和专项 Electron UI smoke 已通过；
- 确定性分镜只是无 Agent 时的保底，不冒充 AI 分镜。

### M1：Agent 结构化分镜

用户结果：在工程中点击“AI 生成分镜”或“AI 优化分镜”，看到生成状态和差异预览，确认后
应用到当前工程；取消或失败不破坏原分镜。

工程任务：

1. 定义版本化 storyboard proposal contract，绑定 project revision 和 source snapshot hash；
2. 由现有 Agent runtime 执行一次有界结构化生成，不创建第二 Agent 状态所有者；
3. 主进程校验场景数量、时长、字段上限和 project revision；
4. renderer 只显示 proposal、差异和“应用”命令；
5. Agent 缺失、JSON 不合法、取消、超时和工程已修改时明确降级。

### M2：本地素材与预览

用户结果：给单个场景选择工作空间文件或从本机导入图片/视频；选择 Logo、音乐和已有旁白；
中央区域显示真实素材预览。

工程任务：

1. 新增 `MediaAssetService`，唯一拥有资产导入、哈希、manifest、来源和缺失诊断；
2. 资产复制到工程目录，使用内容哈希去重，保留原文件来源；
3. 项目只保存稳定 asset ID，renderer 不持有大文件；
4. 通过受信 IPC 提供导入、列表、读取预览和场景绑定；
5. 覆盖路径越界、软链接、超大视频、不支持格式和原文件删除。

### M3：素材搜索与图片生成

用户结果：输入场景搜索词获取图片/视频候选，看到作者和来源后添加；也可复用现有图片生成
能力产生场景图片。

工程任务：

1. 冻结 `MediaSearchProvider` contract，首个 Provider 需通过国内网络和授权验收；
2. 搜索结果不自动下载，用户“添加到工程”后由 `MediaAssetService` 保存；
3. 保存 Provider、远端 ID、原页面、作者、下载时间、许可摘要和文件哈希；
4. 将现有 `ImageGenerationService` 输出导入工程资产，不复制图片 Provider；
5. 无搜索 Key 或 Provider 故障时，本地素材路径仍完整可用。

### M4：国内云视频 Provider

用户结果：设置页配置国内视频 Provider；工程内对一个场景发起文生或图生视频，付费确认后
查看排队、运行、成功或失败，成功结果立即下载为本地资产。

工程任务：

1. 冻结 `VideoGenerationProvider`、任务快照和错误 contract；
2. 新增 `VideoGenerationService`，唯一拥有任务账本、轮询、取消、恢复和结果下载；
3. 首个 Adapter 为 `volcengine-jimeng-video`，复用现有 AK/SK 与签名器，但单独探测视频权限；
4. 付费确认显示 Provider、模型、时长、参考素材上传和可知费用；
5. 输出 URL 成功后立即下载并经 `MediaAssetService` 入库；
6. 覆盖缺 Key、无权限、余额不足、审核拒绝、限流、超时、URL 过期和场景 revision 已变化。

### M5：合成、预览与导出

用户结果：在 Studio 内播放整片预览，导出带字幕、Logo、CTA、简单转场和音乐的 MP4，同时
得到字幕和来源清单。

工程任务：

1. 完成 FFmpeg Runtime Component 的版本、来源、哈希、许可证和编解码器 ADR/评审；
2. 新增 `MediaRenderService`，唯一拥有渲染任务和中间文件；
3. 从工程快照生成确定性 render plan，图片使用平移/缩放，视频裁剪到目标时长；
4. 生成字幕、品牌覆盖、CTA、转场、音乐混音和基础 ducking；
5. 导出 MP4、SRT/VTT、来源 Markdown/JSON；
6. 渲染失败必须返回失败步骤，保留工程、资产和可复用中间结果。

### M6：恢复、诊断与统一验收

用户结果：长任务期间关闭 Tab 或重启应用后，工程和任务仍可判断；所有已定义失败路径有清晰
恢复动作；最终一次性完成完整 V0 验收。

工程任务：

1. 对账未终态视频任务和渲染任务，状态只能是明确终态、继续查询或“状态未知”；
2. 接入脱敏诊断和任务抽屉，不记录 Key、完整提示词或用户素材正文；
3. 覆盖工作空间切换、窗口重建、并发保存、磁盘满、资产丢失和 Provider 离线；
4. 运行 `pnpm verify`、真实 Electron UI smoke、真实国内 Provider smoke 和横/竖屏导出；
5. 由真人按第 1 节八步执行并记录结果。

## 4. 统一质量与止损规则

- 每个里程碑先增加一个用户可操作结果，再补当前结果必需的横向基础设施；
- 任一 Provider 或 Runtime 初始化失败只降级自己，不阻断本地工作台；
- 同一阻塞连续失败两次，停止深挖并记录替代路径；
- 付费生成、素材上传和最终外部发布不因“全部推进”而绕过人工确认；
- 只有 M0–M6 自动门禁和第 1 节真人动作全部通过，才声明 V0 完成。

## 5. 当前最短主线

```text
M1 Agent proposal
→ M2 MediaAssetService + 真实预览
→ M3 搜索/图片资产
→ M4 火山视频任务与结果入库
→ M5 FFmpeg render plan 与导出
→ M6 重启恢复和统一验收
```

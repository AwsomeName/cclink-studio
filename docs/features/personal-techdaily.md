## 1. 用户验收（先于工程任务）

1. **项目设置 · 我的空间 · 科技日报**：选搜索服务（DeepSeek 沿用联网搜索的 Key；或填 SearXNG 地址并“测试连接”），开启。
2. **侧栏点“科技日报”**：下方日历切换为科技日报日历，有日报的日子带圆点；点日期，中间用与日记相同的 Markdown 编辑器显示当天 `科技日报/2026/11/1125.md`。
3. 点“重新生成”或等到点：执行详情显示 10 步随真实执行变化；完成后编辑器直接显示当天日报。
4. 日报包含：头条解读、模型能力榜（7 个榜单）、分领域精选（9 个领域 + 热点补充）、开源热点、论文前沿、今日趋势、数据口径。
5. 同一事件不连续几天重复出现；后续进展标“⬆ 前情：X 月 X 日已报道”。
6. 06:10 时 Studio 没开，打开后补生成当天的；过去没生成的日子显示“这天没有科技日报”，不补。

**首版完成**以第 1–6 项在真实 Studio、真实 Key 或真实 SearXNG 下连续 3 天通过为准。

## 4. 搜索服务

| 提供方                | 首版 | 规则                                                                                                                                                                                                                                                                   |
| --------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DeepSeek              | ✓    | `WebSearchService`，来源记“科技日报”；每次 ≤ 15 条；结果 `date` 作第二级日期                                                                                                                                                                                           |
| SearXNG 远程服务      | ✓    | `GET {地址}/search?q=&format=json&categories=news&language=zh-CN\|en`；**绝不传 `time_range`**（实测清空结果）；只采用白名单引擎（默认 bing、bing news、duckduckgo news）的结果（`engines` 参数不可靠）；同主机间隔 3.5 秒、429 指数退避；`publishedDate` 作第二级日期 |
| Brave / Tavily / 博查 | 后续 | 同一接口，按需接入                                                                                                                                                                                                                                                     |

- SearXNG 不提供网页读取：成稿用搜索摘要；若同时配了 DeepSeek，可勾选“用 DeepSeek 读取原文”。
- “测试连接”：搜一次 `AI chip`，返回条数、带日期比例、实际引擎分布、耗时；不保存结果。
- 凭证（Basic 认证）进凭证文件，不进 `设置.yaml`、日志或界面回显。

## 6. 去重：一个本机 SQLite 库 + 线索标准标题

> 2026-11-25 第二版。用户否定了“多层规则”的讲法，要求端侧替代 ES 的简单基建，并提出“每条线索按规则起标准标题，标题高度相似即去重”。
> 本节按这个思路重写；过滤规则移到 §6.5，它们解决的是“不是新闻、太旧、跑题”，不是去重。

### 6.1 基建：`techdaily.sqlite`

- 位置：`userData/techdaily/<空间>/techdaily.sqlite`，本机，不同步。
- 引擎：`node:sqlite`（Electron 自带，公司空间已在用，**不新增依赖**）。2026-11-25 在本仓库的 Electron 运行时实测：SQLite 3.53.1，FTS5 `trigram` 分词可用，中文标题可直接做模糊检索。
- 只由 `TechDailyService` 读写；所有写入在事务里，崩溃不留半截。
- 取代：Argus 的 Elasticsearch（文章幂等入库）、Neo4j 事件注册表，以及 v2 草案里的 `candidates.jsonl` 和 `事件.json`。

| 表          | 一行是什么             | 主键 / 索引                                    | 作用                                     |
| ----------- | ---------------------- | ---------------------------------------------- | ---------------------------------------- |
| `articles`  | 一篇文章（一个网址）   | `url_key` 主键（规范化网址哈希）               | 同一网址只存一份；记首见、最近抓取日     |
| `leads`     | 一条线索（一件事）     | `lead_key` 唯一索引；`subject, last_seen` 索引 | 同一件事只存一份；记报道过的日子         |
| `leads_fts` | 线索标准标题的全文索引 | FTS5 `trigram`                                 | 找“标题差不多”的线索                     |
| `aliases`   | 一个别名               | `alias` 主键 → 标准名                          | OpenAI / Open AI / 开放人工智能 → OpenAI |

`articles.lead_id` 指向 `leads`：一件事可以有多篇报道，来源数就是该线索下的文章数。

### 6.2 线索标准标题（用户思路）

每篇新文章入库时，由 AI 批量抽成固定字段（一次 ≤ 100 条，纯文本，本机 Codex / Claude，不计搜索费）：

| 字段 | 例         | 进不进去重键   | 说明                                                                                                           |
| ---- | ---------- | -------------- | -------------------------------------------------------------------------------------------------------------- |
| 主体 | OpenAI     | **进**         | 公司或机构；先查别名表换成标准名                                                                               |
| 动作 | 发布       | **进**         | 只能取固定一组：发布、开售、量产、上线、开源、融资、收购、交付、扩产、成立、会议、人事、财报、政策、评测、其他 |
| 对象 | GPT-5.5    | **进**         | 必须是专有名词（产品、型号、项目、轮次）；没有就留空                                                           |
| 人物 | Sam Altman | 不进           | 常常缺席或换人引述，进键会拆散同一件事                                                                         |
| 领域 | 模型能力   | 不进           | 同一件事会被两个领域搜到，进键就无法跨领域合并                                                                 |
| 时间 | 2026-11-24 | 不进键，做窗口 | 报道会持续几天；同键且相隔 ≤ 7 天才算同一件                                                                    |
| 地点 | —          | 不用           | 科技新闻里多半没有，只会制造差异                                                                               |

- 标准标题 = `主体 动作 对象`，例如“OpenAI 发布 GPT-5.5”。日报界面和执行详情里也显示它，便于人核对。
- 去重键 `lead_key` = 规范化后的 `主体|动作|对象`：小写、去空格和连字符（`GPT 5.5` = `gpt-5.5`）、全角转半角。
- 对象为空、或动作是“其他”的线索**不参与按键合并**，只走 6.3 第 3 步的相似判断，避免“英伟达｜发布｜（空）”把几件不同的事并成一件。

### 6.3 一篇新文章进来时（三次查询）

1. **同网址**：`INSERT … ON CONFLICT(url_key) DO UPDATE` 只更新最近抓取日和搜索词。等价于 ES 幂等入库。
2. **同一件事**：用 `lead_key` 查近 7 天的线索，查到就挂上去（来源数 +1），查不到进第 3 步。
3. **标题差不多**：用 `leads_fts` 查同一主体、近 7 天的线索取前 5，算标准标题的三字组重合度：
   - ≥ 0.6 且型号数字不冲突（`5.5` 对 `5.0` 直接判不同）→ 并入；
   - 其余 → 新建线索。宁可漏合，不误合。

跨天去重不再单独实现：线索表本身记着 `reported_on`（哪些日子上过日报）。精选时同一条线索已经报道过就默认不选；
有新进展（同主体同对象、动作不同，如“发布”之后“开售”）是另一条线索，按“⬆ 前情”处理。

于是 AI 精选只面对“线索”而不是“文章”：不再需要 `rep/also` 归组和 `event_uid` 回填，提示词更短，校验更简单。

### 6.4 多设备与重建

`techdaily.sqlite` 不同步。每份日报的 front matter 记录当天入选线索的 `lead_key` 与标准标题；换电脑或库损坏时，
读近 30 天日报重建 `leads` 的已报道记录，文章表从空开始，不影响跨天去重。别名表的用户追加项写在 `设置.yaml`。

### 6.5 过滤（入库前，不属于去重）

照搬 Argus，依次：网址与标题非空 → 域名黑名单（Argus `DOMAIN_DENYLIST`，可追加）→ SearXNG 引擎白名单 → 标题排除词 →
时效（先认网址里的日期，11 种形态；再认结果日期；早于 3 天丢弃，晚于明天视为误匹配，都没有则保留并标无日期）→
标题护栏（标题须含搜索词或领域关键词；无日期且只命中品牌词的拦下）。
网址规范化：小写主机、去默认端口和 fragment、去 `utm_*` `spm` `from` `share` 等跟踪参数、参数排序、去尾斜杠。

### 6.6 这个方案的风险

- **抽取不一致**：同一件事被抽成“OpenAI｜推出｜GPT-5.5”和“OpenAI｜发布｜GPT 5.5”——动作固定成一组、型号规范化后两者同键；
  抽成“OpenAI｜发布｜新模型”则对象不是专有名词，按规则留空，靠第 3 步兜。
- **别名表要养**：首版内置约 200 个科技公司中英文名；AI 精选时发现“这两个是同一家”可提议追加，用户确认后写入。
- **多花一次 AI**：每天约 100 条新文章、1–2 次抽取调用，本机 AI 不计费，约 1 分钟。抽取失败时退回只按网址去重，并在执行详情标出。
- **不做语义向量（2026-11-25 确认）**：Electron 的 `node:sqlite` 能加载扩展但不带向量检索；按 30 天约 3,000 条线索的量，向量存 BLOB、JS 全量算余弦即可，不需要 sqlite-vec。
  难点在向量来源（本机模型约 100 MB 需下载；DeepSeek 据知没有向量接口，待核实），且向量最易把 Sonnet 5.5 / Opus 5.5 这类同系列不同型号判成同一件。
  阶段 0 实测漏合率高时，才在阶段 4 加本机向量作为第 3 步之后的可选补漏，不替代去重键。

## 7. AI 调用（每天 ≤ 6 次自动 + 手动重试，上限 10）

| 调用     | 输入                                                                  | 输出（Zod 校验）                                                  |
| -------- | --------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 热点规划 | HN/GitHub/arXiv 信号 ≤ 30、已采集标题 ≤ 250                           | `{queries ≤ 3, reason}`；精短 2–4 个名词，禁止泛化词              |
| 线索抽取 | 新文章标题与摘要 120 字，≤ 100 条/次                                  | `[{i, subject, action, object, person, date}]`，动作限固定一组    |
| 精选     | 线索 `[i] (领域｜日期｜来源数)⚠ 标准标题｜代表标题`、口味与黑名单品牌 | `items[{lead, reason, importance}]`、`trend_hint`                 |
| 成稿     | 槽位 `领域#序号`、标题、原文或摘要 400 字、来源数、入选理由；速览条目 | `headline{slot,title,analysis}`、`sections[]`、`quick[]`、`trend` |
| 榜单维护 | 当前榜单 JSON、近 7 天模型评测相关候选                                | 完整榜单 JSON                                                     |

- 纯文本 Agent（`disableBuiltinTools` + 空 `allowedTools`），Codex 优先、Claude Code 兜底（ADR 0023）。
- 提示词移植 Argus 的 `DYNAMIC / SELECT / RENDER / LEADERBOARD_SYSTEM_PROMPT`。
- JSON 容错：剥围栏 → 解析 → 修复中文夹英文引号 → 截取最外层花括号；失败带修正提示重试 1 次。
- 网址、日期、来源数、线索首报日由代码回填，AI 输出的网址不采用。

## 8. 模型能力榜

- 状态文件 `科技日报/榜单.json`（随同步、可手改）：`tasks{代码, Agent, 多模态, 图片生成, 视频生成, ASR, 具身智能}`，每榜 `rows ≤ 5`、`new_entries[{until}]`、`_source{name, site, fetched_at}`。
- 源站（主进程直接 HTTPS 读取公开页面，礼貌 UA，间隔 1.2 秒，每天 ≤ 6 页，不经搜索服务、不计费）：
  llm-stats.com 主榜（Agent）、`/benchmarks/swe-bench-verified`（代码）、`/benchmarks/mmmu-pro`（多模态）；
  artificialanalysis.ai 文生图、文生视频（Elo）、语音转写（WER，升序）。具身智能无可读榜单，只按新闻维护。
- 规则（照 Argus）：源站分数为准，AI 不得改回空或删除；无评测证据不动排名；当天新模型进观察区、次日到期；旗舰系列到期默认升入，非旗舰需进前 5 证据；同家族去重。
- 源站解析失败：该榜缺席或沿用旧值，日报注明抓取日期。

## 9. 调度与“每天最多一次”

- 定时任务服务是唯一调度者；日报是内置流程任务，执行交给 `TechDailyService`。**实现前提交 ADR 0027**（扩展“定时任务 = 指令 + Agent”）。
- 运行记录 `runs/<日期>/run.json`：`running → completed | empty | failed | interrupted`。
- 自动触发前：当天 `completed/empty` 或 `running` → 不触发；进程内锁防并发；手动“重新生成”需确认并覆盖当天文件。
- 日期在开始时确定，跨午夜仍算开始那天，不补前一天。
- 补生成：开启时，Studio 启动后若已过设定时间且当天无日报 → 30 秒后排队。
- 多设备：随 Git 来的共享定义默认不启用。

## 10. 存储

| 路径                                         | 同步 | 内容                                                                              |
| -------------------------------------------- | ---- | --------------------------------------------------------------------------------- |
| `科技日报/设置.yaml`                         | 是   | 领域、搜索词、护栏、排除词、黑名单追加、时效、无日期处理、条数、栏目、口味        |
| `科技日报/榜单.json`                         | 是   | 模型能力榜状态                                                                    |
| `科技日报/{yyyy}/{mm}/{MMDD}.md`             | 是   | 日报；front matter：状态、生成时间、漏斗、调用数、入选线索 `lead_key` 与标准标题  |
| `userData/techdaily/<空间>/techdaily.sqlite` | 否   | 文章、线索、别名（§6.1）；文章留 14 天，线索留 30 天                              |
| `userData/techdaily/<空间>/runs/<日期>/`     | 否   | `run.json`、`daily.json`（结构化日报）、`sources.json`（源站与前沿源快照），60 天 |
| `userData/techdaily/<空间>/searxng.json`     | 否   | SearXNG 地址与引擎；凭证在凭证文件                                                |

写入：只有 `TechDailyService`；原子写入、校验 UTF-8。`techdaily.sqlite` 丢失时从近 30 天日报 front matter 重建线索（§6.4）。

### 10.1 同步到哪个仓库（已确认 2026-11-25：不单独配置 GitHub 仓库）

- **复用我的空间同步的那个 GitHub 私有仓库**：`diaryScope` 的同步范围增加 `科技日报/` 一个根目录，
  不新增仓库绑定、同步状态、私有检查或冲突界面（ADR 0026：同步引擎只有一个）。
- 体量：每份日报约 10–20 KB，一年约 5 MB，加 `榜单.json` 不到 1 MB，不需要独立仓库分流。
- 没开我的空间同步时，科技日报只存在这台电脑，功能照常。
- 冲突（只在两台电脑都生成或手改时出现；默认只有启用定时任务的那台生成）：
  - `{MMDD}.md`：生成的日报不交给 AI 合并，保留生成时间较晚的一份，另一份另存为“（另一台 月-日）”；
  - `榜单.json`：取 `_source.fetched_at` 较新的一份；
  - `设置.yaml`：沿用现有文本冲突（AI 按用户的话合并）。
- **只有一种情况值得独立仓库**：想把日报公开（GitHub Pages、公开归档、给别人订阅）。这是发布，不是同步：
  方向单向、仓库须公开、每次公开需要授权，不能和存放日记的私有仓库混用。首版不做；要做时作为“导出到公开仓库”单独设计。

## 13. 测试清单

- 网址规范化、11 种网址日期、未来日期拒绝、长 id 不误匹配。
- 时效门两级顺序；无日期保留/丢弃开关。
- 护栏：话题型查询摘要命中且有日期 → 过；“DeepSeek | Into the Unknown”无日期只沾品牌 → 拦；“DeepSeek 发布 V4.1 Flash” → 过。
- 同网址入库：首见日不变、日期补齐、搜索词追加（跨领域同样合并）。
- 线索去重：`OpenAI｜推出｜GPT 5.5` 与 `Open AI｜发布｜GPT-5.5` 同键；Sonnet 5.5 与 Opus 5.5 不同键且相似判断因型号冲突否决；对象为空不按键合并；同网址二次入库只更新最近抓取日；从日报 front matter 重建线索后跨天去重仍生效；Electron 运行时 FTS5 trigram 可用。
- 精选校验、JSON 容错、榜单“真实分数不可被改回空”。
- SearXNG：不传 time_range、引擎白名单、429 退避、Basic 凭证不落日志。
- 调度：当天已完成不重复、跨午夜不补、中断重来、补生成开关。
- 真实 Electron：项目设置开启与测试连接、侧栏日历切换、点日期显示 Markdown、生成中 10 步、无日报日子。

## 14. 拷问

- **把科技日报配置塞进项目设置会不会太长？** 是长。段落可折叠，默认只展开“搜索服务”和“什么时候生成”；词表细节可直接编辑 `设置.yaml`。
- **日历同时显示日记和日报会不会混？** 不混：侧栏切到哪个，日历就显示哪个的圆点和计数。
- **抓 llm-stats / AA 的 HTML 会不会坏？** 会，Argus 已踩过（arena 页客户端渲染抓不到、mmmu 页停更）。解析失败只让该榜沿用旧值并标抓取日期，不阻塞日报；解析器有快照测试。
- **SearXNG 凭证是否安全？** 存凭证文件（权限收紧），不进同步目录、日志或 IPC 返回；不用系统钥匙串。
- **版权**：只存标题、≤ 500 字摘要、AI 写的摘要点评和链接；原文只在成稿时交给 AI，不落盘。
- **科技日报要不要独立 GitHub 仓库？** 建议不要，见 §10.1。独立仓库意味着第二个同步绑定和第二套状态，违背 ADR 0026；
  唯一正当理由是公开发布，那属于发布功能，另行设计。
- **去重靠 AI 抽字段，会不会漏合或误合？** 会漏合（抽取措辞不一），不会大量误合：动作固定一组、对象须是专有名词、型号数字冲突直接判不同。漏合的代价是同一件事多出现一次；抽取整体失败时退回只按网址去重，并在执行详情标出。

# 文件资源复制粘贴

> 状态：已实现。适用于文件树中的单个文件或文件夹。

## 产品边界

- 文件树右键提供“复制”和“粘贴”；文件树获得焦点时支持 `Cmd/Ctrl+C`、`Cmd/Ctrl+V`。
- 复制只记录一个会话内待复制资源，不立即写磁盘；粘贴才产生文件系统副作用。
- 粘贴到文件夹时进入该文件夹；粘贴到文件时进入文件所在目录。
- 同名目标绝不覆盖：依次生成“名称 副本”“名称 副本 2”。
- 文件夹递归复制；Markdown 正文与其可见资源目录作为一个文档资源组复制，并重写新文档的资源引用。
- 支持在已打开的本地工作空间之间复制。源工作空间或源资源失效时明确失败，不保留半成功 UI。
- 当前只支持单个目标，不包含多选、剪切或与 Finder 互通的系统文件剪贴板。
- 输入框、编辑器和其他文本区域中的复制粘贴仍使用系统文本剪贴板，文件树不得截获。

## 架构与状态

- `fs-store` 是会话内文件剪贴板状态的唯一所有者。
- `fileTree.copyEntry` 和 `fileTree.pasteEntry` 是右键菜单与快捷键共用的命令事实源。
- renderer 不直接访问 Node.js；粘贴通过 `fs:copyEntry` shared contract 进入主进程。
- 主进程分别校验源路径与目标目录所属工作区，拒绝复制工作区根、越界路径、非目录目标，以及把目录复制进自身或子目录。
- 文件系统复制完成后，`fs-store` 刷新目标目录、展开目标并选择新副本；失败时保留剪贴板以便用户修正目标后重试。

## 失败降级与诊断

- 没有待复制资源时，“粘贴”显示为禁用并说明原因。
- 源已删除、权限不足、路径越界或复制失败时，通过文件区错误和上下文命令错误提示，不修改 Tab、编辑器或 Agent 资源状态。
- 同名使用自动副本命名，不弹覆盖确认。
- 复制失败会清理本次创建的不完整目标；不会删除已有同名资源。

## 验收

1. 文件和目录均可通过右键复制，再粘贴到目录或文件所在目录。
2. 文件树焦点内 `Cmd/Ctrl+C`、`Cmd/Ctrl+V` 与菜单结果一致；文本输入不受影响。
3. 递归目录内容和 Markdown 配套资源在磁盘上完整存在。
4. 同名连续粘贴生成递增副本且原文件内容不变。
5. 越界、失效源和目录自包含复制被拒绝。
6. `pnpm verify` 与 `pnpm smoke:workflow` 通过。

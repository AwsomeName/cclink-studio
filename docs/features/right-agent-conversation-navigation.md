# 右侧会话导航与 Agent 执行关系

状态：产品方案已确认；第一批导航与布局已实现并通过受影响工程门禁，待真人验收。子 Agent 与分支尚未接入。本文约束替代 `agent-panel-product-model.md` 中“完整会话管理固定在左侧”的布局约定；运行、权限和状态所有权约束不变。

## 用户验收

1. 在真实 Studio 中打开一个工作空间和文档，保留默认 350px Agent 宽度，点击“会话”。窗口空间足够时右侧自动展开，让列表与聊天同时可见，无需先手动拉宽。在右侧搜索、创建、切换既有会话；运行中的会话继续输出，切回后草稿与阅读位置保留。
2. 右侧整体设为 700px、列表设为 200px，布局从左到右为工作区、当前聊天、会话列表：收列表后外宽变为 496px，聊天保持 495px（外边框 1px）并右移 204px，工作区获得释放的 204px；再次展开恢复原布局。连续收放不得积累宽度误差。收聊天后右侧只占 200px，点会话后恢复 700px。
3. 将窗口缩窄至无法同时容纳列表和 320px 聊天区，列表变成按需打开的抽屉；扩大后恢复用户选择。切换工作空间、重启恢复各自的布局，不覆盖旧数据。空输入框默认约两行，输入多行时增高，最多 240px 或窗口高度的 30%，超过后内部滚动；删除文字后缩回。旧版本固定高度不再恢复，手动拖高只在当前挂载期间生效，双击分隔线恢复自动高度。
4. 后续子 Agent 验收：真实运行产生子任务事件，列表出现对应节点，查看记录、权限确认、停止和重新进入都与后台事实一致。没有真实运行证据不得宣称通过。
5. 后续分支验收：从明确的消息边界创建独立会话，两边继续发送，消息、Session 和 Run 互不污染。
6. 点击左侧导航“会话”展开右侧会话栏，再次点击收起整个右栏并取消“会话”高亮；第三次点击重新展开。左侧当前栏目保持不变，当前会话与草稿保留。仅聊天模式下点击“会话”仍展开列表。

## 第一批边界

先交付验收 1–3。复用现有本地/远程会话 owner、统一命令和消息渲染，不生成示例子 Agent，不开放未经验证的停止子任务或分支按钮。不修改云端或远程 Agent 仓库，不新增守护进程、队列或第二运行账本。

UIStore 的 workspace 布局分区保存内部模式 `chat | split | list`、面板宽度和列表宽度。外部位置继续使用现有 `center | right | hidden`。`agentPanelWidth` 在 chat 模式保存聊天外宽，在 split/list 模式保存两列展开外宽；显式收列表时以实际可见宽度扣除列表与分隔线，展开时加回。仅调整窗口大小仍只改变派生宽度，不回写偏好。没有新增布局字段或第二状态所有者。

左侧导航“会话”在右侧会话模式已激活时复用 `workbench.toggleAgentPanel` 收起整个右栏；其他状态调用 `agent.showConversations` 展开。命令面板中的“打开右侧会话列表”仍保持幂等打开语义，右栏内部“会话”按钮仍只控制列表。

列表位于聊天最右侧，默认 200px，可调 180–240px；并排需要 `列表宽度 + 4px + 320px`。列表每项为标题和时间/运行或错误状态两行，工具细节仍在会话内查看。收聊天只改变有效外宽，不能把展开整体宽度覆盖为列表宽度。收列表、收聊天、隐藏整体均不得发出 abort、reset 或 closeConversation。

明确从仅聊天展开列表时，UIStore 将列表宽度和 4px 分隔线加到聊天外宽上（受既有最大宽度及窗口预算约束）；恢复两列时保留已足够的目标，旧版不足以容纳两列的目标仍回退到 700px。抽屉中的聊天按钮显示“展开聊天”，点击后关闭抽屉并恢复聊天；抽屉未占用独立宽度，因此关闭抽屉不扣减聊天宽度。无需新增持久化字段、运行 owner、IPC 或权限。

本地草稿继续由 agent-store 的目标 conversation 拥有；远程草稿继续由 cclink-store 按精确 target 拥有。收放和切换不得扩大现有持久化范围，图片和远程草稿不因布局改动新增磁盘副本。选中子任务详情必须与发送目标分离。

## 运行关系和契约边界

- Thread：独立的会话、消息、草稿、配置、归档和 workspace 归属。
- Run：一次执行。main Agent Runtime 继续拥有唯一运行事实和可信 Session 绑定。
- 子 Agent：属于一个明确 Run 的执行节点；不能凭列表缩进伪装成可自由发送消息的 Thread。
- 分支：独立 Thread，记录源 Thread 和源消息边界；不得复制原 Thread 的可变 Runtime Session 绑定。
- 本地/远程 owner 保持分离，统一视图只做派生读取和命令委托。

新增子任务契约必须携带 workspace、conversationId、runId 和 taskId，定义版本/事件去重、终态、错误和恢复查询。可查看、可停止和可分支分别声明能力。父回复结束不代表所有子任务完成；取消请求被接收不代表执行已停止。权限继承只能收窄，确认必须精确关联运行身份。

重启先与 main 对账。丢失执行 owner 的本地运行沿用 `runtime_owner_lost` 失败语义；远程离线显示不可确认，不能推断已结束。诊断只记录关联身份、状态转换、能力拒绝和恢复原因，默认不输出消息正文、凭证或原生 Session ID。

## 已核对的 SDK 证据（2026-11-05）

仓库依赖 Claude Agent SDK `0.3.211`。安装包 `sdk.d.ts` 定义了 `task_started`、`task_progress`、`task_notification`、`Query.stopTask`、`listSubagents`、`getSubagentMessages` 和 `forkSession`。这证明 SDK 契约存在，不等于当前选择的 CLI、Studio Adapter 和真实运行都已通过验收。

现有 Claude 后端转发 system 事件；Studio 统一事件模型尚未完整承载子任务关系，主进程 Run store 没有子执行记录，renderer 尚无可恢复的子任务详情投影。Codex ACP 与远程协议须独立核对，不能继承 Claude 的能力声明。

已确认一个生命周期缺口：`agent-runtime.ts` 在收到 `complete/error` 后清除 `activeRunId`，随后到达的事件会被丢弃。接入后台子任务前，必须在现有 Runtime 内明确父回复终态与子执行终态的关系，保证子事件仍归属原 Run；不得直接放开无 Run 事件，也不得用第二套运行状态绕过现有终止保护。

现有专用真实模型 smoke 要求 `CCLINK_AGENT_SMOKE_API_KEY`；当前环境未配置。本轮可完成隔离 Electron UI 与受控事件回归，真实模型子任务与停止验收仍需专用测试凭证，不得以模拟事件替代。

## 生命周期、权限和失败降级

导航组件不拥有 Agent 事件订阅或执行清理。会话运行订阅仍位于 bootstrap；布局卸载不销毁执行。只改变呈现，无新增权限或人工批准点；已有工具确认继续由 Runtime 决策。远程失败只影响远程会话区，本地导航、文件、编辑器与 Agent 保持可用。

快照缺少新字段时恢复为聊天模式及 200px 列表；非法字段及超出新边界的宽度归一化，不继承上一工作空间。窄窗口只改变有效呈现。宽度拖拽在工作空间切换、窗口改变或取消时不得写入过期目标。

工程门禁：受影响 UIStore/布局/命令测试、类型检查及真实 Electron workspace-layout smoke。产品完成还需要上述真人步骤的结果，单测和受控事件不能证明真实子 Agent 闭环。

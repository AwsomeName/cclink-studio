# 眼镜 STEP 外壳 AI 修改

> 状态：需求已确认，修改能力尚未实现。最后更新：2026-10-09。
> 关联：[架构约束](../architecture.md)、[CAD 转换](./cad-conversion-plugins.md)、[硬件工作空间](./hardware-workspace.md)。

## 结论

用户需要在 Studio 中打开眼镜 STEP 文件，直接告诉 Claude Code“加宽”“加长”及具体数值，由 Claude Code 调用本机可编辑 CAD 后端修改文件副本，再在 Studio 中查看和核对新版模型。

Studio 不需要先建设完整 CAD 编辑器。现有 Claude Code、模型查看器、工作空间文件能力和 FreeCAD/OCCT 转换基础继续复用。当前核心缺口是供 Claude Code 调用的 STEP 实体修改工具，以及修改后的回显和基本核验。FreeCAD 是优先验证的编辑后端，不是架构上的唯一选择；现有 `occt-import-js` 只有 STEP 导入和三角化能力，不能直接承担 STEP 实体修改与导出。

## 最小用户闭环

```text
在 Studio 打开现有 STEP
→ 告诉 Claude Code“沿 X 方向加长 5 mm”
→ Claude Code 说明将执行的操作和输出文件
→ CAD 后端修改副本并导出 xxx-v2.step
→ Studio 自动打开新版模型
→ 显示修改前后整体尺寸和执行结果
→ 用户保留新版或删除本次草案
```

首版完成标准：用户不离开 Studio，能对一个真实眼镜 STEP 完成一次受支持的加宽或加长，得到可被 CAD 软件重新打开的新版 STEP，原文件保持不变。

## 已有能力

| 能力 | 当前实现 |
| --- | --- |
| Claude Code Agent | 已有本地 Agent、工具调用和会话能力 |
| STEP 查看 | 已有 STEP 经 FreeCAD/OCCT 转为 STL 后在 `ModelViewer` 中查看 |
| 模型交互 | 已有旋转、缩放、网格、线框和重置视角 |
| 基本模型信息 | 已有整体包围盒、源文件哈希、单位置信度和转换诊断 |
| CAD 后端 | 已有 FreeCAD 探测、OCCT Runtime 和 STEP 预览转换 |
| 工作空间文件 | 已有本地文件读写、Tab 和 Agent 工作空间上下文 |

现有 CAD MCP 工具只支持查询、检查和 STEP 转预览 STL，不能修改 STEP 或导出新版 STEP。

## 首版需要开发的功能

### 1. STEP 修改服务

新增主进程 CAD 修改服务，优先复用现有 FreeCAD 检测与进程执行基础：

- 输入源 STEP、操作类型、方向和数值；
- 修改源文件副本，禁止覆盖原文件；
- 首选使用 FreeCAD Python/CLI 执行实体操作；如果真实样本证明不可行，再评估具备 B-Rep 编辑和 STEP 导出的其他后端；
- 导出新版 STEP；
- 返回输出路径、修改前后尺寸、后端日志摘要和结构化错误；
- 对超时、取消、无有效实体和导出失败进行清理和诊断。

修改服务是 CAD 修改任务和结果的唯一状态所有者。renderer 和 Agent 只提交命令、读取结果。

### 2. Claude Code CAD 工具

向现有 CAD MCP 模块增加受限工具，建议职责如下：

```text
cad_analyze_step
  读取 STEP 的实体数量、整体尺寸、单位和可执行操作

cad_modify_step
  在副本上执行已支持的加宽或加长，输出新版 STEP

cad_validate_step
  重新打开输出文件，检查实体有效性和修改前后尺寸
```

首版不向 Claude Code 暴露任意 CAD Python 或 shell。工具只接受定义好的参数，避免 AI 生成任意脚本直接操作用户文件。

### 3. 第一批修改操作

按后端真实能力逐项开放：

1. 整体沿单轴缩放：最容易实现，但会改变孔径、壁厚和内部结构，只在用户明确要求整体缩放时使用。
2. 沿指定截面加长：用于镜腿等零件，截面一侧保持不动，另一侧平移并补齐实体。
3. 指定区域外扩：用于局部加宽，只有真实 STEP 样本验证可靠后才开放。

Claude Code 不得把“加长”自动解释为整体缩放。如果无法确定操作、方向或修改范围，应说明缺少什么，而不是猜测执行。

### 4. 修改结果回显

复用现有 `ModelViewer`：

- 修改成功后自动打开新版 STEP；
- 显示源文件和输出文件；
- 显示修改前后 X/Y/Z 整体尺寸；
- 提供“打开原版”“打开新版”“删除草案”；
- 转换或加载失败时保留新版 STEP，并显示真实失败阶段。

首版不要求复杂的曲面差异着色、零件树或专业测量工具。

### 5. 基本核验

修改完成后由程序执行，不以 Claude Code 的文字回复作为成功依据：

- 新版 STEP 文件存在且非空；
- CAD 后端能够重新导入；
- 至少存在一个有效实体；
- 目标轴尺寸按要求变化；
- 非目标轴尺寸是否变化必须明确报告；
- 原文件哈希未改变。

这些检查只能证明修改文件和基本尺寸符合预期，不能证明装配、强度或制造工艺合格。

## 首版不做

- 完整 CAD 编辑器和特征树编辑；
- PCB、电池、光学件自动装配与干涉检查；
- 任意复杂曲面重建；
- 专用 CAD 版本数据库；
- 专用实物反馈系统；
- 自动上传供应商或自动下单。

这些能力有真实需求和样本后再增加。首版改版记录可以复用工作空间目录、文件命名、Markdown 和现有 Git 能力。

## 开发顺序

### P0 修复现有 STEP 预览

2026-10-09 真实 App 验收确认当前预览链路尚未闭环：

1. v0.1.105 的设置页已选择 `occt-experimental`，后端检测显示 OpenCascade `0.0.23` 可用；
2. CAD 服务能转换真实样本并生成 `userData/cad-cache/<sourceHash>/preview.stl`；
3. `ModelViewer` 随后调用通用 `fs.readFile(previewPath)`；
4. `FileService` 正确拒绝读取工作空间外的 CAD 缓存，返回 `OUTSIDE_WORKSPACE`；
5. 因此用户仍看不到模型。此前“预览未启用，请选择 FreeCAD”的提示还会掩盖真实阶段和后端类型。

修复时不放宽通用 `FileService` 的工作空间边界。由 `CadConversionService` 继续唯一拥有缓存，通过受校验的 CAD IPC 按 `sourceHash + format` 返回有大小限制的预览内容或受控资源引用；renderer 不提交任意缓存路径。`ModelViewer` 使用该接口加载预览，并按实际错误区分“后端未启用”“转换失败”和“预览读取失败”。

真人验收：在“生产”工作空间打开 `光机左镜框精简20260716.STEP`，模型真实显示，尺寸摘要出现；关闭并重新打开时命中缓存仍能显示；通用 `fs.readFile` 继续拒绝直接读取 `userData/cad-cache`。该验收通过前，不能把 STEP 查看列为用户已可用能力。

### E0 后端可行性验证

使用一个真实眼镜 STEP，优先验证 FreeCAD 能否：

1. 导入并识别有效实体；
2. 完成一种明确的加长或加宽操作；
3. 导出新版 STEP；
4. 重新导入并得到正确尺寸。

E0 只验证几何路线，不算用户功能完成。如果同一种操作连续失败两次，停止扩张 UI，记录失败模型和替代操作。

当前真实样本基线（2026-10-09）：

- 样本：`光机左镜框精简20260716.STEP`，SolidWorks 2024 导出的 STEP AP203；
- 文件大小：1,169,363 bytes；SHA-256：`28eef649442705b570b2b5148a37663b99dc799fd1d5a65ce7cf2d1981680f67`；
- STEP 文本包含一个 `MANIFOLD_SOLID_BREP` 和一个 `CLOSED_SHELL`；
- 当前 Studio 设置已选择 `occt-experimental`；底层 `occt-import-js 0.0.23` 实测读取成功，生成 1 个 mesh、4,645 个顶点、5,678 个三角形；这证明当前依赖能解析样本，但本次未启动 Studio UI 做真人预览验收；
- STEP 明确使用毫米单位；三角化后包围盒约为 `148.1735 × 41.0588 × 50.5921 mm`，该值用于预览基线，坐标轴含义和精确 CAD 尺寸仍需在实体后端或原 CAD 中核对；
- 当前机器未检测到 FreeCAD；现有 `occt-import-js` 未提供 STEP 写出接口，因此尚未证明实体修改和新版 STEP 导出可行。下一步需要的是一个可编辑且能写出 STEP 的后端，FreeCAD 是首选验证路径，不是唯一方案。

### M1 最小产品闭环

- P0 STEP 预览已在真实 App 中通过；
- STEP 修改服务；
- `cad_analyze_step`、`cad_modify_step`、`cad_validate_step`；
- Claude Code 调用说明；
- 修改副本和新版 STEP 输出；
- Studio 自动打开新版并显示前后尺寸；
- 一个真实眼镜 STEP 真人验收。

### M2 按实际需求增强

- 增加第二种加宽/加长操作；
- 原版与新版叠加对比；
- 零件选择与局部测量；
- PCB、电池、光学件装配约束；
- 打样包和实物反馈关联。

M2 不得阻塞 M1。

## 失败处理

| 失败 | 行为 |
| --- | --- |
| 可编辑 CAD 后端未安装或不可用 | STEP 查看按现有 OCCT 能力继续工作；修改工具返回可修复诊断 |
| 模型没有有效实体 | 不生成成功版本，保留原文件 |
| 操作不适合当前几何 | 明确报告不支持，不退化成整体缩放 |
| 修改超时或取消 | 终止后端进程，隔离未完成产物，不标记成功 |
| 新版无法重新导入 | 修改失败，不把文件呈现为可采用版本 |
| 输出路径冲突 | 生成新的版本名，不覆盖已有文件 |

## 验收动作

用户在 Studio 中打开真实眼镜 STEP，对 Claude Code 说出一个带数值的加宽或加长要求。Claude Code 调用 CAD 工具生成副本，Studio 自动打开新版，显示修改前后尺寸。用户用可编辑 CAD 后端或原 CAD 软件重新打开新版 STEP，确认实体和目标尺寸有效。

只有这套真人流程通过，才能声明首版 AI 修改 STEP 闭环完成。预览成功、单元测试通过或 Claude Code 回复“修改完成”都不能替代该验收。

## 最关键的技术问题

第一步不是继续建设 UI，而是用真实眼镜 STEP 证明一个可编辑 CAD 后端能稳定完成一种有价值的加宽或加长。优先验证 FreeCAD；如果失败，再基于失败证据选择其他 B-Rep 后端。这个验证决定首版开放哪种操作；Claude Code 接入、MCP 工具和查看器回显都建立在该结果上。

# AI 芯片工作台产品设计

> 状态：产品方案，尚未实现。2026-10-10。
> 本文只定义 CCLink Studio 内独立的“AI 芯片”产品域；不包含神经网络浏览、神经刺激实验、
> 大脑活动回放或生物行为模拟。`neural-circuit-lab` 中混合的芯片内容由本文取代。

## 结论

CCLink Studio 应增加独立的 **AI 芯片工作台**。它的核心不是“用聊天框替代 EDA”，而是把
需求、架构、设计源、真实工具运行、验证结果和可复现证据串成一条可追溯链路，并在每个需要
工程判断的节点提供 AI 建议。

首版只承诺一个最小纵向闭环：

> 在本地工作空间创建小型忆阻器电路项目，基于一个经过验证的器件模型和固定 ngspice
> 适配器，由 AI 协助准备电路与 Testbench，运行真实瞬态求解，查看波形，修改一个参数，
> 产生第二次运行，比较结果并保存两次运行的输入、工具版本、原始输出和比较证据。

首版不承诺完整混合信号协同仿真、任意原理图捕获、数字 RTL 仿真、综合、时序收敛、模拟版图、
FPGA 下载或芯片可制造性。上述方向只保留对象模型、入口和阶段门；入口存在不等于能力可用。

当前用户只能阅读本方案和页面效果示意，还不能在 Studio 中执行上述闭环。当前开发机也未探测到
`ngspice`、`Xyce`、`iverilog`、`verilator`、`yosys`、`openroad` 或 `gtkwave`，因此首版开始
实现前的第一项技术门禁是：选定 ngspice 版本、模型和输出格式，并在目标平台完成命令行真跑。

## 本轮验收结果

本轮交付是设计，不是功能实现：

1. 用户可以在文档中确认产品定位、首版边界、对象模型、页面、目录、适配器、AI 边界和路线图。
2. 用户可以打开六页交互效果示意，检查从规格到两次运行比较的核心流程。
3. 用户还不能在真实 Studio 中创建芯片项目、运行求解器或获得真实波形。

产品功能进度与工程准备度必须分开：本文、架构文档和效果图属于工程与产品定义准备度，不能计为
“AI 芯片工作台已交付”。

## 目标用户与核心价值

### 首要用户

- 研究忆阻器、存算一体、模拟神经形态电路的器件与电路研究者；
- 需要从计算需求快速形成可验证电路原型的模拟／混合信号工程师；
- 需要维护需求、设计假设、参考向量与验证追踪关系的 AI 芯片系统架构师；
- 后续阶段中的 RTL、FPGA 和物理实现工程师。

首版最优先服务前两类用户，且假设他们能理解基本 SPICE、电压电流、模型适用范围和数值收敛问题。
教学演示可以受益，但不是首版决定技术边界的核心场景。

### 非目标用户与非目标任务

- 不把生物神经系统、线虫连接组或仿生大脑内部对象作为产品内核；
- 不提供神经网络浏览、刺激实验、大脑回放或行为模拟；
- 不以首版替代 Cadence、Synopsys、Siemens EDA、Vivado 等专业环境；
- 不声称通过一次电路仿真即可制造芯片；
- 不建设允许任意 executable 注入 Studio 的 EDA 插件市场。

### 核心价值

1. **需求到证据的连续追踪**：需求、架构模块、设计对象、验证用例、工具运行和结论都有稳定引用。
2. **AI 生成但不伪造成功**：AI 产出候选方案和改动，真实工具产出运行事实，规则引擎产出验证结论。
3. **多工具统一工作面**：Studio 统一展示输入、状态、错误、波形和证据，不复制工具的全部编辑器。
4. **本地可复现**：运行绑定不可变输入快照、工具版本、适配器版本、参数和原始输出。
5. **增量走向实现**：同一项目对象模型允许以后接入 RTL、综合、物理实现、FPGA 和真实器件测试，
   但每个阶段仍由对应真实工具或硬件事实证明。

## 与传统 EDA 工具的关系

AI 芯片工作台是 **设计编排、可追溯性和 AI 辅助层**，不是新的全栈 EDA 内核。

| 领域 | Studio 负责 | 外部 EDA／硬件负责 | 明确不做 |
| --- | --- | --- | --- |
| 需求与架构 | 结构化需求、架构建议、确认基线、追踪关系 | 无 | AI 建议自动变成已确认架构 |
| 电路与 RTL | 受限编辑、文件管理、AI 候选、运行输入快照 | 语法、数值、逻辑与工具语义 | 首版复刻完整 Virtuoso／Vivado 编辑器 |
| 仿真 | 调用固定适配器、状态、日志、波形与比较 | 数值求解或 HDL 执行 | 用模型回复或前端动画代替求解 |
| 综合与物理实现 | 阶段门、配置引用、证据汇总 | 综合、STA、布局布线、DRC、LVS、提取 | 自己推测 PPA、时序或可制造性 |
| FPGA／硬件 | 目标、连接与测试记录的统一入口 | 工具链、板卡、仪器、真实测量 | 用软件参考输出冒充板上结果 |

ngspice 官方手册提供批处理和 rawfile 输出，适合作为首个受控模拟适配器；但具体版本、模型方言、
输出解析和数值结果仍必须通过真机 spike 固定。Xyce 可作为后续大规模 SPICE 兼容求解器候选。
数字方向可在后续分别评估 Verilator、Yosys 和 OpenROAD；候选名称不代表已支持。

## 首版范围裁决

这里的“首版”指拟议的第一项可验收产品能力，不是当前实现状态。

| 方向 | 首版裁决 | 首版可见能力 | 明确后移 |
| --- | --- | --- | --- |
| 模拟／混合信号 | **模拟瞬态进入；混合信号只留入口** | 单一模拟设计、受限瞬态 Testbench、波形与两次运行比较 | AMS 协同仿真、事件／连续域同步、噪声与完整 corner 流程 |
| 忆阻器器件与电路 | **进入首版** | 一个有来源、单位、适用范围和 golden case 的模型；小型脉冲响应电路 | 任意 Verilog-A、材料级器件求解、阵列规模承诺 |
| 数字 RTL | **架构入口** | 项目可索引 RTL 文件和模块接口；仍可使用 Studio 普通编辑器编辑文本 | 领域内 lint、仿真、覆盖率、综合和时序 |
| FPGA | **架构入口** | 目标类型、板卡需求和阶段门占位，明确“尚未接入” | 工具链、bitstream、烧录、设备连接和采样 |
| 芯片物理设计 | **架构入口** | 实现目标与所需 PDK／工具／signoff 清单 | 模拟版图、数字 P&R、寄生提取、DRC、LVS、STA、GDS |

首版电路编辑采用“**受控模板 + 参数表 + 电气拓扑预览 + 可查看生成网表**”。它允许完成真实闭环，
但不承诺任意拖拽连线、层次化符号库或版图。若把完整原理图编辑器拉入首版，范围会立即失控。

## 证据等级

产品不得只显示一个模糊的“成功”。每项结论必须带证据等级：

| 等级 | 含义 | 可声明内容 |
| --- | --- | --- |
| Proposal | AI 或用户提出的候选 | “已生成建议／代码／网表”，不能说已验证 |
| Prepared | 输入、依赖和工具预检通过 | “可运行”，不能说仿真通过 |
| Executed | 外部工具结束且所需输出可解析 | “工具运行成功”，不能说需求通过 |
| Verified | 真实输出满足绑定验证用例和容差 | “指定用例通过”，不能外推未测条件 |
| Implemented | 综合或物理工具产生对应实现证据 | “该实现运行完成”，不能自动称 signoff |
| Signoff／Measured | 真实 STA、DRC、LVS、版图后仿真或硬件测量证据 | 仅声明证据覆盖的 corner、规则集和硬件条件 |

## 核心对象

所有对象都包含 `schemaVersion`、稳定 ID、`chipProjectId`、revision、时间戳和显式引用。AI 只能
提出对象变更，不拥有对象终态。

| 对象 | 含义与关键字段 | 主要关系 | 首版 |
| --- | --- | --- | --- |
| 芯片项目 `ChipProject` | 一个工作空间内的领域项目；名称、目标、活动实现、对象索引 | 归属现有 Workspace；不替代 Workspace | 是 |
| 需求与规格 `RequirementSet` | 功能、接口、模拟指标、环境、约束、优先级、验收方式 | 可由 HTS 导入；追踪到模块和用例 | 是 |
| 系统架构 `SystemArchitecture` | 模块、连接、接口、分区和关键取舍；有 draft／confirmed revision | 满足需求；引用模块 | 是，受限 |
| 模块 `ChipModule` | 模块职责、类型、端口、时钟／电源域及实现选择 | 由 Schematic、RTL 或外部 IP 实现 | 是，受限 |
| 器件模型 `DeviceModel` | 格式、参数、单位、来源、授权、适用范围、验证向量 | 被 Schematic 引用 | 是，一个受支持模型 |
| 原理图 `Schematic` | 电气拓扑、实例、网络、参数覆盖与非电气布局 | 引用模块和器件模型；可生成网表 | 是，模板化 |
| RTL `RtlDesign` | HDL 源、top、模块清单、语言与 include 关系 | 实现数字模块 | 仅索引入口 |
| 约束 `ConstraintSet` | 仿真、时序、物理、功耗、FPGA 引脚和安全限制 | 绑定架构／实现／Testbench | 模拟子集 |
| Testbench `Testbench` | 激励、初态、观测信号、参考数据、断言和容差 | 面向一项设计与若干需求 | 是，瞬态子集 |
| 仿真实验 `SimulationExperiment` | 设计 revision、Testbench、求解配置和参数覆盖 | 每次运行前被快照 | 是 |
| 工具运行 `ToolRun` | 生命周期、固定输入、工具、进程、日志、原始输出和哈希 | 由主进程唯一拥有 | 是 |
| 验证结果 `VerificationResult` | 绑定 run、用例、断言、度量、pass／fail／inconclusive | 只能由真实输出和规则计算 | 是 |
| 实现版本 `ImplementationVersion` | 某个确认设计基线对应的综合、版图、bitstream 或制造包版本 | 引用工具运行和签核证据 | 对象入口 |
| FPGA／硬件测试记录 `HardwareTestRecord` | 目标设备、固件、连接、刺激、采样、环境与结果 | 引用实现版本和参考用例 | 对象入口 |
| Hardware Target Specification `HardwareTargetSpecification` | 外部计算需求、接口、参考向量和验收条件的正式交换契约 | 导入为需求与验证用例候选 | 是，导入子集 |

### 关键引用规则

- `chipProjectId` 是领域 ID，不是 `workspaceKey`；一个本地工作空间可以包含多个芯片项目。
- 实验引用具体设计 revision，运行再冻结文件哈希；“当前编辑内容”不能反向改变历史运行。
- 工具运行状态与验证 verdict 分离：退出码为 0 不等于需求通过。
- 实现版本只引用证据，不复制工具运行状态。
- 硬件测试记录只接受 HardwareConnection 领域产生的连接与采样事实，不能由 Agent 自述创建。

## 完整用户流程

下面是产品北极星流程。首版只实现其中模拟电路分支和“返回设计修改”的闭环。

| 步骤 | 执行者 | 进入条件 | 动作 | 完成条件与证据 | 失败／等待 | 允许下一步 |
| --- | --- | --- | --- | --- | --- | --- |
| 1. 输入需求 | 用户／Studio | 已打开本地 Workspace | 新建芯片项目，填写目标或导入 HTS | 有 schema 校验通过的需求 revision | 字段、单位或引用不合法 | 修订需求或退出 |
| 2. 生成架构建议 | Agent | 需求 revision 已保存 | 生成模块、接口、风险和验证建议 | 保存 Proposal 与输入 revision | AI 不可用或建议不完整 | 手工设计或重试 |
| 3. 确认架构 | 用户 | Proposal 可审查 | 查看差异、修改并确认架构基线 | `confirmedRevision` 和确认人／时间 | 未解决需求、接口冲突 | 返回需求或继续设计 |
| 4. 创建／编辑设计 | 用户／Agent | 模块已有实现类型 | 编辑 Schematic／RTL／模型引用 | 源文件已保存、结构检查通过 | 悬空网络、语法、模型缺失 | 修复或放弃改动 |
| 5. 生成测试 | Agent／用户 | 设计 revision 已保存 | 从需求生成 Testbench 和断言候选 | 用户确认 Testbench 与 trace links | 容差不明确、参考缺失 | 补充规格或仅做 exploratory run |
| 6. 工具预检 | Studio | 实验定义完整 | 探测固定适配器、版本、许可和输入 | `PreparedRun` 与输入快照哈希 | 工具缺失、版本不支持、许可失败 | 配置工具或继续编辑 |
| 7. 调用真实 EDA | Studio／外部工具 | 用户开始运行且预检通过 | 主进程启动进程并记录状态 | 工具退出、输出存在且可解析 | 收敛、崩溃、超时、取消、输出损坏 | 查看错误、重跑或修改设计 |
| 8. 查看波形与错误 | 用户 | run 有输出或错误 | 浏览信号、日志、源定位和断言 | 页面引用固定 run 和原始证据 | 部分输出或单位不兼容 | AI 调试或手工修复 |
| 9. AI 辅助调试 | Agent | 已选择 run 和受限上下文 | 解释错误并给出 diff 建议 | 建议引用错误、输入 revision 和假设 | 证据不足则明确“不确定” | 应用建议、补充数据或忽略 |
| 10. 回归验证 | Studio／工具 | 修订设计和用例已保存 | 运行选定用例集 | 每个用例有独立 run 与 verdict | 任一失败不覆盖旧证据 | 再修订或建立实现基线 |
| 11. 进入实现 | 用户 | 需求覆盖达到阶段门 | 选择综合、物理或 FPGA 目标 | 创建 ImplementationVersion 草案 | 缺工具、PDK、板卡或许可 | 配置目标或停留在验证阶段 |
| 12. 真实签核／测试 | 外部工具／硬件 | 实现与环境就绪 | 运行 STA、DRC、LVS、下载或测量 | 保存真实报告或采样及哈希 | 工具／许可／设备／安全失败 | 修订实现，不伪造通过 |

## 首版页面

六页复用 Studio 现有 Activity Bar、Sidebar、Workbench Tab、Agent Panel、Terminal、命令、权限和
诊断。页面是同一工作台中的领域 Tab，不建设第二套窗口、文件树或 Agent 面板。

### 1. 芯片项目总览

- **页面目标**：回答项目要做什么、当前证据到哪一步、下一项可执行动作是什么。
- **主要区域**：项目摘要、阶段流、未满足门禁、最近运行、工具环境、需求追踪缺口。
- **用户操作**：新建／打开芯片项目、继续上次工作、查看失败运行、打开工具配置。
- **AI 介入点**：总结未覆盖需求、建议下一动作；不得修改阶段状态。
- **外部工具介入点**：只显示主进程探测结果和最近真实运行，不在首页推测工具可用。
- **空状态**：提供“忆阻器脉冲响应”模板和“导入 Hardware Target Specification”。
- **失败状态**：项目格式不兼容、引用损坏、工具缺失分别显示恢复／只读／配置动作。
- **完成证据**：项目对象可读取，下一动作对应真实未完成项；不显示虚构进度百分比。

### 2. 规格与架构

- **页面目标**：把需求、HTS、系统模块和确认的架构版本建立可审计关系。
- **主要区域**：需求列表、追踪矩阵、架构图、模块／接口属性、AI Proposal 差异。
- **用户操作**：编辑需求、导入 HTS、生成建议、逐项采用／修改／拒绝、确认或废止基线。
- **AI 介入点**：提出模块划分、接口、风险和测试建议，并标注来源与假设。
- **外部工具介入点**：无；工具探测结果不能替代架构确认。
- **空状态**：引导填写最小目标、接口和至少一个验收条件。
- **失败状态**：单位不明、需求冲突、HTS 引用缺失、旧 Proposal 基于过期 revision。
- **完成证据**：用户确认的架构 revision，以及需求到模块／验证用例的追踪关系。

### 3. 设计工作台

- **页面目标**：在一个工作面编辑电路／RTL，并清楚区分源设计、生成物和 AI 建议。
- **主要区域**：项目树、Schematic／RTL／模型页签、中心编辑器或拓扑预览、属性面板、问题列表。
- **用户操作**：修改实例参数、查看模型来源、编辑源文件、应用 diff、运行结构检查、创建 Testbench。
- **AI 介入点**：生成网表／RTL／Testbench 候选，解释检查错误，提供最小 diff。
- **外部工具介入点**：首版只在显式“检查／运行”时调用；浏览文件不启动求解器。
- **空状态**：选择受支持模板、导入只读源或创建空模块；未知格式保留原文件但不允许运行。
- **失败状态**：悬空网络、模型不兼容、语法错误、外部修改冲突定位到对象和文件。
- **完成证据**：保存的 design revision、结构检查结果和被用户接受的变更记录；生成成功不是仿真成功。

### 4. 实验与运行

- **页面目标**：定义可重跑实验，并让用户看到真实工具从预检到终态的每一步。
- **主要区域**：Testbench、刺激／观测／容差、运行前检查、工具环境、运行步骤、日志与取消。
- **用户操作**：保存实验、选择参数覆盖、开始、取消、打开 Terminal 或日志、从失败复制新实验。
- **AI 介入点**：从需求建议测试与容差、解释预检问题；不能写运行终态。
- **外部工具介入点**：固定 ngspice 适配器完成版本探测、输入生成、进程运行和输出解析。
- **空状态**：先选择设计和 Testbench；工具缺失时仍可编辑并查看安装／配置说明。
- **失败状态**：工具缺失、版本不支持、许可证、输入、收敛、超时、取消失败和输出解析分开呈现。
- **完成证据**：`ToolRun` 状态时间线、输入 manifest、工具／适配器版本、退出码、日志和输出哈希。

### 5. 波形与比较

- **页面目标**：用真实数据判断“发生了什么”和“是否满足指定用例”。
- **主要区域**：信号树、波形、双游标、Run A／B 对比、断言结果、错误详情、证据索引。
- **用户操作**：选择信号、缩放、对齐、差值／叠加、选择基线、保存比较报告、返回设计修改。
- **AI 介入点**：基于所选信号和日志解释差异、提出可核验假设；回答必须引用 run ID。
- **外部工具介入点**：数据必须来自已登记输出；外部波形查看器可后续作为“打开方式”而非状态 owner。
- **空状态**：没有 run 时引导到实验页；失败 run 有日志但无波形时不画占位曲线。
- **失败状态**：单位不同、时间轴不重叠、输出损坏或证据被外部修改时禁止比较结论。
- **完成证据**：固定两次 run、信号与范围、计算的度量、断言 verdict、报告和全部引用哈希。

### 6. 实现与硬件入口

- **页面目标**：在不伪装已支持能力的前提下，把验证完成的设计交给后续实现路径。
- **主要区域**：数字综合、模拟／数字物理实现、FPGA、真实忆阻器阵列四张目标卡和阶段门详情。
- **用户操作**：查看缺失条件、创建实现草案、绑定工具／PDK／板卡、打开已有外部报告。
- **AI 介入点**：检查准备清单、解释报告；不能生成 PPA、DRC、LVS、STA 或测量“事实”。
- **外部工具介入点**：后续固定适配器；首版全部显示“尚未接入”和明确前置条件。
- **空状态**：说明为什么需要确认设计、工具、工艺或硬件，不展示概念版图冒充结果。
- **失败状态**：许可、PDK 权限、工具版本、板卡断连、安全限值和报告不完整分别处理。
- **完成证据**：对应工具报告或硬件采样及环境指纹；首版只有入口结构，没有完成证据。

效果示意见 [AI 芯片工作台六页预览](../design/ai-chip-workbench/pages.html)，可编辑源见
[pages.fragment.html](../design/ai-chip-workbench/pages.fragment.html)。全部数据均为界面示意。

## 第一个最小纵向闭环

### 用户可执行验收动作

1. 在未登录 CCLink、网络断开但 Studio 可启动的环境中打开本地工作空间。
2. 选择“忆阻器脉冲响应”模板，新建 `memristor-pulse` 芯片项目。
3. 查看模型来源、方程／格式、参数单位和适用范围；缺任一项时不得开始受控运行。
4. 让 AI 生成或补全电路与 Testbench Proposal，查看 diff 后由用户确认应用。
5. 运行前检查显示实际 ngspice executable、版本、适配器版本、输入 revision 和输出目录。
6. 点击运行；主进程启动真实 ngspice，页面显示真实状态、日志和取消能力。
7. 运行结束后选择 `V(in)`、`V(out)`、`I(M1)` 及模型暴露的状态量，查看带单位波形。
8. 把一个已允许参数从值 A 修改为值 B，保存为新 design revision，再运行一次。
9. 在比较页同时选择 Run A 和 Run B，查看对齐波形、差值和至少一个预定义度量。
10. 保存比较报告，关闭并重开 Studio，重新找到两次不可变 run 和报告；重跑会生成第三个 run，
    不覆盖旧证据。
11. 分别模拟工具缺失、数值不收敛和主动取消，确认它们不会阻断普通 Workspace、Agent、编辑器或
    Terminal，也不会被误标为成功。

### 闭环完成标准

- 两次输出确由被记录版本的真实 ngspice 产生，且所需 raw 输出由受限解析器成功读取；
- 每次运行均包含输入哈希、生成网表、命令参数、工具与适配器版本、状态时间线、日志和输出哈希；
- 参数变化可追溯到新 design revision，比较报告固定引用两个 run；
- AI 生成记录与工具运行、验证 verdict 分开；
- 在真实 Studio 中按上述步骤验收并保存结果；自动测试、mock 波形或命令行单跑不足以宣布完成。

## Hardware Target Specification 导入

仿生大脑或任何其他产品域只能通过正式、版本化的 Hardware Target Specification（HTS）提供输入。
AI 芯片工作台不读取对方的数据库、内部目录、运行时状态或私有对象 ID。

### 最小契约

HTS 首期接受 YAML 或 JSON，外部引用必须是包内相对路径并带 SHA-256：

```yaml
schemaVersion: cclink.hardware-target/v1alpha1
targetId: demo-target
revision: 3
source:
  system: external-domain
  exportedAt: 2026-10-10T00:00:00Z
intent:
  summary: 需要被硬件实现的计算与接口，不描述源产品内部结构
compute:
  stateVariables:
    - id: membrane_state
      unit: mV
  modelRef: normalized-model-v3
  updateSemantics: fixed-step
  initialization: refs/initial-state.json
interfaces:
  inputs:
    - id: stimulus_in
      quantity: current
      unit: nA
      range: [-2, 2]
      encoding: sampled
  outputs:
    - id: response_out
      quantity: voltage
      unit: mV
      samplingPeriod: 0.1 ms
requirements:
  - id: HTS-FUNC-001
    statement: 对给定输入产生指定输出响应
    verification: waveform-compare
numeric:
  referenceSemantics: float64
  absoluteTolerance: 0.5 mV
  relativeTolerance: 0.05
performance:
  endToEndLatencyMax: 5 ms
  updateDeadline: 0.1 ms
standardStimuli:
  - id: STIM-001
    path: refs/stim-001.csv
    sha256: "..."
    initialState: refs/initial-state.json
    randomSeed: 42
referenceResults:
  - id: REF-001
    stimulusId: STIM-001
    path: refs/ref-001.csv
    sha256: "..."
    metric: normalized-rmse
    operator: "<="
    value: 0.05
provenance:
  license: user-provided
  sourceObjectIds: [brain-project-id, circuit-id, model-id, reference-run-id]
  sourceRevisions: [7, 3, 5, 11]
  warnings: []
  notes: 参考结果的生成条件、适用范围和限制
```

### 导入流程

1. Studio 校验 schema、单位、ID、相对路径、哈希、包大小和引用完整性；失败时不修改芯片项目。
2. 原始包原样复制到 `imports/hardware-targets/<target-id>/<revision>/`，记录导入时间和内容哈希。
3. Importer 生成规范化快照，不执行包内脚本，也不解析源产品私有文件。
4. AI 基于规范化快照提出 Requirement、Module、Constraint 和 VerificationCase Proposal；状态变量、
   更新语义、通道、精度和性能要求保持为需求，不能提前决定 bit width、忆阻器或 RTL 实现。
5. 用户逐项确认映射；未映射、冲突、单位转换和假设必须显式可见。
6. 接受后创建新的需求 revision 和验证用例，保留 `targetId + revision + source hash` 追踪链。
7. 参考结果只能作为验收输入；真实芯片工具或硬件输出仍单独产生并比较。

HTS 缺少接口、单位、运行条件、参考向量来源或容差时，可以作为探索性需求导入，但不能自动生成
“已验证”用例。源产品更新不会静默修改芯片项目，必须显式重新导入并审查差异。

## AI 能力边界

### AI 可以做

- 把自然语言或 HTS 转为需求、架构、模块和验证 Proposal；
- 生成或修改受支持的 Schematic、网表、RTL、约束和 Testbench 候选；
- 解释工具错误、波形和报告，提出带来源 run／revision 的诊断假设；
- 建议参数扫描、回归集合和下一项真实验证；
- 生成比较报告草稿和证据索引。

### AI 不可以做

- 把文件生成成功写成仿真成功；
- 把退出码为 0 写成需求通过；
- 把电路仿真成功写成芯片可制造；
- 自己填写 PPA、DRC、LVS、STA、版图后仿真、FPGA 或硬件结果；
- 绕过工具许可、PDK 权限、器件安全限值或用户确认；
- 把不可解释、缺来源或超出模型适用范围的输出包装成确定结论；
- 直接启动任意 executable、任意模型脚本或任意 shell 命令作为 EDA 适配。

AI 生成物必须记录模型／Agent run、输入对象 revision、Prompt 或结构化任务摘要、产生时间及用户是否
采用。AI 对事实的描述只能引用 ToolRun、VerificationResult 或 HardwareTestRecord 的稳定 ID。

## 方案拷问

### 是否过度承诺“完整 EDA”？

是，若把长期对象模型误读为首版功能就会过度承诺。本文把“从规格到真实硬件”作为产品方向，
但首版只交付一个模拟瞬态纵向闭环。完整原理图、AMS、RTL、综合、物理实现和 FPGA 都必须在后续
分别通过真实用户动作验收，不能用六个入口或一张流程图宣称完成。

### AI 是否只是包装？

有这个风险。若 AI 只生成一段网表，而项目仍无法追踪需求、复现运行、解释错误和比较两次证据，
它就是聊天包装。首版必须验证 AI 是否实际减少“从需求到可运行 Testbench”和“从错误到可验证
修改”的时间；即使 AI 不可用，用户仍应能手工编辑并运行，证明产品价值不依赖幻觉。

### 外部工具能否真实运行？

当前不能证明：开发机未安装候选工具，旧文档也没有真实求解证据。最先要做的是 ngspice + 选定模型
的命令行 spike，不是先造漂亮画布。若同一模型在目标平台两次仍不能稳定运行，应停止首版 UI 扩张，
重新选模型、求解器或输出格式。

### 项目能否复现？

只能在“输入快照、版本、适配器、单位、随机种子、输出和哈希齐全”的意义上可复现；不同平台和
数值库不保证逐位一致。商业许可、外部 PDK 和不可分发模型会限制他人复跑，必须显示为依赖缺失，
而不是悄悄降级到另一模型。

### 是否具备芯片制造条件？

当前没有证据表明已有 foundry、PDK、忆阻器工艺模块、DRC/LVS deck、封装、测试或 signoff 工具。
因此任何“芯片面积、功耗、可制造、流片就绪”的 UI 数值都属于伪造。物理设计入口必须保持阶段门，
直到具体工艺与授权成立。

### 首版是否足够小？

只有在坚持“一种电路模板、一个模型、一个求解器、一种瞬态分析、一次只运行一个项目任务、两次
运行比较”时足够小。首版若同时加入任意画布、Verilog-A 编译、参数扫描、RTL、FPGA 或 PDK，
就不再是最小闭环。

### 下一步最该做什么？

先冻结首版验收样例并完成真实 ngspice 技术 spike：确定模型来源、命令、版本、raw 输出、单位、
预期波形、收敛失败和取消行为。只有该 spike 给出可解析的真实证据后，才值得进入实现计划和 UI
施工；否则当前方案仍只是结构正确的产品设想。

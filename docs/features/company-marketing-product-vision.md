# 公司市场与用户：产品愿景

> 状态：产品愿景，待用户确认；未实现、未排期，不是交付声明。日期：2026-11-22。

## 一句话

**一个人经营的公司的市场助理。** 它把你已经在做的研发工作变成值得讲的内容，送到对的人面前，保证每个感兴趣的人都有回应，并告诉你什么真正带来了受众和试戴者。你始终是发声的人，它做跑腿的事。

本文从产品目的出发，先说清理想形态与用户期望，再对照现有能力说明可以复用什么、缺什么。实现方案另行编写。

## 在公司项目里的位置

公司项目要支撑日常经营，不只是市场。它有三项业务功能，共用一个公司首页：

| 功能       | 回答的问题                                 | 事实来源                                         |
| ---------- | ------------------------------------------ | ------------------------------------------------ |
| 业务项目   | 每件业务的目标、交付物和进展               | 公司领域：业务项目与关联                         |
| 公司账目   | 这个月的账是否清楚、各业务花了多少         | 公司账目：导入、核对、月度汇总、导出给代账、备份 |
| 市场与用户 | 谁在关注、谁想试戴、谁在等回复、什么有效果 | 本文定义                                         |

- **公司首页**把三项功能里需要你处理的事项放在一起：账目待核对、发布卡住、有人等回复、试戴报名待筛选。每条都回到原功能处理。
- **市场与用户**取代原侧栏的“运营内容”。文章发布仍是其中一步，但页面围绕“人”组织，而不是围绕平台或文章。
- **账目与市场相连的地方只有花费。** 样机寄送、试戴物料、推广费用照常作为流水导入账目、人工确认，并归到“早期试戴招募”业务项目；市场页面只读取已确认金额，不另记一套费用。
- 发布、评论读取和回复的执行能力是全 Studio 共用的，日记项目或电子开发项目也能用；公司项目按业务把它们组织起来。

## 用户与阶段

**谁在用：** 正在做 AR 眼镜的创始人，几乎没有时间做市场，也不想成为营销专家。

**处在什么阶段：** 上市前。产品还在迭代，没有定价，没有现货。这个阶段的市场目标不是销售，而是：

1. **建立受众**：让关心智能眼镜、近视适配、轻量化硬件的人持续关注研发进展。
2. **招募早期试戴者**：例如 30 名愿意试戴并反馈的人，覆盖近视、长时间佩戴、户外使用等不同情况。

**这个阶段怎么算有效：**

| 指标                       | 说明                                                 |
| -------------------------- | ---------------------------------------------------- |
| 试戴报名、筛选与确认人数   | 主目标。报名表实际收到的人数，确认参加的人数         |
| 被感兴趣的人等待回复的时间 | 有试戴意向、购买询问、合作邀约的消息多久得到回应     |
| 有效对话来源               | 哪篇内容、哪个平台带来了报名和有效对话               |
| 反复出现的问题             | 例如“近视能不能用”，转为产品问题和下一篇内容的选题   |
| 关注者变化                 | 次要参考；只显示平台上实际读到的数，读不到写“未获取” |
| 每周花在市场上的时间       | 应该明显下降                                         |

## 用户真正要做的五件事

1. **不从白纸开始。** 研发日记、测试记录、设计取舍、解决掉的问题，本身就是素材。
2. **在受众所在的地方，用平台自己的形式出现。** 一个进展写成知乎长文、小红书图文和 B 站口播稿，不是同一段文字贴八次。
3. **不漏掉任何想要点什么的人。** 想试戴的人、问价格的人、想合作的人、报告问题的人。上市前漏掉一个试戴者，比少发一篇文章代价更大。
4. **回复得快、像自己、事实正确。** 用你的名义说错续航、价格或上市时间，比不回复更糟。
5. **知道什么有效。** 哪些主题和渠道带来了真实对话和报名；用户反复问什么，应该回到产品决策，而不只是下一篇内容。

## 理想的一周（AR 眼镜一代）

- **周一，有什么值得讲。** 助理从眼镜研发项目和日记里找出本周进展：铰链改为双轴并通过两万次开合测试；首轮 8 人试戴，3 人反馈鼻托压痕。它给出角度和适合的受众，例如“耐久测试 → 关心可靠性的技术读者 → 知乎长文”。你挑一个。
- **起草，每个平台一版，像你写的。** 草稿只使用研发资料和产品事实表里的内容。与事实表冲突的地方标出来，例如草稿写“续航约 4 小时”，事实表是“3.5 小时”。文末统一放试戴报名入口。
- **审阅与批准。** 你在一个地方看到每个平台版本、使用哪个账号、会发生什么（公开发布一篇）、事实核对结果，修改后按账号逐个批准。
- **发布并核验。** 助理用已登录的账号发布，只有在平台上读回公开全文和图片后才算“已发布”，然后给出链接。遇到扫码、验证码时停下来交给你。
- **每天，跟进感兴趣的人。** 已发布内容下的评论、私信和报名，按对方想要什么分好：试戴意向、购买询问、合作、问题反馈、其他。每个人显示从哪篇内容来、之前聊过什么。助理起草回复，你批准后发送。
- **试戴招募。** 报名的人按你的条件筛选（是否近视、使用场景、所在城市），你确认邀请名单，助理起草邀请；确认参加后转入试戴者名单，寄送样机的费用在账目里归到对应业务。
- **周五，什么有效。** 不是点赞数，而是：哪篇内容带来了几个报名，最常被问的三个问题是什么，哪些问题应该交给研发。

## 用户期望与产品承诺

| 用户期望（常常不说出口） | 产品承诺                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 真正省时间               | 一个页面代替八个浏览器标签；每周花费的时间可以看到并下降                                                   |
| 像我，不让我难堪         | 从我写过的内容学语气；不编造事实、价格、承诺或上市时间                                                     |
| 以我名义说的话由我控制   | 信任逐级放开、随时收回（见下节）；发出的每条内容都有记录                                                   |
| 不让账号被封             | 遵守平台规则，按人的节奏操作；不刷量、不群发、不制造虚假互动                                               |
| 不漏掉任何人             | 有试戴或购买意向的人立即出现在“需要我处理”；显示等待时长                                                   |
| 数字诚实                 | 只显示核验过的结果；读不到的写“未获取”，不写 0 也不估算                                                    |
| 用户的资料安全           | 对话、报名信息和联系方式只保存在本机，不进入 Git、诊断或项目共享配置；只收集招募需要的信息，报名时写明用途 |
| 几乎不用配置             | 账号登录一次即可；产品事实表可以从已有资料起草，再由我确认                                                 |

## 信任阶梯

每类动作、每个渠道单独设置，可以随时降级，所有动作可审计：

| 级别 | 含义                                 | 上市前的默认                                 |
| ---- | ------------------------------------ | -------------------------------------------- |
| 0    | 只起草，不在平台上做任何事           | 合作、媒体、投诉、价格与上市时间相关回复     |
| 1    | 我逐条批准后执行                     | 发布内容、回复评论和私信、发出试戴邀请       |
| 2    | 我批准一条规则，规则内的动作自动执行 | 可选：感谢类回复、事实表里已有答案的常见问题 |
| 3    | 在规则内自主执行，事后汇报           | 上市前不开放                                 |

这与 [ADR 0016](../decisions/0016-agent-web-account-execution.md) 一致：用户看到目标网站、账号、内容快照和预期结果后点击开始，就授权与快照一致的常规动作；验证码、扫码、风控、法律或版权声明、付款、批量或范围扩大、未知页面状态一律交给用户。第 2 级规则也不能越过这些卡点，并且每次公开发布仍需对具体账号和文章授权。

## 产品事实表

上市前最容易出错的是事实：续航、重量、近视适配范围、是否可以预订、试戴是否收费。公司项目里保留一份由用户确认的**产品事实表**：每条事实有内容、确认时间和来源（测试报告、设计文件）。

- 起草内容和回复只能引用事实表或研发资料；与事实表冲突、或事实表没有答案时，标为待确认。
- 事实更新后，列出引用过旧事实、尚未发布的草稿和待发送的回复。
- 已发布内容不自动修改；需要更正时由用户决定。

## 跟进感兴趣的人

“人”是这个功能的核心对象。每个人的记录从对话中自动形成，不需要手填表：

- 在哪个平台、哪篇内容下出现；说了什么；想要什么（试戴、购买、合作、反馈、其他）。
- 当前状态：新消息、已回复、已邀请试戴、已确认参加、不合适、已结束。
- 下一步和等待时长；同一个人在不同平台出现时，由用户确认是否合并，不按昵称猜测。

上市前最重要的去向是**试戴报名表**：内容和回复里都引导到同一个报名入口，报名结果进入同一份名单。筛选条件由用户设定，邀请名单由用户确认。

## 不做什么

- 不做群发、刷量、自动关注或虚假互动。
- 不做以点赞和浏览量为中心的数据面板。
- 不做需要手工录入的客户管理表单。
- 不做脱离研发事实的泛泛 AI 写作。
- 上市前不做自动回复（第 3 级）、广告投放、电商与订单。
- 不新建账号登录体系，不读取或保存平台密码、Cookie。

## 分阶段验证

每一阶段以用户在真实应用里能完成的动作为准；只有前一阶段在真实平台上通过，才进入下一阶段。

1. **从进展到一篇已发布的内容。** 从眼镜研发的一条真实进展起草知乎和小红书两版，事实表核对通过，逐账号批准，实际发布并核验公开结果，文末带试戴报名入口。大部分能力已经存在；需要用户对具体账号和文章授权。
2. **跟进已发布内容下的人。** 读取第一阶段那篇内容的评论，识别出想试戴和有疑问的人，起草回复，逐条批准后发送，并在平台上核验已发出。
3. **试戴招募闭环。** 报名进入名单，按条件筛选，确认邀请并发送，记录确认参加；样机寄送费用在账目中归到“早期试戴招募”。

## 待用户决定

1. **受众主要在哪两三个平台？** 当前设想以知乎（技术读者）和小红书（佩戴体验）为主，B 站作为口播补充。
2. **试戴报名表放在哪里？** 第三方问卷、公众号还是自有页面；它决定报名信息从哪里读取、存在哪里。
3. **试戴者的筛选条件和人数。** 例如 30 人，近视与非近视各半，覆盖通勤、办公、户外。
4. **谁可以代表公司回复？** 上市前是否只有你本人；“价格”“上市时间”这类问题的统一口径是什么。
5. **公开研发细节的边界。** 哪些进展可以讲，哪些（供应商、成本、未申请的专利）不能讲。

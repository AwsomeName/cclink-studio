# Markdown S 级所见即所得编辑器

> 状态：首轮实现完成，已完成自动化与真实应用集中验收。
> 适用格式：`.md`、`.markdown`。
> 关联文档：`docs/features/document-editor.md`、`docs/features/file-type-support.md`。

## 产品结论

Markdown S 级是：

**面向常用 Markdown 的单一所见即所得文档编辑器，加上安全保存和选区带行号发送给 Agent 会话。**

产品形态参考飞书文档：

- 用户始终在一个可视化文档界面中编辑。
- 不提供 Markdown 源码模式。
- 不提供 Frontmatter、Mermaid 或原始内容专用块。
- 只承诺支持本文明确列出的常用 Markdown。
- 检测到范围外语法时不进入编辑态、不改写草稿、不允许保存覆盖原文。

## 支持范围

首轮支持：

- H1-H6 标题和正文。
- 粗体、斜体、删除线和行内代码。
- 有序列表、无序列表、嵌套列表和任务列表。
- 引用、分隔线和围栏代码块。
- 围栏代码块的语言标识和语法高亮。
- 链接插入、修改和移除。
- 图片插入、替代文本、标题和地址。
- GFM 表格插入、增删行列和单元格编辑。
- 撤销、重做和常用 Markdown 快捷输入。

Mermaid 围栏代码只作为普通代码块显示，不渲染图表。

### 键盘交互

| 场景               | 快捷键                                           | 行为                                            |
| ------------------ | ------------------------------------------------ | ----------------------------------------------- |
| 保存               | `Cmd/Ctrl+S`                                     | 保存当前 Markdown；未命名文档进入另存为         |
| 撤销/重做          | `Cmd/Ctrl+Z`、`Cmd/Ctrl+Shift+Z`、`Cmd/Ctrl+Y`   | 撤销或重做编辑                                  |
| 粗体/斜体/删除线   | `Cmd/Ctrl+B`、`Cmd/Ctrl+I`、`Cmd/Ctrl+Shift+S/X` | 切换当前选区或后续输入的行内格式                |
| 行内代码           | `Cmd/Ctrl+E`                                     | 切换行内代码                                    |
| 链接               | `Cmd/Ctrl+K`                                     | 插入、修改或清除链接                            |
| 正文/标题          | `Cmd/Ctrl+Alt+0`、`Cmd/Ctrl+Alt+1...6`           | 切换正文或 H1-H6                                |
| 引用               | `Cmd/Ctrl+Shift+B`                               | 切换引用块                                      |
| 有序/无序/任务列表 | `Cmd/Ctrl+Shift+7/8/9`                           | 切换列表类型                                    |
| 正文缩进           | `Tab`、`Shift+Tab`                               | 按 `editorTabSize` 缩进或反缩进当前块/选中块    |
| 列表缩进           | `Tab`、`Shift+Tab` 或 `Cmd/Ctrl+]`、`Cmd/Ctrl+[` | 缩进或提升普通列表与任务列表项                  |
| 代码块             | `Cmd/Ctrl+Alt+C`                                 | 切换围栏代码块                                  |
| 代码缩进           | `Tab`、`Shift+Tab`                               | 按 `editorTabSize` 插入或移除空格，支持多行选区 |
| 表格导航           | `Tab`、`Shift+Tab`                               | 移到下一或上一单元格；末格继续前进时新增一行    |
| 硬换行             | `Shift+Enter`                                    | 在当前块内换行                                  |
| 任务框快捷输入     | `[] `、`[ ] `、`[x] `、`【】 `、`【x】 `         | 独立段落转换为未完成或已完成任务项              |

输入 `# `、`- `、`1. `、`> `、三个反引号等标准 Markdown 前缀后继续输入，
由 Tiptap 输入规则转换为对应结构。普通正文中的 `Tab` 写入标准 Markdown
前导空格，`Shift+Tab` 删除最多 `editorTabSize` 个前导空格；连续缩进达到四个
前导空格时，重新解析后会按 Markdown 规则成为缩进代码块。这是源码语义，不承诺
Word 式仅改变视觉位置的段落缩进。

### Tab 无动作回归（2026-08-08）

已确认当前实现存在回归：普通正文收到 `Tab` 后会调用列表缩进命令，但即使命令返回
失败仍把事件标记为已处理，导致内容没有变化、浏览器默认行为也被阻止。原单元测试与
工作流 smoke 错误地把“内容保持不变”作为通过条件，因此无法发现用户可见故障。

本次修复的真人验收动作：

1. 在普通正文或引用中的段落按 `Tab`，当前块出现由 `editorTabSize` 控制的前导缩进。
2. 按 `Shift+Tab`，最多移除一级前导缩进；光标仍留在编辑器。
3. 选中多个普通块后按 `Tab` / `Shift+Tab`，所有选中块一起缩进/反缩进，并且一次撤销可恢复。
4. 保存、关闭并重新打开文件，缩进仍按标准 Markdown 语义存在。
5. 列表继续嵌套/提升，代码块继续按设置宽度缩进，表格继续前后切换单元格。

完成条件不是“按键事件被捕获”或“测试为绿”，而是上述真实应用操作产生可见且可保存的
内容变化。自动化必须断言序列化后的 Markdown 和重新解析结果，不能再把普通正文无变化
写成预期行为。

修复状态：已修复。普通正文的真实键盘事件、撤销/重做和磁盘保存已由工作流 smoke 验证；
多块缩进/反缩进及 Markdown 序列化后重新解析已由真实 Tiptap 文档模型验证。标题没有独立
的 Markdown 缩进语义，不列入正文缩进承诺。

### 只读状态误触发保存回归（2026-08-13）

已确认 0.1.28 存在回归：Markdown 水合、往返保护或兼容性诊断切换编辑器的可编辑状态时，
直接调用 Tiptap `setEditable`。该 API 默认发送 `update`，现有 `onUpdate` 又把所有更新都
视为正文变化并重新序列化 Markdown，因此用户没有编辑也可能产生 dirty、保存提示或内存
草稿。往返保护仍会阻止有错误诊断的草稿写入磁盘，但不能把误触发的 dirty 当成可接受降级。

本次修复的用户验收动作：

1. 打开普通 Markdown，不输入、不点击格式工具，加载完成后保持“已保存”。
2. 文档在可编辑与只读保护之间切换时，正文、磁盘版本基线和 dirty 均不变化。
3. 打开往返检查失败的文档只进入只读预览，不用序列化结果生成未保存草稿。
4. 用户真实输入、删除、格式化或勾选任务项时仍正常产生 dirty，并可显式保存。

修复状态：已修复。所有可编辑状态切换统一禁止发送 Tiptap update；正文更新入口同时只接受
非水合阶段的 `docChanged` 事务。真实 Tiptap 回归验证状态切换不发送 update，逻辑回归覆盖
非正文事务、水合事务和真实正文事务。

### 任务框、层级编号与列表标题回归（2026-08-13）

已确认三个交互缺口：任务项虽然有工具栏入口，但 `[]` 加空格缺少稳定应用级快捷输入；有序
列表所有嵌套层都显示十进制编号，层级辨识度不足；Tiptap 默认要求列表项第一块必须是段落，
导致 CommonMark 合法写法 `1. ### 标题` 被降成普通文字并触发往返结构差异。

本次修复的用户验收动作：

1. 在独立空段落输入 `[]` / `[ ]` / `【】` 后按空格，出现未勾选任务框；`[x]` / `【x】`
   出现已勾选任务框。正文中的括号文本不转换。
2. 有序列表第二项按 `Tab` 后成为子层；一级显示十进制、二级显示小写字母、三级显示
   小写罗马数字，继续嵌套时三种样式循环。
3. 输入 H3 后创建有序列表，或打开 `1. ### 标题`，界面同时保留列表序号和 H3；保存、
   关闭、重开后结构不变。

编号样式只属于所见即所得视图；磁盘继续保存标准 Markdown 嵌套整数列表，不引入 `1.1.`、
字母或罗马数字列表方言。这样同一文档离开 CCLink Studio 后仍能被标准 Markdown 工具读取。

修复状态：已修复。任务框快捷输入由编辑器键盘扩展统一处理；列表项文档模型允许任意首个
块并在送入 Tiptap 前展开同一行列表标题；嵌套编号只通过编辑器 CSS 分层显示。自动化覆盖
任务标记、误触发边界、标题列表的交互转换、同一行源码打开及往返保存。

首轮不支持：

- Frontmatter。
- Mermaid 图表渲染和编辑。
- 原始 HTML。
- MDX/JSX。
- 数学公式的专用排版和公式编辑器。
- 脚注。
- Markdown directives 和其他方言扩展。
- Word 式字体、字号、颜色和分页。
- 图片裁剪、浮动环绕和任意像素定位。
- 高级表格公式、排序和合并单元格。

## 范围外文件

检测到可能破坏原文的范围外语法时：

1. 保留磁盘文件和工作台原始缓冲区。
2. 不创建替代内容块。
3. 不把范围外内容转换成普通正文。
4. 不进入可编辑状态。
5. 显示具体的不支持原因。
6. 禁止保存覆盖原文件。

范围外语法以后是否支持，按具体格式专项讨论，不预留半成品入口。

数学公式采用容错降级：当前不做专用公式渲染，而是按普通文本显示并允许编辑。公式送入 Tiptap 前，会对 `_`、`*`、`&`、`<`、`>` 等 Markdown/HTML 敏感标点添加仅供解析的临时转义，避免 TeX 下标被解释成强调、比较符被改成 HTML 实体；统一序列化出口负责撤销临时转义并解码解析器产生的实体。未修改的公式以当前磁盘/缓冲区内容为基线逐字保留，确实修改过的公式才按编辑结果写回，再将公式分隔符和内容纳入往返校验。完整保留时可以正常保存，只有解析结果丢失或改变公式语义时才进入只读保护并禁止覆盖原文件。公式之外的美元符号统一保存为转义文本，金额不会被误判为公式；代码块和行内代码不做改写。

## 本地图片

支持文件选择、拖入和剪贴板粘贴。

本地图片默认复制到：

```text
<Markdown 文件名>.assets/
```

规则：

- Markdown 文件和同级可见资源目录共同组成一个“Markdown 文档资源组”。
- Markdown 写入相对路径。
- 文件名冲突时自动改名，不覆盖现有图片。
- 网络图片保持原地址。
- 渲染进程通过安全 IPC 管理本地文件。
- 未命名文档插入本地图片前，先要求保存 Markdown。
- 旧版 `.assets/<Markdown 文件名>/` 在下一次保存、另存为或成组移动时安全迁移；迁移失败不得破坏原引用。

目录示例：

```text
工作空间/
├── 方案.md
└── 方案.assets/
    ├── manifest.json
    ├── 架构图.png
    └── 截图.jpg
```

Markdown 保持标准相对引用：

```markdown
![架构图](方案.assets/架构图.png)
```

## Markdown 文档资源组

### 磁盘格式

`.md` 是正文唯一事实源，必须能脱离 CCLink 被普通 Markdown 工具读取。资源目录及其中附件均为普通可见文件，不使用点号隐藏目录，不把编辑态正文封装进 `.mdpack`。

存在受管资源时，磁盘文件头可写入一条受控、不可见的依赖声明：

```markdown
<!-- cclink-document: {"version":1,"resources":"方案.assets/manifest.json"} -->
```

- 声明只用于资源完整性提示，不是打开正文的硬依赖。
- 所见即所得编辑器不显示也不编辑该声明。
- 编辑器保存声明占用的源码行偏移，选区发送和点击回跳仍使用磁盘文件的真实行号。
- 仅允许这一种受控注释；普通 HTML 仍属于不支持范围。
- 第三方工具删除声明后，CCLink 仍须通过 Markdown 相对引用检查缺失资源。

`manifest.json` 记录格式版本、所属 Markdown、资源相对路径、媒体类型、大小和 SHA-256。Markdown 正文不复制进 manifest，避免双事实源。

### 资源完整性

打开 Markdown 时检查：

- 声明的资源目录或 manifest 是否缺失、无效。
- Markdown 引用的本地资源是否存在。
- 本地引用是否仍位于同名受管资源目录；目录外引用会提示先收集资源，并阻止 ZIP 产生断链包。
- manifest 中资源的大小或 SHA-256 是否变化。
- 资源目录中是否存在未被正文引用的孤立文件。
- 是否仍在使用旧版隐藏资源目录。

缺失或变化只产生明确诊断，不阻止打开仍然安全的正文。用户可以定位资源目录、重新关联、替换、忽略或清理；第一版不得自动删除孤立资源。

资源完整性提示固定在编辑区底栏并默认折叠，不占用工具栏和正文顶部空间；展开后可查看详情并重新检查。

### 成组文件操作

在 CCLink 内执行另存为、复制、移动或重命名时：

- Markdown 与同名 `.assets` 目录作为一个逻辑资源组处理。
- 自动改写受管资源相对路径、依赖声明和 manifest。
- 不覆盖目标位置已有文件或资源目录。
- 操作失败时回滚，原文档和原资源必须仍可使用。
- 打开的编辑 Tab、草稿、Agent 挂载引用和文件树路径同步更新。
- 删除 Markdown 时询问“仅正文”或“正文和资源”，并移到系统废纸篓，不做不可恢复的静默删除。

在 Finder 或其他文件管理器中单独移动 `.md` 无法被 CCLink 阻止；重新打开时必须通过依赖声明和引用扫描提示缺失资源。

### 压缩与导出

日常编辑格式保持 `.md + .assets/` 透明结构。分享和归档时一键导出标准 ZIP：

```text
方案.zip
└── 方案/
    ├── 方案.md
    └── 方案.assets/
        ├── manifest.json
        └── ...
```

- ZIP 是导出物，不是编辑事实源。
- 解压后仍是普通 Markdown 和普通资源文件。
- 导出前检查缺失资源；有缺失时拒绝生成看似完整的压缩包。
- ZIP 条目必须使用相对路径，禁止路径穿越和符号链接。
- PNG、JPEG、WebP、音视频通常已压缩，ZIP 主要解决成组传输，不承诺显著减小体积。
- 图片重采样、格式转换和视频转码属于独立的“优化资源”功能，不在保存时静默执行。

## 保存与恢复

- `Cmd/Ctrl+S` 明确写入磁盘。
- 编辑过程只镜像工作台恢复草稿，不自动覆盖磁盘文件。
- 保存前比较文件版本或内容指纹。
- 外部修改冲突提供重新载入、查看差异、另存为和确认覆盖。
- 写入失败后保留正文和 dirty 状态。
- 磁盘写入采用临时文件和原子替换。
- 打开但未编辑文档不得产生 dirty。
- 解析或序列化结果异常缩减时必须阻止保存。
- 关键结构校验按 Markdown 语义比较，Setext/ATX 标题、引用式/行内链接等等价规范化不得误报。
- 缩进式与 fenced code、空语言与 plaintext 等代码块规范化按正文和有效语言比较；代码正文丢失仍须阻止保存。
- 自身保存产生的新版本指纹只更新版本基线，不得触发二次水合、隐藏编辑器或阻止重新打开。
- 往返校验失败时保留只读渲染结果和原始缓冲区；重新读取磁盘必须强制重新校验，不得只提示成功。
- 文件读取完成后必须经过显式水合状态才能展示编辑器；解析期间显示“正在渲染”，非空源文件不得静默落入空白可编辑状态。
- 解析或往返校验失败时生成当前 Tab 的脱敏诊断日志，错误界面可一键复制；日志记录版本、触发方式、重载次数、文件指纹、结构摘要、受节点预算约束的编辑器摘要和逐项差异。节点过多时记录省略数量，不能在 JSON 字符串中间截断。
- 诊断日志不得包含全文；用户主目录替换为 `~`，只有发生差异的代码内容允许保留最多 240 个字符的预览，并在日志中明确隐私提示。
- 保存包含受管资源的 Markdown 时同步刷新 manifest；manifest 可重建，正文仍是唯一事实源。

## 选区发送到会话

用户选中文档内容后，可通过浮动工具条或右键菜单执行“带行号发送给会话”。

片段包含：

```ts
interface MarkdownFileRangeRef {
  type: 'file-range'
  format: 'markdown'
  path?: string
  tabId: string
  startLine: number
  endLine: number
  startColumn: number
  endColumn: number
  selectedText: string
  sourceSnapshot: string
  snapshotHash: string
  dirty: boolean
}
```

行为：

- 片段进入当前会话输入区，但不自动发送。
- 一条消息可以附加多个片段。
- 消息发送成功后清除待发送片段。
- 已发送消息保留不可变快照。
- 点击片段可以回到文档并定位对应内容。
- 未保存文档使用当前内存内容和 `tabId` 定位。

限制：

- 单片段最多 200 行或 32KB。
- 单条消息的全部片段最多 64KB。
- 限制在界面、协议和主进程三层执行。

## 技术方案

```text
磁盘 Markdown
    ↓
支持范围检测
    ├── 范围外：保持原文，拒绝进入编辑态
    └── 范围内：进入文档解析
                 ↓
         Tiptap / ProseMirror
                 ↓
           所见即所得编辑
                 ↓
        Markdown 序列化与校验
                 ↓
        版本检查和原子保存
```

每个文档会话保存：

- 磁盘原文。
- 当前 Markdown。
- ProseMirror 文档。
- dirty 状态。
- 文件版本指纹。
- 解析和保存诊断。
- 选区到 Markdown 行号的映射。

源码行号映射是内部能力，不产生源码编辑界面。

## 数据安全红线

以下条件全部满足后，改动才能接入真实编辑器：

- 真实长文档打开后正文完整。
- 打开但不编辑不产生 dirty。
- 打开后立即保存不丢失语义内容。
- 范围外语法不进入编辑态。
- 解析异常不修改工作台草稿。

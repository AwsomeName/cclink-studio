# 上下文压缩失败与恢复

## 用户验收动作

在本地 Claude Code 会话遇到自动或手动压缩失败后：

1. 面板显示“上下文压缩失败”和已确认的原因，例如模型服务内容审核拒绝、上下文超限、认证失败、限流、网络或网关异常。未识别的原因明确显示未知，不推断具体敏感词。
2. 展开“原始错误”能看到服务或 Runtime 返回的信息；消息历史和完整诊断日志同时保留原因与分类。
3. 点击“保留旧会话，新建对话继续”，进入同一工作空间的新对话。旧会话及其消息、草稿、附件和队列保持原状，可以从会话列表返回。
4. 新对话保留角色、Runtime、Skill 引用和操作范围，使用新的会话 ID，不复用旧 Runtime Session，不复制历史、附件或待发送队列，不自动发送。用户补充简短背景后自行发送。
5. 运行仍未结束时，恢复按钮不可用；其他工作空间的事件和旧 run 的迟到事件不能改变当前对话。重启后已记录的压缩失败原因仍可查看。

## 边界与实现

- 主进程 `LocalClaudeCodeBackend` 从真实 SDK 结果、异常和压缩状态事件分类，通过既有 Agent IPC 携带错误码。自动压缩属于 message query，不能只根据 `operation=compact` 识别。
- `agent-store` 的既有 `contextCompaction` 是 renderer 中压缩状态的唯一投影；界面不解析日志来猜测原因。旧快照没有分类时显示通用压缩失败与原始错误。
- 新对话复用现有创建、切换、发送与持久化生命周期，不新增 Runtime、IPC 或权限接口。不会把“压缩失败”当成自动清除 Session 或自动重发任务的授权。
- 此入口不会修复模型服务审核、网络或凭证问题，也不保证新请求一定通过。手动重试原会话时仍使用原有 Session 校验与权限边界。
- 本轮不回写历史系统消息，也不从旧版本的纯文本错误中推断压缩状态。

## 验证

受影响单测覆盖主进程分类、自动和手动压缩、原始错误、会话隔离、迟到事件、恢复前后旧会话不变、无旧 Session 的新对话与快照恢复。

`node scripts/agent-compaction-recovery-smoke.mjs` 在隔离 Electron 中注入已分类失败，操作两种布局的真实恢复按钮、展开原始错误、检查新会话发送参数并返回旧会话。其模型 Runtime 为替身，只证明故障展示和恢复入口的 UI/工程门禁；不代表真实模型服务的 1301 错误已经消失。

2026-10-19 验证结果：`pnpm typecheck`、受影响文件 ESLint、10 个测试文件中的 197 项测试及上述 Electron smoke 均通过。故障注入现场已确认“查看原因 → 展开原始错误 → 新建对话 → 手动提交新消息 → 返回旧会话”；侧栏与中间布局均通过。新消息提交由捕获参数的 Runtime 替身接收，未请求真实模型服务，未执行打包发布。

## /grilling

结论：用户必须能理解失败发生在压缩请求，并自主选择新对话；旧记录和原操作范围必须保留。

仍需区分：服务端拒绝摘要不能被界面修复，新建对话也不能被表述为已恢复模型服务；没有携带旧历史的新会话需要用户补充背景。验证必须同时检查旧会话没有被改动，以及新发送没有偷偷复用旧 Session 或整段历史。

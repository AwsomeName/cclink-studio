# 文章发布中断与重启恢复逻辑

> 状态：目标产品事实源；当前代码只实现其中一部分，完成度以本文验收动作而不是状态字段或测试数量为准。
> 最后更新：2026-09-01。
> 适用范围：CCLink Studio 内置 CSDN 单篇文章发布。
> 上位约束：`docs/architecture.md`、`docs/features/article-platform-publishing.md`。
> 配套开发方案：`docs/features/article-publishing-restart-recovery-development-plan.md`。

## 1. 一句话结论

Studio 中断或重启后，不能依赖原编辑页地址继续发布。Studio 必须记住原平台草稿、正文、图片和
副作用进度，重新进入同一账号的草稿箱找回原草稿，核验网页中的真实内容，再从第一个未确认完成的
步骤继续。不能唯一确认原草稿或外部动作结果时必须停下让用户处理，不得猜稿、重传或重复发布。

## 2. 用户可执行的最终验收动作

1. 用户选择一篇包含三张本地图片的 Markdown，使用已保存的 CSDN 账号开始发布。
2. Studio 创建或打开一篇带稳定平台身份的 CSDN 草稿，填写正文并成功核验第一张图片。
3. 用户关闭 Browser Tab，并完全退出 Studio。
4. 测试环境使上次保存的编辑页 URL 不再可直接恢复，或让 Studio 从普通 CSDN 账号页启动。
5. 用户重启 Studio，从文章发布历史点击“从中断处继续”。
6. Studio 自动进入同一账号的草稿管理入口，找到并打开原草稿，而不是新建文章。
7. Studio 重新读取标题、正文和图片，确认第一张图片已经存在，因此不重复上传。
8. Studio 从第二张图片继续，完成第三张图片、草稿保存和发布。
9. 如果发布动作已经派发但连接中断，Studio 只查结果，不再次点击发布。
10. 如果草稿箱存在多篇无法唯一确认的相似草稿，Studio 显示候选并要求用户选择；选择前不启动
    Agent，不产生任何网页写入。

只有真实 Studio、真实 `WebContentsView`、真实 CSDN 完成以上动作，才能声明重启恢复闭环完成。

### 当前最小实现边界

当前工作区已实现安全的精确 ID 恢复主链：新恢复代次先进入 CSDN 文章管理/草稿入口，只在当前可见
草稿列表中找到唯一相同 `platformDraftId` 时打开；草稿箱和编辑器还必须读出同一个真实 CSDN 主页
账号标识。主进程随后生成“账号 + 草稿 ID + 标题 + 保留段落/换行/代码缩进的正文结构哈希 + 全部
图片 URL/字节哈希 + 已保存状态”完整快照。只有它与中断前持久快照完全一致，才签发绑定当前
Tab、WebContents、Playwright generation 和快照哈希的写入许可并启动 Agent。

恢复开始前，`BrowserTaskRuntime` 会先取得 main-owned 账号恢复租约，再创建/激活账号 Tab、进入草稿
箱和核验快照。普通 Agent 会从 `BrowserManager` 读取 Tab 的真实登记账号并竞争同一份账号租约，因此
找稿期间不能抢占同账号页面。核验成功后，main 在一个同步操作中同时写入 BrowserTask correlation 并
把同一租约 owner 从 recovery 改为精确 BrowserTask；不存在“先释放恢复锁、再让 Agent 抢锁”的窗口。
失败、超时和取消会释放尚未转交的租约；转交后的旧 release 不会释放 BrowserTask 的租约。该租约只
是当前主进程的运行时互斥事实，不另做持久状态；进程崩溃后没有存活 Agent，重启恢复仍由 WebAffair
持久 recovery generation 驱动。

恢复后每次网页写入前都会重新读取并比较完整快照；动作后只有再次确认同一草稿形成完整已保存
快照，才用比较交换方式续签许可。找不到、页面不支持、正文/图片冲突、账号不明、旧保存或图片
结果未知时会在 Agent 启动前停止，不会猜稿、新建、覆盖或重传。发布结果未知时当前只会在文章管理
页尝试寻找与原草稿 ID 相同的公开文章，并再次核验真实账号和标题；不再用同标题链接猜结果。但
“公开文章 ID 等于原草稿 ID”尚未在真实 CSDN 证明，因此该路径只能作为保守探测，不能单独证明发布
成功。

尚未实现候选草稿 UI、分页/虚拟列表枚举、模糊候选后的用户确认，也尚未完成真实 CSDN 三图重启
验收。当前完整快照还包含图片 URL；即使图片字节哈希相同，只要 CSDN 改写 URL，整体快照也会
fail-closed 停止，尚不能自动完成“平台转码/换 URL 后继续”。因此本节只是工程实现边界，不是产品
完成声明。

## 3. Studio 必须记住的不是 URL，而是草稿身份

原编辑页 URL 只是最近一次入口提示，不能作为唯一身份。每条发布 Attempt 必须持久化：

- Studio 侧身份：`affairId + attemptId + executionGeneration + launchOperationId`；
- 账号身份：网站、已保存账号/Profile 引用，以及页面读回的真实 CSDN 主页账号标识；不保存 Cookie、
  Token 或登录材料；
- 平台身份：平台草稿 ID、最后一次已知编辑 URL、适配器版本；
- 内容身份：规范化标题、保留段落/换行/代码缩进的正文结构哈希、最后一次已核验保存时间；
- 图片身份：完整枚举结果、顺序、alt、平台 URL、平台实际字节哈希和最后核验时间；
- 副作用身份：上传、保存和发布的 write-ahead 记录及其已派发、已核验、已否定或结果未知状态；
- 恢复状态：正在定位、等待用户选稿、正在核验、已恢复、未找到或页面不支持。

正文全文和账号凭证不得复制进诊断或第二份状态库。WebAffair 继续是上述业务事实的唯一持久所有者。

## 4. 恢复流程

```text
读取未完成 Attempt
  → 校验本地 Markdown、图片、账号和适配器版本
  → 停止/归并旧 Agent、BrowserTask 和 CDP owner
  → main 在账号级取得 recovery lease
  → 尝试恢复上次绑定的可见 Browser Tab
  → 尝试最近一次已知编辑入口
  → 失败则进入同账号草稿管理入口
  → 列出并定位原草稿
  → 打开候选草稿并只读核验
  → 真实账号、草稿 ID、正文结构、全部图片和已保存状态与持久快照完全一致
  → 持久化新的 Tab/CDP/草稿入口、完整快照和恢复许可
  → 创建新 generation 的 BrowserTask，并把 recovery lease 原子转交给它
  → 完成 Runtime 持久绑定后才让 Agent 获得网页工具
  → 对账正文、图片、保存和发布状态
  → 从第一个未确认完成的检查点继续
```

网页恢复和只读核验必须发生在新 Agent 获得写工具之前。找稿失败时不得先启动 Agent 再让模型自行
搜索。

## 5. 如何从草稿箱找到原草稿

### 5.1 自动匹配

只有同时满足以下条件时可以自动选择：

1. 当前是原发布账号；
2. 草稿列表或打开后的编辑器提供与持久记录完全相同的平台草稿 ID；
3. 打开后适配器确认页面是受支持的编辑器；
4. 真实平台账号、标题、正文结构、全部图片和保存状态与最后持久快照完全一致。

编辑入口路径、查询参数或管理入口变化不影响平台草稿 ID 的身份地位。适配器负责从当前版本页面
提取 ID，公共状态不能把某一条固定 URL 形态当成永久协议。

### 5.2 必须让用户选择

下列情况不得自动选择：

- 草稿列表不暴露稳定平台 ID；
- 只有标题相同或更新时间接近；
- 存在多篇标题、正文或图片相同的草稿；
- 只能通过模糊文本或 DOM 顺序推测；
- 草稿内容被人工修改，无法证明仍是原发布对象。

Studio 可以只读打开有限数量的候选并计算标题、正文和图片指纹，帮助用户判断，但这些指纹只能缩小
候选范围。没有稳定平台 ID 时，最终绑定需要用户明确选择。

### 5.3 未找到与已删除

如果草稿不存在、已删除、账号不符、草稿箱无法访问或页面版本不支持，Attempt 进入可恢复的
`waiting-human`，保留本地文章、图片进度、旧平台证据和诊断。不得静默创建新草稿。

## 6. 正文核验规则

打开候选草稿后，适配器必须重新读取：

- 平台草稿 ID；
- 标题；
- 规范化正文文本或结构哈希；
- 当前正文图片列表；
- 草稿保存状态；
- 当前账号与页面类型。

处理规则：

- 草稿 ID 一致、正文与最后一次平台读回一致：保留已完成正文步骤；
- 草稿 ID 一致、正文为空且之前没有确认过正文写入：允许从填写正文继续；
- 草稿 ID 一致、正文被人工修改：暂停并提示用户选择“保留网页内容”或“停止恢复”；首版不自动覆盖；
- 草稿 ID 不一致：立即停止，拒绝任何填写、上传、保存和发布动作。

正文结构序列化只统一 CRLF/LF，不折叠普通空白；段落边界、换行和 `pre` 代码缩进都会进入哈希。
本地 Markdown 哈希用于证明用户输入是否变化；平台正文结构哈希用于证明网页草稿是否还是上次
看到的内容。两者职责不同，不能互相替代。

## 7. 图片核验与防重复

每张本地图片独立对账：

1. 优先检查编辑器中是否仍引用已保存的平台 URL 或稳定平台资源身份；
2. URL 变化时，比较上次保存的平台图片内容哈希与当前平台图片内容哈希；
3. 本地图片哈希只证明输入文件，不能假定平台没有压缩、转码或重新编码；
4. 图片位置、alt 和出现顺序只能作为候选线索，不能单独证明是同一资源；
5. 只有适配器完整枚举编辑器图片且能证明目标不存在时，才可否定旧上传结果并重新上传；
6. 枚举不完整、图片无法下载或证据冲突时进入 `waiting-human/result-unknown`，不得重复上传。

恢复结果：

- 已确认存在：标记旧副作用为 `verified`，图片保持 `uploaded`；
- 已确认不存在：旧副作用标记 `rejected`，新 generation 可以创建新的上传副作用；
- 无法确认：保持 `reconciling/result-unknown`，停止自动执行。

## 8. 保存草稿与发布恢复

保存草稿不能只相信按钮返回或页面出现一次“保存成功”。完成 `save-draft` 前必须再次读取真实账号、
平台草稿身份、标题、正文结构哈希、全部图片字节哈希和明确的 `saved` 状态，并把完整快照与副作用
记录及下一次写入许可关联。

发布恢复采用严格的一次性语义：

- 尚未派发发布动作：核验草稿后可以继续正常发布；
- 发布已派发并明确失败且平台证明没有生成文章：用户确认后才允许新动作；
- 发布已派发但连接中断：只允许打开文章管理或公开页面核验结果；
- 查到唯一公开文章：记录公开 URL 并完成 Attempt；
- 无法确认：保持 `result-unknown`，不得第二次点击发布。

## 9. 用户界面状态

文章发布 Tab 至少显示：

- 正在恢复原网页现场；
- 正在进入草稿箱；
- 正在查找草稿；
- 找到原草稿，正在核验内容；
- 需要用户选择候选草稿；
- 原草稿未找到；
- 页面版本不支持，需要人工处理；
- 已恢复，将从第 N 个检查点继续。

候选选择界面只展示安全摘要，例如平台草稿 ID、标题、最后修改时间、正文摘要哈希是否匹配和图片
数量。选择行为必须作为用户命令交给 main，由 WebAffair 持久化；renderer 不能直接改草稿绑定。

## 10. 安全不变式

- 一个 Attempt 永远只绑定一篇平台草稿；恢复可以更新入口 URL，不能偷偷更换平台草稿 ID。
- 恢复核验完成前，不创建可执行网页写入的 Agent Run。
- 不按标题自动选稿，不让 Agent 猜草稿，不静默新建文章。
- 已验证图片不重复上传；未知图片先对账。
- 发布结果未知时只读核验，不重复点击发布。
- 页面、账号、Tab、Attempt、generation 或 CDP owner 任一不一致时 fail-closed。
- 找稿和核验期间，同一登记账号只能由 main recovery lease 占有；核验成功后只能原子转交给精确
  BrowserTask，普通 Agent、旧 generation 和过期 release 都不能绕过。
- 草稿箱和编辑器适配器版本未知时转人工，不退回通用 selector 猜测。
- 所有恢复状态、用户选择和平台证据都进入原 WebAffair；不得创建第二状态所有者。

## 11. 明确不保证的事情

第三方平台可能不再暴露稳定草稿 ID，也可能删除草稿、要求验证码、改变编辑器或阻止图片读取。
Studio 能保证的是不串稿、不盲目重传、不重复发布，并在证据不足时安全停下；不能保证任何 CSDN
页面版本下都能全自动恢复。

当前实现还不能保证图片只换 URL、内容未变时自动继续，也不能保证 CSDN 的公开文章 ID 与原草稿 ID
相同。这两项必须以真实平台证据修正 Adapter 和快照比较规则，不能靠放宽 fail-closed 门禁猜测。

## 12. 完成门禁

- 真实三图文章在第一张核验后退出，重启后从第二张继续；
- 关闭原 Browser Tab、旧编辑 URL 无效时，自动进入草稿箱并恢复同一草稿 ID；
- 同标题双草稿不会被自动选错；
- 草稿被人工修改时不自动覆盖；
- 平台转码图片仍能依靠平台侧指纹识别，无法识别时不重传；
- 发布点击后断线只执行核验，不产生第二次发布；
- 重启前后始终是同一 Affair/Attempt，只有 execution generation 和运行时 owner 更新；
- 诊断可以重建账号引用、草稿 ID、候选决策、内容快照、图片对账和副作用窗口，但不泄露正文全文或凭证。

# 文章发布中断恢复规则

状态：当前事实源
日期：2026-09-01

## 用户要得到的结果

Studio 或发布 Agent 中断后，用户再次点击“从中断处继续”，Studio 必须回到原 CSDN 账号的草稿箱，找到原草稿，再从未完成步骤继续。旧网页地址失效不能导致新建文章、串稿或重复发布。

## 唯一状态源

只使用 `WebAffair.articlePublishing`：

- `source`：Markdown 路径、大小、修改时间；
- `draft`：CSDN 账号、草稿 ID、当前 URL、标题；
- `assets`：每张图片的资产 ID、来源路径、出现位置、上传状态、平台 URL；
- `checkpoints`：每个发布步骤的真实状态；
- `sideEffects`：上传、保存、发布是否已预留、已派发、结果未知或已确认；
- `execution`：Attempt、执行代次和 Runtime 绑定。

文章发布不保存、不比较任何正文或图片内容指纹，也不建立第二套内容真相。

## 状态是什么意思

- `pending`：还没有执行；
- `running` / `dispatched`：动作已经开始或已经发给网页，但结果尚未确认；
- `uploaded` / `completed` / `published`：已经从真实网页读回结果，或由用户在可见网页中明确确认；
- `result-unknown`：动作可能成功，也可能失败，禁止直接重放；
- `reconciling`：重启后只核对这个未决步骤。

已经确认完成的步骤不因网页 URL、图片 CDN URL 或 Studio 重启而倒退。

## 恢复流程

1. main 进程先取得该账号的 recovery lease，恢复期间其他 Agent 不能使用这个账号写网页。
2. 打开 CSDN 文章管理页并进入草稿箱，不依赖旧编辑页 URL。
3. 核验当前登录的 CSDN 账号与任务记录一致。
4. 用持久化的 `platformDraftId` 找原草稿；找不到就停止，不新建文章。
5. 打开候选草稿，核验草稿 ID、账号、标题和“已保存”状态。
6. 将当前 URL 写回任务，签发只绑定当前执行代次、Tab、WebContents 和 Playwright Page 的写入许可。
7. recovery lease 原子转交给新的 BrowserTask，然后才启动 Agent。
8. Agent 跳过已完成步骤，只处理第一个未完成或结果未知步骤。

标题只用于二次核验和“发布结果未知”的公开文章查找，不代替草稿 ID。多个同名候选必须停下来让用户选择。

## 图片 URL 变化

CSDN 可能换 CDN URL。这不代表图片内容变了，也不应让已完成图片退回未完成：

- 图片状态已经是 `uploaded`：继续认为完成，不重新检查 URL；
- 图片上传结果是 `result-unknown`：Studio 停下来，让用户在可见编辑器中看这张图片；
- 用户只选择“网页里有这张图”或“网页里没有，重新上传”，不填写图片地址；
- 选择“有”后记为 `uploaded`；选择“没有”后允许下一次恢复重新上传。

## 发布结果未知

禁止再次点击发布。Studio进入文章管理页，用原账号和精确标题查公开文章：

- 唯一匹配且公开页账号、标题一致：记为已发布；
- 没找到：保持结果未知；
- 多个同名结果：交给用户选择。

不能假设公开文章 ID 等于草稿 ID。

## 旧数据处理

Schema v7 是新起点。v1-v6 中的文章发布事务不迁移，加载时从主文件、备份和旧恢复日志中删除；其他 WebAffair 保留。用户需要用当前版本重新创建文章发布任务。

## 失败原则

账号不符、草稿 ID 不符、标题不符、页面未保存、Runtime 身份变化、未决副作用未核验或页面结构不受支持时，一律停止自动写入并说明原因。停止时不得新建文章、切换草稿或重复发布。

# 默认工作空间与业务数据归属设计

> 日期：2026-11-03。
> 状态：用户已确认“默认工作空间与工作空间内统一资料目录”的方向；以下详细设计尚未实现。
> 实施顺序：[默认工作空间与数据迁移实施计划](default-workspace-data-development-plan.md)。
> 验收：[默认工作空间与业务数据验收](../testing/default-workspace-data-acceptance.md)。
> 长期取舍：[ADR 0020](../decisions/0020-default-workspace-data-boundary.md)，状态为 proposed。

## 产品结论

Studio 首次启动即提供可写的默认本地工作空间。公司、账目、运营材料、网页事务和定时任务定义围绕该工作空间保存；用户也可以打开其他普通本地目录。默认工作空间是普通工作空间的默认选择，不新增 Workspace 类型、公司登录或业务运行时。

资料目录解决归属、查找和备份问题。网站账号继续全局复用，登录态和本机执行授权保留在设备上。目录集中不意味着所有模块合并数据库，也不意味着复制目录就获得原账号、原运行或发布权限。

现有普通工作空间保持原位置；升级不会把它们搬入默认目录。公司视图按需启用，个人工作空间不必先建立公司。现有公司 AI 工作、经营决策和文章发布的未完成验收仍按各自产品文档推进，本设计不扩大其完成声明。

## 用户端到端验收目标

以下动作先定义产品目标，工程任务再按这些动作拆分。

1. 在新的本地用户环境启动 Studio，不登录、不先选择文件夹，即可看到默认工作空间及实际保存位置；创建 Markdown，重启后仍能打开。
2. 在该空间启用公司视图，创建业务项目，导入一个实际月份的账目并人工确认，关联一份运营原稿和已有发布事务；这些入口显示相同工作空间归属。
3. 创建一个仅读取所选资料并生成 Markdown 的定时任务，显式启用，在真实 App 中看到一次运行及产物；切换其他工作空间时列表隔离，原任务仍按既有规则运行。
4. 切回并重启，公司、账目、稿件、发布历史与任务定义保留；中断和未知结果如实显示，不自动重发。
5. 升级含旧数据的环境，打开原工作空间，看到同一公司、账目、事务及关联；查看迁移结果，能定位仍待处理的旧记录。
6. 创建工作空间备份，恢复到新目录，打开同一月份账目、原稿、历史证据和任务定义；新副本没有自动执行、登录态或敏感动作授权。
7. 同机移动工作空间时身份延续；原目录仍在时复制为新工作空间，身份分离，原目录的数据与运行不受影响。
8. 默认目录不可用、某个库损坏或远程服务离线时，Studio 仍能进入可用工作台，显示受影响范围与恢复入口。

逐项证据、前置条件和通过标准见验收文档。存储恢复、发布步骤可观测性、实际提交与平台核验是三组独立结果。

## 工作空间概念和默认入口

### 默认目录

默认候选为当前用户主目录下的 `CCLink Studio/默认工作空间/`，由主进程取得平台主目录并拼接，不硬编码 `/Users/apple`，不依赖源码目录、桌面目录或其他仓库。沿用现有受支持的本地路径边界，本轮不扩展任意外置盘、网络盘或远程路径权限。

创建成功后在既有本地工作空间索引登记实际路径及已有基础层生成的稳定 ID，再保存默认路径设置；索引只作定位，不是第二身份源。目录改名或被移动时，不能仅按默认名字认回。路径已被其他资料占用且未被 Studio 登记为默认空间时，不自动接管；展示冲突并提供另选目录或创建不冲突新目录的操作。

首次只初始化工作空间身份及必要状态。资料、运营、账目和任务子目录在第一次保存时创建，不生成演示公司、示例流水、假任务或假发布记录。

### 启动优先级

| 情况                                     | 启动行为                                                                               |
| ---------------------------------------- | -------------------------------------------------------------------------------------- |
| 显式打开文件夹或已有远程工作空间恢复意图 | 先处理原入口，不能被默认目录覆盖；远程失败保持既有独立降级                             |
| 上次明确使用本地空间，目录有效           | 恢复该空间及其现场                                                                     |
| 用户明确选择未归档                       | 恢复 global；进入 Home 不等于切换 global                                               |
| 首次安装，没有历史选择                   | 创建并打开默认空间                                                                     |
| 升级时没有上次空间，但有 global 历史     | 提供默认空间并提示可查看未归档；旧草稿与会话仍在原归属                                 |
| 上次目录或已登记默认目录失效             | 进入可用的 Home/global，展示“定位原目录／打开其他空间／新建空间”；不静默重建同名空目录 |
| 默认目录创建失败                         | 本次进入 Home/global；说明权限、冲突或空间不足，允许重试和另选目录，不循环重试阻断启动 |
| 身份或现场损坏                           | 沿用现有备份恢复和禁止空状态覆盖的规则；不能当作首次启动                               |

“首次创建默认空间”是一次本地初始化，不登录、不自动启动 Agent、不触发定时运行或远程连接。设置默认路径、选择当前工作空间和物理移动数据是三个不同动作。

### 设置和身份所有权

设置拟增加 `defaultWorkspacePath` 和 `startupWorkspaceTarget`，后者为 `resume`、`default`、`unfiled`。旧配置缺字段时只执行一次兼容推导：已有有效历史选择优先恢复，否则使用默认入口；失败与用户主动未归档不能混为一类。具体迁移由共享 schema 校验。

选择具体本地空间记录 `resume`，选择默认入口记录 `default`，主动进入未归档记录 `unfiled`；Home Tab 不改变该记录。`lastWorkspacePath` 沿用既有定位用途。远程选择继续由原统一入口和恢复链路管理，不把远程路径塞入本地设置。以上只是启动选择，当前活跃工作空间仍由原 Workspace transition 和基础层拥有。

默认空间管理并入 `WorkspaceStateService` 及现有设置服务，不新增平行 WorkspaceManager。新接口使用 workspace 命名；现有 `getLocalProjectId` 和 `project.json` 仅作为兼容实现复用。本轮不把身份文件改名作为前置工作，也不创建第二份身份清单。未来 `workspace.json` 迁移必须单独双读、单写并验证回退。

## 数据归属和保存边界

稳定工作空间身份来自基础层，不能拿路径哈希、当前用户的现场 key、公司 ID 或账号 ID 代替它。

| 数据                                         | 唯一所有者                                    | 权威保存位置                                                      | 复制及跨设备恢复                                   |
| -------------------------------------------- | --------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------- |
| 身份与工作台现场                             | WorkspaceStateService；各现场分区仍按原 owner | 空间内身份文件及 `state/`；中央仅索引/global/fallback             | 移动沿用；副本新身份，默认不继承活跃现场           |
| 公司配置、业务和资料关联                     | CompanyWorkspaceService                       | `.cclink-studio/company-workspace/`                               | 保存业务事实，校验并重绑新空间身份与引用           |
| 财务账户、流水、分类、人工确认及原件         | CompanyAccountsService                        | `.cclink-studio/company-accounts/`                                | 按原账目备份恢复；历史确认记录保持来源             |
| 原稿、图片和生成文件                         | 文件服务及原产物领域                          | 用户选择的空间内公开目录                                          | 实际文件随备份携带；外部引用单列缺口               |
| 事务、流程、Attempt、证据和发布结果          | WebAffairService                              | 目标为 `.cclink-studio/web-affairs/`                              | 证据可保留为历史；运行绑定与旧提交授权不能复用     |
| 网站、业务主体、账号、运营矩阵、Profile 绑定 | WebResourceService                            | 本机 `userData/web-resources/`                                    | 不按空间复制；恢复时显式重新选择本机账号           |
| Cookie、Session 和网页现场                   | BrowserManager                                | 原本机 Profile/Session 分区                                       | 不进入工作空间备份，不通过复制 Cookie 恢复         |
| 密码、API Key、CCLink Session                | CredentialService／原 CCLink Session owner    | 原本机受限文件；按既有内存边界保存                                | 不进入工作空间、备份包、普通诊断或 Git             |
| 任务定义及产物                               | ScheduledTaskService／文件服务                | 既有 `scheduled-tasks/`、`shared/scheduled-tasks/` 及用户产物目录 | 定义与产物可携带，副本和新设备默认停用             |
| 任务启用、确认摘要、队列及去重运行账本       | ScheduledTaskService                          | 原本机 `userData/scheduled-tasks/`                                | 不作为可继承授权；历史可以只读导出，不回灌调度账本 |
| 最近空间、默认路径、迁移定位与脱敏诊断       | 对应基础层／领域服务                          | `userData` 的有界索引                                             | 定位信息可重建，不作为业务状态副本                 |

“账户”在财务界面指账本里的支付或银行账户，在网站界面指全局网站账号，两者不能共用对象或迁移规则。公司与运营视图查询原服务；不复制账目确认、发布终态或定时运行状态。

首版保留任务本机运行历史的位置及既有保留上限，备份可附只读导出。新设备的任务 Tab 显示“本机尚无运行记录”，并可打开已导出的历史文件；不能宣称所有历史已经转成目录内权威数据。若后续需要跨设备浏览完整历史，应单独设计，不能为目录统一引入第二个调度账本。

## 目标目录

```text
<工作空间>/
├── 资料/                                  # 新资料的建议位置，按需创建
├── 运营/
│   ├── 原稿/                              # 新建稿件的默认位置，可修改
│   └── 图片/
├── 产物/                                  # 任务可选择的输出位置
└── .cclink-studio/
    ├── project.json                       # 当前兼容身份文件，唯一身份源
    ├── state/<owner-hash>.json
    ├── company-workspace/company.sqlite
    ├── company-accounts/
    │   ├── accounts.sqlite
    │   └── documents/
    ├── web-affairs/                        # 目标新增，事务仍由原 owner 写入
    │   ├── storage.json                    # 格式与迁移来源，不保存第二套业务状态
    │   ├── web-affairs.json
    │   └── 既有格式的备份与恢复日志
    ├── scheduled-tasks/<task-id>.json
    └── shared/scheduled-tasks/<task-id>.json
```

旧 `docs/`、`promotion/` 或其他用户选择目录继续原位使用；新默认位置只影响以后新建，不能批量重命名旧稿件或改写 Markdown 正文。内部目录不在普通文件树默认展开，可通过现有工作空间命令查看保存位置。

内部数据延续现有 Git 策略：`.cclink-studio` 默认排除，仅合法的显式共享任务定义开放；检查暂存区和待推送历史。公开资料是否提交由用户决定，创建默认空间不初始化 Git、不提交、不 Push。工作空间备份必须包含选定内部业务文件，不能把 Git 备份当完整资料备份。

## 公司与运营界面

公司、账目、运营发布和定时任务页展示当前工作空间名；迁移、备份与恢复页再展示实际路径。普通业务页面不展示内部 journal 或数据库细节。可恢复问题显示用户能理解的原因及允许动作。

公司入口继续复用已有经营导航。原稿和发布事务关联均指向原对象，点击打开同一 Tab；存储迁移不创建另一套公司发布表单。账号入口明确标注“本机全局”，切换工作空间仍显示同一账号集合。

原发布执行链路继续覆盖准备、账号与原稿核验、正文与逐图处理、平台字段、保存、提交及平台结果核验。每个可执行小步骤呈现执行者、进入条件、实际状态、完成证据、等待或失败原因及允许下一步，均来自 WebAffair 的真实事件。本次存储迁移不得把步骤重置为成功，不新增完整 operation 账本、claim/report MCP、短 Run 调度或公司 orchestrator。

迁移前正在执行的事务先由原 owner 有界收束；不能安全收束时显示“等待当前运行结束”并延后迁移，原事务仍走既有链路。切换工作空间不取消原后台任务；迁移或显式移动的维护窗口仅限制受影响空间，不冻结全部 App。

## 旧数据迁移原则

按“原位保留、精确归属、双读兼容、单写权威位置、验证后切换、保留回退材料”执行。默认空间创建不顺带重写全机数据。

| 旧数据                                       | 处理                                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------------------- |
| 已有本地空间、公司库、账目库、任务定义与文件 | 原位读取；仅对确有 schema 变化的字段迁移，不为了目录外观搬家                           |
| global 草稿与会话                            | 保留未归档归属，不自动并入默认空间；本轮不新增批量归档迁移                             |
| 中央事务中有可信稳定空间 ID 的记录           | 首次打开或显式准备该空间时，由 WebAffairService 迁入该空间的独立分区                   |
| 无归属、旧路径失效或身份冲突的事务           | 原源保留，展示待处理；用户定位并核验归属后才迁移，不按标题或当前页面猜测               |
| 网站账号库及其历史 v2 数据                   | 复用已有全局迁移路径，保持账号和 Profile ID；不因创建默认空间再迁一遍                  |
| `cclink-accounts.json` 和受控旧文件路径      | 保留既有兼容读取；发现尚未登记项时提示使用原账号导入路径，不自动创建重复账号或合并身份 |
| 任务启用与运行历史                           | 升级且空间身份、路径和定义均不变时沿用；复制、导入、移动后的授权规则分别处理           |

事务迁移必须读取主文件、有效备份及有效恢复日志收敛后的快照，不直接复制某个旧 JSON。事务 ID、业务关联、Attempt、流程版本、证据和历史时间保持一致；任何材料缺失单独报告，不能把空结果当作迁移成功。

详细提交点、断电恢复、冲突处理和版本回退见实施计划。迁移摘要至少区分“已完成”“等待运行结束”“需定位原空间”“源损坏”“目标不可写”“版本不支持”；单项失败不隐藏其他资料。

## 移动与复制

| 动作                         | 身份及资料                                                               | 执行和授权                                                                   |
| ---------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| 同机移动，确认原空间不再使用 | 保留稳定 ID；内部相对路径重定位，绝对旧引用逐项核验；更新索引与默认指针  | 先收束运行；移动后重新确认任务路径和定义再启用；发布只恢复观察，不能自动重发 |
| 原目录仍存在，复制为新空间   | 新稳定 ID；公司库重绑；原业务和账目作为副本保留来源                      | 不继承 Tab/Terminal/Agent 现场、任务启用、等待定时器或发布授权               |
| 同机恢复为原空间             | 必须确认唯一身份与明确替换目标；先备份当前数据，不能自动合并两条写入历史 | 运行一律不恢复；定义、材料和账号重新核验后再执行                             |
| 跨设备恢复或恢复为新空间     | 默认新身份；账号 ID 只是来源引用，必须显式选择本机账号                   | 不复制本地身份、凭证、Profile、权限或去重账本；不自动补跑历史任务            |

副本保留财务确认的历史含义，不产生新的付款、记账确认或外部提交。公司业务和账目在新的空间作用域内保留各自 ID；全局查询的事务分配新 ID 并重建公司关联。原事务的 Attempt、提交回执及运行来源作为只读导入历史保存，仅保留证据所需的稳定来源引用，剔除临时执行凭据、Runtime session 和可执行句柄；可继续工作的未完成事务另建草稿，不把旧 Runtime binding 当成活连接。导入历史仍由 WebAffairService 查询并明确标为历史，不能混入可执行 Attempt 列表。

无法证明是原空间移动，或同一身份有两个可写目录时，暂停相关业务写入并要求定位或以副本打开。跨设备受控恢复默认创建副本；没有本机可信定位信息的既有目录不能仅凭“旧路径不存在”自动认作同机移动，应先恢复定位信息或由用户明确选择继续原空间／创建副本。不得自动全盘搜索、合并公司库或按目录名字判定身份。

## 备份与恢复范围

备份面向选定工作空间，包含身份来源、公司库、账目库及原件、事务与证据、任务定义、选定材料与产物，并可附选定本机任务运行历史的只读导出。用户预览文件数量、大小、外部引用缺口、未包含项目及敏感业务资料范围，明确触发导出；不读取密码或浏览器登录态。

各领域在自己的写队列内提供一致快照或既有备份。备份清单记录各自 revision、schema、取得时间、文件摘要和覆盖范围；聚合后核验跨域引用。不能把分别取得的 SQLite 和 JSON 快照宣称为跨数据库原子快照。

备份输出必须位于被备份目录之外，避免递归自包含。外部关联材料只列缺口；需要携带时由用户选定并复制进包内，不遍历整个主目录。丢失材料可生成明确的部分备份，但不能标“完整备份可恢复”；核心库损坏、引用冲突或不支持版本时停止完整备份。

恢复先在隔离目录验证版本、大小、路径、摘要及数据库，再预览目标身份、冲突和遗漏；明确选择“恢复原空间”或“创建副本”。未知 schema、路径穿越、符号链接越界和摘要错误均在替换前拒绝。恢复完成后通过各领域原入口打开验证，不能只靠备份清单数量判断成功。

## 权限与生命周期

所有创建、读写、迁移和恢复都经主进程有界 contract；校验可信 sender、当前授权目录、规范路径、稳定身份、对象归属与预期版本。默认路径只授权精确的初始化目标，不扩大至整个主目录；Agent 不因默认目录存在而得到额外读写范围。新能力只提供原领域的有界业务命令，不新增直接编辑数据库的 Agent 接口；普通本地 Agent 沿用既有权限边界。

不新增工作空间类型或第二条恢复链路。服务启动、窗口重建和退出复用原运行时注册表；切换使用既有 generation 守卫。后台事务按所属空间持有原绑定，不按 renderer 当前路径回写。停机依原顺序停止定时器和执行，flush 写队列并释放所有句柄。

迁移用的有界提交记录只描述文件搬迁与版本切换，不是业务 operation 账本。所有业务状态继续由原服务写入，UI 只呈现真实结果。CCLink 远程、云服务、独立 Agent runtime、系统计划任务和系统钥匙串均不在变更范围。

## 失败降级和诊断

| 故障                     | 产品行为与下一步                                                     |
| ------------------------ | -------------------------------------------------------------------- |
| 默认目录丢失或创建失败   | Home/global 仍可用；定位、重试、另选或显式新建                       |
| 公司或账目库损坏         | 原文件保留，对应模块只读或不可用；从已校验备份恢复，其他模块继续     |
| 事务分区不可读或迁移冲突 | 该分区停止写入和外部执行；保留未知结果，查看诊断或恢复；其他空间继续 |
| 账号缺失、归档或不匹配   | 稿件与历史可看，执行暂停；用户显式选择并核验账号                     |
| 输出目录不可写、空间不足 | 保存失败保留原文件，任务不伪报成功；另选输出或释放空间               |
| 移动或复制中断           | 根据已落盘阶段继续或清理临时目标；不同时开放两个权威写入位置         |

诊断记录脱敏空间标识、领域、格式版本、迁移阶段、revision、失败类别及允许恢复动作；不包含账号正文、金额明细、密码、Token、Cookie、稿件正文或原件。用户界面可按授权显示路径，普通日志与分享诊断默认脱敏。

## 设计拷问

结论：默认入口可以先形成用户增量；事务目录化和可迁移性必须另有真实数据验收，不能被入口完成掩盖。

| 拷问                       | 本方案的决定及尚需证明的边界                                                       |
| -------------------------- | ---------------------------------------------------------------------------------- |
| 是否只是把文件放到一起     | 必须同时验收归属提示、切换隔离、重启和原记录下钻；仅路径调整不算完成               |
| 为什么不把全局账号也放进去 | 保留 ADR 0014 的跨空间复用；任务引用账号，不复制 Profile 或秘密                    |
| 文件夹复制是否等于完整迁移 | 否。须处理身份、事务引用、外部材料与本机授权；在复制验收通过前不作完整迁移承诺     |
| 为何暂不迁移任务运行账本   | 它兼有本机去重与运行恢复事实；先携带定义、产物和只读历史，避免第二调度 owner       |
| 会不会先做数周统一存储平台 | 按三个用户增量实施，不新建通用存储框架；60 分钟无可验收增量即复查主线              |
| 下一步最该做什么           | 实施第一批默认入口，证明首次使用、公司原记录及任务产物在重启后保留，再进入事务迁移 |

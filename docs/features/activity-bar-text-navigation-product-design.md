# Activity Bar 文字横排产品方案

> 状态：2026-10-15 用户已确认采用“文字横排”方向；已完成最小实现及真实 Electron 自动化；真人使用签收与正式发布未执行。
>
> 实施证据：[文字横排验收记录](../design/activity-bar-text-navigation/README.md)。
>
> 开发方案：[文字横排开发方案](activity-bar-text-navigation-development-plan.md)。
>
> 约束：`AGENTS.md`、[架构宪法](../architecture.md)、[统一上下文操作](context-action-system.md)。

## 结论

将最左侧 Activity Bar 从“图标在上、短名称在下”的 76px 窄导航，改为“图标在左、完整名称在右”的紧凑文字导航。
保留现有 15 个能力入口、三个分组和固定在底部的设置；用户直接点击名称即可进入原能力。

本轮改善能力入口的阅读、查找、状态辨识和布局适配，并定向修复阻碍这些动作的既有入口缺陷。Activity Bar 仍与其右侧的 Sidebar 内容栏分别存在，
不合并文件树、公司导航或其他领域侧栏。工作空间切换仍在顶栏。

源码已采用文字横排；本文件固定产品范围，实际验证见验收记录。本轮未发版，不能据此声称已安装版本已改变或真人签收通过。

独立评审指出三项必须随主线关闭的缺口：公司账目误选“文件”和部分右键打开失败、压缩后往返拖拽可能污染偏好、
现有测试不足以证明完整文字、计数及真实窗口/Browser 行为。2026-10-16 根据用户“偏宽”的反馈，将导航由 154px 收窄至 140px，完整名称、计数及既有宽度分配规则继续保留。
“最小方案”指在现有模块内完整实现需求，不指省略计数、交互、恢复、入口修复或真实 App 验收。

## 用户可执行的端到端验收

以下动作是本轮真实 Studio 验收标准；自动化执行结果及真人签收状态分别见验收记录。尺寸为 renderer 内容视口的 CSS 像素，
不能用截图的物理像素、外层窗口尺寸或网页内部的缩放比例替代。

| 编号 | 用户动作                                                                                 | 成功结果与证据                                                                                                          |
| ---- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| U1   | 免登录启动 Studio，打开本地工作空间，在约 1400 × 900 的内容视口查看导航                  | 15 个入口和设置均可直接读到；图标与文字同行；无需悬停识别名称。保存包含导航、内容栏和中央工作台的截图                   |
| U2   | 点击文件、网站与账号、文章发布、视频创作和硬件生产；将鼠标移到另一项，再用键盘聚焦另一项 | 进入各自原有侧栏，视频与硬件继续分离；最多一个能力项呈现选中状态，悬停和焦点不冒充选中。保存状态对照截图                |
| U3   | 重复点击普通已选中项，再点其他项；点击公司经营、公司账目和设置                           | 普通项保留再次点击收起、切换其他项展开的行为；三个特殊入口按下文约定打开原页面，不丢失现有 Tab 或工作空间归属           |
| U4   | 缩小到约 900 × 560，在导航中滚动并用 Tab 定位到最后几个入口，再点击设置                  | 每个入口均可到达，键盘焦点进入视口，设置始终可见；导航不横向滚动，底部入口不被设置遮挡。保存短窗口截图                  |
| U5   | 在大窗口把内容栏设为 250px、右侧 Agent 设为 350px，保持两栏展开；缩到 900px 宽后再放大   | 小窗口优先保留约 320px 中央空间，左右栏临时压缩；放大后恢复保存目标。收起任一栏后释放其宽度。保存压缩前后截图及布局值   |
| U6   | 在本地 A、B 工作空间设置不同当前面板、栏宽和显隐；切换 A → B → A，再重启 Studio          | 各自布局恢复；仅缩放窗口不能改写保存目标。导航宽度不变成工作空间配置，不要求重新登录或配置远程服务                      |
| U7   | 对入口右键和按 Shift+F10，关闭菜单；在浅色、深色下重复选中、悬停和聚焦                   | 仍使用统一上下文菜单，关闭后焦点回到原入口；文字、计数和焦点均可辨认，右键不先打开被点的能力                            |
| U8   | 在隔离本地工作空间打开真实内嵌网页，切换入口、拖动内容栏、缩放窗口、切回网页并重启恢复   | 原生网页与实际中央 pane 对齐，不能覆盖导航、Tab 栏或工具栏；缩放不回归 30%。保留真实 Browser 诊断，不能只看工具栏百分比 |

验收导航时不要求真实账号登录、模型付费调用、发帖、下单或其他外部副作用。打开文章发布入口不等于文章发布闭环通过。
远程入口需保持可达及原有未登录/离线反馈；真实远程文件、Agent 和 PTY 闭环仍按原专项验收。

### 验收必须补齐的反例

- U1/U7：逐项核对 15 个名称的实际可见文字、文字矩形及无裁剪，不能只检查 tooltip、DOM 含有完整文本或入口数量。
  计数按本次用户要求精简验证：真实 Runtime 经一个受控任务检查 0 → 1 → 0；0/1/99/100 的格式和语义用组件测试检查，
  99/99+ 的实际行末几何用真实 Electron 的展示边界夹具检查并标明来源。
  至少一次经现有主进程 Runtime 真实状态查询/事件订阅驱动非零计数再归零，不能直接改 renderer 计数冒充接通。
  安全测试装配已实现，具体见开发方案；没有调用会访问 Agent 的现有定时任务 smoke，也没有增加生产接口。
- U3：公司账目进入后，侧栏及 `activePanel` 都必须为 `company-accounts`，不得只打开账目 Tab 却选中“文件”；
  从其他入口进入、从折叠状态进入、重复打开、切换工作空间和重启恢复均要检查。
- U5/U6：压缩后先拖离起点、再拖回起点松手，以及拖向受限方向后松手，都不改变原保存目标；
  有最终有效位移才保存新目标。取消、失焦、窗口 resize 或工作空间切换不能提交未结束手势。
  必须同时检查可见尺寸、内存目标和队列排空后的持久值，随后放大及重启确认。
- U7：对全部 15 个能力项及设置，实际执行右键/Shift+F10 的“打开”，不能仅证明菜单出现；
  结果必须是正确能力或原有前置条件提示，不能出现因合法 ID 未登记而产生的“活动入口不可用”。
  菜单“打开”保持幂等，左键普通项保持折叠切换；特殊入口还需检查其 Tab 和已有联动。
- U4/U5/U8：必须实际调整 Electron 主窗口尺寸并记录窗口 content bounds、renderer `innerWidth/innerHeight` 与应用 zoom；
  单独调用浏览器 `page.setViewportSize()` 不算真实窗口验收。正常应用 zoom 和一个既有受支持的非默认 zoom 下都要检查，
  CSS 像素预算以实测 renderer 视口为准。
- U8：新 Tab、页内导航、面板变宽、手动 30% 恢复和重启恢复均须有真实 Browser 证据；
  原生 View bounds 和 page/visual scale 各自记录，不能以宽度纯函数或工具栏百分比替代。

## 视觉与布局规格

下列数值是本轮评审和实施的默认基线。评审若要求改变数值，必须同步修改本文件、开发方案和验收预期，
不能在实现时私自增加一种窄导航模式。

| 项目         | 首版要求                                                                           |
| ------------ | ---------------------------------------------------------------------------------- |
| 导航总宽     | 固定 140px，包含右边框；不提供拖拽、宽度设置或自动展开/收起                        |
| 能力项与设置 | 高 32px，整行可点击；图标在左、名称在右、垂直居中                                  |
| 图标         | 18px，沿用现有图标体系和语义，不在本轮重新设计图标                                 |
| 名称         | 13px、单行、左对齐；现有完整名称应全部显示，不靠缩小字号、换行或省略号塞入         |
| 行内空间     | 按钮左右各约 8px；图标与文字约 6px；导航两侧各约 4px 内距                         |
| 分组         | “工作 / 资源 / 流程”左对齐，11px 次级文字；组间保留约 8px 间隔                     |
| 选中         | 一条 3px 左侧强调色条，加浅背景及清晰文字；与悬停有明显差别                        |
| 悬停与焦点   | 悬停使用中性轻底色；键盘焦点有独立可见轮廓，不改变当前选中项                       |
| 滚动         | 中部能力区垂直滚动；设置在滚动区外。正常尺寸减少滚动，短窗口允许滚动               |
| 定时计数     | 在定时任务行末参与布局，预留宽度，不覆盖名称或图标；零值不显示，超过 99 显示 `99+` |
| 主题         | 使用现有浅色/深色主题变量，不固定为预览图中的配色                                  |

计数继续表示现有 Runtime 提供的排队数加正在运行数，不代表成功数；无障碍文案应说明“排队或运行中”。
导航不推测任务状态，也不在本轮增加其他通知圆点。

## 交互与选中语义

选中表示当前 Activity 上下文，继续由现有 UI 状态决定，不跟随鼠标、焦点或中央 Tab 自行推断。
普通能力项再次点击收起 Sidebar 时，保留当前项的选中标记，表示最近使用的能力上下文。

- 公司经营继续调用 `company.overview`：展示公司侧栏并打开/激活原公司工作台；重复点击仍展示总览，不能改成普通折叠。
- 公司账目正确切换到 `company-accounts` 并打开/激活原账目 Tab；修复现有白名单缺项导致的误选“文件”，不创建第二套账目实例。
- 浏览器继续保留既有 Agent 布局联动，不因导航改版失去该行为。
- 设置继续打开/激活原设置 Tab 并隐藏 Sidebar；它是底部动作，不新增一套“当前设置导航”状态。
  之前的能力项可以继续保持上下文选中，不能为了让设置高亮而覆盖保存的 Activity。
- 右键或 Shift+F10 绑定被操作项，使用现有菜单系统；补齐合法入口支持及其必要打开动作，保留普通项幂等打开与特殊项的业务语义。
  “保留原行为”只指正确的产品语义，不要求保留白名单遗漏、错误回退或打开失败。
- 不可用能力沿用领域原有提示和失败降级；未登录、远程离线或可选模块失败不阻断本地导航。

## 宽度代价与短窗口规则

140px 导航比改版前 76px 多占 64px，相比首版 154px 减少 14px，不能只做一张独立导航截图就认定方案有效。
内容栏（Sidebar，默认 250px）、中央 Workbench 和右侧 Agent 必须一起验收。

1. 在本轮重点覆盖的 900px 及以上内容视口宽度内，优先给中央工作区保留 320px。
2. 继续先压缩右侧 Agent 的有效显示宽度；它达到现有 220px 下限后，必要时临时压缩 Sidebar，
   最低 160px。例如 900px、两栏展开、目标为 250/350px 时，有效宽度为 Sidebar 212px、Agent 220px，
   加上导航 140px 和两条各 4px 的分隔条，中央正好 320px。
3. 临时压缩只影响当前呈现，不保存新宽度；窗口放大恢复原目标。拖拽移动时仅预览，正常松手且最终有效宽度与起点不同才保存新目标；
   拖回起点、始终被边界限制或取消时保留原目标。例如目标 250px、临时显示 212px，拖到 180px 再回 212px 松手，目标仍为 250px。
4. 不自动隐藏左右栏，不自动切换 Agent 模式，不切回短标签/纯图标模式；用户可使用现有顶栏按钮主动收起某栏。
5. 848px 是两栏均取上述下限、中央仍为 320px 的理论边界。更窄视口无法同时满足这些尺寸，中央可低于 320px；
   本轮不承诺极窄视口的三栏可读性，也不提高主窗口最小尺寸掩盖问题。至少检查 800px 下导航和顶栏收栏动作可用，
   收起一栏后中央可恢复可用空间。
6. 在 900 × 560 下允许导航滚动；底部设置必须常驻。缩短窗口不能导致入口丢失或覆盖设置。

Sidebar 的有效宽度适配属于加宽导航造成的直接布局阻塞，限于当前 renderer 的尺寸计算，
不扩张为通用响应式框架或工作空间持久化改造。

## 范围与不做项

首版包含文字横排、完整名称、选中/悬停/焦点区分、行末计数、必要的有效宽度适配，以及入口缺陷定向修复和完整拖拽提交规则。
这些项目及真实 App 验收都是最低交付范围，不得拆掉其中一项后仍称“最小方案完成”。

不包含：常用固定、“全部功能”抽屉、拖拽排序、分组折叠、自动重排、搜索入口、新快捷键、纯图标模式切换、
公司入口替代其他能力、视频/硬件合并、菜单系统重构或新的导航注册框架。
这些项目未进入本轮开发，不作为实现过程中的隐含后续任务。

## 自审结论与残余风险

方向可以形成一个小范围交付，但以下假设必须由独立评审和真实 App 验证质疑：

| 拷问                                   | 当前判断 / 必须验证                                                                    |
| -------------------------------------- | -------------------------------------------------------------------------------------- |
| 加宽后是不是只把“太长”变成“正文太窄”？ | 64px 代价已明确；U5 是交付门槛，不能只验收导航局部截图                                 |
| 15 个入口是否仍有信息架构问题？        | 有可能。本轮缺少使用频次证据，先固定位置并提高可读性，不据此猜测哪些入口应隐藏         |
| 选中问题是否都只是视觉差异？           | 不是。公司账目白名单遗漏是已核对的功能缺陷，须定向修复；其余视觉问题不能据此新增 owner |
| 小窗口适配是否悄悄重写用户布局？       | 禁止；U5/U6 须覆盖完整往返手势、取消，以及放大、工作空间切换和重启后的持久目标         |
| 右键能出现是否就证明入口可用？         | 不能；必须执行全部合法入口的打开，并检查实际侧栏、选中及特殊页动作                     |
| 设置是否应该是当前 Activity？          | 本轮保持已有动作语义，不以新增状态解决视觉问题                                         |
| 预览是否已证明真实浏览器不会覆盖？     | 没有。HTML 预览不能代表 Electron 原生 View，必须执行 U8                                |

用户功能进度：源码版可使用完整文字横排、修复后的入口、小窗口压缩/恢复及拖拽提交规则；真实 Electron 自动化已覆盖 U1–U8，用户本人签收仍待执行。
工程准备度：相关单元测试、类型检查、上下文操作门禁及真实 Electron smoke 已通过，证据见验收记录；未打包或发布。

# 文档自动保存与 Tab 状态评估

## 用户能力与验收边界

本轮实现本地 Markdown 原文件自动保存，以及本地编辑器草稿保存失败的可见提示、重试、退出和工作空间切换保护。其他文档和业务 Tab 只评估，不自动提交业务配置、发布任务、查询或远程文件。

用户验收动作：打开已有 `.md` 文档，修改后停顿 1.5 秒，原文件应更新；立即切到另一个 Tab，原文档仍应保存且不抢焦点；文件写入失败时正文应保留并可重试；草稿存储失败时，退出和工作空间切换不得静默丢弃正文；修复存储后重启应恢复未保存草稿。

“草稿已保留”表示恢复快照已获主进程写入确认，不等于原文件已保存。未命名文档只保留草稿，首次另存为仍由用户选择路径。设置 → 编辑器 → Markdown 自动保存可关闭自动落盘，Cmd/Ctrl+S 继续生效。

## 实现边界

- 内容和文件保存仍由 `EditorStore` 持有，复用串行保存、保存前复查、文件哈希冲突检查及主进程原子写入。自动保存调度器不持有第二份正文，不绕过已有 IPC 权限。
- 调度器属于主工作台生命周期，支持非活动 Tab；工作空间变更后重新调度，销毁时解除订阅和定时器。Tab 的未保存标记随文件保存结果更新。
- 自动保存只匹配共享 Markdown 扩展名规则，排除未命名文档、加载中、保存中、诊断错误、外部冲突和上次写入失败的文件。失败暂停，用户显式重试；不会强制覆盖外部版本。
- 草稿继续使用既有 WorkspaceState 的 `editorDrafts` 分区。新增状态仅投影写入回执，记录保存中、成功及错误；没有新增正文存储所有者。
- 工作空间切换在准备阶段及最终替换编辑器前确认最新草稿。最终确认失败时保留原工作台，并恢复主进程原工作空间选择。
- 退出沿用受信 renderer flush 握手。失败或超时弹出“继续编辑／重试保存／放弃未保存内容并关闭”，默认继续编辑。明确放弃才允许有损关闭。
- 草稿 JSON 大小上限仍为 5 MiB，正文与基线可能同时占空间。超限会显示失败并阻止无确认退出/切换，不承诺无限草稿容量；强杀进程、断电或主动放弃也不在完整恢复保证内。

## 其他文档与 Tab 的评估

代码事实来自 `WorkbenchContent`、各领域编辑组件、draft registry、`workbench-tab-model` 与 WorkspaceState。活动 Tab 之外的多数 React 编辑组件会卸载；Tab 的路径、ID、标题、顺序能恢复，并不意味着组件内的未提交表单也会恢复。

| 类型                                               | 现有内容保存/状态恢复                                                               | 评估与建议                                                                                                     |
| -------------------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 本地 Markdown                                      | 本轮增加自动原文件保存；草稿、冲突、失败状态及滚动位置沿用编辑器状态                | 本轮验收主线                                                                                                   |
| 未命名 Markdown                                    | 自动保留本地草稿，显式另存为                                                        | 不自动猜测文件路径；本轮草稿失败保护覆盖                                                                       |
| HTML 源码                                          | EditorStore 草稿，显式保存；默认点击 HTML 是浏览器预览，“以文本打开”才编辑源码      | 本轮确认不会自动改写 HTML；可后续复用保存策略                                                                  |
| 其他文本/代码/JSON/YAML                            | 非预览类型目前也会落入 MarkdownEditor；没有独立的通用源码编辑面                     | 不能直接统一开启自动保存，否则 Markdown 序列化可能改变源文本；先补无损源码编辑再扩范围                         |
| Word、Excel、PPT、iWork、PDF、图片、音视频、压缩包 | `FilePreview`/`PdfPreview` 等预览，原文件没有正文编辑入口                           | 没有可自动保存的正文；在外部应用修改时由外部应用保存。预览页码、缩放、播放位置应作为视图状态单独验收           |
| 模型、Gerber、Android                              | 预览/设备运行现场，主体由相关主进程服务管理                                         | 不应以“文档自动保存”重放设备动作；视角、图层、设备选择恢复需各自核对                                           |
| 远程文件                                           | 独立远程草稿快照，150 ms 防抖存本机，原文件显式写入；退出会等待草稿 flush           | 后台草稿失败目前主要记日志，需补可见失败/重试；必须保持版本冲突与离线边界。本轮未做真实远程设备验收            |
| 定时任务表单                                       | 表单 `useState`，registry 仅保存 save 回调，配置显式保存；运行事实由任务服务持有    | 高优先级：切换到其他类型 Tab 时组件卸载会丢未提交表单。先做可恢复表单草稿，保存/启用/立即运行保持显式动作      |
| 视频创作（新版口播与旧版分镜）                     | 草稿在组件 state/ref，registry 仅 save 回调；显式保存及部分操作前保存               | 高优先级：未保存文本在跨 Tab 卸载后有丢失风险。应保存编辑草稿，不能自动启动生成、导出或确认口播                |
| 数据源查询                                         | 查询文本、名称、临时结果在组件 state；“保存查询”后持久化                            | 高优先级：未保存查询可随卸载丢失。应保存查询草稿，恢复不能自动执行查询                                         |
| 文章发布                                           | 未建任务的标题、摘要、标签、账号选择等是组件 state；保存后的任务由 WebAffair 持久化 | 高优先级：补准备表单草稿；正文文件保存、任务保存、平台草稿、正式发布必须分开，不可因自动保存自动发布           |
| 角色编辑                                           | registry 内存中保留 draft；显式保存创建不可变角色版本；关闭/切换角色有确认          | 普通 Tab 切换存在内存恢复基础，但重启无持久草稿；已有角色返回时编辑模式也需核对。不应每次输入自动创建角色版本  |
| 新建事务                                           | draft 写入 Tab 描述，再同步主进程 TabModel；已建事务由 WebAffair 持有               | 正文恢复基础较好，但 TabModel 同步异常被后台调用吞掉，flush 等待排空不能证明前次成功；需补失败可见性与退出保护 |
| 网站账号详情                                       | 读取服务快照/登录状态，变更走显式领域操作                                           | 当前详情不是正文编辑器；登录运行现场不等于可恢复表单                                                           |
| 公司经营/公司账目                                  | 已提交数据由各领域服务持久化；正在编辑的业务表单、账目修订在组件 state              | 高优先级：未提交表单可能随切 Tab 丢失；先保留草稿，账目确认/正式提交保持显式                                   |
| 浏览器                                             | 主进程持有页面运行现场；URL、Tab 引用、环境及部分投影持久化                         | 网页内未提交表单没有通用恢复保证；不能自动点网页保存。浏览器投影写入失败也需后续可见化                         |
| 本地/远程会话                                      | 会话存储或远端 runtime 持有消息与运行事实，Tab 主要保留引用                         | 已有独立持久化与 flush，不归 Markdown 自动保存；重启不得自动重发消息，输入框未发送内容需单独验收               |
| Terminal/执行记录                                  | 运行进程与记录由 Terminal 服务持有，Tab 保存引用                                    | 可恢复引用不等于进程跨应用退出仍存活；不能恢复时自动重跑命令                                                   |
| 设置                                               | 设置项通过 SettingsStore 即时持久化；部分凭证表单有独立保存动作                     | 无需文档自动保存；仍应检查各独立表单的未提交内容和失败提示                                                     |

优先顺序：先保护定时任务、视频、查询、发布准备及公司表单在切 Tab 时的未提交内容；再补这些草稿的重启恢复和失败提示；随后补远程草稿及 TabModel/浏览器投影的写入失败确认；最后扩展无损源码自动保存及只读视图恢复。复用各领域状态所有者和统一 WorkspaceState/TabModel，不建立通用第二份业务状态。

## 真实 Electron 验收

运行 `pnpm exec electron-vite build` 后执行 `node scripts/markdown-autosave-smoke.mjs`。脚本使用独立 userData、临时工作空间和真实 Electron，编辑通过可见 UI，磁盘内容由宿主读取核对。失败通过临时目录权限制造；系统目录选择和关闭失败对话框使用确定性选择，不接真实账号，不运行 Agent、不发布内容。

| 编号 | 真人操作步骤                                       | 预期                                        |
| ---- | -------------------------------------------------- | ------------------------------------------- |
| A1   | 打开 Markdown，输入后停顿                          | 1.5 秒后落盘，显示已保存                    |
| A2   | 输入后立即点另一文档 Tab                           | 原文档落盘，焦点不变，原 Tab 未保存圆点消失 |
| A3   | HTML 右键“以文本打开”，修改后等待                  | 原文件未变，保持显式保存                    |
| A4   | 关闭自动保存，修改并等待，再按 Cmd/Ctrl+S          | 等待不改文件，快捷键立即保存                |
| A5   | 文档修改未保存时，从外部改同一文件                 | 显示冲突，外部版本和编辑正文都保留          |
| A6   | 临时工作空间目录设为只读后编辑，再恢复权限并重试   | 显示文件保存失败，重试写入原正文            |
| A7   | 临时草稿目录及备用存储均设为只读，编辑后切工作空间 | 显示草稿失败，保留原工作空间和正文          |
| A8   | 草稿失败时关闭窗口，选继续编辑                     | 保持窗口及正文；另提供重试和明确放弃        |
| A9   | 恢复存储权限，重试保留草稿，关闭重启               | 恢复未保存正文，原文件仍为之前版本          |
| A10  | 修复存储后切换工作空间                             | 正常进入目标空间                            |

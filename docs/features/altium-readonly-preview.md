# Altium 原理图与 PCB 只读预览

## 用户验收动作

1. 在 Studio 打开包含 Altium 文件的本地工作区。
2. 点击 `.SchDoc`（大小写不敏感），看到原理图中的元件、引脚、导线和文字。
3. 滚轮缩放、拖动平移；工具栏可放大、缩小、适合窗口；画布聚焦后可用 `+`、`-`、方向键、`0`。
4. 点击 `.PcbDoc`，看到 PCB 图形；在“PCB 层”选择全部层或单层，查看走线、焊盘、过孔。
5. 默认遵循源文件隐藏标记；需要核对隐藏的位号或型号时开启“显示隐藏文字”。
6. 点击 `.PrjPcb`，从“查看图纸”进入引用的原理图或 PCB。缺失、越界和暂不支持的引用显示原因，不能打开。
7. 文件损坏时看到错误和重试/系统打开入口。关闭、重新打开或切换工作区后仍进入只读预览。
8. 操作前后原始五个文件的 SHA-256 一致；没有文本保存入口。

验收样本位于本机 `生产/20260210_pcb_原理图/`，保持被 Git 忽略；不提交图纸、派生图像或私有工程数据。

## 能力边界与实现

- 本地免登录；解析不上传源文件、不调用云服务、不要求安装 Altium 或 KiCad。
- 支持 `.SchDoc`、`.PcbDoc`、`.PrjPcb`。图形只读，不包含电路编辑、规则检查、仿真、制造校验、3D 或跨图网络高亮。
- 采用固定版本 `altiumts@0.0.95`（MIT）；第三方解析库仍处于实验阶段，不保证全部 Altium 版本和特殊对象的等价渲染。
- `FileService` 继续唯一负责文件授权和读取；复用 `fs:renderFile` 共享契约及参数 schema。工程引用必须经过同一工作区/符号链接权限校验；不凭工程内容授予新权限。
- 既有 Tab Store 负责打开、关闭、切换和恢复；UI 仅持有可丢弃的图像、选层、缩放和平移状态，不引入新的工作区或文档状态所有者。
- 解析在请求独占的 Worker 中完成。最多两个并发解析，正常连续切图进入有界等待队列（最多 8 项，已接纳输入总计不超过 64 MB）；等待和解析各有 15 秒上限。文件上限 32 MB，图形输出上限 16 MB，最多 100,000 个记录和 256 个工程引用，256 MB Worker 堆限制。成功、错误和超时均终止 Worker；不驻留额外服务或缓存。
- PCB 图层按解析库的层栈别名统一，避免 `MID2` / `MIDLAYER2` 或 `PLANE1` / `INTERNALPLANE1` 重复。双参考点线性尺寸在临时渲染模型中按标注轴投影，并使用源单位、精度和前后缀计算；自动文字置于尺寸线中央，手动文字位置保留。修正固定依赖把 `TEXTFORMAT` 当作测量值的问题，不写回原文件。非线性或不完整尺寸明确提示尚未校验。
- SVG 只作为 `img` 图像加载，不注入工作台 DOM；源文字由解析器转义。渲染进程不获得 Node、文件句柄或源解析对象。
- 读取结束后再次校验工作区权限，UI 丢弃卸载后的异步结果；错误或切层等待期间不把旧图冒充新层。
- 原文件不能通过 `readTextDocument`、`writeFile` 或 `saveTextDocument` 进入文本编辑/保存；兼容旧标签恢复路由到 `file-preview`。
- UI 显示对象数量、结构诊断及关键 PCB 图元流数量差异。缺失对象、损坏格式和解析错误不以空白成功代替。

## 工程门禁与真实文件验收

- 单元/集成回归：解析、转义、二进制损坏、单层选择、IPC 参数、工程路径越界及符号链接、文本写入阻断、工作区切换、已有文件预览和标签恢复。
- `pnpm smoke:altium-preview -- /绝对路径/实际工程目录`：在隔离用户配置的真实 Electron 中，通过文件树点击五个实际文件；检查图像加载、芯片文字、层切换、缩放/平移、工程跳转、缺失引用、损坏文件降级、工作区返回及原文件哈希。
- 默认样本目录为本机 `生产/20260210_pcb_原理图/`；文件缺失时验收失败，不静默跳过或改用 mock。
- 截图、哈希及结果 JSON 写入 `/tmp/cclink-altium-acceptance-*`，不会进入 Git。
- 真实验收结果见 [验收记录](../testing/altium-readonly-preview.md)。

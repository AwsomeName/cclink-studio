# 远程 Mac 工作空间与桌面接入讨论记录

> 日期：2026-11-17。状态：需求与候选方案记录，尚未实现或实机验收；网络方案未定。
> 本轮只保存讨论，不授权修改远端 Agent、云服务或部署网络组件。
> 2026-11-20 补充：用户确认“整个流程都麻烦，希望安装后配对就能用”；三条方案与最新取舍见[项目备忘录](../project-memo.md#2026-11-20--美国-mac-远程桌面与简易接入)，仍未批准实现。

## 用户目标与当前结论

用户拥有一台美国 Mac，已安装 Claude Code、Claude 桌面 App／浏览器等工具，希望少量配置后从本地使用。长期偏好是 Agent 自动操作、必要时人工接管；当前优先探索直接远程桌面，并验证现有 chatcc-agent。

本轮形成的方向：

1. 同一台 Mac 可以提供两个入口：打开远程工作空间（文件、会话、终端）与打开真实桌面（鼠标键盘操作）。两种能力分别验收，不相互冒充完成。
2. Claude 的浏览器登录、登录过期后的恢复必须纳入闭环。桌面连接不能依赖 Claude 已经登录或运行正常。
3. Studio 内嵌真实 Mac 桌面有技术实现路径；noVNC/VNC 是候选，不是已选定或已验证的生产方案。
4. 现有腾讯 IM 支持全球接入，不能把“依赖腾讯”直接等同于“不支持美国 Agent”。先在目标 Mac 上定位实际连接结果。
5. Tailscale 是私网连接候选。用户明确反馈此前使用麻烦、复杂，因此不将“用户自行配置 Tailscale”定为默认产品流程，也不将 Tailscale 集成视为已决定的工作。

当前用户功能进度：本轮未增加可使用能力，尚未连接目标美国 Mac；不能宣称 Studio 已能打开其桌面、完成 Claude 登录或运行其 Agent。

当前工程准备度：Studio 已有远程工作空间、文件、会话及 PTY 基础；已有文档仍记录真实远程验收缺项。本轮只核查了客户端相关代码与官方资料，没有完成网络、认证、画面或输入验证。

## 三种不同的能力

- 远程工作空间：Studio 展示文件、会话、终端，远端 Agent 执行工作。
- Web 桌面：网页绘制图标、窗口、文件管理和设置，通过后台接口操作资源。飞牛 fnOS 主界面属于此类入口，不能因此控制任意已有 Mac App。
- 真实远程桌面：传送实际操作系统会话的画面，回传鼠标键盘。浏览器也可以承载这种客户端；飞牛虚拟机的 VNC 连接属于实际虚拟机画面。

本需求中的桌面目标是美国 Mac 的现有 macOS 用户会话。另造 Web 桌面或另开虚拟机不能自然复用其已有 App 和登录现场。桌面可被人控制，也不等于 Agent 已获得桌面自动化能力。

## 连接与内嵌的候选路径

### 真实桌面

先用系统屏幕共享建立真实体验基准，再验证内嵌路径：

```text
Studio 远程桌面 Tab / 内嵌 VNC 客户端
  → 主进程管理的受限连接桥接
  → 已授权的私网连接（Tailscale 等候选）
  → 美国 Mac 屏幕共享服务
  → 现有 macOS 桌面会话
```

macOS 屏幕共享兼容 VNC；noVNC 是可嵌入的浏览器客户端，使用 WebSocket 承载 RFB 协议，因此普通 VNC TCP 服务需要适配桥接。不是把系统“屏幕共享”App 窗口直接嵌入 Studio。

认证方式和当前 macOS 兼容性须实测，不能通过取消认证来适配客户端。普通 VNC 不承诺 Apple 原生客户端全部高性能特性。若体验差，需要重新比较协议或成熟组件，不能仅因容易嵌入就定型。外部客户端可以作为独立使用入口，但不计为 Studio 内嵌交付。

桌面像素流与 Agent 消息使用各自适合的通道，不通过现有腾讯 IM 自定义消息持续传屏。连接网络可达、桌面服务可达、认证通过、画面可见、输入可用分别展示；不能只显示一个“在线”。

### 现有 chatcc-agent

当前 Studio 使用 `TimTransport`，`CclinkRequestRouter` 已有 `CclinkTransport` 接口。美国 Mac 验证分层进行：

1. CCLink 云服务访问、身份获取与设备配对。
2. Agent 的 IM 登录与双向消息。
3. 远程目录、文件、会话、审批与 PTY。
4. Claude 的安装、运行用户、认证与实际请求。

Tailscale 打通 IP 网络不会自动改变上述传输。若要走私网直连，还要核对 Agent 是否提供相应入口，并评审双方认证、协议和生命周期。更换客户端 transport 不等于摆脱整个云端身份与配对依赖。

## Claude 登录闭环

默认候选路径：远端发起登录 → Studio 提示需要人工处理 → 打开远程桌面 → 用户在远端浏览器完成登录 → 远端 Claude 核验 → 返回原工作。

- Claude 未安装、登录失效或运行失败时，桌面入口仍须可用。
- 必须核对发起登录与执行 Agent 的系统用户、环境和凭证作用域，不能只看浏览器页面。
- Claude Code 官方另有远程／SSH 场景复制授权 URL 的流程，可作为适配版本验证后的补充；不能假定跨设备自动回调成功。
- Claude Code、Claude 桌面 App 和网页版的认证分别验证，不假设它们自动共享登录状态。
- Studio 不读取或迁移系统钥匙串，不复制第三方登录 token；自有凭证遵循现有受限本地文件规则。验证码和登录授权由用户处理，不进入任务日志。

## Tailscale 复杂度反馈与设计修正

用户明确反馈：“之前使用 Tailscale，感觉很麻烦，很复杂。”随后确认是“整个流程都麻烦，希望安装后配对就能用”。这属于整体接入体验要求；下面的可能来源不代表已逐项复现的故障。

可能的负担包括两端安装和登录、系统网络权限、设备加入与访问策略、屏幕共享开启和认证，以及“设备在线但桌面连不上”时跨多个产品排错。把这些步骤复制到 Studio 向导中，只是集中入口，不等于解决复杂度。

建议把用户体验目标定为：

> 美国 Mac 完成一次接入安装和必要系统授权，在本地 Studio 确认短时配对信息；以后选择该 Mac 即可连接。失败时告知具体恢复动作，不要求用户自行理解 IP、NAT、DERP、ACL 等概念。

这是待评估的产品目标，不是现有能力。配对码只确认设备归属和访问授权，不能单独完成网络穿透、系统授权或认证。没有任何已有访问方式时，首次安装和授权仍需要现场操作或其他远程通道。

候选方案比较：

| 方案                                   | 能减少什么                                        | 剩余成本与结论                                                                                        |
| -------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 复用已安装的 Tailscale                 | Studio 可检测状态、列出可访问设备、诊断和打开桌面 | 用户仍管理第三方安装／账号／网络；适合先验证及已有用户，不直接确定为默认新手流程                      |
| 内嵌 tsnet 等网络组件                  | 有机会隐藏部分系统组网配置，由产品管理连接        | 仍有节点身份、登录、权限、过期恢复、中继、升级和运维；Electron 还需辅助组件，不能宣称打包后自然免配置 |
| 采用有配对／连接能力的成熟远程桌面方案 | 有机会复用设备接入、穿透和中继体验                | 需比较 macOS 支持、嵌入 SDK、授权许可、服务依赖和成本；本轮未选择产品                                 |
| 自建配对与连接服务                     | 可控制账号和交互                                  | 服务端安全、直连／中继、带宽、可用性与长期维护成本由产品承担；不作为本轮自动扩张事项                  |

Tailscale 支持直连及中继回退，但不是跨洋低延迟保证，也不会默认把美国 Mac 变成本地全部网络流量的出口。本轮不涉及全局代理或 exit node 配置。

最新结论：保留 Tailscale 为技术验证／兼容候选；默认功能的选择以安装、首次成功连接、登录恢复及日常重连的真实体验为依据，不以组件是否容易接入为依据。尚未决定捆绑 Tailscale、要求第三方账号或自建网络服务。

## 架构边界与失败处理

- 复用 Studio 现有 Workspace、Tab、Workbench、IPC 和生命周期；不增加平行的工作空间或 Agent 状态系统。
- 桌面连接由主进程单一 owner 管理；桥接仅接受经过授权的设备目标与有界操作，renderer 不获得任意 TCP／shell 能力。连接凭证不进入 URL、普通设置、日志或 Workspace。
- 主进程连接、事件监听、辅助进程和桥接端点成对创建与释放；关闭桌面连接不自动终止远端 App 或 Agent 任务。
- 网络、Claude 或桌面模块失败独立降级；Studio 本地免登录能力始终可用。第三方网络接入不能自动变成 CCLink 托管权限，也不能绕过其服务端授权。
- 断线保留最后事实及时间，重连对账；不得将失联显示成成功、停止，或自动重试可能已发生的副作用。
- 后续 Agent 桌面自动化另行设计控制权交接：人工接管先确认自动输入停止，交回后重新观察。当前不新增通用调度框架或第二运行账本。
- 新增非 CCLink 直接网络接入须在实施前复审架构宪法；需要例外时先有 ADR。不得在本次记录中顺便修改 `/Users/apple/Desktop/chat-cc/Agent` 或 `/Users/apple/Desktop/chat-cc/deploy`。

## 下一步与拷问结果

1. 按用户已确认的“安装后配对就能用”要求比较具体底座，不把优化某个 Tailscale 配置步骤当成整体问题已解决；最新三方案取舍见项目备忘录。
2. 获取目标 Mac 的机型、macOS 版本、现有访问方式和后台运行条件；安排一次最小实机连接验证。
3. 分别验证系统远程桌面和现有 chatcc-agent，保存真实失败层级，不先重写网络。
4. 桌面可用后做最小内嵌原型，用 D2/D3 和输入体验决定是否继续；同步记录首次配置成本。
5. 再决定默认连接方案，以及是否需要 Agent／云端跨仓工作。本记录不代表实施批准或产品能力完成。

最容易偏航的地方是先做大量网络管理页面、重建 Agent 通信或仿制 Web 桌面，却仍不能从 Studio 完成一次真实 Claude 登录。持续实现按项目的 60 分钟偏航检查与同一阻塞连续两次失败止损规则执行。

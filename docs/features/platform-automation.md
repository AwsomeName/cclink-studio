# 平台自动化 — 路径选型与合规边界

> 本文档界定 CCLink Studio Agent 操作各类外部平台(电商 / 内容 / IM)时的**路径选择、合规边界与禁区**。
>
> 当前边界：本文作为本地浏览器、真机设备和 Agent 自动化合规参考；官方账号和消息网络由 CCLink 官方侧接入。
>
> Markdown 文章发布的产品闭环、通用内核和平台薄适配器边界见
> `docs/features/article-platform-publishing.md`；当前仅记录方案，尚未实现。

## 概述

CCLink Studio Agent 要替用户操作各种平台，存在三种本地执行路径；高敏感消息场景另由
CCLink 官方通道承接：

| 路径                      | 机制                                     | 合规                      | 稳定性                    | 适用                           |
| ------------------------- | ---------------------------------------- | ------------------------- | ------------------------- | ------------------------------ |
| **官方 API / 开放平台**   | 平台提供的 OpenAPI、Webhook、SDK         | ✅ 按官方授权范围         | ✅ 高（契约稳定）         | 官方能力覆盖目标操作的平台     |
| **UI 操控（内嵌浏览器）** | 可见 Browser Tab、BrowserTask 和薄适配器 | ⚠️ 取决于平台规则         | ⚠️ 中低（页面会变化）     | 有明确账号和影响范围的网页任务 |
| **UI 操控（真机设备）**   | ADB 输入、截图和语义 UI 分析             | ⚠️ 看平台（可能违反 ToS） | ⚠️ 低（客户端更新即失效） | 无 API 的低风险移动端任务      |

**核心原则：官方能力覆盖时 API 优先。** 官方 API 不覆盖目标操作、用户只能在网页完成，且平台规则
允许时，可以使用同一可见 Browser Tab 执行有明确账号、对象、内容快照和影响范围的任务。只有真人
能完成、特别敏感、范围扩大或后果未知时暂停交给用户；UI 自动化不是绕过平台授权或风控的通道。

## 平台合规地图

| 平台             | 类型        | 官方 API                            | UI 操控封号风险    | CCLink Studio 路径                                 |
| ---------------- | ----------- | ----------------------------------- | ------------------ | -------------------------------------------------- |
| 京东             | 电商        | ✅ 京东开放平台                     | 低(浏览/搜索)      | API(商品/订单);设备 UI 仅做无 API 的浏览采集       |
| B 站             | 内容        | ✅ 开放平台(投稿等)                 | 中(自动化发布检测) | API(投稿/数据);UI 仅兜底                           |
| **钉钉**         | 企业 IM     | ✅ **极完善**(机器人/服务端/Stream) | 低-中              | **走开放平台 API**,不走托管设备                    |
| **企业微信**     | 企业 IM     | ✅ 完善(企微开放平台)               | 低-中              | **走 API**,不走托管设备                            |
| **飞书**         | 企业 IM     | ✅ 完善(Lark/Feishu Open Platform)  | 低-中              | **走 API**,不走托管设备                            |
| **微信(个人号)** | 个人社交 IM | ❌ 无                               | **极高(必封)**     | **禁区**；如需消息能力，由 CCLink 官方消息网络承接 |
| **QQ(个人)**     | 个人社交 IM | ❌ 无                               | 极高               | 禁区                                               |

### 通用规律

- **企业级协作平台**(钉钉/企微/飞书)→ 把开放 API 当核心竞争力,**自动化的合规主场就在 API**。
- **个人社交 IM**(微信/QQ)→ 刻意封锁自动化,**UI 操控必踩风控,是禁区**。
- **电商/内容平台**(京东/B 站)→ 多有开放平台,**API 优先**;设备 UI 只做无 API 的浏览/采集。

## 分层策略

CCLink Studio 的 Agent 工具体系按此分层(MCP 工具模块):

1. **官方 API 类(优先,默认)** —— 各平台开放平台 SDK 封装为 MCP 工具
   - 钉钉 / 企业微信 / 飞书:消息收发、群管理、机器人
   - 京东 / B 站:商品 / 投稿 / 数据
   - 特点:合规、稳定、契约化,客户端更新不影响

2. **网页 UI 类（受控兜底）** —— Studio 可见 Browser Tab + BrowserTask + 平台薄适配器
   - 用于读取、填写、上传、下载、保存草稿和结果核验。
   - 登录验证、验证码、法律声明、付款、账号权限、破坏性动作、范围扩大或后果未知时转人工处理；
     结构化任务中已经明确授权的单对象常规发布可以由 Agent 完成。
   - 文章发布首个方案见 `docs/features/article-platform-publishing.md`。

3. **设备 UI 类（受控兜底）** —— 用户自有真机 + ADB
   - 仅用于平台规则允许的浏览、搜索、采集或用户明确授权的低风险设备操作。
   - **绝不碰个人社交 IM（微信/QQ）、绝不碰批量多账号营销。**

4. **官方通道（无 API 的高敏感场景）** —— CCLink 官方消息网络
   - 微信场景的合规替代应走官方消息网络，不操控个人微信号客户端；Studio 默认不内置官方消息 SDK。

## 设备 UI 在平台自动化中的定位

- ✅ 适合:无官方 API 的低风险平台的**浏览 / 采集 / UI 操作**
- ✅ 适合:用户自有真机上的端到端 App 任务执行
- ❌ 禁止:个人社交 IM(微信/QQ)操控
- ❌ 不必要:钉钉/企微/飞书等有完善 API 的平台(直接用 API)

## 决策清单(Agent 选路径时)

判断一个平台任务该走哪条路径:

1. **该平台有覆盖目标操作的官方开放 API 吗？**
   - 有 → 优先使用官方 API，并继续校验授权范围、资质和人工确认要求。
   - 没有或不覆盖 → 继续。
2. **该平台是个人社交 IM(微信/QQ)吗?**
   - 是 → **禁区**,不提供 UI 操控工具；如需消息能力，应由 CCLink 官方消息网络承接。
   - 否 → 继续。
3. **任务发生在网页还是用户自有设备？**
   - 网页 → 使用可见 Browser；高频稳定差异可以由薄适配器处理。
   - 移动端 → 用户自有真机 UI 操控兜底。
4. **任务是否包含登录、发布、发送、删除、付款、法律声明或批量营销？**
   - 单次登录态任务 → 明确账号、对象、内容快照和影响范围；常规目标动作可执行，人工专属、特别
     敏感、范围扩大或后果未知时暂停交给用户。
   - 批量营销、风控绕过或无法说明影响 → 默认不提供。

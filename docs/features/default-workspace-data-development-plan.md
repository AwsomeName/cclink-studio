# 默认工作空间与数据迁移实施计划

> 日期：2026-11-04。
> 状态：第一批代码及真实 Electron 自动验收通过，真人签收待执行；第二、第三批尚未实现。实际结果见[第一批实现与验收](../testing/default-workspace-first-batch.md)。
> 产品边界：[默认工作空间与业务数据归属设计](default-workspace-data-design.md)。
> 架构决策：[ADR 0020](../decisions/0020-default-workspace-data-boundary.md)，accepted。
> 验收记录：[默认工作空间与业务数据验收](../testing/default-workspace-data-acceptance.md)。

## 实施结论

按三个用户增量实施：先让用户首次启动即能保存和恢复真实资料，再让旧事务随工作空间保存并保持原记录可打开，最后交付可验证的备份、移动与副本恢复。公司、账目和任务已有空间内存储，优先复用，不先构建统一存储平台。

每批完成声明都必须写明用户现在能做什么、还不能做什么，并分列用户功能进度和工程准备度。文档、schema、迁移代码或自动化通过均不能代替真人操作。本文不授权公开发文，不启动发版或云服务变更。

## 开工前工程准备

此节属于工程准备度，不单独记产品进度。

1. 对照架构宪法评审 ADR 0020，核对唯一 owner、默认路径权限、维护窗口和单写规则，再更新其状态；不把账号隔离、身份文件全面改名或调度账本重建混入本轮。
2. 记录基线 SHA、已有工作树修改与当前受影响门禁。准备隔离 userData 和合成旧格式空间 A、B；不得用用户经营原件做破坏测试。
3. 只固化当前批次需要的 shared contract、错误模型和迁移样本。样本至少包含有效备份、有效恢复日志、一个无归属事务和一条公司到事务关联。
4. 明确本批真人动作和证据存放位置。工程自动化和真人记录分开，未执行项保持待验收。

单项前置超过 60 分钟或同一阻塞失败两次时停止深挖，报告已经耗时、实际结果、替代路径和下一步取舍。连续开发 60 分钟没有增加用户可验收行为时执行偏航检查；不得以测试数、提交数或补日志替代主线增量。

## 第一批 默认空间可直接使用

### 第一批完成标准

用户无需选目录即可创建一份真实 Markdown，在同一空间启用公司、关联该稿件、使用原账目及定时任务入口，切换 A/B 和完整重启后内容仍在。默认目录故障时其他本地入口可用。对应验收 A01 至 A06、B01 至 B04、E01、E02。

### 第一批任务

| 任务              | 代码落点                                                                                                   | 具体变化及核验                                                                                                  |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 启动选择 contract | `src/shared/settings-constants.ts`、`src/shared/ipc/settings.ts`、设置 IPC schema 与测试                   | 增加设计中的两项设置；缺字段兼容、非法路径拒绝，区分首次、失效与主动未归档                                      |
| 默认空间初始化    | `src/main/workspace/workspace-state-service.ts`、`workspace-state-ipc.ts`、对应 shared contract 和 preload | 提供有界查询及初始化；复用唯一稳定身份，串行幂等，失败不覆盖用户文件或创建第二身份                              |
| 精确目录授权      | `src/main/fs/file-service.ts` 与可信 renderer 校验                                                         | 仅允许主进程确定的默认目标；不把整个主目录变成新增授权，新 contract 不暴露内部控制文件写入，沿用既有 Agent 权限 |
| 启动与切换        | `workspace-bootstrap-core.ts`、`use-workspace-bootstrap.ts`、`fs-store.ts`、原 workspace-open controller   | 按优先级确认真实目录后再恢复；复用 generation/transition，不能先读旧路径快照再猜当前空间                        |
| 工作空间入口      | 既有工作空间选择器、设置及统一 command/contribution                                                        | 提供打开默认空间、设置默认位置和查看位置；物理移动入口留到第三批，不复制右键实现                                |
| 公司及运营归属    | 公司、账目、文章发布与定时任务既有组件                                                                     | 显示实际归属；新稿默认路径按需创建且可修改，旧 `docs/` 文件保持原引用；账号标明本机全局                         |
| 原能力串接        | 现有 CompanyWorkspaceService、CompanyAccountsService、ScheduledTaskService                                 | 不新增业务状态；证明真实文件、账目确认及一次任务产物经过原 IPC 与服务保存                                       |

默认目录创建协议：校验候选及最近存在父目录 → 检查未登记占用与符号链接 → 排他创建必要目录 → 通过原基础层建立并读回稳定身份 → 在既有本地空间索引登记路径及身份 → 记录默认设置 → 原 transition 激活。设置提交失败时保留已登记且可定位的目录，下次按身份重试；索引登记失败时保留目录并明确提示未完成，允许用户选择该目录核验后继续，不自动接管未知占用。不能清理已有业务文件。并发初始化最终只认一个目录与身份。

旧配置推导只发生一次；已登记默认目录丢失后不自动新建。用户明确打开其他空间或进入未归档，必须影响下次启动；显示 Home Tab 不修改工作空间选择。现有远程打开和恢复优先，不新增远程身份字段。

### 第一批验证

有意义的单测覆盖创建幂等、并发、冲突、设置提交失败、目录丢失、非法 sender/路径、启动分支和过期响应。真实 Electron 覆盖首次启动、原公司/账目/任务 UI、A/B 切换、重启和只读降级。测试不要求真实公开发文。

仅默认目录出现、或只看到静态公司页不能关闭第一批；必须至少有实际保存和恢复的文件、公司关联、账目及一次受限任务结果。Agent 不可用时可以另记录其降级通过，但任务成功运行验收仍待完成，不能改成“模板保存即 AI 成功”。

## 第二批 事务随空间保存并兼容旧数据

### 第二批完成标准

用户在原目录看到同一事务 ID、历史证据和公司关联；新变更只写该目录。迁移崩溃后能够确定唯一权威位置。A 的分区故障不隐藏 B，也不阻断普通浏览器。对应 C01 至 C07、B05、E03、E04。

### 目标存储和读取规则

WebAffairService 继续是单一实例和唯一执行 owner，其内部按稳定 workspaceId 管理分区存储。WebAffairStore 的原子写入、备份、压缩及恢复日志保留，不改为 renderer 文件读写或按 Tab 创建 service。

`storage.json` 拟使用独立 `formatVersion: 1`，至少包含 workspaceId、migrationId、来源分区摘要、来源 revision 和格式兼容信息。它用于识别存储来源，不保存发布状态。中央迁移记录位于 `userData/web-affairs/migrations/<workspaceId>.json`，只记录本次分区切换与定位信息，不形成通用 operation 账本。

每个目录分区独立 revision。原共享查询、变更事件及其消费者在同批改为携带 workspaceId 并按作用域比较 revision；不假设多个分区的 revision 全局可比较。中央全局索引只是定位和迁移路由，不存第二份事务状态。

| 读取情况                               | 权威来源                                               |
| -------------------------------------- | ------------------------------------------------------ |
| 已有合法目标目录且格式、身份和快照有效 | 目录分区；同机中央旧副本不可合并回来                   |
| 无目标，中央记录未迁移且源有效         | 中央源的该空间分区，可准备迁移                         |
| 中央记录 committed，但目标丢失或不可读 | 对应分区故障；不重新导入旧快照制造“恢复成功”           |
| 已有目标损坏、未知版本或身份不匹配     | 明确故障，优先本分区有效备份；不得当作缺文件创建空分区 |
| prepared 或 staged 的迁移中断          | 依据下节落盘状态完成或撤销准备，禁止双写               |
| workspaceId 为 null 或无法可靠定位     | 保留中央未归属区，经原认领动作与用户归属核验后再处理   |

新建本地事务直接建立目录分区。分区未加载与“事务列表为空”必须区分；公司聚合入口先 await 分区就绪，再查询真实快照。当前 `company-workspace-runtime.ts` 的同步 publications source 需在同批适配，不能因懒加载返回空发布列表。

启动时依据已有空间索引和迁移定位加载有后台工作可能的已登记空间，由原 owner 读取真实 waitPlans 并恢复原定时器。索引不保存另一套等待状态。空间不可达时该空间等待明确暂停；关闭 Tab 或切换空间不卸载仍有后台工作、待核验结果或未 flush 写入的分区。

### 迁移提交协议

以单个稳定工作空间为单位，禁止一次性扫描并改写整个主目录。WebAffairService 用原写队列及该空间的维护门阻止新执行和变更；当前长运行有界收束，不能安全停止则等待，不强行复制运行中状态。维护只覆盖迁移空间。

1. **读取和预检**：通过原 loader 收敛主文件、备份和恢复日志；固定该空间的事务集合、ID、revision、材料引用与内容摘要。其他空间可以继续通过同一 owner 使用中央文件。
2. **prepared**：在中央落盘迁移记录，保存不可变的迁移前源备份及该分区快照，记录源摘要、目标和 migrationId。权限收紧，业务内容不进入普通日志。
3. **staged**：在目标 `.cclink-studio` 下建立同文件系统临时目录，写入 storage 元数据、分区快照及所需备份，flush 后重新加载；验证 ID 集合、字段、证据、引用和身份。源恢复日志先收敛到完整快照，不能把带全局 revision／哈希的旧 recovery 原样放进新分区。此时中央仍是权威来源，目标不接受业务写入。
4. **target-finalized**：以同文件系统 rename 将已验证的临时目录切为正式 `web-affairs/`。目标已有内容时按一致性核验，不能覆盖冲突目录。
5. **committed**：中央记录落盘切为 committed，原 owner 读回目标并切换路由，随后释放维护门。业务写入必须在此步骤完成后才能开放；迁移目标一旦开始承接新写入，旧分区不再是可回退的最新数据。
6. **读回与展示**：从原公司与发布 UI 打开同一事务，展示迁移摘要。中央活动快照排除已迁移分区，旧内容保留在不可变备份；清理失败不改变权威路由。尚未迁移的其他空间仍可写中央文件，不能把整个中央源文件误称为只读。

所有持久步骤采用临时文件、原子替换和适用的文件及目录同步，写入串行。迁移按分区内容摘要判断源是否变化，不能因其他空间提高中央总 revision 而误判冲突，也不能忽略该分区本身变化。

### 迁移中断恢复

| 最后可靠阶段                       | 重启行为                                                                  |
| ---------------------------------- | ------------------------------------------------------------------------- |
| prepared 前失败                    | 原源继续可用；仅清理本次已知临时文件                                      |
| prepared 或 staged，正式目标不存在 | 校验源摘要后继续或撤销准备；此阶段从未开放目标业务写入                    |
| 正式目标存在，中央尚未 committed   | 校验 migrationId、身份和快照，补交中央记录后再开放；不向两个位置写入      |
| committed，目标有效                | 从目标恢复，中央备份不重放；中断运行走既有 interrupted／lost binding 收敛 |
| committed，目标丢失或损坏          | 停止该分区执行；定位目标或恢复经过校验的备份，不自动回用过时中央源        |
| 源或目标变化、阶段信息冲突         | 保留全部原件，返回结构化冲突及允许动作，不自动取时间较新文件或做逐项合并  |

迁移不得重新激活旧 final-action 授权。已提交但结果未知的对象只允许恢复核验；历史完成记录保留原证据与时间，不伪造新一次平台核验。

### 第二批任务

| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 分区格式与错误   | `src/shared/web-affairs/`；存储格式、迁移摘要、workspaceId 事件、版本/冲突/等待错误先行；只读导入历史格式留到第三批                      |

### 程序回退与数据回滚

迁移前失败可撤销准备并继续使用原源。迁移 committed 后、尚无新业务写入时，可在维护门内核验内容摘要，将该分区恢复为中央权威并保留目标备份。其他空间的数据必须保持不变。

目录分区已有新写入时，回退必须由理解新格式的版本导出最新兼容分区，验证后替换中央对应分区；存在旧版无法表达的新字段或证据时拒绝无损回退，保留新版本只读导出路径。回到迁移前备份属于明确的数据恢复，会丢弃之后变更，必须向用户列明并由其确认。

直接安装不理解目录格式的旧 App 可能只显示旧数据，不能将其宣称为已支持的数据回滚。不得依赖旧 App 能识别后来增加的保护标记。首次承载新格式的发布说明必须写清回退路径、备份位置与这一限制。

## 第三批 备份恢复和移动副本

### 第三批完成标准

从 UI 导出工作空间资料包，在隔离的新目录恢复并逐项打开；同机移动保留稳定身份，新副本获得新身份且无自动运行。外部材料、缺失账号和本机历史遗漏均可见。对应 D01 至 D08、E05、E06。

### 备份取得与验证

1. 用户选择空间、材料及目标目录，主进程验证目标在源目录之外，并预览范围、大小及遗漏。只读取已授权空间和显式选定外部文件。
2. WorkspaceStateService 提供身份来源；CompanyWorkspaceService 提供自己的事务快照；CompanyAccountsService 复用已有备份与原件验证；WebAffairService 提供分区及证据；ScheduledTaskService 提供定义和可选只读运行历史。不能直接 cp 正在写入的 SQLite/WAL 或混读 JSON。
3. 分别记录各域版本及取得时间，核验公司到账目/事务、事务到材料等引用。取得后若必要输入已变化，至多重试一次；仍变化则提示稍后重试，不无限冻结工作台，不声称跨库共同原子性。
4. 清单使用 `backupFormatVersion: 1`，记录来源稳定身份、每域 schema/revision、文件相对路径、字节数、摘要、外部缺口和不包含项。包内禁止路径穿越、越界链接及已识别的应用凭证文件；用户资料自身可能包含敏感内容，预览和选择不能由“自动脱敏”承诺替代。
5. 备份写入临时包，完整校验后提交最终包。只读任务历史不回灌原运行账本；不能为了“历史完整”复制本机激活、去重或权限文件。

### 恢复与引用映射

恢复在隔离 staging 目录预检，先展示创建副本或恢复原空间的选择及覆盖范围。替换既有目录或回退数据需要针对具体目标与备份的用户确认；新建到空目录沿用用户明确的恢复动作，不追加通用二次口令。

| 对象                 | 移动原空间                                                           | 创建副本及跨设备恢复                                                                             |
| -------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 空间身份             | 原稳定 ID，维护窗口中唯一切换                                        | 由 WorkspaceStateService 生成新稳定 ID                                                           |
| 公司库               | 校验 ID 不变，修正经证实的空间内引用                                 | 原 service 在事务内重绑空间 ID；保留空间内业务 ID 及来源                                         |
| 账目库及原件         | 复用原库及校验，内部相对引用保留                                     | 原 service 恢复，保留流水与确认历史；不执行新的财务动作                                          |
| 事务                 | 保留 affairId、历史和发布结果，旧 Runtime binding 不复活             | 分配新 affairId 并重建公司关联；原 Attempt、回执存只读导入历史，未完成工作生成不可自动执行的草稿 |
| 账号引用             | 仍解析同一本机全局账号，执行前核验实际身份                           | 来源账号引用不自动匹配；按用户显式选择的本机账号映射，不按名称或 URL 合并                        |
| 任务定义             | 保持 taskId 和原定义；旧路径改动由 owner 核验                        | taskId 可在新空间作用域保留；定义 schema 和摘要重新校验                                          |
| 任务激活及历史       | 暂停后重新确认路径再启用；本机历史按稳定空间 ID 关联，保留原发生路径 | 不导入 activation、occurrenceKey 或运行队列；历史仅只读文件，定义默认停用                        |
| Tab、Agent、Terminal | 原 transition 按新路径恢复静态现场，活跃进程不迁移                   | 默认干净现场；不会自动启动旧会话、PTY 或 BrowserTask                                             |

导入历史由 WebAffairService 增加有界只读查询，采用允许列表保留稳定证据引用，剔除临时执行凭据、Runtime session 和句柄；不能创建另一个历史 Store owner，也不能把历史 Run 接入执行索引。新事务及草稿与只读来源清楚区分，发布结果不因恢复而变成“本机刚完成”。

### 物理移动协议

移动是显式工作空间命令，与“将另一个目录设为默认”分开。运行、写队列、文件句柄和目录 watcher 先在原 owner 下有界收束；无法收束则返回等待原因。

同文件系统可用受控 rename；跨文件系统先复制到 staging 并逐项验证。沿用基础层有界维护记录保存原路径、目标、身份、摘要和切换阶段；在新目标通过校验前不改活跃路径。切换后更新基础索引、默认指针、业务路径解析和任务定位；旧路径保留为退役恢复材料，不再被当前版本作为第二可写空间打开。

中断后依维护记录确定源或目标，不能两边同时写。完整读回及重启通过前不删除原恢复材料；自动清理只处理本次创建且可证明无用户资料的临时文件。手工打开退役目录时显示定位新位置或创建副本。移动后先检查账号与任务定义，由用户重新启用，不批量补跑旧发生时间。

手工在文件系统移动原目录时，仅对具有本机可信定位信息的目录沿用已有“原路径不存在则视为移动”规则，并核验业务引用。没有本机可信定位信息时先恢复定位信息或由用户明确选择继续原空间／创建副本；受控跨设备导入默认副本。旧路径仍在或存在歧义时，先通过受控复制/恢复路径处理；不能先让基础层单独改 ID，再让公司库以身份错误失败。

## 完成与止损规则

每批收尾更新验收记录、相关当前事实源和 ADR 状态，列明真人通过项、自动化通过项、失败及未执行项。整个方案完成须三个用户增量的验收均通过；保留的本机历史及不携带登录态继续作为明确边界。

发现迁移数据不明、无法判定唯一权威位置或重复执行风险时，停止该空间迁移/执行，保留现有保护及原件，回到原路径的可用能力；不得降低保护条件、关闭原发布功能或用诊断增强替代主线交付。

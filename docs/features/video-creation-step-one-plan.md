## 四页设计

1. 稿件与口播：左侧只读原稿；中间独立分段口播和候选审阅；右侧画幅、时长、改写要求。
   明确“生成口播文字，不是生成声音”。底部确认保存与查看下一页骨架。
2. 分镜与素材：左侧段落参考，中间空画面，右侧素材来源禁用控件；底部空场景序列。
   段落不是已生成的镜头。没有搜索、下载、云视频或采用副作用。
3. 声音与节奏：配音/音乐设置占位、空试听区、无音轨时间线。TTS、上传和混音按钮禁用。
4. 预览与导出：空播放器、尚未检查清单、输出设置占位、无导出记录。不得显示假成功。

## 首步数据与边界

- 复用 MediaProjectService 作为唯一 owner，新增可选 narration 字段，旧工程无需破坏迁移。
- narration 保存稳定段落 ID、顺序、文字、口播 revision、确认 revision、改写要求、最近候选、
  最近生成任务 ID/状态/输入版本/错误。AI 候选只有明确采用才替换正文。
- 本轮沿用已有“每视频独立目录”，增加 script/narration.md 可读副本；JSON 为唯一事实源。
  可见目录迁移、全部素材相对路径和整工程便携搬迁不属于首步范围，不借此扩张主线。
- 保存使用 expectedRevision；保存中不允许覆盖后续编辑。AI 期间可离开页面，任务由主进程拥有；
  重启中断不自动重试。内容改变使确认失效；候选绑定输入版本，过期不直接应用。
- 调用模型前说明会发送原稿、当前口播、要求及可能产生模型用量；不新增视频/TTS Provider。
- 不删除已有素材、生成和合成代码。旧工作台保留为明确的兼容入口，与新页面骨架区分。
- Cmd/Ctrl+S 和关闭保护复用既有机制；本轮先可靠显式保存，不假称已实现自动保存。

## 拷问与止损

- 不能把现有分镜旁白换标签就叫独立口播：首步保存不得改写旧分镜。
- 不能把候选生成成功等同用户确认，不能让过期回复覆盖新编辑。
- 不能让模板文本冒充 AI 结果；未调用真实模型时只声明模拟链路验证。
- 不以做目录框架代替可用首步，不继续实现后续三步。持续开发 60 分钟无用户能力增量则停止扩张。

### 真人验收清单

1. 启动最新开发版本，打开本地工作空间，在“视频”侧栏选择 Markdown 新建。
2. 手写两段口播、移动顺序并保存确认；关闭 Tab，从侧栏重开，核对段落和确认状态。
3. 点击“AI 生成口播”，审阅发送内容/用量说明后确认；等待候选，检查事实和语气，采用并保存。
4. 修改一句正文，再保存；确认状态应失效，旧候选不能直接覆盖新版本。
5. 打开工程文件夹，核对 project.json 的 narration 和 script/narration.md；原稿不变。
6. 切换后三页：只能查看骨架，不能启动搜索、生成视频、配音或新版导出。

第 2/4/5/6 类动作已有自动化证据；第 3 步真实模型输出及真人质量判断仍待用户验收。

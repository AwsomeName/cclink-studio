# 本地链接目录

## 用户验收目标

在本地项目里通过 `ln -s` 建立目录链接后，用户能在 Studio 文件树展开它，打开其中的
Markdown、修改并保存到真实目录。外部目标首次访问需要确认，重启后保留确认结果。

## 当前行为与边界

- 文件树按真实目标类型识别目录链接，显示文件夹和链接标记，悬停可查看真实目标。
- 工作空间内部的目录链接可直接展开；外部目录由主进程原生对话框展示链接路径、真实目标
  和编辑影响，取消不会展开或授予权限。
- `FileService` 是文件权限唯一所有者。授权只匹配当前本地工作空间、链接路径、真实目标
  和目录/链接身份，持久化于 `userData/linked-directory-grants.json`，权限为 `0600`，
  串行原子写入。损坏记录按未授权处理，不阻止本地工作台启动。
- 授权不接受 renderer 提供的目标或确认布尔值。IPC 校验可信 renderer 和路径，确认前后
  复核工作空间及链接。授权只供交互式 Studio 文件访问使用，绑定工作空间的 Agent/MCP
  调用不继承；直接请求外部绝对路径也不会因此获准。
- 嵌套链接的最终目标仍须属于当前授权范围，越界时必须单独确认。断链和循环链接在文件树
  显示原因，子目录读取失败不隐藏整棵树。恢复展开状态不会自动弹出授权对话框。
- 更换、重建、移动或重命名链接会使原授权不再匹配，新入口再次展开时重新确认。删除后
  重建链接也可撤销原链接授权；目前没有独立授权管理界面。
- 重命名、移动、删除链接项只操作目录项，不操作真实目录；编辑或删除链接中的子文件则
  会影响真实文件。写入和原子保存使用已经验证的真实路径，并再次校验可见路径。
- 直接指向文件的符号链接仍不支持打开；目录中的普通文件可用。全局搜索仍跳过符号链接，
  Browser 本地 HTML 预览等独立模块不继承此文件权限。
- 本改动不提供 OS 沙箱，也不宣称完全消除外部进程并发替换真实父目录的 TOCTOU 风险。
  现有文件句柄检查和 `O_NOFOLLOW` 保留。

## 验收步骤

1. 在用户主目录下准备项目 A、项目外的目录 B，在 B 中建立 `note.md`，在 A 中建立指向 B
   的 `研发日记` 目录链接；用“打开工作空间”选择 A。
2. 点击 `研发日记`：应显示真实目标确认；取消后仍不展开，再点击并允许后可看到 `note.md`。
3. 打开 `note.md`，编辑后按保存快捷键，核对 B 中原文件确实改变。
4. 重启 Studio 并打开 A：链接目录仍可展开和读取，不重复询问。
5. 把链接改指向另一目录 C：未经再次确认，读取和写入均须失败；C 中内容不能改变。
6. 删除链接项：只移走链接，B/C 及其中文件保留。对断链、指向祖先的循环链接应显示就地错误。
7. 对 A 内部目录的链接重复展开和读取，应不出现外部目标确认。

## 工程验证与实际验收的区别

- 定向测试覆盖授权、取消、持久化恢复、工作空间切换、链接替换、嵌套越界、Agent 隔离、
  文件树状态和原生确认入口。
- `pnpm build && node scripts/linked-directory-smoke.mjs` 启动完整的构建产物，使用独立
  `userData` 和用户目录下由 `mkdtemp` 创建的工作空间。文件树点击、编辑器打开、快捷键
  保存、重启恢复、错误展示和系统废纸篓均经过真实 Electron。
- Smoke 仅自动代选原生文件选择器及授权对话框的响应；这属于应用集成自动化验收，
  不能冒充真人点击原生对话框。脚本保留隔离目录和截图供复核，不接触日常项目或配置。
- 2026-09-20 已在本机执行上述应用自动化；安装版尚需包含此代码的后续正式发布。

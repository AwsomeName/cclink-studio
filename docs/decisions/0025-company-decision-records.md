# ADR 0025：公司经营决策记录只保存决策，思考由一次性 Agent 会话完成

- 状态：accepted（2026-11-22 用户确认效果稿并要求实现）
- 日期：2026-11-22，Asia/Shanghai
- 产品方向：[经营决策卡效果稿](../design/company-home-decision-2026-11-22/README.md)；公司首页左栏最上方“帮我想清楚一个问题”。
- 关联：[ADR 0024](0024-personal-company-space-bindings.md)、[ADR 0023](0023-automatic-task-agent-selection.md)、[Owner 0.1](../design/owner-0.1/README.md)。

## 问题

技术背景的用户需要有人帮忙想经营问题（卖给谁、怎么定价），并把结论留在公司页面上可直接使用。思考需要 Agent；结论属于公司。若公司领域自己跟踪 Agent 运行，或把公司资料交给 Agent 随意读写，会产生第二个运行状态所有者，或扩大权限。

## 决策

1. 公司数据库新增 `decisions` 表（schema v3），每条决策记录保存：问题、用户补充情况、本次授权的只读资料范围、Owner 给出的追问与回答、已校验的建议草稿、用户最终决定和时间。
2. 思考由该决策专属的本地 Agent 会话完成（会话 ID `company-decision-<决策 ID>`，标题“Owner · 经营决策 · …”），Agent 选择复用 ADR 0023 的启动前检测。决策记录只保存会话 ID、本次派工票据和 runId 引用；运行状态、消息、权限仍归 Agent 服务，重开只按 runId 对账，不重派。
3. 资料以“仅作为数据”的只读摘要随委托发出，按用户勾选的范围裁剪：账目月度汇总、推广与客户记录摘要（不含客户姓名）、业务项目。默认不给 Agent 公司工具或文件写权限。“网上公开资料”默认不勾选；勾选后仅允许引用 http(s) 链接。
4. Agent 只能回复带票据的 JSON；主进程按 Zod 上限校验后才写入草稿。每条依据必须标注来源（已授权范围、用户补充或网址）和性质（事实／估算／未核实）；未核实项单独展示，不作为建议依据。
5. “采纳”只写决策结果，不改价格、不发消息、不动账目、不创建任务；“先不决定”保留草稿；“重想条件”只是文字，不做到期提醒。

## 与 Owner 的关系

本版不在 Owner“我的事务”列表中新建事务类型：Owner 0.1 的事务结构面向调研取证，硬塞决策会让列表状态失真。用户在决策卡上看到的“Owner”是同一工作方式（一次委托、追问、带依据交付、人来定），会话可在 Agent 面板中打开查看。若以后要在 Owner 列表统一显示，另行评审，不得复制决策状态到 Owner 存储。

## 不变量

- 决策记录是公司领域唯一的决策事实；首页、侧栏计数都从它投影。
- 账目、客户、推广事实仍归原领域；决策卡只引用，不回写。
- 公司未启用、Agent 不可用或运行失败时，首页其他部分照常可用，失败原因显示在卡片上。
- 不使用系统钥匙串，不修改云服务或独立 Agent runtime。

## 备选方案

- 在公司领域实现自己的 Agent 调度与状态：第二状态所有者，不采用。
- 给 Agent 开放读取整个公司数据库的 MCP 工具：权限面扩大且难以审计本次读了什么，不采用。
- 把决策作为 Owner 事务保存：现有事务结构不匹配，需改 Owner 存储，暂不采用。

## 验证

服务单测覆盖 v2→v3 迁移、草稿校验、版本冲突、采纳不改其他表；真实应用中交办 → 追问 → 决定 → 采纳，重启后决策仍在、不重复派工。

# ADR 0016：Agent 使用全局网站账号执行网页任务

- 状态：accepted
- 日期：2026-08-18
- 补充：ADR 0014 的全局账号目录与项目事务引用

## 问题

ADR 0014 已确定网站账号全局管理，Agent 也可以读取安全账号目录，但当时没有决定 Agent
能否打开和操作账号。只读目录不能完成审核查询、资料填报、应用商店发布准备、工商办理或
事务进度跟踪，产品也就不能形成“个人或公司的网页事务代理人”闭环。

本次产品决定不建设复杂权限中心，也不为 Apple、阿里云、工商或知识产权网站分别建立
执行架构。底层只提供一套通用能力，由上层 Agent 和事务复用。

## 用户可执行目标

1. 用户可以告诉 Agent“用哪个已登记账号做什么”；未指定且存在歧义时，Agent 必须询问。
2. Agent 能打开该账号唯一的登录环境，在当前工作空间得到可见 Browser Tab。
3. Agent 能在该网页读取、点击、填写、上传和下载，并把结果报告给用户。
4. 登录、验证码、扫码、签名、付款、账号安全和关键最终动作可以随时交给用户。
5. 用户处理完成后把页面交还 Agent，Agent 重新观察页面并继续，而不是从旧状态盲目执行。
6. 任务关联网页事务时，执行进度、卡点、证据和结果写回该事务；普通临时任务只回到当前
   Agent 对话，不强制创建事务。

## 决策

### 1. Agent 底层只开放四类能力

- **账号目录**：读取已登记网站、账号、主体、角色、用户确认状态和运营矩阵的安全投影。
- **账号启动**：用显式 `accountId` 解析唯一入口和 Browser Profile，在当前工作空间打开或
  激活可见 Browser Tab。
- **网页操作**：通过绑定该 Tab 的 BrowserTask 读取、点击、填写、上传和下载。
- **人工接管**：暂停当前 BrowserTask，用户在同一可见页面处理后交还，Agent 重新观察再继续。

密码、Cookie、Token、验证码、恢复码和 `browserProfileId` 不提供给模型。Agent 获得的是
受控网页使用能力，不是凭证本身。

### 2. 授权采用“明确任务 + 敏感动作人工接管”

- 用户在 Agent 对话中明确要求使用某账号，或从已绑定账号的事务节点点击“交给 AI”，即构成
  本次任务的普通网页操作授权，不再增加逐项目配置、全局总开关或复杂权限等级。
- Agent 必须使用显式账号；无法唯一确定账号、主体或目标时先询问，不能根据当前 Tab、URL、
  Cookie、Profile 名称或最近使用记录猜测。
- 查询、页面导航、填写草稿、上传用户已选择的材料、下载回执可以在任务范围内执行。
- 对外提交、发布、发送、删除、注销、撤回、接受协议、真实性或法律声明、付款、电子签名、
  账号安全和权限变更必须转人工接管，由用户在可见页面完成；验证码、扫码、人脸和 2FA
  同样只允许人工处理。

### 3. 执行链只有一条

```text
Agent 读取账号目录并确定 accountId
  → 主进程校验账号存在、未归档和任务上下文
  → renderer 复用统一账号启动入口创建/激活当前工作空间 Browser Tab
  → BrowserTask 固定 accountId、tabId、profileId、conversationId 和 agentRunId
  → 在同一可见页面执行普通网页动作
  → 敏感边界暂停、确认或人工接管
  → 交还后重新观察
  → 有事务则由 WebAffairService 保存进度、Attempt、证据和结果
```

主进程不能为 Agent 建立第二套隐藏账号浏览器；renderer 不能自行拼装账号入口或 Profile；
BrowserTask 不能在执行中改用全局活跃页面。

### 4. 状态所有权和生命周期

- `WebResourceService` 继续唯一拥有全局账号元数据和 Profile 绑定，只向 Agent 返回安全投影。
- `Workspace/Tab` 基础层继续拥有当前工作空间的可见 Browser Tab 投影。
- `BrowserTask` 只拥有一次网页执行、页面关联、暂停和动作日志；同一账号首版只允许一个
  Agent BrowserTask 执行，冲突时明确等待或拒绝，不并发写网页。
- `WebAffairService` 继续唯一拥有事务、流程节点、Attempt、人工交接、证据和等待状态。
- Browser 工具动作守卫承担账号任务的产品级敏感动作阻断并暂停 BrowserTask；
  `PermissionManager` 仍负责通用工具确认，但其确认不能授权 Agent 执行账号任务的最终动作。
  不新增永久账号授权 Store。
- 进入人工接管时 Agent 运行可以结束或暂停；交还时必须新观察页面。进入外部等待时当前
  BrowserTask 和 AgentRun 结束，后续检查创建新运行，不保留假运行。

### 5. 失败降级

- 账号不存在、已归档、身份不明确、登录失效或跨站后无法确认身份：停止并请用户处理。
- 验证码、扫码、人脸、风控或平台阻止自动化：转人工，不尝试绕过。
- Browser Tab、BrowserTask 或 Agent 绑定失败：不执行网页动作，不改事务为成功。
- 无可靠结果证据：只能记录“待验证”“需要人工处理”或“外部状态未知”。
- Agent 账号执行模块故障不能阻断用户手动打开账号、普通 Browser、Editor、Terminal 或其他
  Studio 本地能力。

## 不变量与禁止项

1. 不向模型、renderer 日志、事务快照或诊断输出密码、Cookie、Token、验证码、恢复码或
   `browserProfileId`。
2. 不建设逐项目账号授权配置、全局“允许 AI 使用全部账号”开关或第二套账号 Store。
3. 不为特定平台增加账号启动分支；所有账号先走通用 Browser 能力。
4. 不把账号目录可见、事务引用存在或侧栏“已登录”直接解释为实时网页身份已核验。
5. 不让通用点击绕过敏感动作阻断；最终外部动作必须停下并由用户接管完成。
6. 不让 Agent 处理验证码、人脸、电子签名或秘密值，也不绕过网站条款和风控。
7. 不在首版开放运营矩阵批量执行、后台无人值守提交、团队权限、云端账号共享或平台适配器。
8. 不把 BrowserTask、Agent Thread、Tab 或定时任务变成第二事务状态所有者。
9. 不用 Mock、Schema、单测、工具调用成功或“按钮点到了”替代真实网站结果证据。

## 备选方案

- **只让 Agent 看账号，不允许执行**：拒绝。不能形成网页事务代理闭环。
- **为每个项目逐个配置账号权限**：拒绝。重新引入全局账号已经消除的重复配置。
- **一个全局总开关放开全部账号和动作**：拒绝。无法限定主体和高风险外部副作用。
- **先做各平台专用适配器**：拒绝。会把产品重新做成预定义网站能力矩阵。
- **所有网页动作逐次弹窗**：拒绝。普通查询和草稿准备无法连续执行；只在敏感边界确认。

## 复审条件

- 单账号通用执行闭环经真人验收后，需要开放运营矩阵串行批量任务；
- 真实站点证明仅靠通用动作守卫无法可靠识别最终外部动作；
- 团队、多用户或云端账号共享成为正式产品目标；
- 同一账号并发需求无法用首版单任务占用满足；
- 需要把成功轨迹升级为平台增强程序或后台定时执行。

这些变化必须新增或更新 ADR，不能在实现本决定时顺手扩张。

## 验证

- Agent 能从真实登记目录选择一个明确账号，在当前工作空间打开正确可见 Tab，并复用该账号
  原登录环境；另一个工作空间的 Tab 不被移动。
- 两个同站账号分别执行时页面身份不串用；无法核验身份时停止。
- Agent 能完成一次真实只读状态查询，返回页面状态和可复核证据。
- Agent 能填写并保存一次草稿；最终提交、付款、删除或协议接受被阻止并转人工完成。
- 用户接管完成登录或验证并交还后，Agent 重新观察并继续；旧页面假设不被沿用。
- 关联事务的 Attempt、节点状态、卡点和证据由 `WebAffairService` 恢复；临时任务不创建假事务。
- 受影响 smoke、`pnpm verify` 和本文定义的真人端到端步骤全部通过后，才可声明对应产品
  里程碑完成。

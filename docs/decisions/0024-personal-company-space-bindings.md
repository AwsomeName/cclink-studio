# ADR 0024：个人与公司固定入口引用现有工作空间

- 状态：proposed
- 日期：2026-11-12，Asia/Shanghai
- 产品方向：用户已确认“我的空间 / 我的公司”两个固定入口；本轮仅设计，不实施。
- 关联：[产品设计](../features/personal-company-spaces-product-design.md)、[实施计划](../features/personal-company-spaces-development-plan.md)。

## 问题

单一默认空间解决了默认保存位置，却没有稳定区分个人与公司。公司入口跟随当前目录，使用户切到研发目录后可能看到另一份空公司。旧默认目录可能已经包含公司、账目及个人内容，不能通过改名和复制数据库完成兼容。

## 决策提案

1. 顶栏固定个人与公司两种用途。二者引用不同的普通本地工作空间，不增加 WorkspaceRef kind、第二套 WorkspaceManager 或公司运行时。
2. 用途关联由现有 WorkspaceStateService 统一持久化和校验，引用基础层稳定身份与登记位置；启动偏好、实际活跃空间与用途关联是不同事实。
3. “公司经营 / 公司账目”顶层快捷入口前往绑定公司；历史 Tab、业务链接和原记录保留显式原 scope，不能强制重定向到主公司。
4. 兼容只绑定引用；旧公司目录整体保留，混合资料不自动拆分。原默认已是公司时，为个人用途提供独立空间。多个候选需用户选定。
5. 只读识别使用已登记且已授权的目录和稳定身份；损坏、丢失、无权限不冒充“没有公司”。不降低安全检查以提高识别率。
6. 固定引用与兼容版本一次原子写入；失败保留原关联，已初始化目录可重试复用。旧默认设置保留为回退证据，不双向维护第二份绑定。
7. 账户、账号、Profile、Agent、发布、定时任务的 owner 与执行权限保持原边界。切换入口或换绑不搬迁运行、不复制授权、不触发外部提交。

## 与 ADR 0020 的关系

实施并验证后，替代 ADR 0020 中“单一默认入口”及公司导航跟随当前空间的产品入口前提。ADR 0020 的工作空间内资料归属、全局网站账号、本机运行授权、原路径失效不建空目录以及移动复制边界继续有效。本 ADR 不授权事务迁移或公司资料拆分。

## 不变量

- 两个固定入口不得引用同一稳定身份或同一实际目录；首版也不允许根目录相互包含。
- 公司服务只拥有公司数据；所有空间切换、Tab 和现场继续经过基础层原 transition。
- 公司未启用或故障不阻断个人能力；个人空间故障也不阻断可用公司与普通空间。
- 默认初始化、候选选择与名称修改不构成 Agent 执行、账号操作、发帖或调度授权。
- 不使用系统钥匙串，不修改云服务或独立 Agent runtime。

## 备选方案

- 两个标签引用同一目录：无法形成明确资料归属，不采用。
- 复制旧公司到新的公司目录：会影响稳定身份、账目关联、事务和历史记录，不采用。
- 扫描所有目录并自动合并公司：没有可靠归属依据，且扩张权限，不采用。
- 创建独立公司容器和独立会话系统：增加第二状态与生命周期，不采用。

## 风险、迁移与验证

主要风险为混合资料误分类、多个旧公司被误选、半提交的用途关联，以及全局公司快捷命令误伤旧记录 deep link。按产品兼容矩阵与 P1–P3 验收；先取得个人记录与旧公司下钻的真实闭环，再调整侧栏。

## 回收或复审条件

需要多公司并列固定入口、多人权限、公司数据拆分／合并、跨设备同步或将远程空间作为固定个人／公司空间时，重新评审。本次不预建这些框架。

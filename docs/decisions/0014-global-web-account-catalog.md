# ADR 0014：全局网站账号库与项目事务引用

- 状态：accepted
- 日期：2026-08-18
- 负责人：CCLink Studio Maintainers
- 取代：`docs/features/ai-web-affairs-agent.md` 中“网站账号必须属于单一项目”的旧产品约定

## 问题

当前 `WebAccount.projectId` 把同一个网站账号变成单一项目资源。用户在多个项目复用 Apple
Developer、阿里云、微信公众号或一组运营矩阵账号时，必须重复添加、重复登录，并产生彼此
独立的 Browser Profile。这既增加配置成本，也会让同一真实账号在 Studio 中出现多个身份和
登录状态。

用户已经确认：网站与账号应统一管理并跨项目复用；事务仍属于具体项目；AI 是否可以调用
账号暂不决定。

## 用户验收目标

1. 用户只添加并登录一次网站账号；切换任意本地项目后仍能看到同一账号。
2. 在不同项目点击同一账号，Studio 在当前项目打开 Browser Tab，但复用同一个账号 ID、
   Browser Profile、Session 和登录状态。
3. 用户可以把多个全局账号组成一个可复用的运营矩阵，不必在每个项目重复配置。
4. 事务继续只属于当前项目，可以保存全局账号或运营矩阵的稳定引用，但不复制账号和登录态。
5. 本次变更不新增、推断或放宽 AI 使用账号的权限；相关产品决定另行评审。

## 决策

1. `WebResourceService` 继续是网站、业务主体、账号、账号组和账号元数据的唯一状态所有者，
   但资源作用域从“单一项目”调整为“本机 Studio 全局”。
2. `WebAccount` 使用全局稳定 `accountId`，不再以 `projectId` 作为所有权字段；同一个账号只
   绑定一个正式 Browser Profile 和一套持久 Session。
3. “网站与账号”Activity Bar 入口展示全局账号库。切换工作空间不切换账号集合；用户从
   任意工作空间点击账号时，在当前工作空间创建或激活一个可丢弃 Browser Tab 投影。
4. Browser Tab 仍属于工作空间并参与该工作空间的 Tab 恢复，但只保存全局 `accountId`
   引用；Tab 不是账号所有者，关闭 Tab 不删除账号或 Session。
5. `WebAffairService` 继续以稳定 `workspaceId` 拥有事务、材料、流程、Attempt 和证据。事务
   可以保存全局账号或账号组引用；是否允许 Agent/BrowserTask 自动调用这些账号不在本 ADR
   决定范围内。
6. 新建账号仍采用“先进入真实网页并登录、后只确认显示名称”的单路径。新建动作从当前
   工作空间打开临时 Browser Tab，但保存结果进入全局账号库，按钮和成功文案不得再写
   “保存到当前项目”。
7. 增加全局账号组 `WebAccountGroup`，产品名称使用“运营矩阵”。账号组只保存稳定
   `accountId` 集合和版本，不复制账号、Profile 或 Session。事务引用矩阵时必须保留绑定
   版本或当时解析出的账号清单，矩阵后续变化不能静默扩大旧事务范围。
8. 现有 v2 账号迁移为全局账号时保留原 `accountId` 和 `browserProfileId`。疑似重复账号
   不自动合并；用户明确选择主账号和保留的登录环境后才能合并或归档其他记录。
9. 账号被事务或历史证据引用时不得直接物理删除；首版使用归档语义保留稳定引用。

## 不变量

1. 密码、Cookie、Token、验证码和网页正文不进入 WebResource 快照；真实 Session 继续由
   `BrowserManager` 持有。
2. 事务仍属于项目；本地材料、流程、证据和事务列表不改成全局对象。
3. “所有项目可见”不等于“所有 Agent 可调用”。本次不得新增 AI 自动选号、默认授权、
   跨事务调用或自动发布能力。
4. renderer 只持有可丢弃投影，不建立第二个账号 Store，不根据 URL、当前 Tab 或 Profile
   名称猜测账号。
5. 账号 Profile 变化会影响所有引用该账号的工作空间；界面必须把重新登录、退出和状态变化
   表达为全局影响。
6. 工作空间删除、移动或复制不能删除、复制或重新拥有全局账号。
7. 最终发帖、提交、付款、删除等不可逆外部动作继续需要产品级人工确认。

## 备选方案

- **继续让账号属于项目**：拒绝。无法解决运营矩阵和公共企业账号的重复配置、重复登录与
  身份分裂。
- **复制账号元数据但共用 Profile**：拒绝。会产生多个资源 ID、重命名冲突和删除生命周期
  分叉。
- **全局账号默认开放给所有 AI**：拒绝。当前尚无经过真人验证的授权模型，会扩大串主体、
  串账号和跨事务副作用风险。
- **账号全局，但每个项目先建立一份授权配置**：本轮不采用。它会把用户刚要求消除的逐项目
  配置重新引入；事务或人工操作中的显式选择已经能表达资源引用。

## 风险与影响

- 同一账号在多个工作空间同时打开时共享 Session；一处退出登录会影响全部工作空间。
- 旧项目可能各自保存了同一真实账号，迁移后会出现疑似重复项；不能用标题、URL 或 Cookie
  启发式静默合并身份。
- 运营矩阵变化可能扩大事务影响范围，必须使用版本或绑定快照阻止静默扩权。
- 当前事务和 AI Attempt 代码包含 `account.projectId === workspaceId` 校验。迁移时必须先让
  人工打开和事务引用使用全局资源，再单独评审 AI 调用边界；不得简单删除校验后直接放开。
- 当前账号保存、侧栏文案、IPC 和测试大量使用“当前项目”，需要一次完整 Schema 迁移和
  真实 App 跨工作空间验收，不能作为纯 UI 改名处理。

## 迁移计划

1. 发布可回滚的 WebResource v3 迁移：保留 v2 原文件与备份，逐项保留 ID、Profile 和登录
   确认时间，移除账号单项目所有权。
2. 先交付全局列表和全局新建，再交付跨工作空间 Tab 复用；任何阶段失败时不阻断普通浏览器。
3. 为旧账号生成疑似重复诊断，只提示用户处理，不自动合并或清理 Profile。
4. 迁移事务的账号引用时保持 `workspaceId` 和 `accountId` 不变；账号组是新增引用类型，旧事务
   不自动加入矩阵。
5. AI/Attempt 路径在新授权方案确认前保持 fail-closed，不因账号全局化获得额外调用范围。
6. 全部数据迁移和 UI 通过后，删除仅用于 v2 `projectId` 所有权的兼容写路径；读取兼容保留
   至少一个稳定版本周期。

## 回收或复审条件

- 产品决定账号需要团队、云端或多用户共享；
- 事务真人验收后需要正式定义 AI 调用账号的授权模型；
- 同一账号并发操作出现可复现冲突，需要引入账号级运行串行或租约；
- 运营矩阵需要动态成员、审批或团队权限，超出本机单用户账号组范围；
- 发现全局账号可见性造成不可接受的隐私或项目隔离风险。

## 验证

- 项目 A 新建并登录账号，项目 B 能看到同一 `accountId`，且不会生成第二账号。
- 项目 A、B 分别打开该账号时使用同一 `browserProfileId`，Tab 仍分别属于各自工作空间。
- 任一 Tab 重新登录或退出后，所有工作空间看到一致登录状态。
- v2 迁移保留账号、Profile、事务引用和备份；疑似重复项不自动合并。
- 运营矩阵可跨项目复用；修改矩阵不会静默改变已绑定事务的账号范围。
- 事务列表仍按工作空间隔离；未确认的 AI 路径没有获得新的账号调用能力。
- 真实 App、受影响 smoke 与 `pnpm verify` 均通过后，才能声明对应里程碑完成。

## 用户验收动作及判定

1. 在同一版本 Studio 中选择已授权文章、三图及对应账号，开始发布；记录实际运行版本、文章、任务 ID。
2. 逐个平台查看准备、账号、正文、图片、平台字段、保存、提交、结果核验的真实步骤；等待原因与可继续动作必须可见。
3. 填写、上传、提交均由 Studio Agent／有界 Runtime 完成。不得由外部工具补发、改持久化状态或重建任务绕过结果未知。
4. 打开公开结果，对照全文及三图，保存 Studio 界面证据与 WebAffair 结果。点击成功、草稿保存、平台审核中均不算公开核验完成。
5. 连续三轮均覆盖六平台，使用同一源码版本；逐次记录是否修改代码、重启、人工定位页面、恢复任务及重复提交。三轮是本轮验收门槛，不是长期可靠性的统计保证。

正常投稿需要改代码、重启救场或人工补操作，即不能通过无干预验收。登录／验证码由用户完成、平台审核等待单独记录；必须验证清晰提示与原任务安全续接，不混作自动完成。发生有证据的软件阻塞才修复，修复后以新版本重新累计连续轮次，保留此前失败证据。

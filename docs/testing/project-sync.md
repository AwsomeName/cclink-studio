# 项目同步验收

日期：2026-11-25。决策：[ADR 0026](../decisions/0026-project-sync.md)。设计：[项目同步产品设计](../features/project-sync-product-design.md)。

## 当前结论

- **工程门禁已过**：真实 Git 两台电脑单测（`src/main/git/project-sync.test.ts`、`src/main/company-sync/company-sync.test.ts`）；真实 Electron 两个独立应用目录模拟两台 Mac 的 smoke（`scripts/project-sync-smoke.mjs`，GitHub API 为主进程内替身，Git 远端为本地裸仓库）。截图在 [acceptance](../design/project-sync-2026-11-24/acceptance/)。
- **真人验收未做**：还没有在真实 GitHub 私有仓库和第二台 Mac 上走过下面的步骤。通过前不能宣称能力完成。

## 准备

- 两台 Mac 都装同一版本 Studio，并在 设置 → API Key 与连接 → GitHub 保存同一个账号和 Token（需要 `repo` 权限）。
- 第一台有一个公司项目（不是 Git 仓库），里面有普通文件、一个 `.env`、一个超过 50 MB 的文件；公司首页已启用，至少有一条售后记录和一个月的流水。

## 步骤与预期

1. **第一台：设置同步。** 公司首页“同步”卡片 → 设置同步 → 选“在 GitHub 新建私有仓库” → 核对“第一次会上传什么” → 保存并同步。
   预期：
   - 全程没有额外密码。
   - 不会上传列表里有 `.env` 和大文件。
   - 状态栏变为“已同步 · 时间”。
   - 在 github.com 上，仓库显示 Private，里面有项目文件和 `.cclink-studio/shared/company/`。
   - 仓库里没有 `.sqlite`、`.env`、大文件，提交信息里没有客户名和金额。
2. **第二台：下载。** 新建／打开 → 从 GitHub 下载项目 → 选这个仓库 → 选保存位置 → 下载并打开。
   预期：
   - 打开后状态栏是“已同步”。
   - 点“开始使用”启用公司视图后，售后记录、流水和原件与第一台一致。
3. **双向。** 在第二台改一篇文档、新记一条售后、确认一条流水，然后点“立即同步”。回到第一台，切进项目，或点“立即同步”。
   预期：三项都出现，月度收支随之变化。
4. **同一条记录两边都改。** 两台都改同一条售后的“下一步”，先后同步。
   预期：
   - 后同步的一台暂停，按字段并排显示两份。
   - 选一份后两边一致，这台电脑上的记录在选择前不变。
5. **同一份对账单。** 两台各自导入同一份流水，各同步两次。
   预期：没有重复流水，已确认的那一笔保留。
6. **表格冲突与大量删除。** 两台同时改同一份 xlsx；第二台删除一个含 30 个文件的文件夹。
   预期：
   - 表格可选这台的、另一台的，或两份都留。
   - 删除先暂停，可选“照做”或“不删除，重新上传”。
7. **仓库变公开。** 在 GitHub 把仓库改为 Public，再在 Studio 立即同步；然后改回 Private，点“已改回私有，重新检查”。
   预期：
   - 公开期间显示“仓库不是私有的，同步已暂停”，不上传也不接收。
   - 改回私有后继续同步。
8. **降级。** 断网；清除 GitHub Token；填一个公开仓库地址设置同步。
   预期：
   - 断网或清除 Token 时，本机项目、公司首页、账目照常可用，状态如实。
   - 公开仓库地址无法保存。
9. **代码项目。** 打开 cclink-studio。
   预期：同步卡片写“由 Git 管理”，没有自动提交。

## 已知限制

- 只支持 `https://github.com/<账号>/<仓库>`；SSH 和其他平台不支持。
- 首次读入要等第二台的第一轮同步完成（打开项目时自动触发）；启用公司视图前记录已经读入，但页面显示“启用公司视图”。
- 两台各自导入同一笔流水后，如果两边都改过它，只保留修改次数多的一份，另一份的修改不会作为冲突询问。
- 客户记录删除或修改后，旧内容仍留在 Git 历史里。
- 决策记录引用的 Agent 会话只在原电脑上。

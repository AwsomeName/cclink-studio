# 本地地址导航回归

## 用户验收

在连接小米路由器的电脑上，打开 Studio 的浏览器新标签，在地址栏输入
`192.168.31.1` 并回车。地址应使用 HTTP，最终显示小米路由器登录页。
无需登录路由器或修改设备设置。独立浏览窗口应使用相同的地址补全规则。

## 2026-11-09 实测

- 路由器 HTTP 端口返回 200；HTTPS 443 端口拒绝连接。
- 修复前，真实 Studio 中输入裸 IP 被补成 `https://192.168.31.1`，
  页面显示 `ERR_CONNECTION_REFUSED`。
- 修复后，在同一 Studio 中输入裸 IP，地址变为
  `http://192.168.31.1/cgi-bin/luci/web`，原生网页视图显示“欢迎使用小米路由器”
  和管理密码输入框。未输入密码、未修改路由器设置。
- 系统设置中的 Studio 本地网络权限处于开启状态，未改动该权限或系统代理。
- 用户提供的旧日志同时包含 HTTP 和 HTTPS 的 `ERR_ADDRESS_UNREACHABLE`。
  该错误在本轮 HTTP 实测中没有复现；本次确认并修复的是地址补全缺陷，
  不把旧进程的不可达错误归因为已证实的权限故障。

## 实现边界

- 主窗口和独立窗口共用 `normalizeBrowserAddress`；仅处理用户地址栏输入，
  导航、权限和 Browser View 生命周期仍由现有主进程入口拥有。
- 裸私有 IPv4、回环、链路本地地址、IPv6 ULA、`.local` 和 `localhost`
  使用 HTTP；其余地址仍默认 HTTPS。不进行 DNS 探测或失败后的协议降级。
- 用户显式输入的 HTTP/HTTPS 协议保持不变；包含凭证的输入不推断明文协议。
- 不更改代理、证书校验、系统权限、浏览器缩放或页面内容。

## 工程验证

- 地址补全及相关浏览器用例：5 个测试文件、51 项通过。
- `pnpm typecheck` 与受影响文件 ESLint 通过。
- `node scripts/ui-smoke.mjs --tab-create-only` 覆盖真实地址栏输入无协议的本地
  HTTP fixture、Browser View 成功加载，以及失败页返回原网页。首次执行未找到隔离实例
  的 CDP 端口，尚未进入用例；干净重跑通过（1/1）。

回归边界：公网地址和形似内网的公网域名仍用 HTTPS；显式 HTTPS 内网地址不被降级；
路径、端口、查询参数保留；原有失败/重试路径保留。独立窗口复用已测试的补全函数，
本轮真人界面验证针对主窗口，未单独重复独立窗口的路由器加载。

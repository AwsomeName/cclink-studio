# Markdown A1-A9 真实应用验收（2026-11-25）

> 对照：`docs/features/markdown-editor-review-and-stabilization-plan.md` 的 A1-A9。
> 版本：`main` @ `a4586094`（v0.2.31 之后），`electron-vite build` 产物。
> 方式：`scripts/markdown-a1-a9-acceptance.mjs` 启动真实 Electron，隔离 home、userData 与工作区，
> 全部使用模拟文档；不需要模型或账号。连续两轮结论一致。
> 结论：**4 项通过、3 项部分通过、2 项不通过**；Markdown 稳定完成声明仍不能恢复。

## 用户现在能做什么、还不能做什么

- 能：打开常用 Markdown 即为已保存状态；改一段、保存、关闭重开，内容和行内格式都在；含
  Frontmatter、脚注、原始 HTML、指令块的文件不会被改写，可以“切到源码”逐字编辑；外部改动
  与草稿冲突时，“保存并关闭”不会丢草稿，必须显式覆盖或重新载入；`.txt/.json/.ts/.py` 进入
  源码编辑且逐字保存，HTML 的网页预览与源码是两个明确入口；同名新建被拒绝且原文件不变。
- 不能：Agent 写入仍绕过打开中的文档直接改磁盘；首次保存会重排未触碰的表格并追加空行；
  打开含多张大图的文档要等 12 秒以上，没有任何预算或降级；已打开但非当前 Tab 的文档不能被
  Agent 保存；保存与关闭、重命名、文件监听交错的竞态没有真实应用证据。

## 逐项结果

| 项                      | 结果     | 证据                                                                                                                                                                                                                                                               |
| ----------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A1 普通编辑闭环         | 部分通过 | 打开后显示“已保存”、无 dirty、磁盘未变；修改一段并 ⌘S、关闭重开后修改仍在，粗体/斜体/删除线/行内代码及嵌套全部保留。但首次保存把未触碰的表格改写为 `\| 列A  \| 列B  \|`、对齐 `:-:` 改为 `:---:`，并多出 2 个空行。语义等价，字节不等价，Git diff 会出现无关改动。 |
| A2 范围外语法退路       | 通过     | 打开时显示“文档未被改写”，磁盘不变；工具栏“切到源码”可用；只改一行普通文本并保存后，diff 只有那一行，Frontmatter、脚注、HTML、指令块逐字保留；文件树始终可用。                                                                                                     |
| A3 外部冲突与关闭       | 通过     | 输入未保存内容后外部改写文件，出现冲突条；关闭 Tab 选“保存”后 Tab 和草稿都保留，磁盘仍为外部版本；点“覆盖”后才写入草稿。另存为、合并和“任一路径失败后恢复”未逐一覆盖。                                                                                             |
| A4 Agent 与用户共同编辑 | 不通过   | 在 `editor_write` 的真实边界（直接写磁盘，`src/main/mcp/modules/editor/index.ts:228`）模拟 Agent：用户有草稿时 Agent 内容直接落盘，编辑器只能事后显示冲突条；草稿仍在视图中，未保存修改时会实时重载。A4.3 要求请求命中文档会话、不绕过草稿写磁盘，当前架构不满足。 |
| A5 精确目标保存         | 部分通过 | 从主进程发送 `editor_save` 同款 `editor:saveRequest`：未打开的 C 立即（<1 ms）返回“目标文件未在当前编辑器会话中打开，无法保存”，不再等 30 秒；没有任何串写。但 B 已在非当前 Tab 打开并有草稿时，同样被拒绝而不是保存 B。                                           |
| A6 文件类型路由         | 通过     | `.txt/.json/.ts/.py` 全部进入源码编辑器，不经过 Markdown 解析；`.txt` 追加一行保存后与原文逐字一致；`.html` 提供“网页预览 / HTML 源码”两个入口。                                                                                                                   |
| A7 重复保存与并发关闭   | 部分通过 | 连续两次 ⌘S 不误报冲突，磁盘为最新内容；“保存并关闭”正常落盘并关闭。A7.3 保存完成前继续输入、A7.4 双“保存并关闭”、A7.5 保存中关闭重开/迁移、A7.6 监听读取竞态、A7.7 等待期间重命名，都需要可控的主进程延迟注入，本轮没有真实应用证据（只有单元测试）。             |
| A8 大图片降级           | 不通过   | 8 张 1600×1200 噪声 PNG（每张约 7.7 MB）：打开到可编辑约 12.1 秒，同环境小文档约 1.3 秒；8 张全部以 data URL 进入 DOM，合计约 82 MB；没有预算、懒加载或降级提示。打开完成后的 4 秒内最长帧间隔 19 ms，卡顿集中在加载阶段。                                         |
| A9 排他新建             | 通过     | 在含 `notes.md` 的目录新建同名文件：提示“新建文件失败: 目标文件夹中已存在同名文件或文件夹”，原文件逐字不变，未打开新 Tab。                                                                                                                                         |

## 与审查文档的差异

- P1-2 文件路由、P1-4 范围外退路、P0-4 排他创建已在真实应用中成立，可以从“待验收”移出。
- 新发现：首次保存的表格格式与空行改写（A1）。它不是数据丢失，但违反“未触碰结构完整保留”，
  且会让日记等 Git 同步项目产生无关 diff。
- A5 的 30 秒超时已不存在；剩余缺口是“已打开但不在前台的会话”不可被定向保存。

## 建议的整改顺序

1. A4：Agent 写入改走受管保存，携带磁盘版本并与打开中的会话协调（P1-1）。这是唯一会让用户
   修改被静默覆盖到磁盘的路径，且“每日起草”正落在这里。
2. A8：图片按可见性懒加载，设单图与总量预算，超限显示占位与降级提示（P1-6）。
3. A1：序列化保留未触碰表格的原始文本与结尾空行，或在保真门禁中把这类改写视为差异。
4. A7：为保存、关闭、重命名和文件监听加可控延迟注入，补真实应用竞态验收。
5. A5：非前台会话的定向保存属于 DocumentSession（M3/M4），在 1、2 之后再评估。

## 用户现在能做什么

- 打开常用 Markdown 即为已保存状态；只改一段并保存，其余内容（含表格原有排版）逐字不变。
- Frontmatter、脚注、原始 HTML、指令块不被改写，可“切到源码”逐字编辑。
- 外部改动与草稿冲突时，“保存并关闭”不丢草稿，必须显式覆盖或重新载入。
- 用户有未保存修改时，Agent 的 `editor_write / append / insert` 被拒绝并收到
  `EDITOR_SESSION_DIRTY`，不覆盖任何一方；文档干净时 Agent 写入经版本校验落盘并实时显示。
- Agent 的 `editor_save` 能保存后台 Tab 中的文档；未打开的文件立即报错，不再串写或等待超时。
- `.txt/.json/.ts/.py` 进入源码编辑且逐字保存；HTML 的网页预览与源码是两个明确入口。
- 保存、关闭、重命名、文件监听交错时草稿不丢、不乱序。
- 含多张大图的文档秒开：图片滚动到附近才加载、同时最多 2 张；超过 5 MB 的图片显示
  “图片较大（x MB），为保持编辑流畅未自动加载”和“加载此图片”。
- 同名新建被拒绝且原文件不变。

## 本轮整改

- A4：`editor_write / append / insert` 先经 `editor:sessionStateRequest` 询问渲染进程；有未保存修改或
  待处理冲突时返回 `EDITOR_SESSION_DIRTY`；否则经 `saveTextDocument` 携带读取时的磁盘 hash 原子写入，
  期间磁盘被改返回 `EDITOR_DISK_CHANGED`；渲染进程 5 秒不应答返回 `EDITOR_SESSION_UNKNOWN`。
- A5：保存与会话状态请求改由窗口级 `use-editor-agent-requests` 统一应答（以 editor-store 为准），
  不再由各编辑器组件各自应答，后台 Tab 可被定向保存，也不会出现两个挂载编辑器抢答。
- A8：`markdown-image-budget` 提供可见性懒加载、2 路并发队列与 5 MB 自动加载上限。
- A1：保存时把单元格与对齐未变的表格还原为磁盘原文，并在代码块外折叠序列化器多加的空行。

## 残余风险

1. Agent 用 shell 命令（例如 Codex 的 `commandExecution`）直接写文件时不经过 `editor_write`，
   不受 A4 保护，只能靠外部变更检测显示冲突。“每日起草”若走 shell 写日记，仍可能在用户编辑时落盘。
2. A4 的检查与写入之间用户恰好开始输入，写入仍会落盘，编辑器随即显示外部冲突（既有保护）。
3. 2026-11-26 起，保真门禁比较粗体、斜体、删除线、行内代码及其嵌套（P1-3），保存时渲染结果
   不变的顶层块一律保留磁盘原文（`*` 列表、`__粗体__`、Setext 标题等非规范写法不再被改写；A1
   夹具已加入这些写法）。本机 842 篇 Markdown 实测：未改动直接序列化的改写行数从 22058 降到 429，
   逐字不变的文档从 401 增至 716 篇，行内格式检查零新增误报。仍会整块重写的情况：松散列表被写成
   紧凑列表、相邻且标记不同的两个列表被序列化器合并，以及用户改动过的块（采用序列化器写法）。
4. A7 保存途中重命名时，草稿写入新路径后 Tab 随“保存并关闭”正常关闭，而非审查文档描述的“保持打开”；
   数据未丢失。
5. A3 的另存为、合并与失败恢复路径未逐一验收；自动加载的图片仍以 data URL 传输，只是受数量与大小约束。

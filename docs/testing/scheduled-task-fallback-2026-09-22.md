# 定时任务每日日志模板兜底验收

日期：2026-09-22。

## 用户能力与边界

已在隔离的真实 Electron 中验收：通过任务 UI 保存每日日志模板，运行遇到本地模型
端点返回的内容拒绝后，日志文件仍被创建，运行标记失败且可点击打开文件。七个字段
默认留空，四个章节保留，打卡行明确为格式示例；错误响应不写进日志正文。

未验收 `/Users/lc` 所在目标设备、既有“每日简报”任务、真实昨日资料或生活作息文件。
未发布新版本，也未改变目标设备的任务定义。模板兜底不等于正常 AI 补充完成。

## 验证结果

- `pnpm verify`：通过，396 个测试文件，3063 项通过，2 项跳过；类型、lint、构建通过。
- 补强已有文件碰撞测试后，runner 的 6 项测试再次通过。
- `node scripts/scheduled-task-fallback-smoke.mjs`：通过。
  - 使用隔离的 Studio userData、Claude 配置目录和主目录内临时工作空间。
  - UI 点击“填入每日日志模板”，保存后验证定义中的模板原文一致。
  - 本地 HTTP 端点返回 `[1301]`，主进程记录 `SCHEDULED_TASK_CONTENT_REJECTED`。
  - 真实 Markdown 文件以模板正文开头，带未完成说明，不含 `[1301]` 错误正文。
  - 运行卡片显示“模板已保存，AI 补充失败”，点击打开可看到今日体重字段。
  - 测试退出后删除本轮临时工作空间和配置。

早期 smoke 设置存在两个问题：工作空间位于主目录外而被正确拒绝；Claude 配置未
隔离时测试未命中本地端点，发生了正常生成，不能计为拒绝路径验收。已修正测试设置，
最终通过记录包含本地端点的实际请求计数。业务代码没有为测试放开路径或覆盖保护。

## 工程约束

运行事实仍由 ScheduledTaskService 持有；renderer 只展示持久化结果。新增可选
`outputPolicy.failureTemplate`，沿用现有 IPC、定义存储和 artifact 契约，模板参与
execution digest，保留 Markdown 原始空白。原任务没有模板时保持原行为。

Agent 正常生成时不落兜底模板；取消、无效资源/路径、同名文件和写入失败不伪装成功。
模板使用既有 create-only 写入和写后核验，不自动覆盖已填写的日志，不保存被拒绝的
流式内容，不增加自动重试或跨模型转发。

全量门禁中遇到的目录 `EISDIR` 已在 OSS 扫描器中通过跳过非文件条目修正，未修改
被扫描目录内容或关闭内容检查。

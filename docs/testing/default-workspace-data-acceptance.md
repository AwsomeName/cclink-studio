## 验收结论和记录方式

默认空间及公司、运营稿件与任务的保存恢复已经实现，通过真实 App 自动验收；事务目录化、整体备份及副本恢复尚未实现。以下矩阵保留真人签收状态，不把自动化结果填成真人通过。

每项结果只使用“待执行／通过／失败／受阻／不适用”，附实际 App 版本、源码 SHA、操作人、执行时间、环境、实际结果和证据位置。自动化与真人结果分别记录。没有具体验证证据不得将待执行改为通过；受阻不计通过。

下列按钮和操作名称是设计目标，实施后记录实际入口。验收从 Studio UI 发起；工程人员可以在隔离环境准备旧格式和注入故障，最终仍须核验真实主进程、文件及 UI 行为。生产账户和经营原件不用于破坏性测试。

## 测试资料与前置条件

- 准备隔离 userData 和主目录边界内的空间 A、B、恢复目标 C。真实业务验收另用用户选定的真实资料，不清空真实 userData。
- A 包含公司“验收公司”、一个业务、实际可打开的 Markdown 及图片；通过原账目 UI 导入测试月份流水和原件，人工确认一条并关联到业务。
- 旧版本样本包含中央事务主文件、有效备份和一份有效 recovery 日志；至少各有未开始、等待、结果未知及带历史证据的事务，以及一条公司到事务的关联。
- 准备一个仅读取所选资料、输出新 Markdown 的受限定时任务；输出文件名不与用户文件冲突。正常生成需要可用的本地 Agent；缺失时记录受阻，不能以兜底模板替代成功生成。
- 账号测试使用用户允许操作的测试账号；两空间复用同一正式账号。副本和异机恢复使用干净的全局账号库，证明没有登录态继承。
- 故障样本、迁移前后摘要及备份保存到隔离测试目录。共享证据只保留脱敏 ID、计数、阶段和错误类别，不附秘密值、账目明细或正文。

### C04 的断点与期望

| 注入断点                            | 重启后期望                                                 |
| ----------------------------------- | ---------------------------------------------------------- |
| prepared 落盘之前                   | 仍使用原源，清理本次可证明的临时文件                       |
| prepared 之后、目标未完成           | 原源仍权威，可校验后继续或撤销准备                         |
| staging 已验证、正式目录未切换      | 同上，不提前接受目标业务写入                               |
| 正式目录已 rename、中央未 committed | 根据 migrationId 和摘要补交切换，不从两处执行              |
| committed 之后、旧分区未清理        | 目标权威，旧分区不重新进入活动列表                         |
| 目标已有新写入后异常退出            | 从目标及其有效 recovery 恢复；中央迁移前备份不能覆盖新事实 |

上述每个断点分别记录通过或失败；C04 只有全部通过才可关闭。还须覆盖业务写入前断电、磁盘满与目录同步失败，不能只模拟抛出普通异常。

## 发布步骤与真实提交分别验收

F01 验证迁移前后在真实应用中仍显示同一执行计划：步骤随真实运行、等待、失败与中断恢复变化；没有静态凑步骤、前端推测完成或第二套公司进度。此项保持待执行，不能由存储测试关闭。

F02 验证一次实际提交及平台结果，需要用户对具体账号、文章、材料快照与目标动作的明确授权。本次文档任务没有该授权，不执行发布；以下是将来操作规范。

| 执行步骤       | 执行者和进入条件                                      | 完成证据                                             | 失败或等待时允许下一步                                 |
| -------------- | ----------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------ |
| 准备           | Studio；原事务及空间材料可读                          | 原事务 ID、已保存的目标与材料版本                    | 修复材料或明确修改任务，不能伪造准备完成               |
| 账号与原稿核验 | Studio／Agent；有显式账号及用户接受的内容范围         | 实际账号身份和原稿版本核验结果                       | 缺失/不匹配暂停，用户重新选择或登录                    |
| 正文与图片     | Agent；原稿与逐图计划已核验                           | 页面正文、每张图片上传及顺序的真实观察               | 只重试允许的失败项，特殊卡点由用户接管                 |
| 平台字段       | Agent／用户；页面就绪                                 | 标题、分类等必填字段的页面事实                       | 补字段；法律或版权声明转用户处理                       |
| 保存           | Agent；平台允许且在授权范围                           | 平台草稿保存及可重新打开的证据                       | 保存失败明确失败；只保存草稿不能计已发布               |
| 提交发布       | Agent／用户；具体单对象授权有效且无必须人工处理的卡点 | 真实提交动作与平台接受证据                           | 验证码、扫码、声明等转人工；结果未知只进入核验，不重发 |
| 平台结果核验   | Studio／Agent；有可核验平台对象或回执                 | 对应文章的真实结果、URL 和观察时间；按原契约核验内容 | 等待审核保持等待；拒绝显示原因；未知继续核验           |

每步当前状态、开始与完成条件、等待原因及允许下一步由 WebAffair 原 owner 提供，证据缺失不计成功。F01 与 F02 分别记录；未经授权或平台条件不具备时 F02 为受阻或待执行，不影响对已通过的存储能力作精确声明，也不能据此宣布文章发布闭环完成。

# 公司账目首版验收

> 日期：2026-10-09
> 结论：代表性样本的最小闭环通过；真实月份金额与现有代账可用性尚未验收。

## 用户现在能做什么

用户可以在普通本地工作空间打开“公司账目”，一次点击启用后导入所选月份的银行或支付 CSV 与凭证，核对 Agent 建议并人工确认，查看月度收支和眼镜项目实际支出，导出代账交付包，并创建可校验的完整备份。

AI 建议始终停留在待核对表单。只有用户点击“人工确认入账”后，记录才进入月度和项目统计；修改已确认记录会自动回到待核对。

## 桌面端代表性验收

验收在 `cclink-studio` 普通工作空间中使用 2026-09 脱敏样例完成：

- 首次进入只显示“开始使用”和“从备份恢复”；点击一次后直接进入导入页。
- 导入一份支付流水 CSV 和一份 PDF 凭证，生成 3 条待核对流水和 2 份原始文件，未把 PDF 重复计为支出。
- 两笔研发支出关联“AR 眼镜一代”项目；确认前汇总为 0，确认后收入为 3,000.00 元、支出为 1,540.50 元、净流入为 1,459.50 元，项目实际支出为 1,540.50 元。
- 再次导入同一批资料，结果为新增 0 条、重复 3 条，汇总不变。
- 使用“日期/收支/金额/账户/交易对方/用途/交易号”简洁表头导入 99.90 元研发服务支出，修复并验证了“日期”和“交易号”兼容。
- 使用带说明行的 UTF-16LE、Tab 分隔流水导入成功；CSV 同时兼容逗号、Tab 和分号分隔，并在 UTF-8 解码失败时尝试 GB18030。
- 只有金额但没有收支方向的 CSV 不会被猜成收入，避免发票或订单表格被当作第二笔收支；负数金额仍可明确表示支出。
- 本地 Agent 返回“研发服务”分类并建议关联“AR 眼镜一代”；返回后记录仍为待核对。人工确认后支出更新为 1,640.40 元、净流入为 1,359.60 元。
- 把待核对流水的日期改到另一个月份后，界面会切换到新月份并保留该流水，可继续人工确认。
- 最终项目支出按器件采购 1,280.50 元、研发打样 260.00 元和研发服务 99.90 元显示，合计 1,640.40 元。
- 导出目录包含 `已确认账目.csv`、`确认与修改记录.csv`、`月度汇总.json`、`交付说明.md` 和关联凭证。
- 导出 CSV 会转义以 `=`、`+`、`-`、`@`、Tab 或回车开头的文本，避免电子表格把业务文本当作公式执行。
- 币种只接受三个英文字母的代码（例如 CNY）；导出或备份目录不能选在当前账目数据目录内，避免界面格式化失败或备份自我复制。
- 完整备份包含 SQLite、原始文件和 manifest。自动验收已证明正常备份可恢复，凭证被篡改时恢复会在覆盖现有账目前拒绝；现有账目无法读取时，恢复仍要求用户确认替换。

## 工程验证

- CompanyAccountsService 自动测试覆盖零配置启用、待核对导入、Agent 建议不入账、人工确认、已确认修改回退、跨月日期修正、重复导入、退款与内部转账口径、单一默认币种及币种校验、简洁中文表头、UTF-16LE/Tab 流水、无方向金额拒绝、CSV 公式转义、唯一且位于账目目录外的导出/备份目录、备份恢复和损坏凭证拒绝。
- 零配置测试直接校验数据库只有 `settings`、`import_batches`、`documents`、`projects`、`records`、`record_documents` 和 `record_events` 七张业务表，且 `PRAGMA user_version = 1`；没有为报销、应收应付、库存或通用迁移框架预建表。
- IPC contract inventory 覆盖全部账目 invoke 通道，renderer 参数经 Zod 校验，主进程 CompanyAccountsService 是唯一状态所有者。
- 完整 `pnpm verify` 通过：405 个测试文件通过，3273 个测试通过、4 个既有测试跳过；类型检查、ESLint、格式检查和生产构建同时通过。

## 尚未通过的业务验收

- 尚未导入用户真实月份的银行、微信或支付宝导出文件，未知真实表头和编码是否还需适配。
- 尚未取得退款、内部转账和缺凭证的真实人工答案；当前规则与自动测试不能替代业务人员核对。
- 现有代账尚未打开导出包并确认字段、文件命名和凭证组织方式可直接使用。
- 当前配置的本地 Agent 返回一次建议约耗时两分钟。它不阻断手工核对，但需要真实使用后再判断是否值得优化运行时响应。

因此，首版工程实现和代表性样本验收可以通过；“这个真实月份算得对、代账实际能用”仍必须由真实资料和代账反馈关闭。

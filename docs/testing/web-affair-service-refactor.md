# WebAffairService 分批拆分验收

> 2026-10-16：工程回归与真实 Electron 自动冒烟通过；真人签收未执行。

## 结论与范围

这四批没有新增用户功能。首批移出文章发布生命周期转换与通用节点/流程规则；第二批移出
流程修订生成、差异应用和校验；第三批移出检查点完成条件及平台 URL 判定；第四批移出图片
上传转换及人工确认的无状态计算。`WebAffairService` 当前仍为 7,590 行，整体维护成本问题
尚未解决，不能宣称服务拆分已全部完成。

| 模块                                                          | 职责与边界                                                                                                                                 |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/main/web-affairs/web-affair-service.ts`                  | 唯一状态 owner；保留身份/证据校验、权限判断、队列、快照、持久化、通知和定时器。                                                            |
| `src/main/web-affairs/article-publishing-lifecycle.ts`        | 无状态转换：同次计算 Attempt、节点、checkpoint、asset、sideEffect、publication、current operation 和恢复写许可；返回新快照，由原服务提交。 |
| `src/main/web-affairs/web-affair-flow.ts`                     | 节点创建、合法转换表、依赖放行、事务状态推导和 DAG 环检测，不保存流程状态。                                                                |
| `src/main/web-affairs/web-affair-flow-revision.ts`            | 生成修订流程、映射临时节点 ID、应用差异并校验资源范围、历史依赖和 DAG；不决定版本冲突、建议是否获准或提交结果。                            |
| `src/main/web-affairs/article-publishing-checkpoint-rules.ts` | 检查点页面事实、已派发动作凭证、只读恢复分支和八个平台公开 URL 的一致性判定；仅返回结果，不修改发布状态或签发权限。                        |
| `src/main/web-affairs/article-publishing-asset-rules.ts`      | 图片上传转换、尝试上限、动作凭证匹配及人工确认后的图片/尝试投影；返回新数组，动作凭证更新、Attempt 与 execution 收敛仍由原服务提交。       |

没有新增 IPC、MCP、持久化 schema、operation 账本、服务实例或生命周期。辅助模块不反向依赖
`WebAffairService`。UUID 生成仍只用于既有节点和操作记录，transition 上限仍为 200。

## 必须保留的失败路径

- 已派发的发布动作结果不明时，中断、取消或失败保持 `result-unknown`，不能变成允许自动重发。
- 取消、接管和终止时同步收敛当前 operation、Runtime binding、步骤、资源及恢复写许可。
- 迟到回执和旧 generation 继续通过原服务的身份、证据及 CAS 校验；无状态函数不授予权限。
- 原服务仍在同一 mutation queue 中进行验证和落盘，不拆成多个异步提交。
- 流程完成只解锁满足依赖的节点；终态和已执行节点的历史保护继续有效。
- 无效修订或建议应用失败不能产生部分修改；内存快照、版本、事件、建议决定和磁盘保持原状。
- 同版本并发修订只能提交一次；AI 建议仍须确认后才改变执行流程，过期版本继续拒绝。
- 检查点结果仍须先通过原服务的报告者、Runtime binding、执行代次、当前 operation、步骤顺序
  与页面时效校验；无状态规则不能绕过这些检查。
- 缺少可信平台证据、目标身份、公开 URL 或已派发动作凭证时，不得把发布结果标为已核验；
  预派发拒绝、已对账历史动作与当前待核验动作的筛选语义保持不变。
- 同一图片并发开始上传只能新增一次尝试；缺少本 Attempt 的已派发凭证时不能标记上传成功。
- 结果未知图片仍须核验后才能恢复；确认存在将图片/尝试/凭证收敛为 uploaded/succeeded/verified，
  确认缺失收敛为 retryable-failed/retryable-failed/rejected，均保持执行中断而非伪装运行。
- 微博缺图确认的当前编辑器证据、未提交条件，以及头条图片不可重复认领和暂停条件继续保留。

## 工程验证

第四批完成后，以下相关回归共 43 个测试文件、728 项测试通过（首批 706 项，第二批 717 项，
第三批 725 项）：

```bash
pnpm exec vitest run --silent=true \
  src/main/web-affairs \
  src/main/article-publishing \
  src/main/image-research \
  src/main/diagnostics/web-service-startup-error.test.ts
```

另通过 `pnpm build`（包含 renderer/main 类型检查）、受影响源码的 ESLint、Prettier 和
`git diff --check`。

首批真实 Electron 自动冒烟使用独立 Profile、本地 Markdown 和合成账号元数据：

1. 创建三个串行节点的普通事务，完成首节点，得到 `completed / ready / blocked`。
2. 创建本地文章测试任务，准备 Attempt 后进入人工接管，确认事务、Attempt 与 execution 对齐。
3. 通用事务结果上报不能改写文章发布状态；通过正式 `articlePublishing.terminateRuntime`
   及其执行身份校验取消任务，确认节点、Attempt 与 execution 同步取消，迟到交还被拒绝。
4. 在真实文章发布历史 UI 中看到测试稿；关闭并完整重启 Electron，确认取消终态与普通流程
   进度均保留，没有恢复成假运行；主文件中的状态与查询一致。

此冒烟未调用模型、未登录真实账号、未访问发布页面或公开提交；不能用于宣称文章发布端到端
能力新增或重新完成真人验收。

第二批真实 Electron 自动冒烟使用独立 Profile、工作区和合成网站账号元数据：

1. 在真实流程编辑器中新增并行核验节点、选择前置依赖并保存；确认临时 ID 被映射、版本升至
   v2，四个节点及四条依赖正确。
2. 在编辑器中引入环依赖；保存时显示有向无环图错误，内存快照和磁盘逐字保持不变。
3. 完成首节点后，编辑器锁定历史节点；通过正式 IPC 尝试改写历史、删除历史依赖、引用事务外
   账号和提交旧版本，全部拒绝且没有写入。
4. 通过正式 IPC 生成流程建议，确认尚未改变流程；在真实 UI 点击“确认应用”后，新增节点才
   生效，版本升至 v3，建议成为 accepted。
5. 建议先修改节点标题、再加入环依赖；UI 确认时拒绝整个建议，标题和版本不变，建议仍为
   pending，内存和磁盘没有部分更新。
6. 完整关闭并重启 Electron，确认 v3 流程、完成节点、已接受和待处理建议均保留，UI 与磁盘
   一致。持久化比较按 JSON 语义进行，允许可选字段的 `undefined` 在落盘时省略。

第二批同样未调用模型、登录账号或公开发布。上述是工程自动化证据；真人可按“创建三节点
普通事务 → 编辑并行依赖 → 尝试保存环依赖 → 完成首节点并检查历史锁定 → 重启检查”复验；
真人签收尚未执行。

第三批真实 Electron 主进程冒烟在独立测试进程加载实际 `WebAffairService`、Store 和规则模块，
使用本地固定页面、合成 Runtime 绑定及独立状态文件：

1. 通过实际 `WebContents` 读取本地页面，完成 `open-editor` 并落盘推进到下一检查点。
2. 缺少平台账号标识时拒绝完成 `verify-account`，内存和磁盘不变；页面身份完整时正常推进。
3. `fill-body` 没有已派发凭证时拒绝完成；经原服务的保留、消费、派发命令记录测试凭证后，
   可完成正文检查，凭证变为 verified，publication 保持 not-started。
4. 八个平台的合法 URL 继续接受，HTTP 与其他平台地址继续拒绝。此处只判定 URL，不访问站点。
5. 销毁实际 `WebContents` 后，同一报告者的页面证据时效检查拒绝后续回报，内存和磁盘不变。

新增八平台服务回归覆盖缺证据、错误适配器、过期页面、错误 Agent Run、外站 URL、HTTP、
未派发凭证及动态图文未授权，验证拒绝时不写入。成功推进由既有完整流程回归和上述 Electron
本地页面冒烟覆盖。第三批没有启动模型、访问真实账号或执行平台写入，不构成真人平台发布验收。

第四批真实 Electron 主进程冒烟沿用实际服务与 Store，在“图片存在”和“图片缺失”两个独立
测试进程中分别完成以下检查。图片来自本地固定页面的数据 URL，平台 URL 与 Runtime 绑定
是合成元数据，未请求真实网站或模型：

1. 正常完成编辑器与账号检查点，缺少账号身份时拒绝写入。
2. 旧代次图片回报被拒绝；并发发起两次上传，只持久化一条上传尝试。
3. 通过原服务记录测试上传凭证后模拟回读中断；图片变为 result-unknown，旧报告者不能重新上传。
4. 过期人工确认被拒绝，图片、凭证、内存和磁盘均不变。
5. 存在分支读取实际已加载图片；缺失分支移除图片后读取页面。调用原服务的人工确认命令后，
   图片、上传尝试、凭证与生命周期同步收敛，publication 均保持 not-started。
6. 重载实际服务，确认人工决定和中断状态保留，没有恢复成运行或发布成功。

新增服务回归还验证：无已派发凭证时拒绝上传成功且不写入，补齐正式凭证后可完成核验；
人工确认的两个分支在服务重载后均保留。以上是工程门禁，未替代真实平台上传与真人签收。

## 剩余边界

平台专用回执命令、Runtime 恢复核验、即刻/B 站草稿重建和副作用命令仍主要集中在服务中。
后续应先复审这些命令的输入输出与失败边界，再决定下一批；不得为了减少行数拆分状态所有者、
持久化事务或人工确认边界。

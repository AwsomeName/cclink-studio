# Agent 大图片输入验收

日期：2026-11-11。

## 用户能力与验收动作

在 Studio 的本地会话中拖入单张 20MB 内的图片（每次最多 5 张），等待处理，打开预览检查文字后发送；Agent 应接收到图片，历史消息应能恢复对应的发送副本。图片失败时必须保留可重试内容，不能静默漏图发送。

1. 添加小透明 PNG：发送副本字节不变、透明通道不丢失。
2. 添加恰好 20MiB 的有效 PNG：正常处理，生成不超过 3MiB 的发送副本；点击缩略图可查看尺寸、大小和原尺寸预览。
3. 添加大于 20MiB 的图片：显示明确错误，保留文字；处理错误后才允许发送其余附件。
4. 添加五张各大于 5MiB 的图片：逐张后台处理，全部可发送；第六张被拒绝且不覆盖前五张。
5. 添加长截图：保持完整画面；明显缩小或长图缩小后必须查看预览并点击“已检查，使用此图”。过度缩小会损失文字细节时拒绝，提示分段截取。
6. 添加损坏文件：显示错误，不把文件名或伪造 MIME 当成有效图片。
7. 处理五张大图时取消：Worker 退出，没有迟到的附件回填，文字不丢失。
8. 发送五图后重载窗口：历史图片从主进程资产存储恢复，与 Studio 发送预览字节一致。
9. 模拟接口拒绝：恢复文字和图片；若已输入下一条内容，失败消息进入暂停队列，不覆盖新草稿、不自动重发。
10. 使用真实 Codex 读取五张合成图片顶部的英文、数字与中文，验证压缩后的实际识图。

## 当前边界

- UI 沿用 MB 文案，容量按 MiB（1024 × 1024 字节）计算。原图单张 20MiB，每条最多五张；不新增合计 50MB 的隐藏导入门槛。
- 原图还受 5000 万像素、单边 32768 像素的解码保护。解码前读取 PNG/JPEG/GIF/WebP 头；在 Worker 中串行解码，单图最多处理 30 秒，可取消。
- 原图不覆盖、不进入 Agent IPC 或消息队列；只对发送副本做 Base64 编码。静态小图符合 3MiB、8000 像素单边预算时保持原样；大图先优化编码，再按需缩小，不裁切。非 JPEG 优先 PNG，必要时用保留透明通道的 WebP，不统一转换成 JPEG。
- GIF、动画 PNG、动画 WebP 仅发送首帧，并明确显示该事实。暂不提供自动长图切片或内置裁剪工具。
- 单图发送副本最多 3MiB，五图 Base64 合计最多 20MiB；共享 Schema 另留有界的 UTF-8 名称、ID 和元数据空间。本地与远程共用数量、格式、真实 Base64 字节数和总量校验。
- 历史资产继续允许读取旧版的 5MiB 图片；新附件按 3MiB 预算发送。
- **预览表示 Studio 交给 Runtime 的版本。** 真实 Claude CLI 已观察到再次转码，模型服务也可能缩放；预览不承诺是模型最终处理的像素。
- 原生 Codex、Claude Code 与支持 `image_input` 的远程 Agent 使用同一导入入口。旧 Codex ACP 在添加与发送阶段明确拒绝图片。
- 准备失败阻止当前草稿发送，用户可取消或明确保留已添加图片；单图低清晰度风险由用户预览确认。普通合规图片不增加确认弹窗。
- 图片准备任务只拥有瞬时 Worker/取消状态；已接受附件仍归现有本地或远程会话 Store。组件离开其准备作用域时取消任务，过期任务不回填。原图不写入持久化快照。
- 本地异步失败恢复由现有会话 Store 持有 Run 和用户消息引用，成功、取消与恢复后清理；重复错误只恢复一次。重启不自动重发图片消息。
- 无新 IPC、文件系统权限、登录依赖、云端或远程 Runtime 改动。诊断用结构化准备元数据和可见错误，不记录图片 Base64。

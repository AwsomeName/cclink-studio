# Studio GEO：现状核对与最小实验提案

> 研究日期：2026-11-05，Asia/Shanghai。状态：研究提案，未批准架构、未开始 GEO 功能开发、未执行效果实验。
> 源码基线：`main@ea320c828eda940a29209f4fe7d98a1787e80ec3`，`package.json` 为 0.1.128。
> 研究范围：本仓库的 macOS Electron 桌面 Studio；不把 CCLink 手机客户端、iPad Studio 模式或远程 Agent 当成本地桌面能力。
> 并行修改提示：研究后段工作树出现模型用量 Worker/IPC 和 Agent 导航等其他任务增量。本报告的实现判断固定在上述已提交基线，不为这些在途改动背书，也未修改或回退它们。

## 结论与本轮交付边界

用户现在可以借助现有 Studio 浏览网页、整理本地 Markdown、运行 Agent 和生成定时报告；还不能在 Studio 中完成经过验收的 GEO 采样、效果比较及获客归因闭环。本轮交付可审阅的研究、公开入口核查与实验协议，不宣称新增产品能力或 GEO 有效。

推荐先采用“可复用任务说明／Skill + 少量本地工具”，在现有工作空间执行一次人工参与的实验；暂不新增 GEO Activity、通用营销平台或独立 SaaS。首先补准确的桌面产品入口、上手教程与可区分测试流量的下载路径。自动化首要作用是保存、校验和比较证据，而非批量模拟消费者提问。

最影响判断的四个发现：

1. **官网并非不存在，但实体说明混杂。** 当前官网有 macOS 下载卡，却在桌面 Studio 展示区使用 iPad 界面图；结构化产品资料和主要教程仍描述移动端远程任务。
2. **发布能力并非只有规划。** 有真实 CSDN 发布、后续多平台提交及部分公开核验记录；仍有人工协助、审核等待和恢复限制，不能宣传稳定无人值守多平台发布。
3. **定时与 Skill 不能按想象复用。** 定时任务实际只放行本地编辑器只读工具；Studio 原生 Skill Registry 当前只有内置 `grill-me`，没有已验证的任意 Skill 安装市场。
4. **国内 API 能力已变化。** DeepSeek 现有官方 Search/Fetch；Kimi 文档已提供独立搜索、抓取及 Responses 搜索路径。旧教程不能作为当前边界，但这些 API 仍不代表消费端回答。

用户功能进度：本次未新增 GEO 功能，推广有效性与外部客户需求均未验证。

工程准备度：完成源码和既有验收证据核对、官方资料研究、公开入口只读检查及文档落盘；没有重新运行 App smoke、付费模型请求或安装验收，也没有购买、发帖、部署、修改线上配置、提交或推送。

配套材料：[首轮实验协议与问题集](experiment.md)、[公开入口机器可读核查快照](public-entry-audit.json)。

### 首个用户场景与内容范围

先服务**使用 Apple Silicon Mac、愿意配置自己的模型服务、有网页调研和本地写作需求的个人开发者／产品作者**。这是基于已有能力的候选人群，不是已证明的市场需求。先用少量访谈确认自然问法，避免设计只有 Studio 才符合的特征堆叠题。

代表问题：“Mac 上做产品调研，想把网页资料整理成自己电脑里的 Markdown，有哪些工具值得试？”另一类是“已有 Claude Code，想要图形工作台同时查看文件和网页，有什么选择？”不以“全免费 AI”“全平台无人值守发帖”“手机远控桌面 Studio 会话”为卖点。

目标真人验收：一个原本不知道 Studio 的人，在指定消费端提出不含品牌的选型问题，得到准确的桌面 Studio 推荐，沿真实来源进入产品页，下载合适版本，在自己的 Mac 打开工作空间，完成“参考公开网页→保存并重新打开本地 Markdown”的首任务；如体验 Agent，明确使用其本人已配置的模型服务并单独记录成功。当前该链路**未执行**。

最小内容缺口：

1. 一个桌面专用、匿名可读、固定 canonical 的产品页；明确 macOS/架构、GPL、本地免 CCLink 登录、模型费用另计、远程边界和已验证能力。使用真实 Electron 截图，区分 iPad 模式。建议路径 `/studio/` 只是提案，未检查部署权限或创建页面。
2. 一篇能照做的桌面安装与首任务教程，写明实际公开版本、模型准备条件、失败时的操作和文件落点；由非作者在干净环境验证。不要先堆泛化“十大工具”文章。
3. 一个可记录来源与下载点击的入口，以及自愿反馈实际首任务完成的方式。优先评估现有站点日志，不默认新建分析服务或安装遥测。
4. 产品事实表：每项主张指向版本、测试/真人证据、限制与最后复核日期。正文、截图、README 和结构化数据一致；没有证据的性能数字、客户案例和推荐词不发布。

技术准备优先检查匿名HTTP可读正文、正常站内链接、页面标题/canonical、robots与sitemap；可读性和结构化资料是帮助理解的条件，不是排名开关。本轮没有核实到五平台共同承诺的“提交即收录/推荐”入口，也不把添加 `llms.txt`、schema或放行某个训练爬虫视作消费端实时检索效果证明。

首轮只改变这组必要资料并记录版本。它测的是“入口修正 + 有用内容 + 可发现性”的组合，不声称识别某个措辞的独立因果效果。若以后拆分优化方法，需另做分批干预。

消费端 App、消费端网页、模型 API、云厂商托管的同名模型、自建搜索+模型，分别是不同实验层。即使模型名字一样，搜索触发、查询改写、索引、过滤、上下文、系统指令、账号记忆都可能不同；没有官方等价承诺或配对实测就不能合并指标。App 也不能由网页样本代替，详见实验中的独立桥接小样本。

技术可行性判断：

- **高可行性**：人工取得原始回答后，做本地归档、品牌消歧、引用与事实审核、按日期比较、生成修订建议。
- **有条件可行**：在授权、条款允许的 API上诊断目标资料能否被检索，或检查自建 RAG 引用；这些结果标为 API/检索层，不能记入消费端推荐率。
- **尚未证实**：五平台低维护、无人值守消费端采样；国内自然流量到下载/使用的真实增量；任一内容方法持续提高推荐概率。

实现采样时保留原回答、引用角标与目标URL的对应关系。来源列表只表示“展示了此来源”；答案句子实际引用此URL才记引用；链接可打开仍需逐项判断是否支持原句。不要把 API authority/rerank 分数、Agent 自述“我参考了它”、或某网站出现在来源列表中，当成推荐因果解释。

稳定性预算须包含登录过期、验证码、风控、UI/模型升级、App版本变化、流式中断和引用弹层失效。遇到明确禁止、验证码或同一阻塞连续失败两次就停止该自动路径，转人工或标缺样；不换账号/IP规避，不补造答案。后续商业采样需确认相应使用许可；本报告不是取得批量采集许可的证明。

估计以一名熟悉仓库的开发者、每日6小时有效工程时间、两平台人工导入、一次实验为前提；误差约±50%，不是承诺排期。官网与内容工作、研究观察期及访谈单列，不能拿工程完成度替代产品验证。

用户流程：填写产品事实与目标用户 → 审核自然问题并冻结题集 → 人工在消费端新会话采样 → 将本人回答/截图/引用导入工作空间 → 工具校验完整性 → Agent给候选标签与事实差异 → 人工确定结论和修改 → 在已有编辑器审稿 → 未来取得具体对象授权后发布 → 到期按同条件复测 → 查看按平台/日期/题类分开的报告及真实访问/使用证据。

自动化边界：

- 可自动：文件校验/hash、重复检测、URL规范化但保留原URL、统计、生成候选标注与内容diff、读取已保存资料生成报告。
- 需人工：正常登录/验证码/选择实际模型与联网模式、消费端采样与完整性确认、产品事实与推荐判定复核、最终修订审核、外部发布授权、匿名转化证据核对。
- 不做：自动购买、账号池、验证码绕过、跨平台刷问、伪造测评/案例、关键词堆积、隐藏提示注入、海量近似页面、自动公开分享聊天记录。

### 状态、权限与失败设计约束

- 实验文件仅拥有“采到了什么、谁审核、何时修改、何种条件下比较”的事实。原始样本只追加，标注独立版本；报告可重建。首版单写入者，不新建通用 operation 账本。
- BrowserManager/WebResourceService继续拥有浏览器与账号；BrowserTask/Agent Run拥有执行；WebAffair唯一拥有发布；ScheduledTaskService只拥有触发与既有产物。实验包仅记录这些对象的稳定引用。
- 不增加 renderer Node权限、常驻后台进程、OS级定时器或新的模型代理。工具退出释放资源，中断保留 incomplete，重开不会自动重发问题或文章。
- 只允许显式实验目录读写；网页、答案和模型建议均为不可信数据，内容里的操作指令不能变成执行授权。人工导入不包含Cookie、验证码、完整账号信息或凭证。
- API若以后启用，复用CredentialService或用户现有受限凭证路径；不把Key写入实验包、普通配置或日志。真实Token按已有观察范围记录，搜索次数另记供应商回执，预算与估算不充当授权边界。
- 一个站点、模型或分析工具故障只影响对应样本；文件、编辑器和无模型的证据浏览继续可用。不为GEO改缩放链、远程登录或既有定时工具白名单。

## 6. 首轮实验、成本与阶段判断

完整步骤、问题、样本数、判定规则见[实验协议](experiment.md)。建议豆包和DeepSeek网页作为两条主线；元宝、千问、Kimi先做少量探索。此选择为降低执行成本的建议，不声称这两者在目标人群中市场份额最高；实际可登录性和用户习惯确认后再冻结。

计划为3个基线日期、1次内容干预、3个后测日期（发布后7/14/28天）。两平台16题每日期各一次，共192份；另三平台4题在前后各一次，共24份；两个主平台App桥接4题前后各一次，共16份。合计232份，App与网页、探索与主实验分开报告。前置准备约1周，发布后观察4周；有发现滞后证据时最多延长至第42天。

### 继续／停止条件（建议，实验前冻结）

1. 准备门：入口无桌面/iPad混淆，公开资料准确，至少一名非作者完成安装和首任务；两主平台可按条款与现有账号正常采样。否则先修产品/入口，不建设GEO专用UI。
2. 测量门：正式样本有效且完整比例≥90%，每份采集+初标中位数≤7分钟。低于门槛先缩平台或题数；同一自动路径失败两次停止深挖。该阈值是成本控制选择，不是统计标准。
3. 技术信号门：至少一个主平台在两次后测出现多个非品牌问题的真实推荐改善，且留出题也有重复信号、无新增关键事实错误。只在已优化题出现或只有一次截图，不能通过。仍只称样本信号，不称因果定论。
4. Studio推广门：独立记录自然来源的新访问、下载与首任务；建议至少3个可核对的新下载、其中1人完成首任务，才值得继续扩张该渠道。招募测试者和作者自测不计入自然获客。指标不可观测则结论为证据不足，不能补零或宣称成功。
5. 第28天若资料仍没有被发现的证据，区分入口/收录问题与内容效果；有抓取或新版可见的进展且预算允许才延长一次至42天。若新版已可见而多日期推荐、留出题与获客仍无改善，停止本轮优化方法和扩张开发，保留事实修正成果。

推广Studio与出售GEO工具是两个假设：另访谈5位真实产品作者，至少3位愿提供资料/真实问题，至少2位愿完成两轮复测；随后以实际付费试点与复购意愿验证收费，不能用“觉得有意思”替代。访谈不需要先开发工作台，也不因本报告自动获准外发联系。

只有跨至少3个不同产品、两个周期，流程可复核、维护成本可控，且有至少2个实际付费试点，才评审独立入口或收费。若用户主要在Studio工作且证据整理反复耗时，再做专用工作台；若多数客户不愿安装Studio、希望协作且已有授权数据渠道，再评审网页服务。即使推广结果不显著，事实审计可能有独立需求，但必须按审计价值卖，不能暗示优化效果。

## 7. 拷问结论与待决定事项

最危险的假设不是“能不能调用五个模型”，而是“题目代表真实需求、公开资料确实被消费端发现、推荐后产品能留住用户”。当前三项都没有实验证据。已有浏览器和发布能力降低制作与取证成本，却不能解决流量分母和消费端随机性。

需要用户决定的事项仅三项：

1. 是否将首个目标人群冻结为“Apple Silicon Mac上的个人开发者/产品作者，网页调研→本地Markdown”，并用桌面专用产品页承接；若不同，先换问题集，不同时推广全部能力。
2. 两个主测入口是否采用豆包+DeepSeek；谁可用本人账号人工采样，是否能额外用手机完成少量App核对。没有可用账号的平台保留未测，不用API代替。
3. 是否接受约5周日历时间、20–34小时采样分析的投入；先批准手工试跑，再按瓶颈决定3–4工程人日的小工具。官网修改与内容发布仍需在具体稿件、账号、对象可审阅时另行明确授权。

本轮保留原有未跟踪推广素材和模型用量设计文件，没有改变产品代码或运行配置。文档中的数值门槛、工时、题集和页面路径均为待确认提案，不是既定产品架构或已执行结果。

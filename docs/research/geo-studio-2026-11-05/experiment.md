# Studio 首次 GEO 实验协议（候选预注册）

> 日期：2026-11-05。状态：待确认，未冻结、未采样、未修改或发布内容。
> 背景、源码核对、平台资料与成本见[研究报告](README.md)。本协议不是对外发布或使用付费服务的授权。

## 1. 先定义可由人执行的结果

最终目标：原本不知道桌面 Studio 的人，在指定AI消费入口提出不带 Studio 品牌的自然选型问题；看到适配其需求且事实准确的推荐；沿真实来源进入桌面产品页；下载，在本人Mac完成一个有用的本地任务。

首任务验收动作：安装核对版本 → 不登录CCLink打开本地工作空间 → 打开一篇公开网页作为参考 → 创建并保存Markdown → 关闭重开后内容仍在。若测Agent价值，增加“使用本人既有模型配置，在授权范围生成有来源的初稿，人工审核保存”，作为独立指标，不能把手工编辑成功记为Agent成功。

实验操作闭环与获客闭环分别验收：

- 操作者在Studio能从原始回答追溯到标签、引用和修订，再用新日期样本重建报告，证明实验流程可用。
- 受招募测试者完成上述首任务，证明可用性；不证明自然发现。
- 非招募用户报告从不含品牌的提问首次发现产品，且有回答/来源及下载或首任务证据，才计自然发现转化；没有证据时写未知。
- 本轮研究未执行以上任何消费端实验和真人首任务，结果均为“未测”，不是0次成功。

两项独立假设：A＝GEO可给Studio带来适配的真实新用户；B＝其他作者愿意持续使用或购买证据采集/内容核验/复测服务。A的实验不替代B的访谈、实际使用与付费试点。

## 2. 前置检查与冻结条件

1. 确认桌面目标用户、公开下载版本与可访问产品入口；产品页应明确区分桌面/iPad模式，模型服务另计费。
2. 至少一名非作者按教程在自己的Apple Silicon Mac完成首任务。记录失败与耗时；如果安装失败或核心价值不清晰，先修产品，不继续为推荐率调内容。
3. 确认两主平台账号、允许的正常使用方式和人工执行者；正常登录、验证码由本人处理，不读取或导出Cookie。可用官方网页或App，不强制必须嵌在Studio。
4. 用两平台各5题做一次试跑，检查新会话、联网模式、保存全文和引用、单条耗时。试跑数据标pilot，永不混入正式前后比较；不得试到出现Studio才选择题目或平台。
5. 将最终题集、条件、主要指标、阈值、内容版本、日程和分析规则写入本地协议，保存时间与SHA-256。当前文件仅候选版本，用户确认后再冻结。
6. 当前官网错误可先作为准确性问题修正，并记录时间；冻结后再采基线。若选择把纠错也纳入干预，须如实标记“多项组合干预”，不把效果归因某一段文字。不能为保持对照而继续保留误导信息。

不购买服务、不自动新建账号、不发布聊天分享链接。官网修改、内容发布和统计配置，均等具体对象/稿件可审阅并取得用户明确指示后再执行。

## 3. 候选固定问题集

目标样本偏向有真实需求的Apple Silicon Mac用户；它不是国内全网问题分布，也没有真实搜索量权重。先向3–5位目标用户收集原话再做最后一次冻结；访谈问题不能暗示必须找到Studio。

### 留出4题

H01–H04见[留出题文件](holdout-questions.md)。采样者可读，内容修订Agent只接收T组、产品事实与已批准资料；不得挂载本文件的留出题全文或其输出。留出题也采基线，但在干预前封存结果，内容作者不据此迭代。

这是“未用于优化”的留出，不声称模型训练未见或研究者完全盲测。若只有一个人同时采样和编辑，记录未实现人员盲法，并预先承诺不依据H组修订。任何泄露/据此改写均将H组降为探索组；不要偷偷替换为表现更好的新题。可以另请未参与内容编辑的人在最后一天写全新自然问法作为探索，结果不能补入预注册主要指标。

## 4. 采样计划与条件

主平台候选：豆包网页、DeepSeek网页。选择理由为覆盖两种实际消费者入口并限制执行成本，不依据未经核实的市场占有率；最终依账号可用性和目标用户习惯在冻结前确定。

| 样本层   | 条件/题集                                                    | 日期                                       | 计划份数    |
| -------- | ------------------------------------------------------------ | ------------------------------------------ | ----------- |
| 主实验   | 两平台，T8+H4+B2+N2，每题每日期一份首次完整回答              | 基线D−7/−4/−1；一次干预D0；后测D+7/+14/+28 | 2×16×6＝192 |
| 探索平台 | 元宝、千问、Kimi，T01/T03/T06/T07                            | D−1与D+28                                  | 3×4×2＝24   |
| App桥接  | 两主平台App，H01–H04，使用正常默认入口；同一终端条件前后一致 | D−1与D+28                                  | 2×4×2＝16   |
| 合计     | 主实验、探索、App分别报告                                    | 不含试跑、故障重试和可选API诊断            | 232         |

主实验采用平台明确提供的联网开启/搜索入口，原始题目不附品牌、不附产品网址、不上传产品资料、不通过“请优先引用此页”诱导。若只能自动搜索，作为独立auto条件标记，不伪称强制联网。联网开启但未实际触发搜索的完整回答仍保留在主要分母，另记triggered=no/unknown；不能只留下触发搜索的好样本。

App桥接用于观察真正默认入口差异，不与网页联网上线样本合并，也不能用16份桥接推断手机总体表现。API与自建RAG如果以后运行，独立放diagnostic层；没有对应消费端样本时保持未测。

固定并记录：

- 平台准确URL或App名称/版本、UI版本标记（如可见）、运行设备、操作系统、浏览器/Studio版本；App与网页各自独立。
- 所选模型/模式和其可见名称；不可见写unknown，不从回答语气猜。消费端温度/seed不可设时写unavailable。
- 账号匿名编号、登录/游客、会员层级、记忆/个性化开关、新会话与历史上下文。可关闭的记忆在基线前关闭；无法关闭如实记录，不能称完全无个性化。
- 简体中文、同一网络地区与正常出口、Asia/Shanghai时区、每次固定90分钟采样窗（候选20:00–21:30，允许冻结前改），实际开始/结束时间。两平台顺序按预先生成的轮换表交替，题目顺序固定随机种子轮换，避免总在相同时段末尾采某类题。
- 联网设定与实际搜索证据、是否使用深度思考/研究模式；模式变化或平台升级时打断原序列，另标epoch，不静默拼接。
- 冻结的题目字节内容和prompt hash、会话为新建、首次回答、无追问、无“重新生成”。一次完整回答后不因为没推荐就重问。

每条最长等待5分钟作为试跑可调整的上限；验证码/登录问题交本人处理。技术失败允许一次预定补采，但保存原失败及replacementOf，不能挑选更好答案；中断答案标incomplete，不补成完整文本。明确拒答是有效完整回答（推荐为否），技术错误不是未提及。

新会话不能保证后端完全独立、模型/索引不变或账号不受历史影响。本实验是固定条件下的观察性前后比较，最多提供准实验线索，不能单凭前后差异证明因果。测试者的查询、文章推广、版本发布与其他渠道活动都写入干扰日志。

## 6. 最小证据包

建议实验目录是用户工作空间内的普通资料目录，非新的Workspace/Tab状态分区。首轮无需数据库。

- `protocol.md`、`product-facts.md`：实验约定、事实版本、批准范围；原稿与修订稿分文件，先保存再交Agent。
- `questions/`：训练题与留出题分文件；优化任务只挂载允许的文件。
- `samples/<sample-id>/answer.txt`：可见最终回答原文；不以Agent概括代替。截图/导出文件与多屏顺序并存；只有截图时OCR结果另存、人工核对，不覆盖原件。
- `samples/<sample-id>/metadata.json`：实验/样本ID、精确prompt及hash、平台/界面/模式/账号匿名ID、日期/时区/耗时、设定联网状态和实际触发证据、采集者、completed/incomplete/blocked/error、原文件hash、缺失原因、retry关联。
- `citations.json`：每个角标/来源卡片的原URL、规范化URL、重定向后URL、标题、对应答案段落、是来源列表还是实际句子引用、访问时间/可访问性、是否支持该句。不擅自去掉有语义的query参数，不把不同版本页合并。
- `annotations/<revision>.json`：正确实体/推荐/引用/事实标签、unknown、原句定位、人工审核时间与修订原因。标签与原始回答分离，不让后续模型覆盖历史结论。
- `content/`、`reports/`、`interventions.json`：内容前后版本、公开URL与时间、事实修正/宣传等干扰记录、分层统计与方法版本。发布事实只引用现有affairId和已验证结果。

证据只保留自己有权保存的会话和必要公开资料，不收其他用户聊天。截图先检查个人信息，原件仅本地受限保存，对外材料另做脱敏副本。默认不上传到其他模型、不入公开Git；需要云模型分析时仅提供已同意发送的资料并保留完整原件在本地。网站来源可只存必要证据段落与URL/hash，不批量镜像全文。

生命周期：一次手动导入/比较结束即退出；不驻留新进程。重复导入相同sample-id/hash幂等，冲突拒绝并让用户查看；取消只保留incomplete。工具只写实验目录。凭证和浏览器Session仍由Studio既有owner管理。

## 7. 评分规则与分母

实体先消歧：`CCLink Studio`、明确的桌面产品别名及其官方仓库/桌面入口可判定；仅`CCLink`、iPad模式、工业CC-Link或同名他物不能自动匹配。关键词检测只给候选，保留人工确认。

| 指标                   | 判定                                                                                   | 分母与限制                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| M 提及                 | 答案正文确实指向桌面Studio                                                             | 主平台T/H的有效完整回答；来源卡片单独出现不等于正文提及                                          |
| R 实际推荐（主要指标） | 明确建议尝试/选择/采用，或作为适合该需求的候选并给出理由；中性提及、否定、免责声明不算 | 同上；每份至多1次。记录条件性推荐和实际依据，不把列在首位称为全网排名                            |
| C 引用                 | 答案有可对应到URL的实际引用，并且引用关联Studio主张                                    | 分开报官方域被引用、第三方提及Studio的来源被引用、仅来源列表出现；均显示n/N                      |
| Q 事实准确性           | 把平台/许可/费用/登录/模型/发布/调度拆为原子主张；标正确、错误、无法核实               | 逐主张报告正确/全部待核主张、错误数与unknown数；无Studio主张时为N/A，不给100分；人工确认关键错误 |
| Citation support       | 来源实际支持相邻主张；404/登录不可读标无法核实                                         | 被核查引用数；链接存在和文中内容相似不是支持充分的证明                                           |
| 访问                   | 站点记录或自愿证据证明进入桌面页                                                       | 区分可识别AI来源、未知referrer、其他渠道；无来源不能都归GEO                                      |
| 下载点击               | 点击桌面下载按钮/受控跳转                                                              | 不是下载完成；研究者访问和测试用点击排除                                                         |
| 下载完成               | 用户确认文件取得，或未来具备可靠传输完成证据                                           | GitHub累计download_count仅作辅助总量；不同版本/更新/机器人不算新用户                             |
| 使用/激活              | 新用户完成第1节首任务，保存匿名核验或本人自愿反馈                                      | 与下载分开；打开App不等于有用任务完成；邀请者和自然发现者分别计                                  |
| 付费                   | 未来真实交易/试点回款                                                                  | 免费桌面下载不推定付费；模型账单不算Studio收入；本轮无收费验证                                   |

样本有效率＝完整且条件可识别样本/计划样本；按平台报告失败和缺样。不用删去错误/不利结果来提高比例。主要推荐指标按平台分别计算T/H，品牌B和边界N单列；App与API绝不混入主分母。

分析采用同一题在3个基线日期的均值与3个后测日期均值作配对差，先给原始n/N、逐日结果和每题变化，再给汇总百分点；不按模型市场份额加权。12个非品牌问题每平台每阶段36份回答具有重复相关性，不能当作36个独立用户，更不能当真实曝光率。

若计算置信区间，采用按问题聚类的配对bootstrap，并报告日期敏感性（逐次去掉一个日期）；样本很少，区间仅探索用途。不得用反复选择日期、题目、平台或阈值制造显著性。多个指标只以预注册R为主，M/C/Q为解释与护栏。N组仅作边界检查，不能冒充没有受到干预的随机对照。

人工复核：所有Studio正向推荐、所有负面/关键事实错误、所有unknown均复核；另从未提及样本随机抽20%检查漏识别。先核对原文再看前后标签；能请第二人复核则记录分歧，只有一人就诚实标明。模型可以辅助标注，不能自己证明其分类正确。

## 8. 发现、波动与无效如何区分

| 观察                                             | 合理判断                                             | 下一步                                                                      |
| ------------------------------------------------ | ---------------------------------------------------- | --------------------------------------------------------------------------- |
| 官网不可读、误导实体或下载不可达                 | 入口/事实准备失败                                    | 先修此直接阻塞；不开始“文案排名优化”                                        |
| 直接给URL可读，但品牌诊断/固定检索未找到         | 只能证明页面可读取，发现状态尚未观察到               | 记录独立诊断，查正常站内链接/robots/sitemap；有迹象才延长。不得说一定未收录 |
| 搜索API找到页面，消费端没有引用                  | 只证明该检索接口能返回，消费端链路仍未知             | 分层记录，不把API检索命中解释为消费端故意不推荐                             |
| 消费端答案引用旧页面/旧事实                      | 有发现证据，但版本可能未更新或选了旧来源             | 检查实际引用版本与修改日期；保留旧答案，不重复刷问要求刷新                  |
| 两个后测日期都引用新版事实，但推荐及留出题没改善 | 在当前范围未观察到优化收益；可能需求不匹配或来源不足 | 检查内容是否解决真实需求，暂停该优化方法；不继续堆文章                      |
| 同题时好时坏，各平台差异大，去掉一天结论翻转     | 自然波动或条件变化足以解释，证据不足                 | 保持内容版本不变，按预设最多延长一次；不汇总成确定增长                      |
| T组涨、H组不涨，或只有作者账号好                 | 过拟合/个性化/选择偏差疑虑                           | 不宣称泛化效果；未来换新的独立自然问法和用户观察                            |
| 推荐增加但没有可核对访问/使用                    | 只验证回答样本，未验证商业结果                       | 检查目标用户需求、链接呈现和上手成本；也可能真实曝光很少，不能反推曝光量    |
| 访问/下载增加但伴随社区推广/发版                 | 归因混杂                                             | 分渠道及日期记录；不能把总增长全算GEO                                       |

不能观察到内部索引或检索过程时，坚持“未观察到被发现”，而不是宣称“未收录”。同样，仅有引用只能提供来源关系证据；不进行私有平台随机实验就无法证明这个来源导致推荐。自建RAG可用同候选来源做受控改写对照，但结论只适用于自建环境。

## 9. 获客归因与外部需求验证

第一版建议先核对官网已有服务端日志能力，再设计最少的页面访问、下载点击和自愿反馈记录。新增路径/事件仅为方案，本轮不配置上线。

- 公共产品页保持可读的canonical；不要把实验问题改成含指定追踪URL的诱导查询。自然引用往往丢失UTM/referrer，因此允许“来源未知”。
- 如未来增加下载跳转，在同站记录匿名事件和版本，再进入官方Release；它证明点击，不证明DMG完整取得。服务器IP去重不是独立人数，不能伪造精准用户数。
- 自测用独立标识/受控测试通道排除；机器人及预取能过滤的过滤，不能识别的保留限制。测试者询问后自己的点击不计真实获客。
- 通过用户自愿提交的“第一次在哪看到、原问题/回答、使用版本、完成什么任务”建立少量证据；只保存匿名编号和必要内容。不默认加安装指纹或静默遥测。
- 从免费产品到远程付费服务是另一个漏斗，目前服务端付费闭环未验收，不估收入、不宣称ROI。

外部需求验证不依赖GEO成败：未来经授权可在已有开源/开发者社区发布一次真实实验招募，或由用户联系其认可的产品作者；本轮不外发。访谈5位，了解最近一次获客问题、现有工具/费用、能否提供资料与重复测量时间。至少3位给出真实资料、2位完成两轮复测后，才讨论付费试点；问卷勾选“愿意付费”不算支付证据。

## 10. 结束条件与真实验收记录

第28天固定检查：数据是否足够完整、留出题是否重复改善、关键事实是否准确、自然新下载和首任务是否可核查；达不到哪个环节就报告哪个缺口。继续/停止阈值见[研究报告](README.md)。仅存在发现滞后进展且仍有预算时延长至42天一次，不无限观察、不断换题。

工程通过：未来若实现工具，需完成重复导入、截断、缺来源、引用错配、实体混淆、中断、路径越界及统计分母验证，运行受影响检查。只改文档无需跑整套应用构建。

产品通过：操作者在真实Studio完成“导入→查看原文→纠正标签→审修订稿→新日期导入→重建报告”，再另验收公开发布和自然获客。不能把前者、mock结果、官方API成功或保存草稿称为后者。

当前结果：全部消费端样本、获客结果和外部客户需求未测；公开入口只读核查已完成。没有对外内容发布、收费、在线配置或定时任务创建。

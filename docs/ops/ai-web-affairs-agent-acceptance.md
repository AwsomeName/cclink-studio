# AI 网页事务代理人验收手册

> 当前范围：W1–A4“项目网站资源 Tab、持久事务、AI 交接、外部等待和动态流程”
> 当前状态：2026-08-04 W1 实现和自动化门禁完成，等待本手册真人验收；A1 同项目事务
> 归属和真实网站代理闭环尚未实现
> 管理事实源：`docs/features/ai-web-affairs-agent-development-plan.md`

> 2026-07-31 决策：用户明确批准本次真人登录验收延期，以继续开发不产生网页外部副作用
> 的 A1 手工事务能力。该决定不代表本验收通过；A2 真实网页执行前必须补测。

## 1. 验收目标

证明用户可以在当前项目把未预置网站和两个真实测试账号纳入“网站与账号”，添加后
立即打开实际 Browser Tab，关闭后由侧栏用同一项目资源和登录环境重新打开；项目切换、
移动、复制和重启均不串用。进一步证明事务和 AI 复用同一资源 Tab 启动逻辑。此验收
不执行发布、付款、提交审核或其他不可逆业务动作。

## 2. 前置条件

- 选择一个允许此类测试、风险可控且不会触发真实业务提交的网站。
- 准备两个本地测试项目和两个可区分的测试账号；不要使用唯一管理员或高权限生产账号。
  Browser Profile 由 Studio 自动生成，不由验收人员填写。
- 验收人员能够完成验证码、扫码、2FA 和隐私授权等人工步骤。
- 如验证旧配置导入，使用一个可备份的真实旧项目，并先记录
  `cclink-accounts.json` 的 SHA-256。

## 8. 失败时记录

每个失败至少记录：步骤编号、时间、项目、网站 URL、账号标签、资源 Tab、诊断中的脱敏
Profile/Session 引用、页面实际账号身份、错误文案和截图。不得记录密码、完整 Cookie、
验证码、2FA 恢复码或身份证件正文。

出现以下任一情况，W1 保持 `In Progress` 或退回 `In Progress`：

- 重启后资源或登录态丢失。
- 两个账号共用同一 Session Partition，或页面身份发生串用。
- 项目 A 可以看到、打开或执行项目 B 的网站账号或事务。
- 侧栏点击只能进入静态详情页，不能直接激活或创建实际资源 Browser Tab。
- 事务或 AI 使用了与侧栏不同的网页启动逻辑。
- 资源页把 Cookie 启发式误报为确定的页面账号身份。
- 导入覆盖、删除旧文件或修改既有 Browser Profile。
- 登录失败时没有明确的人工接入或重新登录路径。

## 用户现在可以做什么

源码版 Studio 使用 154px 文字横排导航：完整名称、18px 图标和 32px 行高，保留 15 个能力与底部设置。
选中、悬停和焦点可区分；短窗口可滚动及用 Tab 到达底部入口。公司账目不会再误选“文件”，全部合法入口的菜单打开均可执行。

900px CSS 视口、左右栏目标为 250/350px 时，实际导航/Sidebar/Workbench/Agent 为 154/198/320/220px。
缩小窗口只压缩呈现，放大后恢复目标；拖拽实时预览，正常松手有最终有效位移才保存，往返、受限、取消或缩窗不保存。
工作空间分别记忆当前面板、栏宽与显隐，切换和重启后恢复。

这些能力已通过真实 Electron 自动化，不能改写成用户本人已签收；已安装版本也不会因源码修改自动更新。

## 精简计数验证

- 真实链路：现有 `ScheduledTaskService` 构造注入一个受控执行器，使用真实 WorkspaceState、任务保存/运行、队列、IPC、TrustedRendererGuard、原 preload 及 ActivityBar。
  一个任务实际写入临时 Markdown，观察到 4 次服务变更事件，真实 badge 经 `0 → 1 → 0` 自动更新，并以可访问状态呈现“排队或运行中”；没有手动发送 changed、没有调用 Agent。
- 展示边界：组件测试验证 0/1/99/100 的文字、隐藏及无障碍文案；真实 Electron 用明示的临时行副本检查 99/99+ 不重叠。
  这些行副本只证明几何，不冒充实际排队 100 个任务；未新增生产调度机制、执行器 setter 或测试 IPC。
- 证据：[真实非零画面](runtime-one.png)、[计数结果](counter-result.json)。测试窗口、服务与临时工作空间均已清理。

## 实施中关闭的边界问题

真实取消用例发现“窗口尺寸已变、resize 事件尚未处理、pointerup 先提交”的竞态。
最终实现同时保留 resize 取消，并在提交前复核手势起点的 CSS 视口宽高与 DPR；预算已变化时丢弃预览。
该反例已纳入真实 Electron smoke；没有通过延时、关闭功能或更改 Browser 规则规避。

开发过程中失败的测试装配、未恢复活动 Tab 和动画未收敛时的瞬时测量均已修正。
本目录仅保留最后一轮全部通过的结果，不把此前失败运行当作通过证据。

## 真人复验与边界

用户本人复验尚未执行。可在退出正在运行的安装版后启动 `pnpm dev`，按以下步骤签收；不应把安装版旧界面当作本轮源码效果。

1. 打开本地工作空间，直接阅读全部名称；依次进入公司账目、角色、账号、发布、视频、硬件和设置；使用右键及 Shift+F10 打开能力。
2. 在浅深色下观察选中、悬停和焦点；缩小窗口，滚动和用 Tab 到达末尾入口，确认底部设置仍可操作。
3. 将左右栏设为 250/350px，缩至约 900px 宽，拖离再回起点松手；放大确认目标未变。再以不同最终位置松手，确认新宽度保存。
4. 给 A、B 设置不同面板和栏宽，切换并重启恢复；拖拽期间缩窗或切工作空间，确认未提交预览没有成为永久偏好。
5. 打开内嵌网页并切换 Tab、拖动栏宽和缩放窗口，确认导航/工具栏可点击、页面不异常缩小；需要时对照本目录的真实 View 诊断。

远程入口只验其正确打开及未登录/离线降级；未验证真实在线远程业务。未进行真实发布、付款、硬件下单或其他外部副作用。

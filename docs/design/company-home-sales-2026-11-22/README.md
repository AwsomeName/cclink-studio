## 用户要求

1. 一个首页同时看到：每日待办、项目进度、本月收入与支出、需要核对的账目。
2. 明确标出“去哪里推广产品、跟进感兴趣的人”。
3. 招募试用者是可选的，可以直接销售。

## 直接销售与可选试用

- **直接销售始终开启。** 感兴趣的人可以直接问价、报价、成交。
- **“同时招募试用者（可选）”是一个开关，默认关闭。** 关闭时漏斗中的“试用”显示为虚线“未启用”，不出现报名筛选；打开后出现“试用 7/30”、报名待筛选的待办和跟进行，项目进度多出“试用招募”一步。
- **已成交只认账目里已确认的收入。** 不新建订单系统：一笔收款核对确认并关联到对应的人，才算一单。演示中确认 ¥1,299.00 预订款后，收入、已成交数和项目进度一起变化。
- 价格、发货时间、发票等对外承诺只由助理起草，由你发送。

## 拷问与待决

1. **直接销售与市场愿景冲突。** [市场与用户愿景](../../features/company-marketing-product-vision.md)假设上市前只招募试戴者、不做销售。确认本稿后要修订愿景的阶段、指标和“不做”清单。
2. **“已成交”来源。** 本稿以“已确认收入 + 关联到人”为成交，不建订单表。如果需要退款、分期或一单多台，要先决定是否扩展账目，而不是另建销售账本。
3. **“跟进感兴趣的人”全部是新能力**，涉及读取平台评论与私信、保存人的记录和代你发送回复；这是最大的一块工作，也是权限与对外发言风险最高的部分，应在真实平台上分阶段验收。
4. **首页直接确认流水**会让首页成为账目的第二个操作入口；它只能调用账目原确认动作，不能有自己的状态。若希望更保守，可改为只显示摘要，确认一律进账目页。
5. **真实月份验收仍是第一步。** 收支区块的数字可信，前提是账目通过[项目备忘录](../../project-memo.md)中的“公司账目真实月份验收计划”。

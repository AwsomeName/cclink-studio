# 公司项目首页：必要功能评估与效果稿

日期：2026-11-22。状态：设计评估与效果稿，待用户确认；未改代码，不是交付声明。界面中的公司、金额、事务与平台结果均为示意。

依据：[公司工作空间产品设计](../../features/company-workspace-product-design.md)、[有类型的项目](../workbench-modes-2026-11-18/product-design.md)、[Owner 0.1](../owner-0.1/README.md)，以及当前 `CompanyWorkbench.tsx` 总览实现。优先级背景见[项目备忘录](../../project-memo.md)“超级项目下一步优先级”。

## 结论

公司首页只需要回答三件事：**现在要我处理什么、各业务进展到哪、这个月的账和对外结果是否可信。** 必要功能只有五块，全部是对原领域事实的投影；公司领域自己只拥有“业务项目与关联”。原设计中的“普通工作 / 验收 / 决策 / 经营回顾”不应由公司领域另建，工作推进交给 Owner 事务，公司只保存引用。

## 拷问与待决

1. **Owner 代替公司“普通工作”是否成立？** 需要确认 Owner 事务能挂在公司项目下、读取该项目授权的资料，且关闭公司项目不影响事务。若成立，先写 ADR 修订公司产品设计的“业务项目与工作”一节。
2. **首页的发布行依赖 WebAffair 查询按业务过滤。** 当前公司领域只存发布事务引用；需要确认现有查询能按引用取当前步骤与等待原因，不复制步骤状态。
3. **“资料可能未齐”的判断来源。** 账目服务需要能列出已导入来源与覆盖日期；没有这项事实就只能写“完整性未核对”，不能推测缺了哪个渠道。
4. **真实月份仍是公司打磨的首要验收。** 首页做得再好，账目没有用真实月份和代账交付验证，经营账区块的数字就只是演示。

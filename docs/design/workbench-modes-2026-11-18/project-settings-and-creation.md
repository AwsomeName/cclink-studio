# 项目自己的设置与新建项目流程

日期：2026-11-19。状态：产品设计补充；首版实现和验收范围见 [实施记录](./implementation.md)，未合并或发布。本稿补齐每个项目的配置持久化、新建入口、类型选择，以及打开已有目录/Git 项目时的行为。

同日收口补充：固定入口、业务项目关联、关闭/移除、共享资料、运行生命周期、换机、Git 副本交接和用户偏好统一遵循 [产品方案第 9 节](./product-design.md#9-八项生命周期规则)。三条完整流程和效果图见 [使用流程](./user-journeys.md)。本稿中的“接回”不等于复制本机运行状态，Git 共享开关也不等于已推送。

## 1. 产品结论与验收动作

每个项目都有自己的设置文件。项目类型属于项目配置，保存后重新打开仍然生效。新建项目时直接选择类型；已有项目可以从项目设置修改。工作模式仍是独立的内容版面，不用在创建时选择 Markdown、网页或 3D。

目标验收：

1. 点击项目栏“＋ → 新建项目”，选择公司、名称和位置，创建后直接进入该公司的首页；磁盘有新增的项目配置。
2. 在当前项目打开项目设置，把通用类型改为日记，看到首页/入口变化预览，保存后生效；原文件、任务和会话仍在。
3. 关闭、重开或完整复制项目目录，在另一台 Mac 读取同一类型和相对资料映射；本机账号、权限和运行现场不随配置复制。
4. 打开没有配置的已有目录，按兼容规则初始化最小配置；原文件不覆盖、不重排，不自动生成模板日记或公司账本。
5. 从 Git 获取项目时先读取随仓库携带的有效配置；缺少配置按通用项目打开。只读或损坏配置不阻断浏览，但不能谎报已保存。

## 2. 隐藏配置的位置与职责

建议复用既有隐藏目录，为项目设置新增一个明确的文件：

```text
星河公司/
├── .cclink-studio/
│   ├── workspace-settings.json   ← 本提案：项目名称、类型、非敏感资料映射
│   ├── project.json              ← 当前已有身份文件，继续保留
│   └── state/                    ← 当前已有本机工作现场，继续保留
└── 原有文件与目录
```

这是隐藏目录中的普通 JSON 文件，默认不在业务文件树中展示。“项目设置 → 在文件夹中显示配置”可以定位它。用户不需要手工编辑 JSON。

现有代码实际使用 `.cclink-studio/project.json` 保存身份；架构文档的 `workspace.json` 身份命名迁移尚未完成。新增设置不承担身份、不写第二个 ID，不借本次产品设计改名或覆盖旧身份文件。继续由现有 WorkspaceState 领域拥有配置读写与验证，不新增项目状态所有者。

首版实际配置示例（`src/shared/workspace-settings.ts`；公司/通用/电子开发只需前三个字段）：

```json
{
  "version": 1,
  "name": "我的日记",
  "type": "diary",
  "diary": {
    "directory": "000-个人计划",
    "timezone": "Asia/Shanghai",
    "taskIds": []
  }
}
```

第一版实际保存名称、主要类型，以及可选的日记相对目录、时区和原任务 ID。图标随类型显示；自定义图标和更多类型默认值尚未加入配置；侧栏固定/按钮排序保存在本机 layout，不进入共享配置，不应手工添加未知字段。首页和标准功能从类型定义得到，不同时保存一份可漂移的完整菜单和工具清单。类型 ID 固定为通用、日记、公司、电子开发对应的受控标识，不是可执行脚本或任意插件路径。

| 保存到项目配置                            | 继续保存在本机/原领域                      |
| ----------------------------------------- | ------------------------------------------ |
| 项目名称、类型（图标由类型决定）          | 稳定工作空间身份与复制/移动识别            |
| 日记/计划等项目内相对路径                 | 本机外部绝对目录映射、远端设备映射         |
| 类型特定的非敏感默认值                    | API Key、Token、网站登录 Cookie、私钥      |
| 原任务 ID 引用（任务定义须另行共享/导入） | 会话现场、打开标签、运行状态、机器依赖路径 |

外部原日记仍可通过已有本机关联接回，不为方便共享而移动到项目里；另一台机器找不到该来源时提供“重新关联”，不猜测路径或创建空文件冒充原资料。

配置是新的项目设置唯一事实源。普通项目的类型不能继续只保存在全局“最近项目”记录中，也不能由是否恰好打开默认个人目录来猜测；中央索引只做定位/缓存。只读目录的临时偏好必须标为本机临时状态，不能默认为跨机器项目配置。

### Git 与复制

完整复制目录时，设置随目录走；原身份复制识别规则继续决定新实例身份，不能把类型配置中的显示名称当身份。

Git 默认不自动提交任何新文件。提供明确“将项目配置纳入 Git”的选择，只允许此文件的已验证非敏感字段；账号、运行现场、身份和本机路径继续排除。首版已为这个精确配置路径增加有界规则并校验内容，整个 `.cclink-studio` 仍不开放共享。“纳入 Git”仅暂存这个文件，提交和推送继续由原 Git 流程处理。

## 3. 项目自己的设置入口与页面

固定两个入口，指向同一个页面：项目名菜单 → 项目设置；现有设置窗口 → 当前项目。无需再增加一套设置系统。

```text
项目设置 · 星河公司

基本信息
  名称        [星河公司                ]
  项目类型    [公司                  ▾]
  资料位置    /…/星河公司    [在文件夹中显示]

类型设置
  ……仅显示当前类型确实需要的资料关联与默认值……

项目配置
  隐藏配置文件             [在文件夹中显示]
  项目设置                 [仅在本机] [纳入 Git]
  资料                     [项目内 / 关联本机目录]
  自动整理                 [本机尚未启用] [查看任务]

                                      [取消] [保存]
```

修改类型后，在保存前展示明确影响，例如“通用 → 日记：默认首页变为今天，增加日记、计划、定时整理入口”。类型切换不删除旧业务数据、不停止旧任务，也不迁移原文件。旧类型数据仍可从文件/原功能入口打开，换回原类型继续识别；不能用隐藏入口暗中完成数据迁移。

上图三行状态按真实事实显示；已跟踪但尚未提交/推送时附对应状态，未配置整理任务时显示“尚未接回任务”，不能统一显示为未启用。固定入口重新关联只改变本机引用，不向目标项目配置写一个第二身份。侧栏固定/排序及版面现场保留在本机项目 UI 状态；不因保存项目类型而重置。

如果新类型缺少资料，只显示关联/创建引导；不得在点击保存类型时顺便创建新账本、日记或启用定时任务。新建业务对象属于后续明确动作。

写入成功后才显示“已保存”。配置变化会影响当前项目的首页与导航，已打开的文档、版面、会话和任务保留。界面配置覆盖应用默认值；当前文件/标签的临时版面选择不会反向改项目类型。

## 4. 新建入口：和打开已有项目清楚区分

项目栏“＋”固定提供：

```text
＋
├── 新建项目…
├── 打开已有项目…
├── 从 Git 获取…
└── 打开远程项目…
```

没有打开任何项目时，欢迎页提供相同入口。原“打开工作空间”继续指向打开已有项目，不把用户习惯的打开动作改成必须选类型的向导。

### 新建项目

用一个紧凑页面完成，不拆多层向导：

```text
新建项目

类型    [通用] [日记] [公司] [电子开发]
名称    [星河公司                         ]
位置    [父目录                         …]
将创建  /所选父目录/星河公司

公司类型将提供：公司概览、业务项目、账目、运营内容
创建内容：项目目录与必要配置
可选初始化：按当前类型列出可创建的模板及目标位置

                              [取消] [创建并打开]
```

- 创建时选择类型，默认通用，允许直接创建。明确从“新建公司”等类型入口进入时预选公司，不凭目录名自动改类型。
- 类型说明展示现有可用能力；电子开发不能承诺完整 EDA 编辑或全部 CAD 操作。
- 创建按钮写入新目录、必要身份与设置；模板初始化明确列出且可选，默认不自动运行 Agent、开通账号或启用任务。
- 目标目录已存在时，不合并覆盖。提供改名/换位置，或转为“打开此目录”；不要先创建一半再覆盖原配置。
- 创建成功后进入该类型首页。没有业务数据时提供具体的第一步，不显示假数据或空白工作区。

### 打开已有项目

1. 有有效设置：直接按保存的类型打开，不再次问类型。
2. 没有设置：检查明确的既有 Studio 关联/元数据；已有日记或公司绑定保持原语义。普通目录默认通用，在可写时只新建缺失的最小设置，不覆盖任何同名文件。
3. 对普通内容识别出的类型只是建议。页面提供“选择项目类型”，用户可稍后在项目设置修改；不能强制进行类型判断才让文件可用。
4. 新建设置只记录当前项目信息，不自动整理目录或生成业务数据。已有配置损坏/新版本不认识时不按“缺失”处理。

### 从 Git 获取

先填写地址和新目标位置、完成下载，再读仓库配置。不能在下载前要求用户选类型并覆盖仓库里保存的类型。

有兼容配置就加载类型；没有配置按已有目录规则处理。克隆来的配置只改变界面和非敏感默认值，不自动执行脚本、安装组件、授予账号权限或启用共享任务。原有 Git 新副本更新与显式关联策略保持不变。

### 打开远程项目

由远端能力决定能否读取/保存项目配置，不在本机伪造一份远端已保存设置。暂不支持配置操作时保持已有远程文件/会话/终端能力，显示当前项目设置只读或不可保存的具体原因。

## 5. 必须处理的失败路径

| 情况                     | 用户看到什么                     | 处理原则                                                 |
| ------------------------ | -------------------------------- | -------------------------------------------------------- |
| 目录只读                 | 项目配置无法保存；可继续浏览     | 不声称已创建隐藏文件，不反复尝试覆盖                     |
| JSON 损坏/不支持的新版本 | 配置错误，原文件仍可打开         | 保留原配置，通用版面降级；提供定位与显式修复             |
| 类型暂不支持             | 显示原类型名和通用打开选项       | 不把配置里的类型自动改写成通用                           |
| 外部资料目录失联         | 原来源离线，需要重新关联         | 保留关联事实，不自动建立同名空资料                       |
| 创建中途失败             | 显示已创建目录和失败步骤，可重试 | 不删除已有内容；重试只补本次缺失内容，不重复创建业务对象 |
| 配置被外部修改           | 提示重新加载/核对冲突            | 不用旧页面快照覆盖新磁盘内容                             |

本轮只补产品设计，不实际向任何用户项目写入上述新配置。实现时复用现有身份、原子写入、作用域和迁移机制，保持一个状态所有者。

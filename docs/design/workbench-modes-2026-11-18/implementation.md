## 用户验收与顺序

1. 新建日记/公司/电子开发项目；项目设置保存名称、类型和相对资料目录；重开保持，非法/只读配置不覆盖，目标目录已存在不创建。
2. 日记项目接回模拟旧目录和两个原任务，首页预览原文；今日日记已有就打开，不存在才独占创建。旧文件、附件、任务定义校验值不变。
3. 公司与工程之间使用原入口和对象；类型侧栏、工具目录与设置收纳全部旧功能；内容标签使用原编辑器/浏览器/CAD，不建立第二份文档状态。
4. 全新隔离配置从本地 Git 远端获取项目，读取类型和相对目录，共享任务默认不启用；更新新副本明确核对旧任务，原目录不改写。

## 实现边界

- WorkspaceStateService 继续是设置和本机关联的 owner；新增共享 Schema 与可信 IPC，复用激活授权、身份、序列化写入。不新增项目身份、调度器或 Runtime。
- `.cclink-studio/workspace-settings.json` 仅保存受控类型、名称和非敏感相对配置。缺失独占创建；保存核对读取版本；损坏/新版本/符号链接拒绝写入。读失败只降级当前类型 UI，文件仍可用。
- 日记来源按所属工作空间分区；旧全局来源仅兼容原固定个人入口，不能泄漏给新建日记实例。原任务由原服务继续负责。
- 新建仅在主进程授权的父目录创建新子目录；不合并存在目录，不移动/删除用户内容。创建失败保留失败位置及原因。
- Git 只允许精确项目配置路径及原共享任务，验证内容；不放开整个隐藏目录。凭证保持原本机管理，配置不执行脚本或自动启用任务。
- 类型切换前显示影响，保存成功后生效；副本关联前核对原运行/启用任务。权限、发布人工处理和既有命令不因导航重组改变。
- 设置/保存/克隆/接回失败必须在操作位置显示，保留旧状态；无远程设备或 CAD 后端不影响本地日记。

## 验证

自动门禁：配置文件安全/冲突/创建、日记分区兼容、Git 精确共享策略、类型导航与原命令；类型检查与受影响测试。真实应用：隔离 HOME/userData、本地 Git bare remote、模拟资料、原文件哈希；Playwright 操作真实 Electron 页面并保存截图与结果。换机以第二份隔离用户配置验证，不宣称已在用户另一台 Mac 上测试。

## 用户功能进度

三条主流程已在真实 Electron 中通过：新建与项目配置 → 接回原日记/计划/两个定时任务 → 日常编辑与版面切换 → 全新用户配置从 Git 获取与接回任务。详见 [逐步验收动作与截图](../../testing/typed-workspaces-2026-11-19.md)。

- 通用、日记、公司、电子开发由项目配置决定首页与侧栏；普通同类型项目可以有多个。固定入口只是本机快捷引用，进入时读取实际项目类型。
- 原日记、附件、计划和两个任务定义在两轮真实验收前后字节一致；今日日记已有就打开，缺失才创建。任务定义导出/导入保留原 ID，重复导入不重复创建，新设备不自动启用。
- 公司业务可关联已有工程，也可新建并关联；切换类型再切回公司保留原业务。公司账目、发布、设备、Terminal、数据源等继续由原领域处理。
- 账号、角色管理移入设置；类型主入口与通用“工具”分开。当前标签可选择“内容与 Agent”或“专注内容”；现有 Markdown、内嵌网页、模型预览继续使用原对象。
- Git 获取、差异检查和更新副本均已验证；项目配置仅精确暂存，资料来源切换先核对原任务与本地编辑。原来源未完成交接时保持原关联。

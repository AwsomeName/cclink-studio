# 我的空间 · 科技日报：方案评估与效果稿

> 日期：2026-11-25。状态：效果稿，未实现。
> 参考：Argus techdaily（服务器上的复刻规格书 `/home/lc/argus/docs/techdaily-每日搜索流程复刻方案.md` 本机读不到；
> 本评估依据 2026-10 本机留存的 Argus 代码 `src/argus/techdaily/`、用户给出的流程摘要和截图）。
> 前置能力：[联网搜索（DeepSeek）首版](../../testing/web-search-v1.md)。

## 结论

1. **建议在 Studio 里做一个“小号 Argus”，而不是让定时任务 Agent 自己去搜。**
   Studio 主进程跑确定性的流程：按词表搜索 → 过滤 → 去重 → 保存；AI 只做两步纯文本工作：精选、成稿。
   这正是 Argus 跑了两个多月才稳定下来的结构，Studio 不该重新踩一遍“让模型自己决定搜什么、信什么日期”。
2. **不搬 Argus 的基础设施。** SearXNG / Elasticsearch / Redis / Neo4j / systemd 在桌面端都不成立，
   分别换成已接入的 DeepSeek 搜索、本地文件、当天一次的运行锁和现有定时任务服务。
3. **日报是独立文件，不写进日记文件。** 日记页顶部只显示一张入口卡片；日历上用另一种颜色的点标出有日报的日子。
   这样“每日起草”和日报互不覆盖（今天日记大纲为空的问题正是 create-only 写入导致的，不能再叠一个写同一文件的任务）。
4. **最大的未知是 DeepSeek 搜索能不能替代 SearXNG。** 召回率和“发布时间”字段的覆盖率决定日报质量，
   先用真实 Key 做一天对比（约 $0.04）；不达标就补第二个搜索提供方。

## 已确认（2026-11-25）

- 科技日报是**我的空间的标准功能**：任何用户配置好搜索服务的 Key（首版 DeepSeek）并有可用的本机 AI 即可开启。
- 按 Argus 做**基本复刻**，包括过滤门、网址合并、候选库、同事件归组和跨天事件去重。逐层规格见
  [personal-techdaily.md](../../features/personal-techdaily.md)。

## 状态所有者与边界

- **调度**：定时任务服务仍是唯一的调度所有者，不新增第二个计时器。日报是一种内置流程任务，
  执行交给 `TechDailyService`。这改变了“定时任务 = 指令 + Agent”的契约，实现前需要一份 ADR。
- **运行与候选**：`TechDailyService`（主进程）拥有当天运行记录、8 个步骤的状态和候选清单。
  界面只展示它发出的真实事件，不按计时推测进度。
- **联网**：只通过 `WebSearchService`；日报有自己的每日调用上限（默认 80），同时计入联网搜索的每月总上限。
- **AI**：只拿到候选文本，不联网、不读文件、不写文件；输出 JSON 由 Studio 校验，失败重试一次。
- **文件**：Studio 写 `科技日报/{year}/{month}/{MMDD}.md`（头部含状态、计数、事件 uid、来源）。
  同一天重新成稿时覆盖当天日报，不碰日记文件。
- **多设备**：设置和日报随我的空间同步；生成任务照现有规则只在启用的那台设备运行，避免两台机器各生成一份。

## 失败与降级

| 情况                                      | 用户看到                                                 | 不做的事         |
| ----------------------------------------- | -------------------------------------------------------- | ---------------- |
| 联网搜索未启用 / 缺 Key                   | 首次开启页提示先去启用；已开启的日报显示“联网搜索不可用” | 不改用其他搜索   |
| 达到每日或每月上限                        | 用已得到的结果继续；日报头部标明“搜索未完成 24/36”       | 不超额调用       |
| 候选少于 8 条                             | 生成“今日候选不足”的短报，列出各领域结果数               | 不凑条数、不编造 |
| Codex 与 Claude Code 都不可用             | 第 6 步失败，候选已保存；可登录后“重新成稿”或只看候选    | 不重新搜索       |
| AI 输出不是合法 JSON / 引用了不存在的候选 | 重试一次，仍失败则停在该步并说明                         | 不采用半截结果   |
| 退出 Studio                               | 运行中断；下次打开从头生成当天的                         | 不补昨天         |
| 某条缺来源网址或发布时间                  | 第 8 步核对时剔除该条                                    | 不保留无来源条目 |

本地功能（日记、编辑器、Agent、浏览器……）在以上任何情况下都不受影响。

## 费用

按 9 个领域 × 4 个搜索词估算：每天 36 次搜索 + 最多 10 页原文 ≈ 46 次 ≈ **$0.035/天，约 $1/月**。
每月约 1,400 次，会吃掉联网搜索默认每月 2,000 次上限的大半，开启日报时提示把上限调到 4,000。
精选与成稿用本机 Codex / Claude Code，不另计费。

## 拷问

- **DeepSeek 搜索是否够用？** 没测过。SearXNG 聚合多个引擎，DeepSeek 是单一来源；中文垂直媒体的召回、`date` 字段的覆盖率都未知。所以第 0 步是硬门槛。
- **“打开时补生成”是否让人等？** 搜索 36 次几秒内完成，两次 AI 调用约 1–3 分钟；在后台进行，不占当前会话。但首次打开 Studio 时会立刻开始花钱，设置里可以关掉补生成。
- **会不会和“每日起草”打架？** 不写同一文件就不会。日记里需要留痕时，只插入一行标题和链接，由用户点击触发。
- **AI 编造新闻怎么办？** AI 只能引用候选编号；标题、网址、日期都由 Studio 从候选里填，AI 只写评论。第 8 步再核对一次来源。
- **版权**：只保留标题、要点、评论和链接，不保存或展示原文全文；原文只在成稿时临时交给 AI。
- **没有读到 Argus 的复刻规格书。** 本机只有 2026-10 的 Argus 代码，规格书里新增的坑（例如 LLM 裸引号、跨午夜不补跑）是根据摘要推断的。实现前请把规格书放进 `docs/references/`，或在 argus 项目里把它复制过来。

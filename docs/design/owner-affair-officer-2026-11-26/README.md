# Owner 事务官 · 分工与授权方案

2026-11-26 方案稿，尚未实现。[打开可交互设计稿](mockup.html)，可在三件不同类型的事务之间切换。

## 一句话

Owner 是聊天问答的升级：它不靠对话记忆，而是为每件事维护一套事务文件（目标、约定与授权、计划、进度、决定、资料、交付物）。真正动手的是它派出去的会话，每个会话只领一步、只看给它的文件、只用这一步分到的能力，做完交回，由 Owner 写回文件。授权在确认约定时一次给到事务上，运行中只在边界上停下来问。

## 方案评估结论

截图里的"多模型分工"可以支持，但不能照搬成开发流水线。它对 Owner 有用的部分是三个通用机制：

1. 某一步交给另一个模型、只给它最少的信息，换来独立意见；
2. 交付前换模型复核，只有带证据的问题才能挡住交付；
3. 复核有轮数上限，过不去就交给用户决定。

这三个机制都可以表达成"计划里的一步"，不需要新的流水线或编排框架。调研、写作、问答、改代码都用同一套表达。

## 要解决的问题

| # | 问题 | 解决办法 |
| - | --- | --- |
| 1 | 现在的上下文是会话消息，换会话、换运行时就断 | 事务文件是唯一事实。每一步的输入由 Studio 从事务文件切片生成，输出写回指定文件。会话可以随时更换，不影响事务 |
| 2 | 角色带着场景名（取证执行、前端、后端） | 只保留通用职能：Owner（维护事务文件、做判断、和你对话）、执行、独立意见、复核。具体做什么写在每一步里 |
| 3 | 授权太精确：按文件、按调用逐项弹窗，看不懂全貌，运行被打断 | 授权按"能力类别 + 范围"写在约定里，分三档：直接做、先问我、不做。确认约定即授权，运行中不再逐项问 |
| 4 | 授权太模糊会失控 | 精确只保留在三处：范围（哪个目录、哪个账号）、边界动作（约定外、不可逆、对外、命令）、每一步分到的子集。会话不能扩大自己的能力 |
| 5 | 独立意见只靠提示词隔离 | 每一步写明"给它看的文件"，Studio 只把这些文件交出去，并在工作记录里留下输入清单和哈希 |
| 6 | 复核变成"另一个模型发表看法" | 复核意见分阻断、建议、不计入。阻断必须引用资料里的具体位置，经 Studio 核实才生效；最多两轮，之后进入待你决定 |
| 7 | 运行时写死成 Codex 或 Claude Code | 全局登记运行时（ACP 后端改成实现清单，先接 Gemini CLI），Owner 设置里按职能排偏好。独立意见和复核尽量与产出方不同，凑不齐时照常运行并在调度里注明 |
| 8 | 小问题也走一整套太重 | 计划按事务裁剪：快问只有一两步，不加独立意见和复核；全部在默认授权内时可以直接开始（见待决事项） |
| 9 | 平台操作会出现第二个状态所有者 | 存草稿、发布等平台动作仍由 WebAffair 执行计划持有进度，Owner 的步骤只引用它的结果和核验证据 |

## 授权怎么写

能力类别是用户能看懂的一层"模糊"：

| 类别 | 范围示例 | 默认档 | 规则 |
| --- | --- | --- | --- |
| 读本地资料 | 某个已登记目录 | 直接做 | 约定外的文件逐个先问，60 秒无回应跳过 |
| 写事务目录 | 本事务目录 | 直接做 | 固定开启，不能关闭 |
| 查公开资料 | 公开网页、公开仓库 | 直接做 | 只读 |
| 使用网站账号 | 某个账号 + 允许的动作（只读 / 存草稿） | 先问我 | 约定里点名账号和动作后可改为直接做 |
| 对外发布或发送 | 某个账号 + 某篇内容 | 不做 | 只有约定里点名具体账号和内容，才能改为先问我；永远不能直接做 |
| 运行命令 | 某个工作区 | 先问我 | 锁定，永远先问 |
| 删除、付款 | — | 不做 | 锁定 |

- Owner 设置只放每个类别的默认档。约定把默认档实例化成这件事的范围，写进 `事务配置.md` 的"授权"一节，你确认即生效。
- 每一步列出它分到的能力，是事务授权的子集。独立意见和复核默认没有外部能力，只能看交给它的文件。
- "先问我"沿用全局 60 秒超时：无回应就跳过这一步，其余步骤继续。跳过的是必需步骤时，事务停在"待你决定"，不能交付；事后允许只会重跑受影响的步骤。

## 运行时与 AI 分工

参考用例的核心是"在合适的任务上用合适的人"：Claude 统筹，Gemini 独立出方案、改文案，GPT 写后端和严格审查。Owner 保留这个思路，但把"谁擅长什么"做成可改的偏好，不写死厂商。分三层：

**1. 运行时登记（全局，设置 › Agent 运行时，Agent 面板共用）**

| 字段 | 说明 |
| --- | --- |
| 接入方式 | 原生后端：Claude Code、Codex。ACP：Gemini CLI，之后 OpenCode 等；"添加 ACP 运行时"填启动命令即可 |
| 登录与计费 | Studio API Key、本机登录、Google 账号等；写明费用记在哪里（API 用量、订阅、配额） |
| 模型 | 可选模型列表和默认模型 |
| 状态 | 已就绪、未登录、未安装、版本不兼容；由主进程探测，"测试连接"只发不含事务内容的探测消息 |

凭证留在各运行时自己的登录或 Studio 现有本地凭证文件里，不使用系统钥匙串。

**2. 按工作类型分工（Owner 设置）**

每一步标一个工作类型，每个类型有一个按顺序的运行时偏好，取第一个可用的。默认值照参考用例排：

| 工作类型 | 做什么 | 默认顺序 |
| --- | --- | --- |
| 统筹 | 维护事务文件、拆解、合并、判断 | Claude Code → Codex |
| 独立构思 | 只看目标，独立出方案或意见 | Gemini CLI → Codex → Claude Code |
| 写作文案 | 写正文、改文案 | Claude Code → Gemini CLI |
| 检索取证 | 读资料、查源码、记出处 | Codex → Claude Code |
| 审查核对 | 挑错，只认带证据的问题 | Codex → Gemini CLI → Claude Code |
| 代码实现、界面视觉 | 第二阶段 | Codex → Claude Code；Claude Code → Gemini CLI |

**3. 分工规则**

- 独立意见和复核不能与被评价、被复核内容的产出方是同一个运行时（锁定）。例：Ibex 对比里审查核对首选 Codex，但证据是 Codex 采集的，所以自动改用 Gemini CLI。
- 凑不齐不同的运行时：默认照常运行，在约定和调度里标"独立性打折"；也可以设成停下来在右侧问你。
- 运行中某个运行时不可用：按顺序换下一个并写进工作记录；全都不可用时这一步变成"等你"。
- 每件事务有模型运行次数上限（默认 20），超出前在右侧问你。

**在约定里怎么看**：约定多一张"分工"卡，列出每一步的工作类型、运行时和模型、为什么这么排，确认前可以逐步改（或在右侧说"第 4 步换成 Codex"）。确认后写进 `事务配置.md` 的"分工"一节，每一步的实际运行时和原因写进 `调度.md`。Owner 记录只存每一步的绑定快照，运行时登记和健康状态仍由设置与主进程运行时服务持有。

**实现要点**：ACP 后端从只认 `codex-acp` 改成实现清单（启动命令、版本探测、登录检查、环境变量）；Owner 派出的步骤都以纯文本方式运行，读取仍由 Studio 完成，所以新运行时不需要文件或终端权限。Gemini CLI 的 ACP 启动参数需要在本机探测确认。

## 右侧对话：事务官和人的唯一交互入口

- 右侧固定一栏"事务官"对话，绑定当前事务。不论中间在看板、事务文件还是 Owner 设置，它都在，窄窗口也不收起。
- 所有要人处理的事都只出现在这里：确认约定、批准"先问我"的动作、待你决定、补授权、提出新约定（例如要发布）。60 秒倒计时也在这里，切到别的页面照样计时。
- 中间只呈现事实（看板和事务文件），不放操作按钮。有待办时中间显示一行"有 1 件事等你，在右侧对话里处理"，栏头显示"等你 N"。
- 你在对话里说的话会写进事务文件：改约定写入 `事务配置.md` 的待确认草案，确认时一并生效。对话本身不是上下文，事务文件才是。

## 每一步写什么

每一步在 `调度.md` 里都有同样的七项，看板、文件和诊断读的是同一份：

1. 做什么；
2. 谁做（Owner / 执行 / 独立意见 / 复核 / Studio 核验）和实际运行时；
3. 给它看的文件；
4. 它能用的能力；
5. 完成条件和核验证据；
6. 交回写到哪里；
7. 当前状态：待开始、进行中、等你、已跳过、完成。

## 验收

真人在真实应用中完成：

1. 在 Owner 设置里看到并修改能力类别默认档；
2. 交办 Ibex 对比，在约定里看到三档授权和每一步的输入、能力，确认一次后运行中不再弹出约定内的请求；
3. 约定外文件请求 60 秒后跳过，事务进入待你决定，允许后只重跑受影响步骤并交付；
4. 交办写文章，草稿出现在博客园草稿箱，事务显示"已存草稿，未发布"；
5. 快问在默认授权内直接给出带引用的答案，事务目录里能看到这次的记录；
6. 打开 `事务配置.md` 和 `调度.md`，内容和看板一致。

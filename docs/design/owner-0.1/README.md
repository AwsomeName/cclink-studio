# Owner 0.1 · 独立面板

设计定稿范围 · 2026-11-19 · 首个可运行切片见下。[Owner 定义](../../features/ai-employees.md)｜[新版 Studio 工作台](../workbench-modes-2026-11-18/product-design.md)｜[打开六步可点击原型](preview.html)。自研，不引入 [AgentOp](../../research/owner-0.1/agentop.md) 或 [pi-missions](../../research/owner-0.1/pi-missions.md) 代码。

**开发版入口：** Studio 顶栏「Owner」，在右边直接说“帮我调研开源芯片项目”。Owner 先提议比较对象、维度和交付物；可用自然语言修订。确认后派原生会话 A 为约定仓库提出 README 读取请求；Studio 逐个获取公开原文，同一 A 比较并写简报。看板记录请求、实际读取、回执和核对。项目覆盖及引文匹配才可交付；不匹配退回原会话一次，仍失败保留待处理。

当前限 1–4 个公开 GitHub 仓库的 README；不搜索全网、不安装或实跑项目。快照最多保留开头 9,000 字符，分析最多使用每份前 6,500 字符。引用匹配不保证分析结论完全正确。来源、原文、时间和报告均可回看，简报可导出 Markdown。进程中断不自动派工；重试使用已读资料。原「从已有材料做摘录」仍保留为次要入口。后续 HTML / PNG 展示的其他交互属于完整设计，不代表全部实现。

**用户验收动作：** 未打开任何项目时，从 Studio 的固定 Owner 入口交办开源芯片调研；在右边明确这次只查文档，在中间看它派工、退回缺证结果、补查并交付。全程只需确认一次。关闭面板再回来，仍然看到同一事务、同一主对话、真实执行记录和下一步。以下图片是交互设计样例，未执行 Agent 或芯片仿真。

## 面板归属与使用方式

- Owner 是 Studio 里的独立面板，不占项目栏中的项目名额，不作为项目类型或工作版面；第一版不需要另弹桌面窗口。固定入口进入事务列表，可新建或回到一件事务。项目只可按需提供明确授权的资源；切项目不改变任务或授权，一个 Owner 不管理其他 Owner。
- 中间是**当前事务的看板**：目标、事务状态、Owner 当前动作、谁需要处理、执行步骤，及当前步骤的材料和结论。资料与出处、交付物、事务设置、委托与回执在中央查看。右边始终是**本事务的 Owner 主对话**：可以提问、修改要求、确认边界；核查执行记录不把右边换成 A 的聊天。
- 事务状态（待确认／进行中／等待你决定／暂停／已交付）描述整件事；Owner 动作（派工／等回执／核对／补查）说明此刻在做什么；执行会话显示本次运行的真实终态。三者分开，发现缺证不意味着在等用户。
- 默认偏好只管格式、惯用来源和提醒方式，不赋予权限。在交办时回显本次范围、交付与验收、可用资源、时间限制（截止时间与最多投入时长分开；无要求则不设硬限制）以及用户指定的流程。明确的要求直接采用；足以改变工作量或交付的歧义才问。右边确认的修改要同步反映在中央设置；单纯询问不算改动或授权。
- Owner 自行安排查询顺序、派工和补证。需扩大范围、安装或实跑、改截止时间或降低验收标准时，展示影响与可选动作，等人决定；到期给出已核对的结果和未完成项，不把部分完成标为交付。

## 从 Studio 到一件事务

[入口与列表交互预览](entry.html) · [首次进入](entry-01-home.png) → [空列表](entry-02-empty.png)；[再次回来](entry-03-list.png) → [进入事务](entry-04-detail.png)。

1. **固定入口在 Studio 顶栏右上角。** 无项目也可用，欢迎页提供同名快捷入口。两处始终进入「我的事务」；不创建项目，不自动跳到上次对话。顶栏的“1 等你”只数确实需要用户作决定的事务；零件不显示。
2. **第一次列表为空。** 点「交办第一件事」到新事务；之后可从列表的「新建事务」交办。再次进入，默认先列「等我确认」，再列「进行中」「已交付」；可点分组筛选。列表读各事务现有的状态和最新动作，自身不启动或统筹执行。示例中的三件事各自有独立的 Owner。
3. **一行足以决定点不点。** 等人的直接写待决问题；进行中的写 Owner 当前动作和剩余事项；已交付的写产物。同组较新变化在前。确认数不等于未读消息数；会话结束、Owner 正在自行补证都不产生待办。
4. **点哪一行，就进哪一件事。** 中间是这件事的看板，右边才出现它的主对话；列表层没有跨事务的聊天框。从详情左上「‹ 我的事务」回列表，不暂停任务或关闭主对话。图中“1 等你”属于另一行的资料引用问题，不是芯片调研在等你。
5. 走查首次入口、空态、新建使用设计样例；有数据的返回场景以固定的三个示例展示，「开源芯片调研」可查看执行，「芯片资料引用范围」可讨论并确认。实现后应在无项目、切项目、重启三种情况下验收固定入口、待确认计数及返回关系。

## 等我提供资料：保留白皮书原文

[从待补材料列表重放](entry.html#material-demo)。本例延续 OW–018，甲乙文件和说明均为虚构样例；不读取本机文件，不执行真实审查或派工。

[01 列表列缺项](material-01-list.png) → [02 指定提交入口](material-02-add.png) → [03 收到待核对](material-03-review.png) → [04 部分通过](material-04-gap.png) → [05 回来只补乙](material-05-return.png) → [06 复核通过、续用 A](material-06-resume.png) → [07 列表更新](material-07-list.png)。

- 待决定和待补料分别计数。顶栏“1 待补料”按需要补件的事务计，不按文件个数计。列表优先显示哪份、哪个版本/章节、缺原文还是使用依据。点该行到同一事务看板提交，右侧仍是原主对话。
- 提交限定到本事务。Owner 先验可读性、版本和摘录位置，再核对说明的来源、适用内容、受众、使用方式。资料不足只回退有问题的项。甲通过、乙仅供个人阅读时，保留甲和乙正文，只请求乙的团队离线分发依据。说明矛盾或出具方不明时继续等待，不自行判通过。
- 补件收到时先回到复核；已通过的甲不会重查（除非其材料或要求发生变化）。两份均通过且 A 真实开始后才显示“A 正在整理”；需要用户提交时不反复续派，恢复提交或重复回执不多开运行。交付前仍要核对资料包，不能把材料通过计为整件事务完成。
- 走查中用示例附件、底部“查看下一份核对回执”模拟事件。已在原型验证选分支、提交、部分不符、刷新列表精准补件及同会话续办；真实持久化、文件读取和运行回执需在应用实现后另验。

## 派工与核对规则

1. 已有会话能用、问题连续且环境和权限相容，默认续用。无可用会话时才开第一段。需要独立复核、执行环境隔离或原会话不能续用时可另开，并记下原因。换步骤或一次运行已结束，都不是另开会话的理由。0.1 同时只派一个执行；派工单包括本步问题、已知事实、可用资料、权限和所需证据。
2. Owner 将每份回执关联到事务、步骤、会话和具体运行，先确认运行终态，再检查来源能否打开、具体章节是否支持结论、产物是否覆盖约定。资料有冲突则展示双方出处；证据不够而范围内能补，就退回具体缺项。只有用户才能排除的阻塞，才标为等待用户。
3. 重开先对账，不重派已完成的运行；旧或重复的回执不能覆盖较新的判断。权限撤销即停止对应工作；中断且不能核对的保持“待核对”。暂停后不再派工；不自动重试可能产生外部副作用的动作。面板不自作运行事实源：会话消息、Run 和权限仍归既有服务，网页发布进度仍只由 `WebAffairService` 维护。参见[架构宪法](../../architecture.md)。

## 一件事务走六步：开源芯片调研

读者懂一点 RISC-V，第一次读 CPU 源码，希望跟懂一条指令。一个 Owner、一个主对话、一段执行会话 A。三次运行：比较架构 → 查示例 → 定向补缺。

| 时刻 | 谁决定、依据是什么 | 是否需要你操作 |
| --- | --- | --- |
| [01 确认交办](01-brief.png) | 你在右边发起；Owner 把三个项目、一页简报、仿真入口与记录位置、只读官方文档和时间问题写入交办草案。 | **需要**：同意只查文档、不实跑，无硬截止。 |
| [02 委派 A](02-session-a.png) | 尚无执行会话，首次创建 A，委托比较三个项目并附官方出处。 | 无需。 |
| [03 续用 A](03-continue-a.png) | 核对三份架构出处后初选 Ibex；同一目标、环境、权限均未变，续用 A 查示例与输出。 | 无需。右边可问“为什么”，不打断工作。 |
| [04 退回缺证](04-gap.png) | A 第 2 次运行结束，只报 Verilator 的名字。Owner 按交办条件指出缺示例入口、输出位置，保持进行中。 | 无需，公开资料可继续查。 |
| [05 定向补查与复核](05-resume.png) | A 第 3 次运行只补两处，Owner 对照 Simple System README 核实，未核对前不算交付。 | 无需。 |
| [06 交付简报](06-delivery.png) | 三项目定位、首选理由、示例入口和输出文件对得上四份官方资料，产物可读。交付注明未实跑。 | 可打开简报，无须为交付再点一次批准。 |

官方资料：[Ibex Pipeline Details](https://ibex-core.readthedocs.io/en/latest/03_reference/pipeline_details.html)、[CVA6 README](https://github.com/openhwfoundation/cva6)、[Earl Grey Datasheet](https://opentitan.org/book/hw/top_earlgrey/doc/specification.html)、[Ibex Simple System README](https://github.com/lowRISC/ibex/blob/master/examples/simple_system/README.md)。原型底栏 01–06 用于走查，非正式应用的流程控制；主对话为固定样例。

**实现后还须单独验收：** 零项目也可交办；切项目、关闭执行会话标签或重启后，事务不丢、主对话不换、不重复派工；有实质变更才请求授权；若原 A 已归档且不可续用，才新建并交接，右侧仍是原 Owner。若某项来源失效、矛盾或简报不可读，不能标成已交付。

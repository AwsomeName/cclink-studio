# 我的空间 · 产品功能与逻辑（第二版）

2026-11-21，已确认。AI 是必选能力，可读取全部日记，并在用户要求时修改原文且说明改动；Git 同步是核心能力；保留移动端扩展；富媒体基于 Studio Markdown。效果图见 [第二版效果图](mockups-v2.html)。

## 1. 定位

「我的空间」是 Studio 内置、始终存在的个人日记项目。一个本机目录承载日记、计划和资料；AI 每天起草、每周复盘；Git 在多台设备间同步。

核心闭环：**每天定时 AI 自动生成当天草稿 → 用户打开即补写 → 每周 AI 自动复盘 → Git 同步到其他设备**。日常不需要用户点击生成。

| 能力 | 级别 | 说明 |
| --- | --- | --- |
| 本地日记目录 | 必选 | 唯一事实来源，Markdown 原文 |
| AI（本机 Codex / Claude Code） | 必选 | 可读取全部日记与计划；每日起草、每周复盘；按用户要求修改原文；首次使用即配置并验证 |
| Git 同步 | 核心，首次推荐配置 | 多设备同步的唯一通道；可稍后连接，未连接时首页持续提示 |
| 富媒体 | 基于 Studio Markdown | 图片、表格、任务清单、代码、附件链接 |
| 移动端 | 本期不做，保留能力 | 数据与规则保持跨端可读，见第 12 节 |

不做：多人协作、自建云存储、日记加密、专有日记格式。

## 2. 原则

- 一个项目目录：首页、文件树、会话、终端、任务、Git 都指向它。
- 原文是唯一事实：不建索引库，不改已有文件名；AI 产物也是普通 Markdown。
- AI 可读全部、按要求修改：AI 能查阅项目内全部日记、计划和资料；只有用户明确要求时才修改已有文件，改完必须说明改了哪些文件、改了什么，并可一键撤销。定时任务无人值守，只新建、不覆盖。
- 同步可审阅：拉取前看差异，上传前看变更；保存、检查更新都不上传。
- 失败可继续写：AI 或网络临时不可用时，用户仍能新建空白日记并编辑，状态如实标注。

## 4. 入口

- 顶栏第一个标签固定为我的空间，不可拖动、关闭；文字为项目显示名，默认「我的空间」。
- 点击进入「今天」。左侧单栏：今天、日记、计划、定时整理；分隔后为文件、会话、工具。项目设置在首页右上角。
- 状态栏：「本地 · 显示名 · AI 状态 · 同步状态」，点击状态进入对应设置。

入口状态（主进程判定）：

| 状态 | 判定 | 显示 |
| --- | --- | --- |
| 未设置 | 未确认目录 | 首次使用 |
| 可用 | 目录存在且身份一致 | 今天 |
| 失联 | 目录不存在或身份不一致 | 重新定位 |
| 不可读 | 权限或设置损坏 | 原因 + 重试 / 重新定位；不新建空项目 |

AI 或同步异常不改变入口状态，只在今天页和状态栏提示。

## 5. 首次使用（四步）

查看任何一步都不写入；只有最后确认才写入。

1. **目录**：使用默认目录（`~/CCLink Studio/我的空间`，确认前不创建）或选择已有目录（只读核对：日记目录、篇数、最近一篇、是否 Git 仓库、远端）。
2. **同步**（推荐）：
   - 新设备从已有仓库开始：填仓库地址与认证 → 克隆到所选空目录 → 核对日记、附件、任务。
   - 已有目录已是仓库：自动带出远端和分支。
   - 已有目录不是仓库：可初始化为仓库并连接远端（首次提交前展示将纳入的文件），或稍后再连。
   - 选「稍后」：首页和状态栏保留「未同步」提示。
3. **AI**：检测本机 Codex / Claude Code 是否已安装并登录；未就绪时引导安装、登录，并做一次短测试。未通过不能完成首次使用，但可以先保存前两步，下次回到这一步。
4. **核对并确认**：列出目录、日记目录、时区、同步状态、AI 运行时、将新建的内容（设置文件、日记目录、默认模板、每日起草与每周复盘两个任务）。「每日起草」「每周复盘」默认在本设备启用（勾选项默认选中，此确认即本设备授权），默认每天 01:00、每周日 21:00，可在此处或之后在定时整理中修改。确认后进入今天；若当前已过起草时间且今天没有日记，立即生成一次。

识别已有目录的日记根：项目设置 → 「个人计划」→「000-个人计划」→ 用户指定。

## 6. 今天

日期按项目时区计算。

| 情况 | 显示 | 主操作 |
| --- | --- | --- |
| 今天尚未到起草时间 | 「01:00 自动生成草稿」、将写入的路径、起草依据 | 无需操作；可选「现在起草」或空白模板 |
| 已自动生成（日常状态） | 摘要、来源「01:00 自动起草」 | 继续写 |
| 起草中 | 实时进度、已读取的文件 | 取消 |
| 已有一篇（手写或其他设备同步来的） | 摘要（各二级标题首段）、来源标记 | 继续写 |
| 自动起草未成功（错过、失败、中断） | 当天第一次进入今天页时自动开始起草并显示进度；仍失败时显示原因 | 「重新起草」或空白模板 |
| 多篇（兼容命名） | 各篇原名 | 选择一篇继续写 |
| AI 不可用 | 原因与修复入口 | 空白模板（标注未经 AI 起草） |

下方固定：本周计划（缺失时显示最近一份及日期，并提供「AI 生成本周计划」）、同步状态（远端有更新 / 本地未上传）。

规则：
- 每日起草默认每天 01:00 自动运行，用户日常不需点击，进入首页即看到当天日记。到点时 Studio 未运行，则下次打开 Studio 且今天尚无日记时自动补起草一次（只补当天，不补以前的日期）。
- 当天的起草失败或中断时，当天第一次进入今天页立即自动重新起草一次；同一天再次进入不重复触发。用户主动取消的起草不自动重来。
- 我的空间缺少每日起草任务时（如旧版本升级），进入今天页自动创建并启用两个内置任务。
- 起草前先检查同步：远端已有当天日记（其他设备已生成或手写）时拉取它，不再生成，避免两台设备各生成一份。
- 独占创建：手动「现在起草」、补起草与定时起草不会产生第二篇；已有文件则直接打开。
- 「现在起草」「重新起草」走同一个每日起草任务，结果同样写入当天路径。

## 7. 日记（历史）

- 按年月翻页，每行：日、星期、文件名、来源标记；同日多篇逐行列出。
- 兼容合并月份目录（如 `07-08`）按文件名日期归月；无法识别日期的放「未识别」组。
- 只收日记；`项目记录`、`资料`、`会话记录` 下的日期文件不算。
- 预览、打开原文、「AI 总结这段时间」（对选定范围运行一次性任务，产物存为新文件）、「让 AI 修改」（见 8A）。

## 8. 编辑与富媒体

基于 Studio Markdown 编辑器：

- 同一文件一个编辑标签；保存写回原 Markdown；含编辑器不支持的内容时自动切源码模式，不拒绝编辑。
- 图片：粘贴或拖入时复制到相邻的 `MMDD_周X.assets/`，正文写相对路径；预览随 Markdown 渲染。
- 表格、任务清单、代码块、链接：沿用编辑器能力。
- 其他附件（PDF、音频、视频、表格文件）：同样放入 `.assets/`，正文以相对链接引用，点击用 Studio 对应查看器或系统应用打开。
- 不引入专有块格式，保证任何 Markdown 工具（含未来移动端）能读。
- 切到文件树自动展开并选中当前文件；切项目再回来，标签与未保存内容保留。

## 8A. AI 读取与修改

**读取**：AI 的默认读取范围是整个日记目录（日记、计划、模板、资料、会话记录）。用户可以随时问「上个月哪几天提到电源板」「整理今年的体重记录」，AI 检索原文后回答，并列出引用的文件和日期，可点击打开。

**修改**：
- 触发：用户在今天页、编辑器或会话中明确要求，例如「把今天的待做按优先级重排」「把 11 月所有日记里的『样品A』改名为『样机A』」。
- 执行前：涉及单个文件且用户正在看时直接执行；涉及多个文件、删除内容或重命名时，先列出将改的文件清单，由用户确认。
- 执行后：显示改动报告——每个文件的修改说明和差异（新增绿、删除红），以及「撤销本次修改」。撤销恢复到修改前版本。
- 冲突：文件在编辑器中有未保存内容时，先请用户保存或放弃，不覆盖未保存内容。
- 记录：每次修改在会话中保留报告；已连接 Git 时，修改也会出现在待上传变更里，可再次审阅。
- 边界：只改项目目录内文件；不改 `.cclink-studio` 下的本机状态；定时任务不做修改类操作。

## 9. 计划（第三版）

计划按周期管理：周度、月度、年度，外加长期计划。计划与日记分开存放，各有固定的目录和命名；每种周期由一个 AI 任务按时生成下一期计划。

### 9.1 目录与命名

计划根默认是项目根下的 `计划/`，与日记根并列（项目设置可改）。日记根只放日记与附件。

```text
woniu-forward/
├── 个人计划/                 # 日记根：YYYY/MM/MMDD_周X.md 与附件
└── 计划/                     # 计划根
    ├── 周/2026/2026-W47.md   # ISO 周：第47周 = 2026-11-16 至 11-22
    ├── 月/2026/2026-11.md
    ├── 年/2026.md
    └── 长期/一日生活计划.md
```

- 文件按**它所计划的周期**命名，不按写作日期；周以周一开始（ISO 周）。因此周日生成的下周计划直接写成下周的文件，不需要“周日算下周”的推断。
- 每份计划一个文件。周期计划固定章节：「上期回顾」「本期目标」「待办」（任务清单）「备注」。复盘写在下一期计划的「上期回顾」中，不再单独成文件。
- 计划根内的文件只由用户或计划任务新建；AI 修改已有计划遵循 8A（改动报告与撤销）。


### 9.2 页面结构

计划页分为中间与右侧两栏。

**右侧上部：周期选择与日历**
- 顶栏切换：「周度」「月度」「年度」「长期」。
- 周度：列出前 6 周、本周、后 2 周，每行「W47 · 11/16–11/22」，有计划的标记完成进度；可向前翻页。
- 月度：所选年份的 12 个月网格，带年份切换；有计划的月份显示进度。
- 年度：前 3 年、今年、明年。
- 长期：长期计划文件列表，可新建、重命名或确认删除。
- 本期默认选中并高亮；点击任一周期，中间显示该期计划。长期计划可自由组织正文。

**中间：所选周期的计划正文**
- 标题为周期与日期范围（如「2026 第47周 · 11/16–11/22」），标注来源（AI 生成 / 手写）与完成进度（按 `- [x]` / `- [ ]` 统计）。
- 直接在 Markdown 富文本编辑器中编辑；底部对话自动挂载当前文件，可输入要求调整正文。
- 所选周期没有计划时：本期或未来周期显示「AI 生成计划」（依据上一期计划、期间日记与上一期待办完成情况）和「空白计划」；过去周期只提供「补写计划」，并显示该期日记篇数。

**右侧下部：设置**
- 这份计划：文件路径、最后修改、来源、完成进度、该期日记篇数（可打开）。
- 该周期的生成设置（即对应 AI 任务）：生成时机（周度默认周日 21:00 生成下周；月度默认每月最后一天 21:00 生成下月；年度默认 12 月 31 日 21:00 生成明年）、保存目录、文件命名、读取依据、本机是否启用、编辑生成要求（打开任务详情）。

### 9.3 规则

- 每种周期一个内置计划任务，首次使用时与每日起草一起创建；周度默认启用，月度、年度默认停用，由用户开启。
- 计划任务只新建下一期文件，不覆盖；已存在则跳过并记录。
- 完成进度只读统计，不改写文件。
- 今天页的「本周计划」直接链接到计划页周度的本周。

### 9.4 工程影响（实现前提）

- 定时任务支持月末、年末和下一期命名。下周使用 `{nextWeekYear}-W{nextWeek}`，下月使用 `{nextMonth}`，明年使用 `{nextYear}`。
- 项目设置新增计划根目录（默认 `计划`），随 Git 同步。
- 计划页新增周期日历组件；第二版的「本周置顶列表」方案作废。

## 10. 定时整理（AI 任务）

列出本项目全部任务，无需额外「关联」。

- 内置两个任务（首次使用时创建并默认在本设备启用，可修改时间与内容、可停用，删除需确认）：
  - **每日起草**：读取昨日日记、本周计划、模板，输出当天日记路径。
  - **每周复盘**：读取上周日记与上一份周计划，输出当年 `周计划/`。
- 用户可新建任务，或从日记、计划页对选定内容发起一次性任务。
- 任务详情：任务内容（自然语言，可约定章节数量、次序、标题、格式、篇幅、缺失事实写法）、读取范围、输出规则、失败模板、运行历史、产物链接。
- 规则：内置任务在首次使用确认时即完成本设备授权；从 Git 带来的其他共享任务在每台设备默认停用，启用需确认当前版本；定义变化后自动暂停并提示重新确认（每日起草暂停时今天页明确提示）；定时运行只新建不覆盖（修改类请求由用户在会话中发起）；产物只写 AI 最终回答；Studio 未运行时不调度；再次打开时每日起草自动补当天，其他任务只显示错过记录并可手动补跑。

## 11. Git 同步

| 操作 | 行为 |
| --- | --- |
| 连接 | 首次使用或项目设置中填写远端、分支、认证（单次使用，不保存到钥匙串） |
| 检查 | 打开我的空间和定时间隔自动检查（只下载）；状态栏显示有更新 / 未上传 / 冲突 |
| 拉取 | 展示新增、修改、删除及正文差异；工作目录干净且未分叉时原位快进 |
| 上传 | 展示将提交的文件；用户确认提交说明后提交并推送；默认不自动推送 |
| 冲突与分叉 | 阻止拉取，列出冲突文件，引导在 Git 变更面板处理；可另存远端版本为独立副本供对比 |
| 排除 | 本机状态、运行记录、认证材料始终不进入仓库 |

换设备：首次使用克隆 → 核对 → 确认；确认页默认启用每日起草与每周复盘（可取消），其他共享任务本机停用、逐个启用；多台设备同时启用时，起草前先同步，远端已有当天日记就不再生成；旧设备内容不受影响。

## 12. 移动端预留

本期不做移动端，但以下约束保证以后可接入：

- 数据只依赖 Git 仓库中的 Markdown、相对路径附件和 JSON 设置，无桌面专有数据库。
- 日期命名、目录约定、模板与任务定义写在仓库内，规则可在其他端复现。
- AI 任务定义与运行分离：移动端可只读查看产物，或通过 CCLink 远程能力请求桌面执行。
- 富媒体只用标准 Markdown 与普通文件。

## 13. 重新定位

失联时直接显示：上次位置、选择移动后的文件夹、核对最近一篇后确认。所选目录必须是原项目；原位置出现其他日记时两边并列、用户选择；不移动、不合并文件；也可改走首次使用。

## 14. 项目设置

显示名、类型（只读）、项目目录（可在 Finder 打开）、日记目录、时区、模板、AI 运行时状态、Git 同步状态与设置、更换项目目录（走首次使用核对）。保存只改设置文件。

## 15. 异常与恢复

| 情况 | 行为 |
| --- | --- |
| 目录移走、外置盘未挂载 | 重新定位 |
| 设置损坏 | 说明原因，可按默认值修复；不覆盖原文件 |
| AI 未登录、额度、超时 | 起草失败显示原因与修复入口；可用空白模板继续写 |
| 起草与手写同时新建 | 独占创建，后到者打开已有文件 |
| 同步认证失败、断网、中断 | 本地照常使用，状态栏标记，可重试 |
| 拉取遇本地改动或分叉 | 阻止并说明；不丢本地内容 |
| 编辑中切项目或退出 | 未保存内容按草稿机制保留 |

## 16. 验收（用户可执行）

1. 首次使用：默认目录 + 新仓库、已有目录 + 已有仓库、新设备克隆三种路径；AI 检测通过；重启回到同一项目。
2. 每天：不做任何操作，到点后打开今天即看到自动草稿 → 补写保存 → 粘贴一张图片 → 回文件树定位；让 AI 重排今日待做，查看改动报告后撤销一次。
3a. 查询：问 AI 某个主题在哪些日记出现，回答列出可打开的引用。
3. 每周：修改复盘章节要求，手动与到点各运行一次，核对产物。
4. 同步：A 写日记并上传，B 检查、审阅、拉取后看到正文与图片；B 有未上传改动时拉取被阻止。
5. 失联：移动目录后重新定位成功，身份不符被拒绝。

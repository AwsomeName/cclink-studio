### 本批修复

- 新增按项目身份重新定位：主进程只在原目录无法证明同一身份时提供；候选目录必须带原项目身份。原路径重建的无身份目录不再被当成复制件而触发身份分叉。
- 首次确认或 Git 切换后，关闭被替换的默认目录标签；目录和文件保留在磁盘及历史项目中。
- 「今日空白模板」原含 HTML 注释，编辑器因此拒绝编辑；改为纯 Markdown 提示行。
- 文件树在打开编辑标签或重新加载项目后，自动展开祖先目录并选中当前文件。
- Git 首次拉取可指定空目录；非空目录、用户目录外或符号链接目标被拒绝。日记固定项目的「确认改用此副本」改为切换项目目录，不再写旧版外部关联。
- 本机 Codex 把进度旁白与最终回答拼成一行作为结果，周复盘首个二级标题因此失效（见 [修复前样例](acceptance/before-fix-weekly-manual.md)）。现在结果只取最后一条回答，完整文本按消息分段。

### 建议实施顺序

1. **每日自动起草闭环**：首次确认创建并启用两个内置任务；补跑改为「今天没有日记就补当天」；生成前检查远端；今天页改为等待 / 起草中 / 已生成摘要 / 失败四态并显示本周计划。这是日常主路径。
2. **去掉任务关联与旧资料接入**（D3、D5）：定时整理直接列任务，旧关联用户迁移提示。
3. **首次使用四步**：确认前不写入（D2）、AI 检测、核对页列出将新建内容。
4. **AI 修改改动报告与撤销**：修改前快照、每文件差异、撤销。
5. **Git 原位快进与自动检查**（D4）。
6. **历史年月视图、含 HTML 切源码、状态栏 AI 状态、项目设置补项。**

## 状态、权限与诊断

固定入口与本机项目身份由 WorkspaceStateService 管理；可共享的目录、时区及项目属性由现有 workspace-settings 管理；Git 以真实仓库为准；任务执行与历史由 scheduled-task 服务管理。renderer 只保存导航和未提交表单。所有文件操作复用授权的主进程入口，检查目录边界与符号链接。通过现有 Git 认证途径处理凭证，诊断不写令牌或私有日记正文。取消初始化、切换失败或 Git 不可用时保留可恢复的本地工作现场。

先验收工单 1 的两个纯本地流程，再扩展 Git 和 AI。检查记录分开列“用户可执行结果”和“工程门禁”；真实运行未通过时保留待办。发布、真实资料推送和启用用户设备任务另按明确授权执行。

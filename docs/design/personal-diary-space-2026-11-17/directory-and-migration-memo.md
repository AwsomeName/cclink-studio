# 我的空间 · 日记项目目录与旧项目迁移备忘

2026-11-20 · 用户已确认第一版目录约定。适用于日记类型的项目。「我的空间」是默认项目名，文件夹可取其他名字。以下使用现有 Studio 能力，并单独标出需要补的产品行为。

## 用户怎么验收

在另一台 Mac 打开「我的空间」，从私有仓库的迁移分支克隆到新目录，确认资料来源。打开旧日记能看原图，从首页继续写能回到同一文件；能打开周计划、留存的会话记录和参考资料。每日简报和每周计划各出现一次，在这台电脑上由用户选择启用。旧 Mac 上的文件、未提交修改和私有任务仍在原处。

## 已确认的目录约定

以下以旧项目为例。新项目的资料根目录默认叫「个人计划」，接回旧项目时直接选择「000-个人计划」。资料根用仓库相对路径表示。示例中的业务目录按需出现，用户不用先建齐文件夹。

```text

├── 000-个人计划/
│   ├── 2026/
│   │   ├── 11/
│   │   │   ├── 1116_周一.md
│   │   │   ├── 1117_周二.md
│   │   │   └── 1117_周二.assets/       # 这篇日记引用的图片等附件
│   │   └── 周计划/                     # 沿用原周计划文件名
│   ├── 一日生活计划.md
│   ├── 精神内核思考.md
│   ├── 项目记录/                       # 按事项长期维护的文档
│   ├── 会话记录/                       # 个人选择留存的完整对话或摘要
│   │   └── 2026/11/1117_电源方案复盘.md
│   ├── 定时任务/                       # 可选，供人阅读和维护的任务材料

│   │   └── <任务ID>.json
│   └── scheduled-tasks/                # 当前项目本机私有任务，留在原设备
└── …                                   # 原仓库中的其他业务目录仍按原用途组织
```

### 目录约定如何生效

- **由日记类型提供默认值。** 新建日记项目和首次选择「从空白日记开始」使用 `个人计划/`，默认时区为 `Asia/Shanghai`。用户可在项目设置指定其他项目内相对目录和时区。已有项目沿用已保存的资料来源；可选目录按需建立。
- **由项目设置携带差异。** `.cclink-studio/workspace-settings.json` 使用 `type: "diary"`，以 `diary.directory` 和 `diary.timezone` 保存位置和时区。将设置纳入 Git 并提交后，「我的空间」会从新副本读取这两项，在用户确认后接入。缺少映射的老仓库仍可手动选择。本机外部来源的绝对路径和任务启用状态属于当前设备。
- **由同一个日期规则定位文件。** 首页、准备当天文件和每日简报的输出核对都按项目时区的年/月和月日定位。当天目录内已有兼容名称就沿用；多份候选交由用户选择。新建采用独占创建。历史合并月份或其他自定义结构列入迁移清单。
- **用实际操作验收。** 新建日记项目，核对资料根和时区；关联旧目录并重复准备今天，核对正文和附件；把目录名和时区不同的仓库克隆到新位置，确认新副本按其配置预览，重启能继续写。两项原任务的输出另行核对。

## 旧项目怎样迁

1. **先收目录和样本。** 两三层目录树，一篇带附件日记的相对路径和图片引用，一份周计划，两项任务的完整指令、周期、时区、共享状态及输入输出；另列已有会话记录是什么格式、希望带走哪些，以及有哪些跨目录引用。此阶段可脱敏，无需提交全部正文。
2. **划定私有仓库范围。** 可只纳入个人资料和经核对的依赖，也可沿用已有整仓。先检查将要上传的文件与已有提交历史，保留原目录层级并记录基线提交。项目设置和共享任务走现有 Git 规则；本机身份、会话快照、运行记录及凭证留在设备上。
3. **在新克隆的独立分支整改。** 先提交迁移清单，逐项记录旧路径、目标相对路径、引用方和处理意见。优先沿用旧目录；确有必要时只在迁移副本调整，并在同一提交修复关联链接。两个旧任务分别核对，每日简报截图显示为私有，每周任务以实际定义为准。
4. **在「我的空间」接入迁移分支。** 填远程地址和分支，克隆到全新目录，核对个人资料根、时区、计划文件与任务后确认连接。先抽查历史和会话文档，再用隔离副本跑两个任务。对同一天重复准备，核对没有第二份日记，已有正文与附件完整。
5. **验收后合并。** 核对迁移前后的日记数量、附件、断链及任务输出样本，把刻意修改与意外丢失区分开。认可后将迁移分支合入日记资料仓库的主分支。日后检查更新、查看差异、拉取新副本、确认接入；有本地修改时先处理修改。要回退可重新接回保留的旧来源。

## 下一步：盘点旧项目

第一份交付物是旧资料映射清单。依据目录树、路径样例和两个任务的配置，逐项列出原路径、引用它的文件或任务、接入位置和待处理的问题。先在清单上确认仓库范围，再在独立副本中动手。

## 本轮验证

2026-11-20 使用真实 Electron、隔离资料与本地 Git 远端运行 `scripts/typed-workspaces-smoke.mjs`。新建日记项目得到「个人计划」和默认时区；在项目设置修改时区后写入配置。旧目录「000-个人计划」原位接回；另一个仓库配置为「旅行手记」和「Asia/Hong_Kong」，克隆后采用副本映射并显示原正文，重启恢复来源。原 Markdown、附件及任务定义通过逐字节核对。用户的真实 GitHub 仓库和第二台 Mac 待迁移时验收。

## 实现边界与迁移选择

现有功能支持选择个人子目录、准备今日日记、关联原任务、Git 克隆与审阅后接入新副本。共享的任务定义需在目标设备上确认启用。日记项目设置可携带资料根相对路径与时区。没有随仓库提交设置时可手动接回。已有会话文档可直接读取；会话一键保存 Markdown 仍是后续建议。

拿到目录清单后优先确定三件事：仓库收整套项目还是个人子目录及其依赖；哪些会话要保留全文、哪些只留结论；哪台 Mac 负责每日、每周自动运行。定下这三项即可开始第一轮迁移预览。

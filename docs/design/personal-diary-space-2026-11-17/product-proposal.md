# 我的空间 日记计划与 Git 接入产品方案

日期：2026-11-17。状态：用户已批准实施。本文冻结产品目标与兼容边界，不代表所有功能已实现。实施顺序：原日记与计划接回 → 两个原定时任务接回 → Git 拉取 → 受控更新；每阶段必须在真实应用验收，不移动或覆盖旧原件。

## 产品结论

“我的空间”以“每天一份 Markdown 日记”为中心，承接每日记录、跨项目推进、周计划、长期目标和定时整理。进入后首先看到今天的日记与下一步安排；已有资料通过原位连接展示，Git 是可选的资料获取和版本管理方式。

保留“我的空间 / 我的公司”两个固定入口。个人日记可以同时记录生活、研发和经营，不按内容自动拆分到公司。公司业务、账目、事务及原有资料关联保持不变。

## 用户验收动作先于工程拆分

| 用户动作 | 可见结果 |
| --- | --- |
| 连接现有 woniu-forward，确认个人计划目录 | 首页出现原日记、周计划和旧任务；没有复制日记、重建任务或修改原文件 |
| 点击今天日记，接着写，再退出重启 | 继续编辑同一个原文件；路径、日期命名、附件和相对链接保留；重启可再次到达 |
| 在当天尚无日记时点击“准备今天” | 运行绑定的原每日简报任务，显示实际状态和输出文件；同名文件已存在时打开原文，不覆盖 |
| 从首页打开每日简报 | 看见原任务的指令、资源、计划、启用状态和历史；打开原工作空间看到的仍是同一个任务 |
| 从 Git 拉取资料到新目录 | 原目录字节不变；拉取成功后确认子目录映射，日记可打开，共享任务处于待本机启用状态 |
| 旧目录不存在、AI 失败、Git 断网或冲突 | 各自有原因和恢复动作；其他本地资料可用，不用空文件或“已完成”掩盖失败 |
| 拉取远程更新之前审阅变化 | 明确看到新增、修改、删除及影响的任务；旧资料保护模式不向原目录应用更新 |

上述是后续真实应用的验收标准。效果图的点击和布局检查仅验证设计表达。

## 一天的使用过程

1. 点“我的空间”，进入“今天”。有今日日记时直接展示原文预览和“继续写今天”；没有时展示“准备今天”。不因打开首页就调用模型或运行任务。
2. 每日简报读取原日记和已确认参考文件，生成昨日总结、今日待做、强调事项、今日打卡。体重、睡眠、收支、运动等未知事实保持空白。建议和真实完成情况分开表达。
3. 白天在原 Markdown 中持续记录；不强制填写新表单或把原有自由文本转换为任务数据库。
4. 首页“昨日遗留 / 今日安排”来自原日记对应段落或已经完成的整理产物，带来源入口。没有相应段落时显示“尚未整理”，不把临时模型推测当事实。
5. “计划”集中到达原周计划、项目记录、一日生活计划及长期思考。周末或周初由原每周计划任务继续整理。

普通重启仍恢复上次工作现场；主动点击固定“我的空间”进入“今天”，保留原来打开的编辑页。今日由用户确认的时区计算，任务发生日期沿用其计划时区。

### 今天

中间是当天日记预览，保留原四个章节和自由记录风格。右侧紧凑展示本周计划与两项整理任务；来源路径在标题附近可见。首页不新增统计分数、虚构完成率或大量空卡片。

日记状态分别处理：已存在→继续写；尚未创建且已绑定任务→准备今天；没有任务→创建空白日记或配置整理；运行中→查看进度；AI 失败而模板已落盘→打开模板并明确失败；目录不可用→定位原目录。

### 日记与计划

日记使用年/月和日期列表；一日可以有多份原文件，不为“统一格式”改名或合并。存在同日多份文件时让用户选择今日主文件。计划按本周、长期参考、项目记录组织入口，内容仍为原 Markdown。普通搜索限于用户接入的路径。

### 来源与编辑上下文

首版连接一份主要日记资料源，源工作空间中可分别映射日记、周计划、项目记录和参考文件。临时笔记仍可放在默认个人目录。多份独立日记库的聚合不进入首版。

“我的空间”保留自己的固定工作空间，来源记录是带归属的引用，不把 woniu-forward 整体改名为个人，也不将个人与公司固定入口绑定到同一根。

首页可展示已授权来源的只读内容投影。点击“继续写”“编辑计划”或“编辑任务”时，通过原空间切换和原资源 Tab 打开；顶栏实际高亮切到来源所属空间，显示“来自我的空间 · 返回今天”。如果来源已是公司固定空间，遵循其实际归属。回到“我的空间”后刷新同一原文件摘要。

这一取舍让第一版有一次显式空间切换，但能保住原文件、原任务、会话、权限和编辑器生命周期。不能为了让顶栏一直高亮个人而在后台偷换写入范围。未来若要在个人壳内直接编辑多空间文档，应另做跨空间编辑产品与架构评审。

## 现有资料怎样接进来

“接入已有目录”是推荐入口，与“从 Git 拉取”“从空白开始”并列。

1. 从已打开/历史工作空间中选 woniu-forward，或明确选择现有目录；不扫描整台电脑。
2. 只读识别候选目录及文件。按截图建议以下映射，必须在实际接入时核实路径：

| 用途 | 建议映射，均相对 woniu-forward 根目录 |
| --- | --- |
| 日记 | `000-个人计划/{年}/{月}/` |
| 命名 | `{月日}_{中文星期}.md`，例如 `1117_周二.md`；现有文件名不改动 |
| 周计划 | `000-个人计划/2026/周计划/`，实际以目录选择为准 |
| 项目记录 | `000-个人计划/项目记录/` |
| 作息参考 | `000-个人计划/一日生活计划.md` |
| 长期参考 | `000-个人计划/精神内核思考.md` |
| 附件 | 原 Markdown 引用的相对路径及同级 `.assets` 文件夹 |

3. 展示接入预览：将显示哪些文件，哪一份作为今日日记，关联哪两项任务。识别只是建议，多候选不默认取第一项。
4. 确认后仅保存本机连接和映射，不改写原文、目录、文件名、附件、任务定义或 Git 配置。既有稳定空间身份直接复用；不得为接入执行初始化/迁移钩子去重写旧资料。
5. 连接可解除；解除只移除个人首页引用，不删除文件、项目登记或任务，也不擅自暂停原已启用任务。界面明确显示“原任务仍按原设置运行”。

目录缺失时保留原连接并支持重新定位；定位到另一个副本不能继承旧运行授权。只读目录允许查看，创建与保存给出明确原因。路径越界、符号链接及附件仍受来源工作空间边界校验。

“不覆盖原文件”约束接入、初始化、自动整理和默认 Git 更新行为。用户主动打开原文编辑保存仍是正常写作；产品不得把这项保护变成所有日记永远不可编辑。

## 两个旧定时任务怎样接进来

### 同一台电脑 原位连接

按原来源的稳定工作空间 ID 和任务 ID 关联“每日简报”“每周计划和总结”，不是按同名复制。任务归属、指令、计划、输出、启用状态与运行历史不变。接入动作本身不启用、重跑、补跑或暂停任务。

新首页显示原任务实际状态及下次时间；立即运行和编辑均调用原任务入口。原界面与新首页不允许显示两套互相矛盾的状态。两个来源有同名任务时显示来源并由用户选定。

截图里的每日简报标记“不随 Git 共享”，所以在当前机器连接旧目录能沿用；在新机器只 Clone 仓库，不能承诺这个私有任务也会出现。每周任务是否共享需读取实际定义，不能从名称推断。

### 计划与路径确认

接入先展示原定时配置，不自动把截图中的 00:40 / 下次 01:40 差异纠正为某个时间。后续真实接入应核验已保存定义、未保存草稿、时区和调度快照；页面统一展示经过核验的保存值。

截图任务文本含旧机器绝对路径。原位接入不替换文本；若换电脑或拉取新副本，显示旧路径不可用，并预览替换成来源内相对引用的具体变化，由用户确认保存。任务名、正文、资源、输出路径及模板分别检查。

### 同名日记与失败

准备今天先查原文件：存在则直接打开。任务执行时再次采用 create-only，处理“预检后用户先创建了文件”的竞争，不覆盖、不偷偷生成第二份同日日记。需要重新整理时结果留在任务历史，用户比较后决定是否手动摘入日记。

AI 失败且已有失败模板时，可以创建模板文件，但任务仍显示失败；没有模板则保留明确失败，不补假内容。未知健康和财务字段为空。跨年/月输出规则需要新增可验证的目录解析，现有文件名变量不等于已经支持动态目录。

应用完全退出后不运行。关闭整理页面不暂停任务；缺模型/网络只影响整理，不阻止查看和手写。遵守现有错过和补执行策略，在 UI 给出事实；不新增系统后台服务。

## Git 的完整产品流程

### 三种入口

| 场景 | 用户看到的入口和动作 |
| --- | --- |
| 资料已在本机 | “接入已有目录”，识别是否为 Git 根；复用已有 remote/branch，不改配置 |
| 资料只在远程仓库 | “从 Git 拉取”，填 HTTPS/SSH 仓库地址、认证、分支和新的本地目录，完成 Clone 后确认个人计划子目录 |
| 从零开始 | “创建本地日记库”，先可离线写作；以后显式初始化 Git、关联远程和首次提交 |

Git 仓库根和日记子目录分别展示。例如仓库根是 woniu-forward，日记仅位于其中的 `000-个人计划`。普通 Clone 拉取整份仓库，不声称只下载一个子目录；首版不做稀疏检出。Git 状态和提交也以整仓为范围，必须显示仓库名与文件清单。

Clone 只使用新建的目标目录，目标已存在且非空时转为“接入已有目录”或重新选地址；失败保留原连接和旧资料。成功下载但还未确认映射时，不自动替换正在使用的日记源。

### 设置与认证

Git 页显示资料源、仓库根、远程地址、当前分支/上游、最后检查时间；提供连接检测、认证配置、提交姓名与邮箱（限定当前仓库）以及明确的操作入口。

支持通用 HTTPS 与 SSH 地址，不把 Git 等同于 GitHub。HTTPS Token 经本机既有凭证服务管理；SSH 只用用户明确选定的本机密钥及可用认证路径，不调用系统钥匙串。密钥/Token 不进入仓库、共享任务、普通设置快照或日志。没有 Git/认证失败时仍可写本地日记。

已经存在的 remote 不静默覆盖。向已有远程发布个人目录前展示仓库范围和选中的文件；“选择日记子目录”不会使整仓 Push 变成子目录 Push。原仓库的既有提交可能包含其他资料，第一次推送必须展示这个事实。

### 把四个动作分开

1. **从 Git 拉取资料**：首次 Clone 到新目录，随后配置连接。
2. **检查远程更新**：Fetch，更新本机 Git 对象/远程引用，不应用到工作文件；保留上次检查时间和失败原因。
3. **查看并应用更新**：会改变当前副本的工作文件，必须先展示变更与目标目录，不能把 Fetch 成功写成日记已经更新。
4. **提交并上传**：选文件、看差异、填提交说明后显式 Commit/Push；不因日记保存或定时任务完成就自动上传。

首次 Clone、Fetch 和 Pull 的语义分别依据 [Git Clone](https://git-scm.com/docs/git-clone)、[Git Fetch](https://git-scm.com/docs/git-fetch)、[Git Pull](https://git-scm.com/docs/git-pull)。

### 对旧原件的保护

本方案默认“保留原目录”：旧资料连接只支持检查和比较远程变化，不在原目录应用 Pull。需要使用远程版本时，提供“拉取到新目录”，原件保留，映射核对后由用户决定是否改用新副本。新副本不会包含旧目录尚未上传的修改，切换前必须逐项提示本地独有文件、改动和旧任务，不能把旧目录冷落后称为完整接回。

这与“保证原文件不被覆盖”一致。若后续用户选择对正在使用的副本应用更新，这是另一个明确授权的写操作，不能承诺所有原文件永远不变。

对可更新的新副本，首版仅支持人工触发的快进更新：编辑器已保存、Git 工作区干净、无运行中的写入任务、无分叉，预览的 HEAD 与文件版本仍一致才执行。更新期间相关写入短暂互斥，完成后重新加载；不能靠自动 stash、reset、force、覆盖文件或丢弃修改来通关。分叉或冲突保留现场并给出文件/分支及处理入口；合并编辑器不进入首版。

### Git 携带什么

- 日记、计划和附件：只有实际进入仓库并提交/上传的文件才会到另一设备；忽略、未跟踪或未上传的资料不会自动出现。
- 任务定义：用户显式选择“随项目共享”后才能提交。当前私有每日简报保持私有；需要跨设备时预览定义共享范围及路径调整，再由用户保存并提交。
- 映射：首版本机确认即可。跨设备自动携带日记库配置留到后续，不为本轮新增 `.cclink-studio` 共享文件白名单。
- 本机启用、历史、运行锁、权限、凭证和公司数据库：不借本功能进入 Git 共享。继续沿用现有 Git 敏感路径和 outgoing history 门禁。

新机器拉取共享任务后默认不启用；确认来源、计划、指令、输出和本机权限后再启用。共享定义更新使旧启用确认失效；冲突定义禁止运行。原私有任务不在仓库时提示“此副本没有原本机任务”，可回旧电脑共享或显式创建新任务，不伪造恢复历史。

建议每日整理只在一台常用电脑启用；Git 不提供多设备单次执行保证。副本切换不自动暂停旧任务或启用新任务，需要分别展示并处理，以免两边继续生成。

## 复用与新增边界

现有基础：Markdown 编辑、文件与 Tab 恢复、固定空间入口、原定时任务、create-only 产物与失败模板、任务定义 Git 共享、本机 Git 状态/Diff/Commit/已有上游 Push。

需新增并验收：个人日记首页、显式资料映射、原任务关联投影、跨月年目录、Clone 与映射闭环、统一远程配置/认证入口、Fetch 与受控快进更新。不能把现有“备份到 Git”视为这些能力已经完成。

来源关联由现有工作空间状态所有者保存，原资源与任务归属不变；任务状态仍由 ScheduledTaskService 拥有，Git 操作由 GitWorkspaceService 拥有。首页没有独立调度器、Git 同步器、任务数据库或隐藏执行会话。来源监听随页面生命周期释放；任务仍按原运行时生命周期运行。

实际实施前确认跨来源只读引用契约和接入阶段零改写的可行性；如需改变 ADR 0024 的固定空间或架构宪法，必须另立 ADR，不能用界面小修掩盖。

| 2 每日连续使用 | 原两项任务接回；准备今天、运行状态、原产物、同名保护、跨月年可验收 | 复用调度与产物 owner；任务 ID/历史一致、竞争创建和失败模板验证 |
| 3 新机器接入 | Git Clone 新目录→映射→打开日记→确认共享任务并运行 | 新目录保护、认证、取消/失败、子目录识别、任务默认停用及本机状态隔离 |
| 4 明确的版本往返 | 检查更新、差异、提交上传、新副本快进更新；旧原件保持保护模式 | 与编辑器/调度写入互斥；仓库范围、冲突/分叉、敏感路径与断网验收 |

每一阶段都先通过真实 Electron 的可见操作，再汇报其用户功能；源码编译和 mock 不能算“日记已接回”。侧栏调整随上述入口一起落地，不独立拖成基础设施阶段。用户已授权按此顺序开始实施。

## 拷问结论

- 只放“新建笔记”或日历皮肤，仍要求用户重建旧资料和旧任务，未满足承接目标。
- 日记是个人持续记录，可以跨多个项目；拆到每个项目会丢失这条时间主线。
- 同机引用旧任务可以保留历史；Git 新副本只能获得已共享的定义，不能伪造历史和执行授权。
- 一个“同步”按钮混合 Clone/Pull/Push 会掩盖影响范围；原目录完全不变与原地 Pull 必须明确取舍。
- 首页可整合阅读，首版编辑仍显式进入来源。若用户要求编辑也始终留在个人页，这是下一项需要单独确认的交互与架构变化，不能悄悄以第二空间 owner 实现。
- 首版先承接一份主日记库；多库聚合、无人值守 Git 同步、复杂合并和多设备调度协调暂不扩张。

## 2026-11-17 实施约束收敛

用户再次明确“确保不移动或覆盖原文件”。本轮把 Git 应用更新统一收敛为 **检查远程 → 审阅文件与正文差异 → 下载已审阅提交到全新副本 → 用户确认连接**，包括此前新拉取的副本也不原地快进。旧目录、旧 HEAD、未上传内容与私有任务保留；有未提交文件、分叉或预览版本变化时阻止快捷更新。此方式替代前文的新副本原地快进路径，不新增编辑器/Agent/定时任务共享写锁，不靠关闭原功能绕过保护。复杂合并与原地更新不属于本轮交付。

首页导航落在工作台侧栏，正文展示磁盘已保存版本，继续写打开原资源。准备今天包含两个明确动作：已关联且输出路径匹配的原每日简报可运行；离线可创建未知事实留空的今日模板。原任务输出不匹配时展示期望路径并打开原任务核对，不替用户改写定义。任务目录支持 `{year}/{month}/{day}` 日期变量，沿用原任务时区，文件名沿用已有变量。原有静态目录定义不变。

Git 新副本使用用户目录内 `CCLinkStudio-Git/diary-*/repository`，主进程独占创建，避免手输目标覆盖已有目录；成功后明确显示完整路径并确认个人资料子目录。HTTPS 账号/Token 首版仅用于本次操作，完成或失败后清除，不持久化新认证字段；SSH 明确指定私钥，使用已有 known_hosts，不调用钥匙串或 SSH agent。整仓提交/上传复用原仓库变更入口，不因 Fetch、日记保存或任务结束自动上传。

本轮真实应用验收必须增加：可点击侧栏、原正文预览、离线新建及重复创建、实际 Git Clone、Fetch 期间原工作文件不变、本地改动在 UI 和主进程均阻挡更新、审阅后新副本切换、共享任务不启用、再次重启与原件逐字节比较。隔离本地 Git 远程可验证传输语义，不能替代用户私有服务器的 HTTPS/SSH 登录验收。

# 真实生产资料与验收手册

## 本次已验证的事实

**2026-11-26 本机只读研究。** 实际样本为桌面“生产”下的 FPC生产文件（左眼 V3.0、右眼 V4.0、一个左眼 ZIP），以及独立的 20260210_pcb_原理图 工程。没有把两组材料视为同一块板，没有将原件、私有截图或其几何放入交付物。以下实测运行现有代码和一个外部 CAM 工具。本次没有运行新版 Studio 产品流程。

| 怎么测 | 观察结果 | 对实现的约束 |
| --- | --- | --- |
| 直接调用当前 HardwareService.inspectProductionPackage，分别选择两个散目录，再选共同父目录。Node 载入仓库 TypeScript，仅用本机目录代替 Electron 的 app.getPath | 单独选任一侧均显示 blocked、“缺少 Gerber 生产包”；父目录显示 quote-only，选择左眼 ZIP、右眼 BOM 和右眼坐标，同时提示没有识别到包内钻孔 | 输入集合要支持散目录和 ZIP；按板号/侧别/修订关联。现有 primary 选择是候选，不可作为交接默认 |
| 用独立 CSV 解析按 GB18030 解码，再比对现有解析器的行数与位号。两侧各自分别处理 | 各 6 行 BOM、17 个唯一位号、17 行坐标；各自集合双向差数为 0，两侧各 4 个顶面及 13 个底面。表含 Center-X、Ref-X、Pad-X 等不同基准及对应 Y，均标 mm。中文字段直接按 UTF-8 解码会有问题 | 显式显示编码和列映射，保留明细及 Fit/Variation。位号、面别相等不意味着来自同一版或方向正确 |

| 检查两侧制造文本及当前几何解析。原 GKO 含英寸与 2:5 坐标格式；钻孔 TXT 含 M48、INCH,LZ、刀具表及镀孔声明 | 左右 GKO 分别输出 34/36 段、各 0 个闭合候选、各 0 个警告。内容内未见上述候选文件的 TF.FileFunction 声明。TXT 可识别为钻孔程序；未证明所有孔/槽加工要求齐全 | 有线段及无警告均不足以证明实际板边。辨认 .TXT 并防止把 drill report、图例或测试点文件当钻孔。几何中保留原单位和显示单位 |

| 通过现有 Altium 解析模块和锁定依赖读取原文件，解析完成即丢弃渲染产物 | 3 份 SchDoc 和 1 份 PcbDoc 均返回 altium-drawing；PrjPcb 提供 6 条引用。在同一对照批次，两个材料根合计 66 个非隐藏常规文件的 SHA-256 读前/读后相同 | 这是解析链实测。真实 Electron 的逐图、隐藏文字、TOP/BOTTOM/MID2 和缺失引用验收记录在 11 月 8 日，未在本轮重新操作 Altium GUI。[历史验收原文](../../../testing/altium-readonly-preview.md) |

**再核代码后的两个缺口。** sourceEditable 当前只看是否存在被分类为 pcb-source 的文件，分类还包括单独 SchDoc 或 .kicad_pro。保存 Markdown 报告会重新调用 inspectProductionPackage，可能选出与用户刚审的内容不同的批次。因此应分别判断“有设计文件”“此动作有后端且输入完整”“有权写副本”，并按所审快照导出。[领域实现](../../../../src/main/hardware/hardware-service.ts)

**本机工具覆盖。** 常用 PATH 与 /Applications 没有发现 KiCad、LibrePCB、ngspice、KiBot；FreeCAD.app 存在，本轮没有据此验证装配。gerbv 临时使用上游 2.13.0 发行件与其附带库，下载包 SHA-256 与 GitHub release asset 的 digest 一致（7d79adf7556508baa6c9d080949866371cbb49809f2082e0e6639cb62c4dba0f）。没有下载或运行候选模型。没有获取工厂报价、DFM 或试装签字。

## 以后如何在 Studio 做真人验收

所有下列 R、A–G 均为**待执行的产品验收**。硬件负责人保存一份完整原件作为金样，原生 EDA、独立 CAM、工厂装配说明和关键实物尺寸构成不同类别的参照。异常注入只在独立工作副本中进行。记录日期、操作者、Studio/工具版本、输入和规则摘要、观察、截图/报告位置及失败项。私有证据留在授权的本地工作空间。

| 项目 | 操作 | 通过标准和证据 |
| --- | --- | --- |
| **R · 初学者读板（第一期）** | 请一位没有读图经验的用户在真实 Studio 打开 power_audio.SchDoc。让他选择“声音”，点 U9 看大意与原图定位。随后收起讲解，独立找数字输入及一个模拟输出，说明 U5 的不同作用；再问这两个器件在本板上的接线证据在哪里。 | 用户用自己的话讲清 U9 转换、U5 放大，能在原图指到 U9 的 1 脚 SDIN 和 7/10 脚其中一个；未提供连线证据时明确下一步是查原图或同版网表。用仅有 Gerber 的材料重试，不能凭空给出原理图或引脚功能。记录原话、是否需提示、错点和证据；没有真人结果时保持待验收。 |
| **A · 选择与交接** | 打开含两眼、左眼 ZIP 与两侧散文件的共同目录，选择右眼 V4.0 贴装；点选左眼 ZIP，观察阻塞；再改选右眼层。关闭并重开 Tab，导出所审报告 | 初始不拼接两侧。明示错配的两个来源和修订，阻止发布交接包，可保存问题报告。修正后每个条目都指到该侧或获准共用版本；能从报告回原文件。导出前更换同名文件，旧结果标过期，绝不以重扫覆盖旧批次。保存各阶段报告、摘要、截屏。离线免登录复测 |
| **B · 制造/贴装分项** | 选择右眼散目录，确认 TXT 钻孔头/单位；独立在 CAM 中打开。BOM 选正确编码，核 6 行/17 位号、17 行坐标和 4 顶/13 底。把副本中的一行删掉，添加 DNP、重复位号、表头歧义及第 101 行的漏项。切换裸板/贴装用途 | 复核报告列 NC 输入、来源/工具和未知孔型；把差异定位到原始行。DNP 及手插有人工依据、数量合理才可排除。重复及第 101 行异常不能被去重/分页吞掉。裸板用途不因缺 BOM 被拦，贴装缺坐标保持待补 |
| **C · CAM 与装配方向** | 打开相同的图层、钻孔、装配 PDF 和坐标；在独立 CAM 里查看。候选轮廓含开口或多个机械层时明确选层。核对三处非共线标志、非对称连接器 Pin 1、上下表面、镜像、原点、旋转零位和 mm/inch。将一份底层坐标错误镜像或改单位复测 | 待确认不绘可信叠加，修正后按厂方图纸允许公差记录三点残差与两面方向。记录宏、区域、负极性、圆弧、镀孔/非镀孔、开槽及步进重复的覆盖和失败项。用 Ucamco 公开测试档补边界，再以真包独立核对；某一层失败不抹去已验证层。[官方规范与夹具](https://www.ucamco.com/en/gerber/downloads) |
| **D · 自有 KiCad 改板** | 由工程师提供获准的真实板工程、配套图、项目规则/库和原生导出金样。在独立副本引入一个预期 ERC 问题、一个已知 DRC 间距问题或图板不符，保存并运行，再修复。记录实际能定位的图元/网络。按当前变体导出新包 | 错误、警告、豁免、工具失败有不同状态。JSON 报告可与原生 KiCad 按规则/对象对上，新修订输出 Gerber、NC、BOM、坐标和可用 STEP；所有适用产物回到 A–C。原件字节恒定。无 CLI 或缺关联图时相应检查不可用，其余工作照常 |
| **E · Altium 兼容** | 打开历史样本三份原理图、LCD 板、工程；切 TOP/BOTTOM/MID2、隐藏文字、缺失引用和损坏文件。挂入工程师从对应原版生成的报告及 OutJob 输出。若试迁移，原生 KiCad 导入新目录，逐网、逐层和 Pin 1 对照 | 原文件仍只读且哈希相同，只有可访问引用可开。原生报告与 Studio 预览分开标来源。迁移列网表引脚差异、叠构、规则、孔槽、变体及制造差异，关键项未闭环不能签迁移。当前这批 Altium 样本不能用于推定 FPC 有源 |
| **F · 板壳/柔性验证** | 用同一修订 ECAD 板形、封装高度、壳 STEP、连接器规格和装配基准在 Studio 对齐；工程师独立量第三点、Z 高度与插接方向。用获准状态模型切换开合，制造/结构方提供叠构、补强与弯折条件 | 报告列姿态、单位、坐标变换、校验残差、容差依据和未覆盖区域。故意翻面/置换旧壳后结论变为未决。样件试装核壳柱、连接器和弯折区；动态弯折寿命留给对应实测。无 MCAD 模型时保留二维核对并标“待结构资料” |
| **G · 仿真及模型助读** | 电气工程师先用有解析解的 RC 基准核单位/瞬态，再用真实局部电路的获准模型、引脚表、负载、供电和台架波形比对。OCR 对匿名装配图隐藏真值，人工记录每项证据 | 记录网表/模型哈希、激励、温度、求解器版本、收敛、预期容差、实测偏差。缺模型和不收敛分别显示。模型错读和弃答入表，任何答案可定位页码/标注区域；OCR、仿真均不能覆盖 DRC 或工厂结果 |

**横向恢复必测。** 同时打开两个工作空间、快速切换版本、取消解析、重建窗口、重启或暂停外部工具。界面应标清取消／中断或失败原因，允许重试、回上一批和导出残留问题清单；旧结果不写入新工作空间。试一次损坏 ZIP、超限 XLSX、越界链接、同名不同摘要、目标目录只读和写盘中断。记录 UI 处置、输入前后指纹与是否留下半成品。实现时跑受影响工程 smoke 和真实 Electron 路径；脚本通过不能代替现场核方向、板厂 DFM 及实物试装。

**生产包复核所需人员与交付。** 一位熟悉生产资料的硬件或贴片工程师可用已有两侧文件独立完成 A/B；只需再提供对板号/版本、用途及共享材料的归属说明。C 需原生装配方向或厂方约定；D 缺同版真实 KiCad 工程与违规金样；E 的迁移分支缺原生规则/输出基准；F 缺已确认的同版装配坐标、公差及实物；G 缺授权模型及测量记录。读板 R 过关后交 A/B，然后按实际补件推进，不让后续依赖挡住首期。

## 原型校验

使用本机 Chrome 和 Playwright 打开 workbench.html，核对初始“左右眼资料混用”、改选同版后“待核对连接器方向”，再切右眼、关外形及铜层。1440、1024、800、390 像素宽度无横向溢出，未捕获页面错误。按 1440 像素宽完整截图并逐图查看中文、颜色图例、未执行状态和“方案示意”标记。展示板图为人工合成，未引用任何客户图层。

2026-11-27 用仓库锁定的 altiumts 只读解析真实音频图，按符号归属核对 U9/CS4344、U5/PAM8404KGR 两组位号与引脚。读板示意只绘器件功能，尚未对两者的板级网络或实物工作状态签认。

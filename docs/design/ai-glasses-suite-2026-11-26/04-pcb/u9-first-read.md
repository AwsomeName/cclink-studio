# 第一版导读｜在自己的 Altium 图上追一段声音

**体验目标**　打开音频原理图，点 U9，能够说出数字声音怎样变成左右声道；问“声音接下来去了哪里”，亲自沿着原图走到功放和板上的输出接口。收起提示后，能自己找出一根输出脚，并解释中途为什么要跳到另一处同名标签。[打开交互原型](read-board.html) · [查看效果图](read-board.png)

## 你实际会看到什么

| 你的动作 | Studio 的回答和图上动作 |
| --- | --- |
| 在黄色矩形上点 U9 | “U9 是图里这颗芯片的编号，CS4344 是它的型号。数字声音从左边的 SDIN（1 脚）进来，转换后分成两个模拟输出，左声道 AOUTL（7 脚）和右声道 AOUTR（10 脚）。”三处引脚都能点；电源、地和时钟保持原样。 |
| 问“声音接下来去了哪里？” | 默认沿左声道示范，随时可换右声道。“先看右侧的 7。顺着这根线，碰到的第一件东西是电容 C83。”画面保留 U9 与 C83 的相对位置，绿色线段只盖到元件端点。 |
| 继续沿 C83 向右看 | “越过 C83，遇到一个分叉。去功放的方向经过锯齿形的 R49，再到写着 AUDIO_L_O 的线。”C83（10 µF）让变化的音频通过并隔开两侧的直流电位。点分叉可查看 R50 接地，以及 R49 后面 C87 接地的支路。 |
| 点 AUDIO_L_O | 先圈出源端文字，再跳到本页 U5 左侧的同名文字。保留“上一步”回到源端。“原理图可以用名字把画在不同位置的同一个网络连接起来。这一端先接电容 C35，再到 U5 的 INL+（20 脚）。” |
| 再沿功放输出看 | “U5 利用电源提供的能量驱动扬声器。左声道由 OUTL+ 和 OUTL− 两脚配成一对，走到连接器 J9 的 3、4 脚。”原图隐藏了 J9 的位号，导读从元件属性读出名字，落点在真实的连接器符号上。板外的线束及扬声器对应关系需装配图或实物。 |
| 收起提示，自己找 | 不显示路径答案和高亮。点 SDIN，得到“这是数字声音的入口”；点到另一个声道，提示看 AOUT 末尾的 L/R；点对后出现原图端点和脚号。点对后再进入功放侧的无高亮原图，从同名网络沿线点出 U5 输入脚。两题都可切换声道。 |

离线 HTML 使用当前样本的三个真实预览裁片和附着在同一坐标系的定位层。支持点选器件、输入本课问题、顺着推荐问题继续、切换声道、回看、放大原图及自测。文本输入只识别本课的作用、入口和去向意图。正式 Studio 中的入口应在现有只读图纸 Tab；样本原型已能走完，产品接入与真人理解测试待实施。界面里“当前路径”显示当前所选阶段的主路径，直接点位置导航会切到相应阶段。

## 图纸到底怎样连

左声道从 **U9.7 → C83 → R49 → AUDIO_L_O → C35 → U5.20**，U5 再从 **2、5 脚 → J9.3、J9.4** 输出。右声道从 **U9.10 → C82 → R47 → AUDIO_R_O → C22 → U5.16**，U5 再从 **14、11 脚 → J9.1、J9.2** 输出。两句话里的箭头描述信号阅读方向。每次越过电容、电阻或功放，进入下一段网络或器件功能；电阻和电容符号自身没有本课所示的信号方向属性。

| 电气关系 | 左声道，同一格中的脚同网 | 右声道，同一格中的脚同网 |
| --- | --- | --- |
| DAC 输出到第一颗电容 | U9.7、C83.1 · NetC83_1 | U9.10、C82.1 · NetC82_1 |
| 第一颗电容另一端到电阻 | C83.2、R49.1、R50.1 · NetC83_2 | C82.2、R47.1、R48.1 · NetC82_2 |
| 有名字的主线 | R49.2、C87.2、C35.1 · AUDIO_L_O | R47.2、C81.2、C22.1 · AUDIO_R_O |
| 功放输入电容另一端 | C35.2、U5.20（INL+）· NetC35_2 | C22.2、U5.16（INR+）· NetC22_2 |
| 功放正输出到接口 | U5.2、J9.3、C2.1 · +OUT_L_0 | U5.14、J9.1、C1.1 · +OUT_R_0 |
| 功放负输出到接口 | U5.5、J9.4 · -OUT_L0 | U5.11、J9.2 · -OUT_R0 |

**支路怎样读。** R50/R48 的另一端、C87/C81 的另一端各自接 GND。左声道的 C35 接到 INL+，邻近的 C36 则接到 INL−；右声道 C22 接 INR+，C23 接 INR−。在输出侧，OUTL− 与 OUTR− 都是功放输出。界面中应把每个声道的一对输出一起点亮，避免把负输出当作地。源图给出的阻容值可展开查看；实际音量、噪声和整机出声状态需要台架或整机记录。

## 工程师如何复核这一课

2026-11-27 本机使用仓库锁定的 altiumts 0.0.95 读取同一工程目录的 power_audio.SchDoc 和 LCD.PcbDoc。原图决定引脚、符号、导线及同名标签的位置。PCB 的元件源 UID、焊盘号与网络给出第二份核对材料。表中 Net 开头的自动网络名取自 PCB；图纸上可见的名字按标签原文保留，包括输出名里下划线的差异。U9、U5、J9 和该路径上的 12 个无源器件均核对了源 UID。

| 可复查的图上落点 | 本次样本定位（records 数组从 0 开始） |
| --- | --- |
| U9 与入口/出口 | 元件 244；SDIN 245；AOUTL 261；AOUTR 255；左/右输出到第一颗电容的导线 1738 / 1737 |
| 沿左侧导线查找 | C83 元件 200、R49 元件 38；导线 1741、1758、1744、1760；源端标签 35 在 (730,820)；远端标签 1378 在 (1183.84252,734)；导线 1861、1852 夹着 C35；终点 U5.20 记录 1361 |
| 沿右侧导线查找 | C82 元件 154、R47 元件 106；源端/远端标签 34 / 1379；远端导线 1862、1849 夹着 C22；终点 U5.16 记录 1353 |
| 到 J9 查找 | U5 左输出导线 1850 / 1859、右输出 1848 / 1860。J9 元件 1573；3/4 脚 1604/1606，1/2 脚 1600/1602；隐藏的位号记录 1612 |

- **几何正例。** 计算真实引脚外端（符号锚点加朝向及脚长），保留 Altium 分数坐标。按导线线段、端点、节点以及落在导线上的同页同名标签核对上述 12 组互不相同的网络。逐组与 PCB 焊盘核对，均吻合。例如 U9.7 的外端在 (380,820)，C83.1 在 (465,820)，恰好是导线 1738 两端。C35 两端分属两个不同网络。
- **断开反例。** 内存移除导线 1738 后，U9.7 与 C83.1 分离。把标签 1378 沿 Y 挪动一个图纸单位，C35.1 与 R49.2 的同名跳转消失。原始文件保持只读。
- **样本身份。** SchDoc SHA-256 为 `e71428d95facf7eb41dae384337c79cf5d2e46dce6e3759126db5f23dc8bef77`；PcbDoc 为 `f34dc2285d4c8187356368cfc118e67f582a8e22114007e5cd164b498124d48c`。记录号只在对应指纹内有效。几何核对覆盖本课的页内路径，尚未验证 Altium 全部层次网络或完整工程的电气规则。
- **手册的用途。** Cirrus Logic 的引脚说明解释 U9 的功能；Diodes 的器件页解释 U5 是模拟输入的立体声功放。板上具体经过哪些器件来自上面的连接证据。[CS4344 手册，第 4 页](https://statics.cirrus.com/pubs/proDatasheet/CS4344-45-48_F2.pdf#page=4) · [PAM8404 原厂器件页](https://www.diodes.com/part/view/PAM8404)

## 调研怎样变成第一版

借鉴 Flux 在图上指出提问对象的动作，选中的符号始终绑定实际源记录。借鉴 DRCY 从答案回到图纸的动作，把每句“连到哪里”绑定引脚组和落点。结合 PCB-QA 的结构化输入结果，把“通过哪些线连接”交给解析器核对。第一课用审核过的本地讲解；以后若接入模型，模型可以换一种方式讲同一条路径，路径、源引用和跳转目标继续来自图纸证据。[调研笔记](ai-circuit-landscape-2026-11-27.md) · [Flux Markup](https://docs.flux.ai/flux/reference/markup-mode) · [AllSpice DRCY](https://learn.allspice.io/docs/drcy-ai-design-review) · [PCB-QA 论文](https://arxiv.org/abs/2606.23704)

## 接进 Studio 的最小开发顺序

1. **用户能点到 U9 并返回原图。** 在现有解析 Worker 派生受限的元件/引脚摘要、图纸指纹及预览坐标变换。仍以隔离的原预览图承载图像，Tab 在图面叠加有键盘焦点的命中区域。复用文件授权、大小/时间限制、显示隐藏项开关及只读生命周期。渲染器获得同版有界坐标和文本，无文件系统路径执行权限。[只读解析入口](../../../../src/main/altium/altium-preview-parser.ts) · [既有预览组件](../../../../src/renderer/src/components/workbench/AltiumPreview.tsx)
2. **用户能追踪一条真实路径。** 首先把上表两声道做成经工程师核对、绑定样本指纹的导读。每步记录源/目标锚点、证据记录、关系类型（同网、经过元件、同页标签、芯片功能、板外边界）。主进程复用现有预览 worker 和共享契约，Tab 持有声道、当前位置、查看历史、叠层和缩放。点标签时先核其附着线与作用域，再跳到远端并保留返回位置。PCB 对照缺失时，已由同版原理图证明的段仍可查看，旁证显示“未提供”。
3. **用户能在出错后自己恢复。** 文件变化即撤下旧定位并重新读取；新修订找不到对应关系时，停在最后一个有依据的引脚，显示“需要此修订的原理图连接或网表”。若 PCB 与原图矛盾，同时呈现两端证据，请工程师确认修订；同名跨页、总线、重复位号或仅有 Gerber 时不沿用这个样本的关系。快速换页、取消和关 Tab 释放相应工作；晚到结果按指纹及请求代次丢弃。只有缩放失败时可以保留文字并提示原图位号。
4. **真人验收才算产品可用。** 一位初次读图者从空白选择进入 U9，能口述“数字进、左右模拟出”；收起提示后独立点中指定声道。再让他在图上指出第一颗电容、两处同名标签、功放输入和 J9 对应的两脚，并解释板外还要查哪份材料。硬件工程师按 12 组网络复核两份文件。换修订或挪开标签，在真实应用中必须看到路径停止。记录原话、错点、是否求助和停在哪里。[真人验收手册](acceptance.md)

**本轮验证。** Chrome 本机逐一走完两声道的图面点击、问题入口、分支说明、标签跳转、返回、功放至接口及两项找引脚练习；已检查桌面与窄屏排版。桌面 PNG 为左声道实拍原型。正式 Electron 原图 Tab 的交互、外部扬声器接线和真人学习结果仍待分别验收。

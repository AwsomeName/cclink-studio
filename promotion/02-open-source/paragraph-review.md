# GitHub 与开源社区稿逐段修订

现在可以直接阅读、修改和转用一套包含四张专用配图的社区长文；平台上传、公开发布和全新环境的模型执行演示尚未进行。

本轮保留 [初稿](article-v1.md) 与 [初稿预览](preview-v1.html)，精修内容在 [正文](article.md) 和 [预览](preview.html)。与公众号版共用视觉风格，叙述重点转为“能做什么、如何启动、源码在哪里、怎样参与”。

## 读者走到哪一步才算文章有效

读者看完应能说清产品及使用条件，找到源码与架构入口，按顺序准备环境、启动工作台、检查本地功能，再配置 Agent 并核对实际文件结果。文章提供了这些动作与入口；本轮未把它们全部在全新机器重跑，因此不以文稿完成替代安装或功能验收。

## 启动与试用

| 位置 | 需要解决的问题 | 本次处理 |
| --- | --- | --- |
| 第 8 段：环境 | 宽泛版本下限可能与当前仓库实际配置脱节 | 使用 CI 的 Node.js 22 与 packageManager 的 pnpm@11.5.0，并标出事实来源；macOS 13+ 与仓库目标保持一致 |
| 命令块 | 启动路径需要可照着做 | 保留克隆、进入目录、安装依赖、启动四步；不使用执行成功的样式包装操作说明 |
| 第 9 段：先用本地 | 把模型配置混进启动条件会提高试用门槛 | 先打开文件、编辑文档与浏览网页，明确这些动作免 CCLink 登录 |
| 第 10 段：再配 Agent | 运行时、认证和 Provider 容易混淆 | 分开本机/自定义 Claude Code 自身认证与内置 Runtime 的 Provider API Key；不暗示设置页代替所有 CLI 认证 |
| 第 11 段：排查入口 | 环境文字会随项目更新 | 以 CI、package.json、README 与开发指南作为后续核对入口，不把本轮版本写成永久要求 |
| 第 12 段：试用准备 | 长命令与能力表之后缺少小目标 | 建议使用可公开的演示材料，按本地功能与 Agent 分层检查 |
| 试用动作 1 | 只看到编辑器不足以证明文件保存 | 修改、手动保存、重新打开并确认落盘 |
| 试用动作 2 | 页面加载与同工作空间使用需要具体动作 | 切换网页和文档，检查材料与草稿能继续使用 |
| 试用动作 3 | Agent 自述不等于工具与结果成功 | 配置后做一项小任务，查看工具调用，再回读目标文件确认结果与保存状态 |
| 第 13 段：网页条件 | 站点差异与人工登录容易被“自动化”掩盖 | 明确页面、账号、任务范围和人工环节，不承诺任意网站任务成功 |

上手图采用纵向三步，保留环境、命令与使用条件，图注标明“上手顺序示意”。本轮没有额外跑安装、调用模型或提交网页任务来制造推广证据。

# 公众号稿逐段修订说明

这轮把公众号稿收束为一条读者能跟上的主线：准备一篇文章，组织材料，提出具体任务，检查和保存结果。原稿中重复的定位口号已压缩，五张配图分别承担封面、区域导览、任务特写、浏览器特写和分工说明。

当前材料仍缺少一次真实模型调用从指令到文档修改的完整录屏。因此，正文说明已有工具能力，截图只作为界面与任务准备的例子，不能把它们写成执行成功案例。

## 开头三段

标题收紧为“CCLink Studio 查资料写文档的开源 AI 工作台”，直接交代产品、用途和开源属性，减少手机端长标题占据的首屏空间。

| 段落 | 现在怎样写 | 为什么这样改 |
| --- | --- | --- |
| 01 | 以几个参考网页、一份笔记、一篇草稿和一个 AI 对话框开场 | 原来“做一件事情要打开很多工具”过于宽泛。先让读者认出一个具体场景 |
| 02 | 写清改到一半时要确认页面、草稿和结果去向 | 把“反复切换”的烦恼落到具体问题上，不编造节省时间或效率倍数 |
| 03 | 直接介绍 CCLink Studio 的产品形态和能力组合 | 合并原来的起点、愿望和定义三段，尽早让读者知道这是什么产品 |

## 资料与文档四段

| 段落 | 现在怎样写 | 为什么这样改 |
| --- | --- | --- |
| 04 | 假设要写一篇产品介绍，先打开存放素材的文件夹 | 用同一场景继续往下走；“假设”明确这是一种使用方式，不是假称真人案例 |
| 05 | 解释左侧文件树、中间文档或网页、右侧 AI 助手 | 让文字与工作台导览图对应，读者知道截图该看哪里 |
| 图注 | 标注真实界面、演示文档和区域编号 | 区分实际界面与外加说明，不把编号当成产品原生控件 |
| 06 | 说明稿件是本地 Markdown，能够手动编辑、保存和继续使用 | 将“资料有归属”改成用户可以判断的结果，并保留工作状态保存的准确范围 |

## Agent 协作五段与示例

| 段落 | 现在怎样写 | 为什么这样改 |
| --- | --- | --- |
| 07 | 解释 Agent 是什么，并把配置条件放在操作能力旁边 | 降低普通读者的术语负担，避免“打开应用就自带免费模型”的误解 |
| 08 | 用一句短引导引出具体任务 | 代替抽象描述，让读者看到如何开口 |
| 任务示例 | 梳理当前文档结构，保留观点，补充例子 | 与真实截图输入框逐字一致；任务包含对象、保留条件和期望动作 |
| 图注 | 明确是任务输入区局部，指令尚未发送 | 不让大字特写被误读成执行结果；完整原图另行保留 |
| 09 | 说明工具读取与写入、用户检查和最终取舍 | 将 AI 能做的动作与人要负责的判断放在同一段，不暗示全自动质量保证 |
| 10 | 说明讨论可以沉淀到具体草稿，后续可以继续修改 | 保留与聊天窗口相比最值得解释的产品价值，避免重复一遍全部功能 |

## 结尾四段

| 段落 | 现在怎样写 | 为什么这样改 |
| --- | --- | --- |
| 18 | 交代 macOS、GPL-3.0-only 和源码参与方式 | 给准备尝试的读者必要信息，不虚构其他平台下载能力 |
| 19 | 邀请从一份笔记、一篇文章或一份文档开始 | 用一个小任务代替空泛的“欢迎体验一切能力” |
| 20 | 邀请反馈操作步骤、卡点和期待的改法 | 让开源邀请有具体内容，也为后续改进留下清楚入口 |
| 21 | 给出项目与上手说明入口 | 文末只保留一个主要行动，不分散到多套尚未核对的下载和远程入口 |

## 配图处理

| 图片 | 这轮的改法 | 取舍与限制 |
| --- | --- | --- |
| 封面 | 将泛化口号换成查资料、写文档、AI 协作；缩减细碎标签 | 右侧为工作方式示意，不是伪造的产品界面 |
| 工作台导览 | 在完整原图外添加三块区域的编号与大字说明 | 手机端主要读编号与说明，细节仍可打开原图查看 |
| 任务特写 | 从原图截取输入区，以更大尺寸展示真实任务文本 | 不修改指令、按钮或状态；局部不包含 Agent 状态栏，正文和图注明确待发送；完整原图显示未连接 |
| 浏览器特写 | 取景保留真实文档标签、网页标签和页面内容 | 只说明标签切换与可见网页，不充当 Agent 已执行的证据 |
| 竖向流程 | 从横向四栏改成纵向四步，补充执行者 | 是协作方式示意，不是实时进度或实际运行结果 |

## 还要追问什么

这篇稿子已经能解释产品形态、入口场景、工具能力和使用条件。最有价值的下一份素材，是一段使用演示文档、真实运行 Agent、最终回读保存结果的短录屏；它能补上当前截图只有任务准备的证据缺口。

项目发起人的具体经历尚未提供，因此没有代写“我曾经每天浪费多少时间”之类个人故事。后续若补充真实经历，可以再调整开头，不影响正文主线。

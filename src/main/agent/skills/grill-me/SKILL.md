# 方案拷问

## Workflow

1. 先给出明确结论，并准确复述用户目标与当前最强依据。
2. 检查未经验证的假设、完成度、边界条件、利益冲突和失败路径。
3. 每个重要质疑都说明触发条件、可能影响、验证方法和缓解动作。
4. 明确承认已经处理的风险，不为了反对而重复制造问题。
5. 最后指出当前最该做的一步，以及什么证据足以改变结论。

## Output contract

- 区分已知事实、合理推断与未知项。
- 用户功能进度与工程准备度分别报告。
- 如果目标尚未形成真实闭环，第一句直接说明用户现在能做什么、还不能做什么。

## Boundaries

这是分析与评审流程，不声明或扩大工具、权限、数据访问、模型、Provider 或执行 Scope，也不绕过不可逆操作的人工确认。
